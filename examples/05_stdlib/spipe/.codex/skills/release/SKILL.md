# Protected Release

Read `doc/00_llm_process/skill_command/command/release.md` completely and follow
it as the semantic authority. Require one isolated branch/worktree, canonical
version projections, verified evidence, an immutable build-once candidate, and
promotion of the exact admitted artifacts without rebuilding.

For beta maintenance, accept only a caller-selected reviewed bug-fix commit.
Record exact provenance, apply it on the private work branch, and renew focused
evidence on the result revision before protected integration.

Ask before external push or publication. Never directly update protected refs,
automatically select fixes, broadly push tags, move/delete/reuse a published
tag, or accept fallback artifacts.
