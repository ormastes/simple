### N2 measurement admission

Before a benchmark run, pin a fixture manifest with the exact staged change or outgoing ref, eligibility and warm/cold state, repository/candidate and toolchain digests, host and runtime identity, policy and required gate rows. The staged-hook fixture exercises an ordinary staged Simple source edit; the one-ref fixture exercises a committed outgoing ref; the warm-preflight fixture exercises an eligible ordinary change with its cache state recorded. Collect at least 20 independent complete invocations for each selected N2 latency row, retain every raw duration and outcome, and calculate P95 by the nearest-rank order statistic (`ceil(0.95 * sample_count)`). A failure, skipped mandatory row, incomplete result or changed fixture does not disappear from the sample set or count as a passing run. Record Git network time separately from the complete local pre-push gate. No N2 PASS exists until the deployed pure-Simple path and these fixtures run successfully.

`src/app/build/scheduler/n2_latency_numeric.spl` implements only the bounded nearest-rank calculation and strict N2 threshold edges. Its focused spec is unrun under the current verification cap. A true numeric comparison cannot substitute for the fixture, mandatory-check, provenance, raw-sample, and deployed-runtime evidence above. The shared test-runner statistics helper uses interpolation and is not the N2 acceptance calculator.

Unit specs for the drafted contract, scheduler, receipts and submodule inventory are narrower evidence and cannot substitute for these end-to-end scenarios. The Clang controller spec includes a synthetic Ninja target that rebuilds mapped files and captures output bytes; it still needs a real C/C++ compile and policy-only collision scenario through the production launcher. The ZIP's 12 Clang counterexample probes do not prove the Simple adapter. The current deployed pure-Simple test runner exits 139 before new spec bodies run; run this plan only after an admitted current runtime is available, then record one result per criterion without repeating unchanged green checks.

Graph restart fault point: kill the parent after the journal admits a graph
action and before its request spool is durable. Restart the issued graph with
the same owner. It must revoke that exact unstarted attempt, advance its fence,
and select a fresh attempt without contacting the worker for the revoked one.
Repeat with a durable spool: the active attempt must stay fenced and resume
through worker status instead. An unrelated graph's active attempt sharing the
owner root must never be revoked by this graph's recovery pass.

Staged two-node qualification requires an administrator-issued plan, a pinned
native staged controller, two nonce-verified Linux OCI workers and a fresh
dedicated owner. Attribute this run's proposed producer and dynamically
resolved link attempts to durable accepted rows on different workers; verify
mounted operand paths, retained producer and executable bytes, cleanup
acknowledgements and an attempt-free repeat. Export the executable only under
a digest-pinned administrator policy row, then check its behavior through an
independently pinned isolated execution verifier. Missing prerequisites,
unsupported executable format or absent verifier must return `BLOCKED`; a
skipped live scenario is not a PASS. The current exporter admits ELF `ET_EXEC`
but not PIE `ET_DYN`, so that format needs separate qualification.

Failure classification gate (REQ-003, REQ-014): exercise native exits 1, 125, 126, 127, 134, 137, 139, 143 and 255 in both fresh and recovered worker paths. A known terminal nonzero exit must write an empty manifest, bounded diagnostics, a versioned failure proof and result wire in that order; the parent must verify the exact proof/status/diagnostics, journal one `action-failure-unclassified` row, free capacity and allow only the durable retry limit. No such exit may become `compiler-failure` from exit code or stderr alone. Missing proof, mismatched result/terminal marker, provider timeout, unknown exit, missing OCI identity, unavailable logs and unverified diagnostics must keep the parent fence active without a failure row. Success metadata transfer must not request the failure proof. Replayed/compacted journal and completed cleanup ACK must preserve the exact unclassified failure; stale/duplicate commits must not add another row. A genuine compiler syntax error may close as a deterministic source failure only after a separate versioned diagnostic-evidence contract and parent verification pass. Successful exit 0 with verified declared output still publishes once.
