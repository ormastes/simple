# Windows Full Bootstrap and Toolchain Suite System-Test Plan

## Test Subject

The exact immutable Windows phase binary and its adjacent authority/provenance, never `bin/simple`, a wrapper, raw source, Rust seed, mutable stage path, or cross-host artifact.

## Primary Flow

1. Admit phase compiler/provenance and reject identity/fallback/conflict drift.
2. Check compiler and authenticated interpreter behavior.
3. Run essential tools in interpreter and native modes.
4. Repeat immediate-parent admission through Stage 4 and run Stage 4 acceptance.
5. Verify named integrated suites, protocol behavior, cache invalidation, startup/latency/RSS.
6. Review and publish the exact phase head.
7. Deploy one immutable generation and prove compare-and-select rollback.
8. Run fixed Gate 1–6 readiness and retain unavailable rows as BLOCKED.

## Evidence

Use `exec`, `log`, `binary`, `artifact`, and `protocol` captures under a content-addressed generation directory. Every command is bracketed by executable identity. Streams obey the 4 MiB-per-stream bound. Missing authoritative verdicts are INCONCLUSIVE.

## Negative and Sabotage Cases

Reject a changed artifact hash, wrong parent receipt, symlinked subject, stale source/base, unsupported command fallback, missing suite row, oversized/unbounded stream, author-approval substitution, duplicate unchanged attempt, fourth fix cycle, mixed-generation deployment, mismatched rollback current pointer, and blocked row counted as PASS. Implementation verification must show green -> sabotaged red -> restored green once.

## Manual Policy

Primary operator flows remain visible. Reusable setup is inline, prior admissions use previous-scenario expansion, large matrices are folded, and evidence links sit beneath the causing step. The mirrored manual is authored now and regenerated by Stage 4 docgen with zero stubs before final verification.
