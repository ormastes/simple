# Host peer gateway evidence plan

HOST-02/ORCH-02 require a fixed private transport policy pinned by trusted
bootstrap, actual native service EUID and distinct mapped client UID, exact
principal/project/service-scope checks before SDK admission, retained returned
domain owner before response handling and canonical cleanup propagation.

Twenty-three authored scenarios cover pure policy boundaries, actual retained-file
metadata, same-root mapping, strict denials, current signed prepare owner update,
same-decode subject checks, explicit reads and nonaccepted effects. Their manual
states exact assertions and limits. All are NOT_RUN. No compiler/build/native
campaign is authorized; permitted checks are scoped whitespace/env guards and
independent source/spec/manual review.

The separate classifier delta adds six focused cases: authenticated status,
unauthorized priority, all three work actions, original validation order,
policy-allowed effects refused and callback revalidation/source recurrence.
No signature decoder, journal read, provider operation or response publication
belongs to classification. Native receive-ready and one-use dispatch remain
the actual daemon/SDK responsibility and require independent qualification.

Later runtime qualification must provide actual native bootstrap/UID/socket
fixtures, cleanup faults and post-admission response-send failures. Warm request
mapping is bounded by 64 rows/eight actions without file reload; measure actual
startup, request latency and control responsiveness separately under the real
daemon loop. The SDK's single selected peer UID is not a multi-UID listener.
