## Scope and exclusions

Cover offline identity, protected Git settlement, semantic patches/reduction, immutable configuration-aware evidence, GitHub-first and provider-neutral Git/CI/bug adapters, SJ writer ownership, external-CAS retention, resnapshot, confidentiality, recovery, measured Operating-B limits, integrity, cryptographic agility, determinism, and portability. Exclude implementation selection beyond requirements, release publication, a new always-on DB service, automatic expectation approval, and evidence inferred from source scans.

The setup names are contracts owned inside the inline checkers; they are not no-op helpers. Until implemented, each checker fails and prints requirement, oracle, and exact failure sequence.

## Manual-first order

1. Create offline semantic changes: disconnected replicas, actor rollback, aliases, encoding, merge, causality, replay.
2. Settle compact identifiers: authorization, atomic candidate, racing integrators, stale head, lost ACK, crash and rollback receipts.
3. Classify configuration-bound evidence: immutable configs/reproductions, complete classification lattice, duplicate/incomplete CI.
4. Reconcile provider changes: GitHub live path, non-GitHub/GitLab-CI/Jenkins-class fixtures, uncertain effects, permissions, SJ lease boundaries.
5. Retain exact or aggregated history: 28-day exact data, external CAS closure, revised rollups, resnapshot, deletion limits.
6. Admit Operating-B performance only after functional integrity passes.

## Environment and receipts

Use pinned Simple, Git, jj and object-format versions; isolated filesystem remotes; disposable protected GitHub repository/Actions workflow; at least one non-GitHub Git fixture; GitLab-CI- and Jenkins-class event/poll/bundle fixtures; deterministic clock/randomness; crash and network fault injection; malicious bounded archives; credential-boundary fixture; and controlled CAS. Operating B requires at least 1,000,000 aliases and observations plus 10,000-record representative imports.

Every receipt records dataset generator/digest, revisions, host/OS/filesystem/tools, cold/warm definition, commands, timeout, samples and percentile method, exit status, elapsed time, max RSS, packed/transfer bytes, and artifact paths.

## Admission policy and risks

PASS requires compiled execution against production owners, verified durable receipts, built-in matchers when values are asserted, digest closure, and every numerical threshold. Any fail-fast scaffold, missing capability/receipt, unsupported protection/read-back, placeholder pass, unexplained flaky result, or absent observation is FAIL. Limit one scope to three fix/verify cycles.

Compound fault campaigns cover racing settlement plus lost ACK, crash during alias projection, stale updates through tombstones, duplicate/reordered CI sources with missing shards, provider create timeout, permission loss versus deletion, malicious archives, 45-day offline replay, late rollup input, restored old authority, and untrusted credential access.
