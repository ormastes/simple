## Evidence schema and controls

Each accepted scenario retains producer/source/grammar/universe/config/policy digests, requested roots, actual output artifact digest, exact executed/passed/failed/skipped/dropped counts, per-module resolver/read/parse/build counters, and process-tree closure receipt. Trace source reads through the existing no-follow bounded I/O owner; do not infer absence from log silence alone. Instrumented counters belong at the actual resolver/I/O/submission boundary.

Negative assertion control must execute exactly one failed assertion under the same vehicle and fail normally. Infrastructure/unknown extern/module resolution failures are not a successful negative control. Match actual diagnostic output rather than assumed wording. Native receipts include child and owner closure; assertion-green with leftover processes is lifecycle-blocked.

Finite property checks enumerate small sealed universes/configurations and bounded formulas. Verify render/parse/evaluate equivalence, branch mutual exclusion and coverage with final else, canonical permutation stability, and broad/pruned observable output parity. State explicitly that finite checks do not prove unbounded equivalence or scheduler fairness. Failure shrinking retains source/config/guard witness. Resource-limit tests reject truncation.

## Cold and warm acceptance protocol

Cold source discovery is allowed to parse semantic bodies when a complete readset does not exist. It must still reject false guarded imports before dependency probes. Warm runs reuse the validated symbolic graph across targets and evaluate only selected closure. A warm source read/hash may remain necessary when observation authority is unavailable; report that cost honestly.

Fixtures include a no-condition source, many nested guards, large inactive platform subtree, required side-effect/coherence modules, cyclic interfaces, generic and inline body dependencies, changing aspect cut target/captured value, source replacement with preserved timestamp, and same payload via native standalone/runner. Count avoided source/module work against an admitted reference manifest, not guessed filesystem totals.

Profiling budgets and counters are in [NFR](../../02_requirements/nfr/static_when_tldr_build_pruning.md). Use one predeclared bounded measurement run for each acceptance criterion; at most three fix cycles. Expected trends are hypotheses until measured. No comparison against old compiler timings contaminated by setup stalls, no seed timings substituted for native execution, and no claim that this feature itself qualifies four independent compiler threads.
