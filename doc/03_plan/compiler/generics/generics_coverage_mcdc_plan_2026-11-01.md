# Generics CD / MC/DC Coverage Lane Plan (2026-11-01)

**Lane:** `generics-coverage-mcdc` (branch `work/generics-coverage-mcdc-20261101`, base `origin/release/1.0.0@8a935437a98`).
**Status:** plan + file list only. No coverage number has been measured yet: there is no self-hosted `bin/release/<triple>/simple` on the Windows host, and the stale seed cannot parse current `src` (see plan §1A.0 E3 row). Numbers in `doc/09_report/generics_coverage_baseline.md` will be produced only from the self-hosted binary; any seed run will be labelled `seed`.

## Goal

Every file in the **Tier 1** list below reaches >= 90% condition/decision (CD) coverage and >= 90% MC/DC (unique-cause + masking) coverage, measured with the repo's own pure-Simple tooling on the self-hosted binary. Tier 2 files are measured and reported; they are raised to 90/90 after Tier 1.

## Tooling

Existing tooling (`scripts/check/cert/mcdc_instrument.spl`, `std.mcdc`) only rewrites `if`/`elif`/`while` headers whose atoms contain no calls or parentheses, and only for a standalone program. It cannot measure compiler modules exercised by unit specs. A separate sub-lane (`work/mcdc-compiler-module-tool-20261101`) designs and lands module-level CD/MC/DC tooling: `doc/05_design/generics_coverage_mcdc.md`, with its own specs.

## Steps

1. Tooling PR (sub-lane above).
2. Baseline per Tier 1 file -> `doc/09_report/generics_coverage_baseline.md`.
3. New condition-targeted unit specs under `test/01_unit/compiler/...` (new files only; sibling lanes E0/E2/E3/generic-RR own their existing spec files). Each `it` names the decision `file:line` and condition it drives.
4. Re-measure, iterate to 90/90, small PRs. A bug the specs expose goes to its own fix PR with a regression spec (max 6 cycles per bug).
