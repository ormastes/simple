**Date:** 2026-09-25
**Status:** Implementation in progress; N2 numerical NFR selected; benchmark evidence pending. No end-to-end distributed build or benchmark is claimed.

## Proposed outcome and scope

The user requested full implementation of distributed builds, faster builds, local/GitHub hooks and push feedback, CI, submodule/branch policy, signed local build evidence for GitHub checks, the related ZIP research, and use of the existing Simple Container/Kubernetes-style Orchestrator across operating systems for distributed development. Use parallel F2 sequencing as a design choice; N2 is the **selected but unverified** performance target. Freeze one action/evidence contract, develop build execution and feedback adapters in parallel, then qualify two-node execution, Clang integration and exact integration-candidate admission. Container-backed attempts share that scheduler and broker through an app-owned adapter; each host runtime requires separate qualification. Grouped Simple/Clang providers follow correctness and measured benefit. Ninja owns its graph in the first adapter. A full Ninja replacement, arbitrary textual-header AST replay, writable cross-process semantic caches and speculative hardware/release actions are later work.

A first app-owned `JobV1`/`PodSpecV1` admission adapter now binds an exact canonical fenced request digest in Job metadata to the observed Linux OCI worker capability without equating controller OS and execution OS. It refuses runtime downgrade, different image/command, Orchestrator retry and resource/policy mismatch. The dedicated worker remains responsible for OCI network isolation, fixed mounts/workdir and live-provider recheck; `endpoint-v1` is routing metadata only. This is structural source only, not a launched Orchestrator Job; its focused spec has no production-runtime PASS and non-Linux providers remain unimplemented.

The app now also derives that exact Job from a fenced request and worker
capability, with a canonical namespace and an admission self-check. This
removes hand-written Job field assembly from the eventual controller handoff.
The construction spec is unrun under the current runtime verification cap;
submission, native identity observation and additional OS providers remain
open.

The parent graph selector and final ledger admission now project historical accepted/active digests onto the current graph for readiness planning while continuing to charge all live attempts to global capacity. A focused fixture covers a new graph alongside prior accepted output and unrelated active work. This is a source draft without a production-runtime PASS; repeated graph execution and real worker overlap remain acceptance gates.

The current Linux worker serializes execution under one `worker.lock`; the parent now rejects another proposed attempt for that worker both at graph selection and under the final owner lock before request staging. This avoids an avoidable `worker-busy` reply after durable admission while leaving other workers eligible. Focused specs assert no second journal attempt on the same worker; no live worker-overlap PASS exists.

Signed local-build reuse now has a Simple protected-controller composition entrypoint: pinned bootstrap gate manifest and independently observed gate receipt first, pinned OpenSSH V2 signature second, then a private byte-verified artifact snapshot. Every rejection returns `FULL_BUILD` with no consumable path. Focused tests exercise gate failure short-circuit and the signature boundary; no production-runtime PASS, base-owned GitHub workflow invocation, retrieved artifact, or required-status result is claimed.

Implementation stays in Simple `.spl` for scheduling, policy, protocol, container composition and recovery. Reuse the current Simple IO/SFFI and Linux OCI provider; any new C must be a small justified OS primitive with a canonical runtime owner. Review new C/C++ files and extern declarations at the verification gate.

## Ownership and contract

| Owner | State and responsibility |
|---|---|
| Main scheduler | Authoritative DAG, ready/blocked status, tenant priority, attempt ledger, current publication fence and accepted result reference. It never runs compiler code. |
| Node agent | Host capacity, process trees, exact toolchain inventory, local immutable payload cache, heartbeats and per-attempt cleanup. |
| Worker/provider | An attempt-private action context and scratch outputs. It returns a candidate result; it cannot accept or publish its own result. Group-local mutable indexes belong to a qualified group only. |
| Publication broker | Checks current fence, complete input/toolchain evidence, declared outputs and byte digests, then atomically accepts one result manifest. |

## First live two-node path (Astra follow-up)

Use one scheduler owner and two trusted Linux agents. Bind each configured `worker_id` to a pinned OpenSSH host key and scoped credential; do not use the existing SSH helper that disables host-key checking. Send bounded dispatch metadata separately from verified immutable source/object payloads. On each agent, use `LinuxOciRuntimeProviderV1` with attempt-bound input/output mounts after a worker materializer has verified and staged the input bytes. Reuse the existing compiler CAS for admitted ELF objects and the text CAS for metadata; neither store alone proves a complete action closure.

The Linux OCI request now accepts optional attempt-bound build input/output roots under its trusted state directory. The provider's create command binds inputs read-only at `/simple-build/inputs`, outputs writable at `/simple-build/outputs`, uses the latter as its working directory, keeps the root filesystem read-only and requires `network_policy=none`. Existing orchestration requests use empty defaults. Its focused scripted spec passed 27/27 under the diagnostic seed. The provider does not yet prove input bytes, prevent a malicious state-directory symlink swap, transfer artifacts, or demonstrate live Docker/Podman execution; those remain worker-materialization and system-test gates.

`src/app/build/scheduler/worker_materialize.spl` now creates a private random attempt root under the trusted OCI state directory, copies only declared source/generated/dependency-output files, checks source and copied SHA-256 digests and byte bounds, and prepares an empty writable output root. The OCI mount validator binds both roots to the same attempt token. The new integrated staging spec passed 2/2 and the updated OCI spec passed 27/27 under the diagnostic seed. This verifies listed bytes only: compiler-owned discovery completeness, trusted parent-directory ownership, immutable lifetime, binary transfer, and live node/container execution remain open. Its current copy facade uses a no-follow leaf predicate before a separate copy; it therefore assumes a private stable source tree and is not a hostile-filesystem race defense.

`src/app/build/scheduler/worker_output.spl` now builds a bounded canonical output manifest from the stopped worker's file digests, sizes, attempt/fence identity and diagnostics digest. The parent can reconstruct that exact manifest from separately copied files; a changed object or diagnostic bytes rejects the claim. Its focused spec passed 3/3 under the diagnostic seed. Version 1 permits only single-segment output names, because the available no-follow predicate checks the final file and a writable nested directory could be swapped for a symlink. A safe component-by-component file-open provider is required before nested output paths can be admitted. This output observation is not durable immutable publication; the parent still needs artifact storage before broker acceptance.

`src/app/build/scheduler/trusted_sftp.spl` now plans binary-safe, bounded transfer of every declared source/generated/dependency input into a fresh remote attempt inbox. The batch uses only restricted path tokens, checks local file digests before transfer, and invokes a pinned SFTP executable with the pinned SSH program, strict known-host policy and scoped identity. The worker materializer must rehash the received files; SFTP success alone grants no build or publication authority. Its two pure planning specs passed under the diagnostic seed. The new local OpenSSH loopback integration fixture did not pass in three attempts; the wrapper initially concealed the decisive Simple failure amid compiler warnings, and now prints filtered errors and the beginning of the test log. No successful live transfer is claimed. A remote Simple worker entrypoint, retained artifact transfer in the opposite direction and two-node compile/link run remain open.

This first transport adapter accepts POSIX absolute local paths and a trusted Linux worker inbox. Windows controller paths and non-Linux worker providers need their own qualified path and execution adapters before claiming cross-OS distributed development.

`trusted_worker_invocation.spl` now builds a fixed OpenSSH command from a validated dispatch and an independently supplied request digest. It rejects unsafe remote executable paths, mismatched node IDs, invalid request digests and result claims from another attempt, worker or fence. Its two focused specs passed under the diagnostic bootstrap seed. The executable is a preconfigured trusted-node deployment path; remote binary attestation, request-file transfer, the one-shot Simple worker and OCI lifecycle remain open. A matching result is still only a candidate for the parent owner.

`worker_request.spl` now serializes every `ActionSpec` and attempt field in a bounded canonical wire, checks derived dispatch identity and rejects malformed or altered requests. Four focused specs passed under the diagnostic seed. A release-path test attempt exited 139 after cover-check and before running them; its output exposed seed fallback, so it is not self-hosted verification. `worker_ready.spl` adds a final request-digest marker and a bounded no-follow remote read; its pure path-collision case passed, but its file-read case cannot run under the stale seed because that binary lacks `rt_file_read_regular_no_follow_last_failure`. No production PASS is claimed.

`trusted_request_upload.spl` now plans and performs ordered declared-input, full-request and final-marker SFTP uploads. It reserves `.simple-control` from declared input paths and returns the request digest for the fixed SSH invocation only after all transfer commands succeed. Its two planning specs passed under the diagnostic seed. Live upload, remote worker execution, output retrieval and production self-hosted verification remain open.

`trusted_result_download.spl` now plans exact named result retrieval into a private parent directory, checks pinned transport configuration, then verifies the fetched result identity, diagnostics and every declared output against a locally reconstructed manifest. A separate failure path fetches only the fixed result, empty manifest and bounded diagnostics. Three earlier planning specs passed under the diagnostic seed. The fetch now downloads bounded metadata first, rejects invalid/oversized output claims, and runs each output SFTP transfer under a shell file-size limit. A new budget spec passed 2/2 under the diagnostic seed. Aggregate declared output remains capped at 1 GiB. A direct shell probe showed macOS `/bin/sh` uses 1024-byte blocks (`ulimit -f 1` stopped a 2 KiB write at 1024 bytes), while Debian Linux `/bin/sh` uses 512-byte blocks (the same probe stopped at 512 bytes). The code now selects those observed units by host and fails closed elsewhere; a transferred file can exceed its claim by at most 1023 or 511 bytes before digest/length rejection. A live SFTP size-limit fixture and immutable retained storage before owner publication remain required.

The new one-shot `worker_execute.spl` and `worker_main.spl` read the final ready request under fixed administrator configuration, check node/toolchain/image/resource policy, stage exact inputs, persist the attempt/container binding before OCI launch, wait for termination, and write verified result files with `result.wire` last. The worker CLI and pinned SSH invocation now agree on `--attempt ID --request-digest SHA`; a completed compiler failure returns a failure candidate with a successful transport exit. Four pure local-policy specs passed under the diagnostic seed. The attempted release-path check identified seed fallback and failed on missing module surfaces; no Linux OCI run has completed. Recovery/acknowledgement of retained stopped containers, cross-OS worker providers and a two-node compile/link fixture remain open.

`parent_retention.spl` now rechecks a successful fetched manifest and diagnostic digest, reads each declared binary output as bounded no-follow bytes, compares those exact bytes to the canonical manifest rows, then stores and rereads the binary and text blobs by digest before returning a publication-ready digest. Its focused byte-level spec cannot execute under the stale seed because that binary lacks `rt_file_read_regular_no_follow_bounded_bytes`; no retention PASS is claimed. This first retention profile admits ELF/Mach-O/COFF payloads only, and its 256 MiB per-file read cap does not cover larger or non-binary build outputs.

Review found that a pinned OCI image could still prepend its own `ENTRYPOINT` to the requested compiler. Build-mode OCI creation now uses an explicit `--entrypoint` equal to the approved command executable; normal container requests keep their existing behavior. A focused diagnostic-seed spec passed 2/2. Worker admission also derives the sandbox digest from the pinned image, engine, compiler entrypoint, network/filesystem policy and fixed mount/workdir profile; changing an image or engine while retaining the old digest now rejects local configuration (focused diagnostic-seed spec 1/1). The actual compiler bytes inside that image still require independent toolchain attestation.

Parent retention now fsyncs every retained blob and relevant CAS directory chain before returning success. The caller must use a dedicated non-GC store and keep that root durable through owner publication. This durability path is not yet verified by a power-loss fixture; the stale seed still lacks the byte-read extern used by the retention spec.

`distributed_attempt.spl` now holds the parent owner across a synchronous attempt: it preflights complete request/input identity, fsyncs a unique spool-protocol intent before journaling admission, persists the canonical request in an exclusive fsynced parent spool, uploads the ready request, invokes only the pinned worker command, compares SSH and SFTP result bytes, retains success outputs or failure diagnostics, then calls the owner's durable publish/fail transition. The spool digest must match the uploaded request digest, and recovery reads only a current active fence. Any uncertainty after admission leaves the attempt active and capacity reserved for explicit reconciliation. Startup reconciliation durably revokes a replayed active attempt only when a matching pre-admission intent proves the spool-first protocol, no spool exists, and no new admission has started; legacy attempts stay reserved. A read-only pinned SSH `--status` path can retrieve a previously completed result without relaunching OCI, then use the same fetch/retain/publish path. For a spooled attempt that never started, pinned SSH `--cancel` writes an exact request/fence tombstone under the worker launch lock and acknowledges only after fsync; the parent then durably revokes. A binding, disconnect or uncertain response leaves capacity reserved. Diagnostic-seed specs passed 1/1 for preflight, 2/2 for spool binding, 1/1 for on-disk spool/reopen/collision, 2/2 for initial no-spool/spooled startup reconciliation before the intent requirement, 2/2 for the new legacy/intent guard, 1/1 for status command planning, 1/1 for mismatched-node resume rejection, 2/2 for local cancellation tombstone/binding refusal, and 1/1 for pinned SSH cancellation arguments. The worker entrypoint compiled and rejected incomplete `--status` and `--cancel` invocations as expected. The earlier reconciliation spec was updated for the intent protocol but not re-run under the no-repeat guard. The secure no-follow recovery reader, worker status body and resumed two-node execution still lack production self-hosted/live PASS. The worker's stopped container and mounts still need acknowledgement cleanup, and the retained store must stay outside GC.

The first Simple transport prerequisite is `src/app/build/scheduler/trusted_ssh.spl`: it validates a worker alias, pinned local OpenSSH executable, known-hosts file and identity file, then issues a bounded `/bin/true` probe with strict host-key checking and forwarding disabled. Its two configuration tests passed under the diagnostic bootstrap seed. It does not execute a build action, transfer binary artifacts, establish a worker service, or close the file-swap race between no-follow checks and hashing. The caller must own an immutable private configuration directory. A loopback OpenSSH host-key rejection test and production self-hosted verification are still required before treating this as authenticated node evidence.

The Simple diagnostic CLI `trusted_ssh_probe_main.spl` and `scripts/check/check-trusted-ssh-loopback.shs` now exercise a disposable local `sshd` with pinned and changed host keys. The first three loopback attempts stopped at the local configuration gate: this host's PATH resolves `ssh` to a symlink, which no-follow admission correctly rejects. The check script now resolves that executable to its real regular-file path, but the revised check has not been rerun because the session's three-cycle verification cap was reached. The loopback authentication result is therefore still open.

The binary object CAS read and staged verification paths now use bounded no-follow **byte** reads, so non-UTF-8 object bytes can retain their exact SHA-256 identity. A non-UTF-8 ELF fixture was added. The diagnostic seed runner cannot execute the updated spec because it lacks `rt_file_read_regular_no_follow_bounded_bytes`; the current native runtime source declares and implements that symbol. This change remains unverified on the production pure-Simple build, and the three-cycle test limit stopped further retries in this session.

The byte-reader symbol is also already registered in the Rust interpreter source (`interpreter_extern/mod.rs` and `file_io.rs`) and the compiler runtime symbol table. The observed missing-extern error belongs to the deployed stale seed binary; no source registry patch is needed.

The signed `pr-fast` path now admits a docs-only committed range (`README.md` and `doc/*.md`, no deletions) after `git diff --check`, before its full Simple spec-import scan. Its signed session ID labels that path `docs-only`; other non-Simple-only ranges remain unsupported. The shared check manifest describes the added branch. `check-pr-fast.shs --selftest` passed 27/27 fixture scenarios, including docs-only success, whitespace failure, unsupported-path refusal and existing signed-receipt verification. This does not make the GitHub context required or solve fork PR admission, missing unit/feature spec mappings, or the 60-second limit for broad Simple changes.

An isolated docs-only Git fixture then signed a receipt, pushed `refs/notes/pr-fast-receipts` to a local bare remote, and ran the remote verifier successfully. Its accepted binding was `prfast.v1.docs-only.60.<binary-size>.<binary-sha256>`. This is end-to-end local receipt evidence, not a live GitHub Actions run.

The live fixture compiles `answer.c` to `answer.o` on node A, transfers the exact verified object to node B, then links and runs `main.c` expecting `42`. Wrong host key, corrupt object, wrong toolchain, disconnect and delayed stale result must fail or recover without publication. The existing provider specs and metadata wire tests do not establish this execution path.

Freeze typed, versioned `SnapshotManifest`, `ToolchainManifest`, `InputManifest`, `ActionSpec`, `AttemptSpec`, `NodeCapabilities`, `ActionResultCandidate` and `AcceptedResult`. Use existing canonical identity encoding for semantic computation inputs; execution location, retry count and queue priority belong in `AttemptSpec`, not in the action key. Keep test/CI validation identity separate. SDN carries bounded control metadata; binary-safe streams carry payload bytes. An immutable snapshot or frozen result crosses an execution boundary; a worker transfers only a candidate receipt to the scheduler/broker. Source mutability remains with the snapshot owner, and accepted mapping mutability remains with the broker.

The scheduler selects ready actions in deterministic priority order with aging and per-tenant limits, then admits only when the node has CPU tokens, estimated private memory plus reserve, file-descriptor allowance and any exclusive device/license lease. Unknown dependency completeness blocks a cache hit and broadens execution. Keep exact host/toolchain compatibility checks distinct from output target triples and runtime/test device requirements. Record queue/admission/transfer/execution/publication times per attempt.

## Failure, retry and security rules

- Execution is at least once under disconnect or crash; publication is once per current fence. A heartbeat gap alone does not prove a worker is dead. Revoke an epoch before reassignment and reject all late candidates from it.
- Preserve every failed attempt and classify source diagnostic, deterministic compiler failure, infrastructure crash, deadline, cancellation and result-validation failure separately. No automatic retry for ordinary diagnostics. Allow bounded isolated crash diagnosis and one justified relocation, per the archive's recovery contract.
- Reject unknown network/clock/environment reads from cacheable actions unless they are explicit inputs or the action is uncached. Verify uncompressed payload bytes, lengths, namespace and toolchain before materialization. A content digest is identity, not authorization.
- Keep compilation's output target separate from where a test can run. Hardware, boards, GPUs, release signing and publication require their own exclusive leases and policies; ordinary compile retries never imply replay of side effects.
- For Clang preprocessing, validate strict policy on cold and warm paths. An approved variant gets a distinct complete context. A scoped `complex` exception needs complete context; `none` forbids enclosing semantic shortcuts. Never omit an input from identity because an exception permits it.
