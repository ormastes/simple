# Bootstrap source-object implementation ownership

User-selected requirements are recorded in
`doc/02_requirements/feature/bootstrap_source_object_default.md`.

1. Compiler execution owner (`source_object_engine`): complete immutable
   full-context declaration/specialization/storage authority transport, actual
   source-to-object process execution, native capsule admission and final object
   validation. The earlier closed-unit frontier remains partial; its owner is
   consulted for interface continuity while repairing the codec.
2. Bootstrap recipe/CLI owner (`fixed_phase3_campaign`): integrate real compiler
   capability negotiation, default source-object selection, explicit phase-batch
   override and explicit supported HIR/MIR/object modes. Keep native packaging
   and existing output-intent parsing independent. Cache defaults on; jobs24.
   Cache opt-out is explicit and request-scoped. Snapshot preparation has a
   two-second end-to-end acceptance target, including authority/admission and
   publication; coordinate the source-authority owner rather than skip checks.
   This owner also implements dependency/SCC scheduling, deterministic readiness
   and parent-authoritative terminal commits, coordinated with the executor.
3. Merge owner and final reviewer: root. Review complete semantics, native
   overlap/failure/cache evidence and original Phase 3/4 acceptance before
   claiming done or landing. No lower-model sidecar is assigned (N/A).

The initial capable compiler may require an explicitly recorded phase-batch
construction build. Its receipt must remain distinct from the Phase 3/4 default
acceptance receipts. Rebuild Phase 2 when lineage policy demands it. Missing
capability must refuse rather than silently fall back.

Ready-unit scheduler design: immutable closure index and stable source order;
declaration/interface graph -> dependency SCC and specialization demand seals ->
bounded ready queue -> resource-admitted owned source-to-object process ->
immutable result receipts -> deterministic parent validation/commit -> final
link only with all required units. Source, dependency and context changes
invalidate affected receipts. Failures terminalize their own unit and dependent
units, while independent ready units continue to the end of the finite graph.

Pending evidence: real native overlap, failure collection with sibling objects
retained, unchanged cache hit, all semantic invalidation dimensions, original
cross-unit language forms, 24-job resource/cleanup receipts, exact generation
Hello gates, full CLI/test-runner and Phase 4 qualification. Authored policy or
parser tests alone cannot satisfy those checks.
