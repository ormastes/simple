# Plan — unblock the 2D showcase cell and de-duplicate the tier split

Date: 2026-07-25
Analysis: `doc/01_research/ui/engine2d_gc_tier/analysis_2026-07-25.md`

Two root causes, deliberately sequenced so the cheap unblock does not wait on
the deep runtime fix.

## Phase 0 — DROPPED (was based on a misdiagnosis)

Originally listed as "fix the wildcard re-export blocking spec runs". It blocks
nothing: `export use ...*` emits a **warning**
(`src/compiler_rust/parser/src/stmt_parsing/module_system.rs:557-567`,
`ErrorHintLevel::Warning`), and the parser returns `Ok`. The spec in fact passes
(`Results: 1 total, 1 passed, 0 failed`).

The misread came from tailing a ~5,200-line run whose `Results:` line sits at
~5,149 with thousands of warnings after it. Keep the entry as a caution: verify
by `grep 'Results:'`, never by tail.

Optional hygiene, not a blocker: 28 wildcard re-exports exist under `src/lib`
and the compiler suggests naming symbols explicitly. Low priority; changing them
risks omitting a symbol a consumer relies on.

## Phase 1 — stop the 2D path using the GC tier (unblocks the matrix cell)

Goal: the software offscreen 2D showcase renders without a GC-tier object live.

- **P1.1** Decide the target API. The nogc `Engine2D`
  (`nogc_sync_mut/engine/core/engine.spl:54`) is a scene graph; the GC one
  (`gc_async_mut/gpu/engine2d/engine.spl`) is immediate-mode. Choose one:
  - (a) port the showcase to the nogc scene-graph API, or
  - (b) add a nogc immediate-mode facade over the existing draw path.
  Recommend (a) if the scene graph already covers the showcase's primitives;
  (b) only if porting would mean reimplementing primitives.
- **P1.2** Retarget `examples/06_io/ui/graphics_2d_showcase_gui.spl` off
  `std.gpu.engine2d`. Audit sibling showcases for the same import.
- **P1.3** Re-run the 2D headless cell.
  - Exit: an evidence line appears (PASS *or* an honest-fail reason). Either is
    a real verdict; the cell is currently a 40-minute timeout, which is neither.
  - Guard: assert wall-clock stays bounded at 320x240; failure must be fast.

**Do not** attempt P1 as an import-line change — the APIs differ. Scope it as a
port.

## Phase 2 — fix the runtime defect (the real fix)

Tier-correcting the showcase avoids the trigger; it does not fix the bug. gpu,
cuda, torch and ML legitimately live on `gc_async_mut` and stay exposed.

- **P2.1** Root-cause `interpreter_gc_root_scan_blowup_large_array_2026-07-25`:
  why per-array-mutation cost scales with live-heap complexity. Suspect a root
  set rescanned per mutation rather than incrementally.
- **P2.2** Fix, with a scaling test: hold a live GC-tier object, mutate a large
  array, assert time does not grow with unrelated live-heap size.
  - Exit: the 8s-vs-2min+ reproduction from the analysis collapses to ~8s.

## Phase 3 — de-duplicate (prevents recurrence)

Three failures today shared one cause: the same entity defined in several places
and diverging. Fix the class, not just the instances.

- **P3.1** `ui`/`web`/`engine`/`websocket` duplicated across all four tiers —
  inventory which copies are live, which are dead, which diverged. **Do not bulk
  delete**: the `ant-trace` audit found 48 differing files and 39 that existed
  only in the "duplicate", so deletion would have destroyed code.
- **P3.2** `ant-trace`/`ant_trace` — 29 colliding pairs under
  `src/app/llm_caret/claude_full/`. Native-build from the repo root fails until
  resolved. Preserve content: rename to non-colliding names, or merge per pair.
- **P3.3** Make the collision loud. Same-named types across modules currently
  collapse silently, first-registration-wins. Emit a diagnostic at registration
  naming both modules, so this class fails at build time with a clear message
  instead of as `unknown variant 'Const'` deep in entry-closure discovery.
  - This is the highest-leverage item here: it converts a whole bug class from
    silent-and-confusing into immediate-and-obvious.

## Sequencing

P0 first (small, unblocks measurement). P1 delivers the matrix cell. P2 is the
correctness fix and can run in parallel with P1. P3 is hygiene — P3.3 is worth
doing early despite being listed last, because it would have caught all three of
today's failures at build time.

## Explicitly out of scope

- Deleting any duplicated directory without a per-file content audit.
- Treating the `sha256_bytes` hardening as a perf fix — it was measured linear.
