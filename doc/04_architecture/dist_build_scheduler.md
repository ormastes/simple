# Distributed build and fast feedback architecture

**Status:** Architecture and partial implementation, 2026-09-25. The user requested full implementation of distributed builds, faster builds and local/GitHub hooks and push feedback, CI, submodule/branch policy, and the supplied ZIP scope. Several contracts and an SSH/Linux OCI attempt path now exist, but no production self-hosted or two-node acceptance pass exists. N2 numerical NFR targets are selected but unverified; rollout selection remains pending. Existing behavior below is distinguished from proposed behavior.

## Context and current evidence

The current [target executor](../../src/app/build/targets/target_executor.spl) orders named targets but explicitly rejects dependency-bearing actions because native-build cannot consume an input manifest. It deliberately returns an unknown action digest and disables executor reuse. Preserve that fail-closed behavior until authoritative imported-closure evidence is available. A hash of an entry file and prior receipts cannot prove the current input closure.

[Action identity](../../src/app/build/targets/action_identity.spl) and [artifact receipts](../../src/app/build/targets/artifact_receipt.spl) already define native action identities, dependency manifests, imported-closure receipts and target CAS paths. Extend these contracts rather than introducing another hash or storage authority. [Canonical identity encoding](../../src/compiler/00.common/cache/canonical_identity.spl) supplies shared canonical primitives.

The existing [push driver](../../scripts/check/check-push-must-pass.shs) already parallelizes blocking checks. Contrary to earlier research prose, ordinary pushes skip advisory rows by default; `MUST_CHECK_ADVISORY=1` enables them. Its per-ref blocking budget is not an end-to-end push SLA. Measure ref enumeration, manifest validation, receipt handling, all outgoing refs and optional advisory mode separately. The push driver was dirty in another session when reviewed; ownership must be resolved before edits.

The [research](../01_research/local/dist_build_scheduler_2026-09-25.md), [archive inventory](../01_research/domain/simple_clang_header_cache_2026-09-25/README.md), and [delivery plan](../03_plan/compiler/build_system/dist_build_scheduler_2026-09-25.md) supply the broader scope. Archive probes demonstrate counterexamples and proposed scenarios, not implemented scheduler acceptance.

## Decision and layer boundaries

Use a parent-authoritative scheduler with isolated execution contexts and a fenced publication broker. Compiler code never runs in the scheduler process. Immutable snapshots and accepted artifacts cross execution boundaries. Workers return candidates; only the broker accepts results. This gives recovery one authority while allowing execution at least once after disconnects.

Common contracts belong in the compiler common layer because both native compilation and app orchestration consume them. App adapters compose scheduling, receipts, native providers and policy; common code must not import app code. Scheduler, transport and provider siblings expose contracts and keep mutable implementation state private. Existing hook shell and GitHub YAML remain boundary adapters; new domain logic belongs in Simple.

The implementation language for new domain code is Simple. The existing `app.io.mod`, no-GC sync process/file facades and Simple Linux OCI provider supply the host boundary; invoke Docker/Podman as an external engine through that provider. Add a small C runtime primitive only if no existing Simple/canonical SFFI operation can provide the required OS behavior, and keep its ABI and ownership in the canonical runtime layer. The scheduler, wire validation, policy, retries and publication decisions must stay in `.spl` files. Verify any newly added C/C++ source and `extern fn` declaration against that rule before accepting a host adapter.

## Identity and protocol contract

Version new schemas as major version 1. Exact field layouts and serializers require golden vectors before independent producers and consumers are integrated. Semantic identity must use canonical typed field encoding rather than serialized SDN field order. Preserve order for arguments, include search paths and linker inputs; sort only collections whose semantics are explicitly unordered.

| Interface | Required semantic content |
|---|---|
| `SnapshotManifest` | Repository/tenant scope, immutable source tree, selected gitlinks and generated-input provenance |
| `ToolchainManifest` | Executable and behavior digests, compiler/provider ABI, SDK/runtime/linker identity and supported execution/target contexts |
| `InputManifest` | Declared byte digests, kinds and paths, dependency artifacts, imported closure and completeness evidence, negative lookup evidence where applicable |
| `ActionSpec` | Input/toolchain identities, ordered invocation, declared environment, target context, declared outputs, cache/replay policy |
| `AttemptSpec` | Action reference, attempt ID, node, epoch/fence, allocation, deadline, execution mode and attempt-private directory |
| `NodeCapabilities` | Authenticated scope, exact toolchains, host execution capabilities and bounded available resources |
| `ActionResultCandidate` | Action/attempt/fence, output byte digests and lengths, diagnostics and execution evidence |
| `AcceptedResult` | Broker-validated candidate reference and immutable output manifest |
| `GateReceipt` | Exact candidate tree, protected policy and checker identities, required-check set, action/test evidence and verdict |

An action key excludes node assignment, retry number, queue priority and physical scratch path. Validation identity additionally binds test/check implementation and current admission policy. Environment, network or clock reads must be declared or force uncached execution. An exception can permit context variation but cannot remove semantic inputs from identity.

SDN transports bounded control metadata. Binary-safe streams transport payload bytes. Authenticate and authorize repository/tenant scope separately from digest validation. Reject incompatible majors, duplicate fields, unknown mandatory fields, oversized frames/nesting/collections and malformed text. Bound decompression and total materialization. Verify lengths and digests over actual uncompressed bytes before exposing immutable blobs. No binary payload passes through a text API. Across hosts, require authenticated encrypted connections; a content digest alone grants no access.

## Scheduling, ownership and recovery

Dependency readiness is tied to publication provenance. For each consumer dependency, the parent resolves an accepted producer in its journal, validates the retained manifest and named output against that accepted attempt, and checks the binary CAS bytes before admitting the consumer. Before admission, the distributed uploader copies source/generated bytes and CAS-backed dependency bytes into one private snapshot, checks their digests, and prepares and fsyncs the request and SFTP batches. After admission it transfers only that snapshot; worker materialization rehashes received bytes. Missing or corrupt provenance leaves the consumer unadmitted; matching a consumer-supplied digest alone is insufficient. A live self-hosted check of this new preparation path is pending.

The scheduler owns the DAG, readiness, tenant priority, allocation and attempt journal. Admission requires completed producer artifacts, CPU tokens, private-memory estimate plus reserve, file-descriptor capacity and exclusive device/license leases when needed. Deterministic ready ordering with aging avoids starvation. Host execution compatibility and artifact target compatibility are separate checks.

The parent first syncs a per-attempt spool-protocol intent, journals the attempt and fence, then exclusively creates and fsyncs the canonical request spool before starting transfer. A restart may inspect that request only under the owner lock and matching active ledger fence. The intent prevents an older no-spool attempt from being mistaken for an unstarted attempt under the new protocol. Node agents own process trees, exact toolchain inventory, local immutable payloads and cleanup. Every attempt writes to its own scratch directory. Publication validates declared outputs and byte evidence against the current fence, then atomically changes the accepted-result mapping. Shared outputs are never written directly by workers.

The graph-action parent route now closes that owner after the complete spool is durable. Its pinned SSH/SFTP upload, execution and result download carry an immutable request snapshot without a journal lease; another worker may acquire the owner and admit while this attempt runs. Before result retention or publication, the parent opens a fresh owner, replays current journal state, recovers the exact active request and matches its digest, canonical bytes and worker identity to the transport snapshot. It retains and fsyncs bytes under that fresh lock, then asks the broker to commit the current fence. The CLI's status and cancellation routes likewise recover an exact active request under one lock, contact the worker unlocked, then reopen and revalidate before publication or revocation. An already committed result answers status directly from the ledger. The lower-level exact-fence API still holds its owner during transport. This source-level split is provisional until a self-hosted run proves overlapping workers, cancellation races and crash recovery. Metadata CAS uses a digest/PID temporary name, so retention remains serialized under the owner pending a separately qualified same-process CAS change.

Revocation advances the fence before reassignment. Delayed workers cannot publish against old fences. A missing heartbeat does not prove a worker is dead. Restart replays the durable ledger and reconciles unfinished attempts. The current startup path can revoke an active attempt with a matching spool-protocol intent and no parent request spool; read-only worker status can recover a completed result without relaunch. A spooled unstarted attempt can be revoked only after the worker durably writes a request-bound cancellation tombstone under the same lock as launch and returns an exact pinned-SSH acknowledgement. A binding or uncertain worker blocks that acknowledgement and keeps capacity reserved. Legacy attempts without spool-protocol proof also remain reserved. Cancellation detaches a consumer before cancelling shared work; isolated process trees terminate on deadline, while an unsafe grouped provider is retired. Preserve failed attempt evidence and distinguish source diagnostics, deterministic compiler errors, infrastructure crashes, deadline/cancellation and validation failures. Ordinary diagnostics are not retried. Crash diagnosis and relocation have explicit bounded policies.

Graph planning now projects accepted and active digests from the durable owner ledger onto the current graph before readiness validation. The owner still charges every active attempt, including work from an earlier or concurrent graph, against CPU, memory and file descriptor capacity. Attempt IDs and fences remain global to the owner. This avoids rejecting a new graph solely because the journal retains a prior graph's accepted action. The focused cross-graph spec is drafted but has no production-runtime PASS.

The Linux one-shot worker holds its `worker.lock` through OCI execution. Parent graph selection therefore refuses to propose a second action for any worker with an active ledger attempt, and final parent preparation repeats that check under the exclusive owner lock before staging or journaling another request. A busy worker does not consume another attempt ID or fence. Another worker can still run if its protected node configuration and global capacity allow it. The focused rejection fixtures are unrun under the current production runtime.

### Simple Container and Orchestrator worker seam

Compose build contracts with the existing strict `PodSpecV1`/`JobV1` and `RuntimeProviderV1` contracts in an **app-owned admission adapter**. Compiler common code must not import orchestration or host container libraries. The scheduler first selects an action and fenced attempt; the adapter then checks physical host OS/architecture, actual execution OS/architecture, requested runtime class and isolation, provider availability, exact toolchain, output target, resource budget and immutable input/artifact identity. A cross compiler's output target can differ from the execution OS. Simple Container admits native execution only: macOS workloads on macOS use `native-sandbox`, Windows Server workloads use process-isolated `native-container`, and SimpleOS workloads use their own kernel provider. A VM is outside this Simple Container route. A macOS parent may also use pinned SSH/SFTP to an actual remote Linux worker; the parent OS is separate from the remote worker's execution OS. The parent preflight queries a nonce-bound worker capability report over that pinned SSH endpoint before attempting admission. The worker must still verify transferred bytes, its installed config and its actual provider identity at execution time. A capability report is advisory because boot/provider generation may change between query and dispatch; it is not output attestation.

The provider returns a candidate result plus native identity, logs, exit status and cleanup evidence. Its scratch and output mounts are private to the attempt; accepted inputs are read only. The existing publication broker alone validates bytes and the current fence. Recovery reconciles `RuntimeIdentityV1` (pod UID, attempt, provider generation, operation ID, engine, native ID and node boot ID); a restarted or delayed provider cannot self-publish. Missing provider support yields `BLOCKED` or `UNSUPPORTED`, never a process fallback.

A known nonzero terminal exit is a failed action, with cause unclassified. The worker's durable terminal observation precedes a canonical `failure-proof.wire` and final `result.wire`; failed outputs have an empty manifest and never enter accepted CAS mappings. The parent checks proof and exact status replay, retains diagnostic bytes, then journals the failure through the same active fence. This releases capacity for bounded retry without claiming source determinism. Missing proof, uncertain provider state and unknown exit preserve the active fence for reconciliation. The separate proof rejects older workers that only emit the V1 failed result. Cleanup ACK is authorized only by the exact committed failure row and result digest. A future source-diagnostic classification needs its own evidence version and parent verification.

A new pure-Simple `app.build.providers.build_job_admission` adapter structurally binds a fenced request, observed Linux capability and Orchestrator `JobV1`/`PodSpecV1`: a Job label must carry the SHA-256 digest of the exact canonical request wire; the adapter also requires one exact image/command, no Job retry, exact CPU/memory reservation, exact toolchain/policy, and native-container runtime class. Controller OS may differ from the verified worker execution OS. The adapter does not launch a Job or authenticate the capability transport. `PodSpecV1.network_profile=endpoint-v1` is routing metadata, not proof of sandbox isolation; the dedicated worker must still enforce OCI `network_policy=none`, fixed mounts and working directory, then recheck its live provider at execution time. Its focused spec is unrun under the production runtime.

The current hosted implementation is Linux OCI only. `LinuxOciRequestV1` now has attempt-bound build input/output mounts and a build working directory. The provider pins the build command entrypoint and the one-shot worker binds the configured image digest, engine and compiler entrypoint into its sandbox identity. The parent driver plans SFTP upload, fixed SSH invocation, SFTP result retrieval and parent-side CAS retention before broker acceptance. Result retrieval now admits bounded manifest sizes before each output transfer and applies a host-specific file-size limit per SFTP process. Observed shell granularity is 1024 bytes on macOS and 512 bytes on Debian Linux, permitting at most 1023 or 511 rejected excess bytes per declared file; other controller hosts fail closed until qualified. These modules have only focused diagnostic bootstrap-seed evidence; they have no qualified two-node or production self-hosted pass. The worker does not independently attest compiler bytes inside the image, and disconnect recovery/cleanup remains incomplete. `pipeline_runner.spl` OS/sandbox admission and Docker daemon-OS fixes are drafted but unverified; `/tmp` remains hardcoded. Windows HCS, macOS sandbox/process, FreeBSD jail and SimpleOS hosted/native paths require individual real provider and isolation evidence. The shared control contract gives portable scheduling; images, executable ABI and isolation guarantees remain OS specific. See the existing [Simple Orchestrator research](../01_research/os/container/simple_orchestrator_and_container_2026-09-06.md) and [container discovery bug](../08_tracking/bug/container_discovery_missing_admitted_linux_runtime_2026-09-23.md).

## Hooks, GitHub and repository admission

Use `config/check/must_check_gates.sdn` as the single obligation registry. Preserve each mandatory check's enforced destination when adjusting tiers. Commit checks inspect staged bytes; push checks inspect every outgoing committed ref. Missing tools, uncertain applicability, deadlines and skipped mandatory children cannot yield PASS. Report PASS, FAIL, INCOMPLETE or evidenced NOT_APPLICABLE and retain unfinished work IDs.

Bind protected admission to the actual current base-plus-head integration candidate, selected submodule closure, candidate compiler, current protected policy and checker digests. A base-owned controller verifies unprivileged candidate execution. A PR that edits policy or checker scripts cannot authorize its own relaxed result. Qualify fork execution and missing/skipped-child behavior before changing required GitHub contexts. Local receipts accelerate feedback; protected remote evidence remains merge authority. Remote ruleset mutation requires a separate authorized action and current ruleset inspection.

Extend signed local evidence to eligible GitHub build/check reuse under a versioned receipt. The existing signed receipt excuses selected rows only in a non-required extended code-idiom job; inspected build jobs do not consume it. A required GitHub context always runs a trusted base-owned verifier. It accepts authorized, complete evidence for the exact integration candidate and all required obligations, or performs the full work. The receipt must bind the selected submodules and generated inputs, compiler/toolchain, execution platform, target configuration, invocation, policy/checker revisions, output digests and lengths, authorized signer scope, freshness and revocation state. A note keyed to PR head transports evidence but does not prove that the current merge candidate was built. Downloaded artifacts require byte verification before use. The V2 verifier now has a private file snapshot handoff that hashes copied bytes and returns that same path after admission; the protected controller and consuming job must preserve its private ownership. A Simple OpenSSH adapter now has a pinned-executable, exact-stdin signature path with protected signer and revocation files, but lacks a live self-hosted run and protected controller wiring. Missing or unverifiable evidence, base movement and unsupported platforms select full execution; a signature alone is not independent proof that an agent ran the build. The user's phrase “build claude” remains unresolved pending clarification.

Gitlinks remain authoritative submodule pins; `.gitmodules` remains native Git configuration. Inventory selected dependencies, prove authorized clean fetch, and bind exceptions to exact pinned content. Publish child commits before parent pin admission. Independent optional examples must not trigger broad fetches. Audit coupled first-party code before any migration. Branches represent version lines; use short-lived owned branches/bookmarks with isolated worktrees and output directories. Preserve protected main/integration/release flow and test changed/unreachable pins, stale exceptions and protected-ref paths.

## Clang, CMake/Ninja and resource sharing

Retain Ninja graph ownership in the initial native adapter. Capture exact launcher invocation and every declared side output. Run the policy gate even when Ninja considers compilation a no-op, and attach effective policy stamps as native dependencies. Generated headers must precede consumers. Strict/complex/none policy is enforced on cold and warm paths; `none` requires fresh processing and forbids enclosing semantic cache shortcuts. Complete macro, search-path, ABI, compiler, SDK and policy context is required for PCH/PCM/BMI reuse. Scoped complex exceptions retain full semantic identity.

Start with isolated compiler processes. Persistent providers are a later qualified optimization with private contexts, bounded group-local indexes, single-flight resource construction, explicit lifetime handles and safe reset. Resource mapping validates format versions, offset/length bounds, alignment and generation. A numeric handle is never treated as a transferable OS capability. Crash or unsafe cancellation retires suspect grouped state. Enable groups only after isolated-reference equivalence and measured memory/performance benefit.

## Performance and verification

Startup loads bounded configuration, ledger indexes and exact node/toolchain inventory; it must not rebuild repository-wide indexes per request. Hot paths perform indexed action lookup and bounded admission checks. Snapshot/input changes invalidate action identity; policy/checker changes invalidate gate identity; provider ABI changes invalidate semantic resources. Cache a validated immutable snapshot by its identity, never by mutable worktree path or mtime alone.

Record baseline host, binary/toolchain digests, fixture identity and cold/warm state. Measure P50/P95/P99 full staged-hook and pre-push wall time, preflight, queue/admission/transfer/execution/publication durations, actions/checks completed, hits, transferred bytes and private/unique or PSS memory. Report multi-ref, fork and cold cases separately. [N2 numerical targets](../02_requirements/nfr/dist_build_scheduler.md) are selected; none is claimed as achieved. Protocol/resource bounds remain explicit.

Freeze manual steps: `step("Select exact source and policy snapshot")`, `step("Plan affected build and checks")`, `step("Dispatch admitted actions")`, `step("Validate and publish results")`, `step("Verify current integration candidate")`. Freeze helpers: `given_pinned_snapshot`, `given_two_node_fixture`, `given_outgoing_refs`, `given_submodule_pin`, `expect_complete_action_manifest`, `expect_current_fence`, `expect_required_gate_receipt`, `expect_pin_reachable`. Any incomplete helper uses `assert(false)` or `fail(...)`, never a passing placeholder.

Acceptance covers canonical round trips, malformed/oversized input, semantic mutations, real dependency consumption, clean/cache equivalence, resource bounds, stale/crashed workers, two-node corruption/disconnect, changed checker/policy, all outgoing refs, fork/base drift, pin reachability and the archive's HC policy/native scenarios. Link each accepted requirement to executable evidence and inspect generated manuals independently. Source changes affecting compiler/core require the repository's core and MCP/LSP smoke gates. Verify only changed or unresolved criteria; do not repeat unchanged green checks.

Signed-build admission also needs a valid artifact-backed reuse fixture, wrong signer or scope, revoked key, changed base/toolchain/policy, unavailable or byte-mismatched output, incomplete mandatory rows, and a PR changing its own verifier or signer allowlist. Each invalid case must execute the ordinary remote build and still produce the intended required status. The local `GateReceipt` data validator is only one part of admission; authenticated signing, artifact bytes and base-owned execution remain separate gates.

## Consequences and scope accounting

The design permits local and remote execution to share action identity and evidence while giving one owner publication authority. It introduces durable journal, protocol validation and immutable-input costs that must be measured. Incorrect closure discovery remains the central correctness risk; unknown inputs therefore disable reuse instead of guessing.

Archive worker/cache/retry/protocol reports map to contracts, local scheduling, two-node transport and qualified providers. Its CI/repository report maps to hook/CI admission and dependency/branch policy. Header policy/resource/native reports map to the Clang adapter and HC acceptance catalogue. Full Ninja replacement, arbitrary textual-header AST replay, writable semantic caches across processes and speculative hardware/release side effects require separate qualification; they are not implicitly provided by two-node compilation.

Full implementation authorization permits common contract and execution work to proceed. It does not select a numerical SLA or make research recommendations accepted requirements. The primary owner must record selected requirements, report unfinished scope explicitly, and obtain verification PASS before release.

The Simple signed-build gate bridge computes a canonical digest across every gate receipt field and observation. It returns `VERIFIED` only when the protected mandatory ID set is complete, every row has evidenced `PASS`, exact candidate/policy/checker/submodule identities match, and that digest equals the signed-build expectation. The protected checker must independently collect those observations; a candidate-supplied receipt cannot prove execution. `NOT_APPLICABLE` cannot authorize reuse until protected applicability rules are implemented.

The bootstrap adapter derives its mandatory IDs from the digest-pinned protected eight-column gate registry. It conservatively requires **every** `bootstrap` row: `push_blocking` describes the local push hook, and cannot identify all bootstrap obligations. CI, PR and push rows stay with their separate required destinations. The base-owned controller must obtain both registry bytes and expected digest independently of the candidate, then collect the gate observations itself. A newly added protected bootstrap row prevents reuse until its PASS appears in the receipt.
