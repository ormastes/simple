# Logical mono keys and complete physical body owners

Status: source implementation and native fixture authored; native execution is
pending admission and the root-owned serialized compiler slot. This change does
not activate the bounded driver route or establish an RSS improvement.

The retained `MonomorphizationPass.process_modules` walks the input dictionary's
logical keys, including aliases, in insertion order. It registers declarations
and generic templates under each key, rewrites roots in that order, and places
each specialization in the last actual template owner. A decoded HIR module's
name can instead be its physical parser path. Renaming the HIR, dropping alias
keys, or choosing source representative order changes those semantics.

The additive logical current-registration entry captures the full existing
collector against an explicit logical key. Original parent name/path and the
complete current body digest remain independent physical identities. Publication
re-reads that complete current artifact and re-collects all rows before mutation.
Ordered sealing and execution preserve every logical root, counter, collision
winner, FIFO request, and applied publication. Missing current bodies cannot fall
back to the unresolved archive. Old physical and unresolved entries remain strict.

Retained aliases additionally share a `SymbolTable` class handle. Specialization
functions belong only to their logical template owner, but the inserted symbol
rows and raised symbol counter are visible in every alias of that same complete
body. Assembly therefore replays only those symbol rows, in the retained module
then specialization order, for aliases with the exact same original archive and
current body key/digest. It never shares by name or SymbolId alone, and it never
copies foreign specialization bodies into an alias's function dictionary.

Actual completed-execution capture records the logical label and exact selected
shared symbol publications in the new module-recipe v3 framing. The immutable
recipe replay selects complete applied function records, reconstructs complete
physical modules, and runs the existing closure-first aggregate verifier. Recipe
v1/v2 encoding stays unchanged when logical mode is absent. Public recipe or
repository consistency remains mechanical evidence, not production admission.

The `logical-mono` launcher selector prepares 23 native checks with genuine parsed
provider/root bodies, a transformed generic body returning 99, two logical aliases
sharing the same physical artifact, repeated generic calls, and actual warnings.
It compares complete module digests, physical names, all six counters, ordered
diagnostics, warnings, shared symbol rows/counters, specialization ownership, and
the actual report against the retained pass. Refusal controls cover reversed
order, duplicate aliases, unresolved-mode entry, changed mode, missing current
bodies, inactive/occupied/paused scope. Replay is checked after closed-scope churn.
All native checks are UNRUN; launcher preconditions still require the actual
admitted producer/runtime packet and frozen fixture source owner.

Production integration still needs the genuine weave/streaming-route owner,
actual cold capture, configured quiet-resolution output, and private final read
pin around this logical mono execution and actual report/policy publication.
The retained zero-generics fast return also needs explicit preservation at that
production controller boundary; the mechanical root/FIFO executor is unchanged.
Declaration first-winner order and MIR emission scheduling are separate admitted
driver/source receipts and must not be inferred from mono's logical order.
