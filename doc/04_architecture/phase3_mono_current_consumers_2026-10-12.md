# Current-body root, FIFO and verification mechanics

This adds complete current-body input mechanics to the existing mono consumers.
It does not establish driver prerequisite/final admission, activate production
archiving, reclaim previously promoted HIR, or qualify the full CLI RSS limit.

The registration compatibility module reexports its unchanged public API from
three lower leaves: body-free registration schemas, actual schedule/state
identity functions, and the current seal. These leaves do not import the
compatibility parent, avoiding a reexport cycle. The complete collector and
unchecked installer remain private implementation in the parent; splitting
does not expose an alternate path that skips body replay. Parent and leaves
remain below the 800-line owned-source limit. Moved function and retained
collector/install/seal bodies are exact source extractions; native 13/20 guard
fixtures remain unchanged and unrun.

`MonoArchiveBodyInputV1` separates an original unresolved parent from an optional
complete `post-hir-resolved-v1` body and raw-cache context. Current mode requires
both fields. It cannot substitute the original archive when the current body
or context is absent. The complete loader returns borrowed HIR and its exact
ordered warnings; it does not open, pause, promote or close a scope.

`MonoArchiveRepositoryV1` retains original parents as source/provider metadata.
Its additive `current_mode`, complete `current_bodies`, explicit `current_cache`
and `current_order` select current inputs. The current mechanical repository
digest binds exact coverage, no duplicates, order, all current descriptors and
cache directory/producer/enabled fields. Default unresolved repositories refuse
ambiguous current fields and retain their existing digest domain.

The current registration seal checks the actual fresh collector predecessor,
full admitted name/path/order inventory and published root schedule. It captures
a digest of the actual initial compact state, descriptor repository, registration
epoch and schedule before closing scratch. Current execution creation rechecks
that capture. The original execution creator does not accept the current digest.
This is mechanical state/byte integrity, not proof that the genuine production
post-HIR source/policy/gate/weave/cold/quiet prerequisite owner accepted it.

The existing root/FIFO rewrite, request allocator, specialization, typed function
record, apply, root barrier, counter publication and applied-publication ledger
remain shared. Each publication now binds the selected input key/body digest
and stores that input's ordered warnings. Default inputs use the original
archive identity; current inputs use the current complete artifact identity.
Changing a current publication back to its unresolved parent is refused before
any persistent state/cursor mutation.

One shared reassembler now accepts either typed input. It loads the complete
selected input, applies exact ordered root and FIFO function records, retains
full function parameters/defaults and symbol/type owners, advances counters and
uses the existing unresolved/emitted pruning semantics. Complete assembly
descriptors additionally bind current input and cache metadata when present.
Decoded modules, expressions, functions and full symbol tables remain scratch.

Immutable verification-use recipes preserve the existing unresolved version 1
byte layout. Current recipes use explicit version 2 with framed current
artifact/body/warnings/stage/boundary/cache fields; exact exhaustion and stable
re-encoding reject omissions or reinterpretation as unresolved version 1.
Captured manifest rows bind the actual selected current key/body digest. Replay
uses the same input-aware reassembler and actual closure-first verifier. It
takes no caller-authored clean report or replacement body selections.

The `current-mono` native fixture creates real complete parsed provider/root
HIR and real cross-module generic requests. A mechanical transform replaces
`outer`'s complete body with literal 99 and removes its call to `inner` while
retaining the complete unconsumed `inner` body (43). Repeated root requests for
integer/text specializations must produce two FIFO publications, rather than
the unresolved parent's four-request graph. The fixture compares full root and
provider codec digests and the actual report against the retained mono pass on
the same complete current inputs. It observes both specialized bodies as 99,
retained inner as 43, consumed outer pruning, current warning seals and actual
epoch/counter writeback. Controls include reversed order, original creator
refusal, post-seal state mutation, absent/mixed current mode, rewritten stale
parent publication identity, incomplete barrier/capture, post-close replay,
4096 allocations and inactive/occupied/paused reads.

The transform boundary values are explicitly synthetic mechanical controls.
The launcher still requires real admitted compiler/runtime/provider receipts
and exact frozen source/fixture snapshots. The 20-check native fixture is
prepared but unrun. Existing recursive/depth/diagnostic controls remain in the
shared mono fixture; they are not claimed to have run on this new path.
The common raw owner retains its existing 8 MiB total-envelope bound. Oversize
complete current frames refuse without truncation; full-inventory qualification
must measure actual largest frames or add exact chunked publication where needed.

Next production dependency is MCP's genuine prerequisite owner and accepted-use
replay, including actual weave intermediate, real cold capture and configured
quiet-resolution output. That owner must pin these exact current descriptors,
fresh registration state/order and immutable verification-use capture before
policy publication or a final repository/reader can authorize MIR. The public
mechanical hashes above cannot replace that authority. No final API stub or
activation flag is provided here.
