# Actual archived post-HIR weave boundary

`driver_hir_archive_weave_boundary_capture_v1` derives its input from the real
driver's accepted publication journal, selected runtime/tool provider, captured
policy, physical source inventory and exact streaming visit/layout schedule.
It reopens frozen physical source bytes through the selected frontend and
restores the frontend claim registries after comparing every captured source
obligation. Authored paths remain labels and do not replace the frozen paths.

Complete declaration collection precedes body facts. A partial dropped-value
census returns before the dereferencing body walkers. Otherwise the shared
layout, layer, effect, RT and aspect gates run on newly collected facts. The
actual shared weaver then runs in claim-major order, rereading the latest
complete body for every claim. Logical aliases of one exact original archive
share every rewrite. Advice still runs after earlier gate errors when aspect
validation succeeds; the fatal diagnostic publication follows weaving. Failed
validation produces no accepted owner or cold capture.

Only genuine capture selects original RT consumption. The RT gate compares
every captured capability field and cardinality before revoking the original
manifest's sealed visibility. Revocation allocates no replacement registry
array inside scratch. Partial census never reaches this operation, and replay
leaves the later compilation's manifest untouched.

Successful capture writes a complete immutable transcript and registers its
exact owner/use bytes in private process-owned pin maps. Public constructors,
secure raw artifact storage, and recomputed hashes alone grant no read use.
`driver_hir_archive_weave_boundary_use_v1` verifies the registered transcript
and repeats the actual source, graph, gate and weave execution. Borrowed reads
require scope state 1 and the exact registered complete use metadata; they do
not open a nested scope or retain complete HIR outside the body lease.
