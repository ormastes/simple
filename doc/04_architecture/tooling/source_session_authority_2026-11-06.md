# Source-view authenticated session authority

The canonical Caret messaging HTTP owner composes authentication, a manager registry and the shared source service. The ordinary MCP stdio transport supplies no logical-subagent credentials and remains explicitly unbound. Do not infer identity from transport, tool prose, working directory, process ID or UI SessionView rows.

The protected configure_primitive_http_server call creates a source authority from its configured principal/workspace/scopes/expiry and binds that logical workspace to canonical cwd at startup. The existing owner bearer authenticates credential issuance. Bound source resolution receives this captured root explicitly and never rereads process cwd. The opt-in messaging server worker launches and publishes a MultiCaretManager in the SAME process before accepting requests; only registered children with canonical opaque owned-process leases can receive a credential. Ordinary messaging mode does not receive source:manage or a manager registry. The workbench publication hook alone does not bridge separate processes. Library imports do not share globals across processes.

Credentials derive from32 OS CSPRNG bytes through sosix_random_hex and existing SHA256 with host epoch and monotone issuance generation; returned bearer is64 hex bytes. The issuer retains only SHA256(token); verifier uses the common constant-time comparator. Exact binding includes configured principal/workspace, SHA256 of the length-framed manager/agent identity, owner-assigned generation, random service epoch and expiry capped by issuer/owner expiry. Requests cannot select principal, workspace or generation. Replacement/revoked/expired credentials fail closed; explicit owner reissue produces a fresh generation. No token logging or persistent credential files.

The canonical HTTP server spawns connection threads. One canonical mutex gate protects authority publication and each source transaction: verify, read preferences, bounded service call, recheck credential/time, commit first-success help, store state, unlock. Every ordinary error returns through the wrapper unlock. This serializes first help and preference replay; no concurrent acceptance is claimed until the threaded test executes. The lock spans bounded file/parser work (maximum source size and payload enforced by shared service); measure contention before latency admission. Mutex lives for the service process; startup config is not an exposed request operation.

The host owns session state, not source parsing. app.source_view.service supplies protocol-neutral SourceOpenResultV1; MCP and HTTP serialize it independently. Source host libraries have no app/MCP dependency. First help is consumed only after service success; failed reads preserve unseen state. Raw source remains undecorated and preferences appear separately.

The optional owned source mode retains the native OwnedProcessLease and a parent-minted spawn identity. PID existence grants nothing. Each issue/verify polls that exact lease; a separate supervisor pumps all leases every100ms even without HTTP requests. It releases the authority gate before sleeping, stops after a finite hour, and disables credentials on exit. It retains/reconciles the actual manager owner, revokes admission under the gate, then performs finite child cancellation/collection outside the gate. The worker joins and checks this owner result on normal return. Abrupt host termination is not claimed to execute cleanup. Runtime owner containment, actual child launch and protected credential delivery remain integration gates.

The authority uses a host-wide monotone generation counter; retired rows and unreachable credential/session entries are reclaimed, so historical identity churn does not consume live capacity. Registry capacity is128 and each manager at most16. Revoked tokens are excluded from retained credential slots. The public adapter samples authoritative time after lock acquisition; the pure authority accepts explicit time for deterministic unit coverage.
