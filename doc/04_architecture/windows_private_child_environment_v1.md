# Windows private child environments

Status: reconciled source candidate against release/1.0.0 revision 570c94eb03a75949ce741f9beceec6735abc14e3. The earlier reviewed component passed real native qualification on an explicitly mixed source capsule; this does not qualify a whole current-release consumer.

The actual selected native C capture owner already supplies CreateProcessW, explicit inherited std-handle lists, a suspended child assigned to a Job, bounded stdout/stderr collection, deadline termination, leader wait, RSS and close. Its inherited environment was private but not configurable. app.io.process_spawn_async_env rejected nonempty Windows maps. The separate pure Windows redirected owner accepts a complete environment but redirects files and currently restricts names to ASCII; substituting it would change the selected serial proxy boundary. ProcessOwnedV4's Windows unsupported fallback is not replaced or advertised as supported here.

The canonical app.io.process_ops function is process_run_bounded_environment_v1(command:text,args:[text],environment:[(text,text)],timeout_ms:i64,max_output_bytes:i64)->Result<ProcessResult,text>. Its sole body belongs to std.nogc_sync_mut.io.process_ops, with the existing ProcessResult from io_runtime. App IO files only re-export it. A native/SFFI owner bridges explicit command pointer/UTF8 byte length to the selected C owner, following the existing native capture ABI. No app-local rt_env/process extern or global environment mutation is introduced.

Exact-environment capture requires a directly executable pinned command path and applies only host_path_native. It does not perform ordinary process_run_bounded command lookup or shell/shebang routing. Async overlays preserve ordinary async's _resolve_posix_tool followed by host_path_native policy; they do not add _resolve_process_cmd lookup.

Full replacement copies precisely the supplied list; no parent keys are inherited or silently stripped. Empty values remain present. The API has no deletion operation; omission only removes a key in full-replacement mode. Unicode UTF8 names/values are validated and converted to UTF16 with MB_ERR_INVALID_CHARS. Case-insensitive duplicate input aliases are rejected. CompareStringOrdinal supplies Windows case-insensitive ordering and merge semantics. A complete environment ends in two NULs, including an empty block. Valid hidden drive keys (=C:) are preserved explicitly; other keys containing '=' and NUL names/values reject before creation. Caller text keys are checked before flattening so A=B cannot silently become key A. Entry/byte/unit bounds fail rather than drop data.

The existing async-map API uses the same builder in inherited-overlay mode and the existing PID-keyed async registry/wait/kill/liveness lifetime. Its original ABI remains; CreateProcessW replaces A so Unicode is not lost. POSIX keeps its existing env utility route. This ordinary PID API must not be serialized as opaque authority, and is not a V4 lease/tree proof. The bounded capture API exposes no PID or handle.

The selected capture Job/pipes/deadline/cleanup path is reused, not reimplemented. Existing ordinary capture calls keep their inherited-environment policy. Explicit-env capture borrows the private UTF16 block through the synchronous owner and frees it after return. Native result flags independently report timeout, output limit, provider failure and incomplete leader cleanup; child text cannot forge these outcomes. Limited payloads are suppressed instead of forwarding cut protocol/UTF8 data. Normal nonzero child exit is an Ok ProcessResult; provider/cleanup failure is Err. No claim about ProcessOwnedV4 admission, descendant identity or general tree proof follows from this ordinary API.

Inputs are copied/borrowed only within a synchronous native call; command/argv/environment remain retained while copied. The new four-word native result (stdout handle, stderr handle, untagged exit, flags) is borrowed per OS thread until its next call and copied immediately by SFFI. No global env setter is used, and TLS prevents another thread's result overwriting the caller. Existing 84e wait/RSS hunks are preserved; the GDB candidate and live/frozen MCP sources are untouched.

The native fixture uses a real Win32 Unicode observer and a native Simple parent invoking canonical facades. It verifies exact replacement/absence, Unicode names and values, present empty values, sorted/hidden-drive entries, double-NUL empty environment, invalid/duplicate keys including Unicode case aliases, bounds, actual grandchild creation then timeout cleanup, overlapping async children behind a release gate, unchanged parent variables, the same shebang through empty/nonempty maps, and finite warm handle retention. The outer checker records descendant counts rather than PIDs/handles; observed fixture cleanup is not a V4 capability proof. No serial hardware or SSH endpoint is executed.
