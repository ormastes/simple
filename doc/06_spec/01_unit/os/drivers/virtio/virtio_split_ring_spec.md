| Scenario | Operation and expected observation |
|---|---|
| Region layout | Construct 128- and one-entry queues; check exact descriptor, available, and four-byte-aligned used-ring addresses. |
| Exhaustion and reuse | Initialize four links, allocate each once, observe exhaustion, free one slot, and recover only that slot. |
| One descriptor | Initialize one link and prove its explicit sentinel prevents allocation of descriptor zero twice. |
| Halfword access | Exercise real queue methods through the existing typed MMIO journal; verify 16-bit values and unchanged 32-bit journal entries. |
| Available-index wrap | Start at index 65535, publish to the last slot, wrap to zero, and preserve slot zero. |
| Wide descriptor address | Allocate and free descriptor 4096 without touching the descriptor-zero link. |
| Invalid geometry | Reject zero, negative, non-power-of-two, oversized counts, unaligned addresses, and a zero base without MMIO. |
| Invalid descriptor index | Reject indices outside the queue without altering the free head, available index, or sentinel values. |
| Maximum ring | Accept 32768 descriptors and consume its unsigned end sentinel correctly. |
| Device initialization | Feed an invalid device queue size through `VirtioDevice.init`; require an error, FAILED status, and no QUEUE_READY publication. |

The journal distinguishes MMIO access widths; it does not emulate byte aliasing.
The native fixture therefore allocates one MiB through the DMA owner and calls
the actual queue methods with the hardware MMIO path. It checks adjacent
descriptor/ring sentinel bytes, exhaustion/reuse, index wrap and maximum-ring
initialization. Every failed check returns nonzero, and allocated memory is
released before return. Success requires exit zero and exactly the marker
`VIRTIO_SPLIT_RING_NATIVE_MEMORY_PASS`.
