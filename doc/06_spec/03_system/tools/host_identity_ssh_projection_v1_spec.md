Prepare separate disposable real OS installations. Linux must use the genuine

1. **Retain both existing files.** Open the actual store and read initial key/pin
   bytes only inside process memory. Begin the paired projection and advance
   bounded production steps to Ready. Missing/unsafe installation or unsupported
   service context fails explicitly; it is never skipped. Require both actual
   transport path suffixes and a successful actual continuation check.
2. **Invalidate before partial projection cleanup.** Copy the actual wrapper,
   close once, require remaining ownership (the pair has two real files), and
   immediately reject copied paths. Complete actual cleanup before assertions.
   Read both records through the still-open store and compare full bytes using
   boolean equality so private data is never an assertion/capture payload.
   Closing the projection must not publish, overwrite or delete either record.
3. **Drain children before parent resources.** Acquire a real Ready pair, start
   owner-bearing store close, immediately reject projection paths and deny Ready
   continuation. Finish bounded store cleanup, then reject stale projection use.
   No second writer or root registry supplies authority during teardown.
4. **Refuse a foreign actual store.** Open the independently prepared second
   store, present it with the first projection and require foreign-store error
   while preserving the original cleanup owner. Original paths are invalidated.
   Complete the original pair and both store cleanups before assertions.
5. **Retire bounded child generations.** Reserve eight actual canonical children
   without claiming Ready or opening fake targets. Require refusal of a ninth
   concurrent child. Cancel/close those original owners, begin a new child, and
   require successful admission/closure rather than a lifetime eight-use limit.
   Old copied projections must refuse after a slot is reused with a new generation.

Fixture loops are finite (128 phased advances). They continue only genuine
progress/no-error states and stop on retained native failure. They never sleep,
retry an uncertain raw descriptor, fabricate a successful close, or discard a
partial owner. Assertion failure leaves diagnostic owner arrays available.

The following require independently prepared isolated native fixtures or real
fault hooks and remain **MANUAL_NOT_RUN**:

- Namespace closure/drift: while an actual service pair and SSH child are live,
  change or invalidate the real service DOS context/token evidence in a
  disposable environment. Paths/current must fail permanently; the consumer
  must cancel the actual SSH process and retain process, pair and store owners
  through terminal cleanup. Restoring names/context must not reactivate that
  failed projection; a new actual producer/admission is required.
- Root identity substitution: arrange a real candidate DOS alias selecting a
  different protected directory. The actual read-root/writer-root equality
  check must refuse before target readiness, even if ACLs look equivalent.
- Either target missing, wrong type/owner/privacy, reparse/hardlink, changed
  inode/name, oversized record, replaced key or pin: require actual refusal and
  retain all partial read-file/read-root capabilities. No path-only or cached
  metadata proof substitutes either file.
- Windows sharing: while both real read files are retained, independently
  attempt write/delete opens/rename on each exact file and observe denial. Both
  remain held until SSH is terminal. Directory sharing is a distinct native
  contract, not a claimed FILE_SHARE_READ restriction on every ancestor.
- Linux read descriptors: perform actual target/name drift tests. The owner
  must detect observed drift and invalidate paths; it does not claim Windows
  write/delete-sharing exclusion. Same-user/root/kernel exclusions remain.
- Genuine fork/PID-namespace collision, worker-thread use and procfs/mount
  substitution: existing retained origin checks must refuse before mutex or
  canonical state access, without closing inherited parent descriptors.
- Failed second-file acquisition or any file/read-root/namespace close: preserve
  every actual native capability. Parent store must remain owner-bearing and
  report the actual failure. Namespace close follows files and read roots;
  store journal/root close follows all child obligations.
- Linux consumed-unconfirmed close: consume the fd before close, never retry
  its raw number, keep the parent's error truthful, and never recycle the
  uncertain child slot. Confirmed closure alone permits new-generation reuse.
- Actual OpenSSH launch/continuation, child cleanup, Service process inheritance
  and crash/restart: retain real process plus paired store proof, cancel on proof
  loss and verify both targets remain bound. This spec launches no SSH process.

No private key/pin bytes are logged, serialized into SDN, captured or supplied
through environment variables. Public path data is never an owner constructor.
