# Authenticated runtime controls — manual corresponding to SSpec

AUTHORED_UNRUN. This manual describes executable source; it is not generated
runtime evidence and does not qualify interactive Container control.

Provision the existing signed binding fixture's compiled smux/orchestrator,
enrolled host, immutable running workload, separate signed helper authorities,
private marker file, real broker/cgroup resources and protected roots. Install
`HOSTROOT/smux-runtime-control-policy.sdn` privately with version 1, kind
`smux-runtime-control-policy`, the installed principal, allowed `[input, geometry]`
and `maxLeaseMs: 15000`. The server reads this snapshot at startup. Preserve
the existing fixture configuration and exact executable digests. No engine CLI
may substitute for a shared Container API effect.

1. Run the actual signed binding setup; create the target, sign/prepare/bind its
   helper and observe a fresh workload nonce through the sole pane reader.
2. **Issue distinct control rights from the authenticated configured socket.**
   Admit a real client attachment, resolve its exact target digest, then issue
   Input and Geometry independently. Confirm distinct secrets and stable issue
   replay expiry. Do not publish raw secrets in diagnostics or evidence.
3. **Reject runtime control effects and the legacy attachment input bypass.**
   Submit each valid capability through its real compiled client. Current
   providers must return unsupported, no effect, and nonzero CLI status. Submit
   legacy leased `client-request ... input`; it must fail at the bound pane guard.
4. **Revoke Input while Geometry remains issued then detach the attachment.**
   Revoke only Input, reject its stale secret, observe Geometry still active,
   detach the attachment, and observe Geometry retired.
5. Clean the actual attachment, retain uncertain cleanup owners, obtain exact
   host settlement, stop the sole writer, and independently inspect the original
   workload still running. Never treat detach or control revocation as workload
   cancel/terminate authority.

The spec retains the live fixture after every effect outcome. Missing backends
or unavailable configured policy fail before a success claim. Full provider
stdin delivery, terminal resizing, interactive exec and independent daemon
restart acceptance remain required future tests; no output-only pass covers them.
