# Protected broker read compatibility delta

Status: AUTHORED_NOT_RUN. Additive feature source only, separate from corrective auth19 R2. No runtime/compiler/native/build/spec execution, no installed authorization or recovery completion claim. The immutable R1 and R2 authentication candidates are unchanged.

The new restrictive function is `linux_protected_root_reader_require_root_v1(owner: LinuxProtectedRootReaderV1, expected_root: text) -> Result<(),text>`. It calls actual canonical current first, then checks the reader's private original binding against SHA256 of the fixed reader-domain prefix plus expected canonical root spelling. It returns no root getter, token or boolean authority. A copied file in rootB cannot satisfy rootA's expected spelling; spelling is exact, never normalized. This is not installed external-root authorization, process association, broker owner authority or cancel/lifecycle proof.

The only storage-limit changes are read maximum and retained-file validation/currentness from8MiB to16MiB (16777216bytes). Every individual read still validates maximum>=1 and <=16MiB, and actual file size<=the requested maximum. Auth512-byte reads, WAL1MiB reads, existing caller limits and all8MiB publish/stage/readback limits remain unchanged. No unbounded allocation/read, pathname fallback, registry, writer or runtime export is added. A known retained16MiB file remains current; requesting that file through a512-byte read refuses and preserves cleanup custody.

Executable specimen preparation: provide two distinct existing current-user0700 roots under trusted root/current-user non-writable ancestors via SIMPLE_LINUX_BROKER_ROOT_A and _B. Each must contain identical real current-user0600 regular single-link UTF8 broker.request bytes; private root matching must still distinguish them. Provide SIMPLE_LINUX_BROKER_LARGE_ROOT with broker.request sized8MiB+1 through16MiB. The actual broker consumer may additionally require valid legacy broker encoding; this storage fixture asserts bytes and security only, not broker authorization. No source fixture creates files insecurely, fabricates handles or prints private contents. Missing prerequisites fail.

Required manual boundaries remain MANUAL_NOT_RUN: exact16MiB accepts if all actual metadata/current checks hold;16MiB+1 refuses; zero/negative/>16MiB requested maximum refuses; retained-current and cached read revalidate original ancestry before exposing bytes; copied/closed/fork/non-main-thread reader cannot match; wrong expected root cannot invoke path fallback; real close failures preserve monotonic consumed/unconfirmed custody. No failure-injection producer is available here, so those fault cases are NOT_COVERED. Unchanged original auth R2 regression/cleanup requirements still apply.

Integration: the broker recovery owner borrows the genuine original reader and must call require_root with the actual launch owner's recorded original root before decoding fixed broker.request via the existing pure legacy codec. It never closes/reopens that borrowed reader, invents a registry or converts decoded DATA to lifecycle authority. Installed external-root policy and live anchored cancel remain independent Host/cleanup obligations; unverifiable resources stay charged.
