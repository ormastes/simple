# Linux installed whole-provider inventory V1

Status: **AUTHORED_NOT_RUN; observational component only.** Root selected the
single dedicated rootless UID/store slice and six unfiltered resource classes;
Astra primary froze its interfaces and closed-store installation model before
implementation. The upper machine writer, charge adoption, genesis and migration
handoff remain blocked and belong to their existing owner. No runtime/build or
engine campaign is authorized for this source-only change.

`linux_installed_provider_inventory_open_v1(supervisor)` accepts the genuine
`LinuxInstalledSupervisorOwnerV1` and retains it by capability. There is no public
constructor from a CLI, endpoint/path list, bytes, parsed JSON or diagnostic
snapshot. The only public result owner has private slot/generation fields;
aliases share one canonical registry. Every public entry and cleanup path uses
the existing native Linux process-origin guard before registry access. A stale,
foreign-process, fork or namespace error is never released/empty evidence.

The root-owned profile must install the exact
`single-rootless-uid-all-stores-pinned-v1` closed provider model and a canonical
installed V3 policy. A separate real protected machine-policy reader compares
the exact policy digest and requires exactly one provider, backend linux-podman,
whose CLI policy bytes match the installed policy. Different real reader owners
have independent generations; equality is checked on actual process identity,
PID, thread and namespace. Every reader independently validates its generation.
The closed store universe is an administrator installation obligation, never
deduced from the response to a scoped query or from caller-provided metadata.

The observer invokes no CLI. Each actual Unix service connection must match the
retained supervisor's actual provider MainPID, UID, incarnation and original
socket inode/device. The actual owned connection is retained before inspecting
any error; post-acquisition failures return the inventory owner, preserving
unresolved socket/reader cleanup. Confirmed native EOF, exact HTTP framing,
pinned service version and strict JSON precede counting any list as complete.
Actual `/info` before/after validates exact graph/run roots, driver, options,
rootless/local mode and engine version. A separate service-store/native-peer
digest is used; no fictitious executable digest or CLI-observation type is used.

No default network, label, image or name is exempt. All rows retain their class,
native identity and quarantine marker. A complete scan can contain noncompute
objects; it cannot treat them as absence or decide how to charge them. Unknown
schemas, continuation headers/pages, duplicate identities, malformed or capped
responses never reduce the resource count into usable absence evidence.

Limits: six list endpoints, one MiB JSON per response, 16 KiB HTTP headers,
2,113,536 bytes per wire response, 12,681,216 aggregate list-response bytes,
16,908,288 total bytes including two `/info` responses, 4,096 aggregate rows,
JSON depth 16 and structural budget 65,536, one absolute 30-second monotonic
deadline. Exchanges recheck actual supervisor exclusion before and after; an
expired collection window permanently downgrades a completed snapshot to
Unknown. Collection never retries automatically and has no renewable lease.
Diagnostics expose limits and counts alongside scope/generation/query evidence.

`CompleteInventory` means only the complete six-query observation within that
installed universe. Any container/pod yields `ExistingExecutionQuarantined`.
Bound/truncation/schema failures yield `Incomplete`; native stream, identity and
continuity failures yield `Unknown`. Partial quarantined rows are retained.
None of these values construct a fence, writer, claim or execution capability.

Provider request drain, asynchronous/background mutation and old persisted
charges remain unproved. `provider_drain_proven=false`,
`unresolved_storage_and_endpoints=true` and `machine_genesis_admitted=false`
are deliberate limitations, not successful proof fields. The upper owner must
prove drain and account obligations while retaining the same actual writer and
supervisor before it can perform any successor consumption. Inventory close
releases its own reader/socket and invalidates aliases, retaining supervisor
inhibition. It never stops/deletes/adopts resources, resets a journal or unmasks
the provider's activation routes.

Cleanup uses the actual native disposition, applied through a data-only reducer
to the canonical acquired component. Exact reader `consumed-error` consumes that
reader once; generic stale/foreign/retained leaves ownership pending. A native
socket is consumed only when its facade reports `closed=true` and no remaining
owner. The first cleanup diagnostic remains sticky across independent component
progress and retries. Once all inventory resources are consumed, a sticky error
yields `consumed-error`; `cleanup_diagnostic_v1()` remains readable after close.
This never closes or transfers the borrowed supervisor. Unit contracts cover
explicit consumption, pending dispositions, independent components and sticky
diagnostics. Actual native fault injection is **NOT_COVERED / NOT_RUN**.
