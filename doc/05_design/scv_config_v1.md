# Native SCV configuration v1 implementation boundary

Owner: configuration lane, 2026-10-27. Implements the first SCVN-C01/C02/C03 slice under the approved [full phase 2 design](scv_full_phase2_2026-10-27.md). Runtime and host integration qualification are pending.

`scv_config_parse_v1(bytes, limits)` calls `sdn_parse_strict_bytes_v1` with the caller's unchanged `SdnStrictLimitsV1`, then validates `schema_version: 1` and every key/type/value in the eight `scv` sections from master-plan §5.3. All sections/fields are mandatory in native v1. Unknown keys, duplicate scalar/collection values, unsafe enum values, malformed types, invalid bounds and unsupported requests reject. There is no foreign metadata namespace in v1. Parser limits remain independent of schema checks. Unsupported schema versions reject rather than falling back.

The resulting `ScvConfigV1.validated` describes syntax/schema only; it does not establish policy acceptance or executable provider availability. Every sample setting remains in `settings`, so downstream owners can explicitly consume or reject an unsupported operational request. In this wave structural deltas, private transcript recording, LLM proposals, timestamp scalar winners, nested pools and mandatory grammar downloads reject. Native authority is not offered; topology shared authority supports `git_upstream` only. SHA-256 records exact raw bytes. No raw hash substitutes for a provider lock or acceptance receipt.

`scv_config_load_v1(root, limits)` reads `config/scv.sdn` and its schema-validated repository-relative `routes_file`. The shared `read_only_file_view_read_beneath_bounded_v1` owner opens the root and traverses each child through retained descriptors with no-follow, rejects nonregular leaves and checks actual descriptor size before allocating/reading. It reads through that exact descriptor and attempts close on every opened path. There is no path-read fallback or fake snapshot digest. Windows reports `file_view_containment_unsupported` because the existing beneath-open owner lacks support. The repository root is caller-admitted; this does not assert race-proof containment of ancestors outside that root, immutable file contents, or an atomic two-file generation. Accepted callers must supply frozen inputs; the ordinary root loader validates captured bytes only.

`scv_config_attach_routes_v1` composes independently bounded full SDN parsing with the exact `id, domain, path, profile` named table. It requires 1–256 routes, unique IDs, normalized relative patterns, supported semantic domains and bounded IDs/profiles. `*` matches within one component, `**` crosses components and `**/` admits zero components. Dynamic programming bounds match work by pattern × path byte lengths, with no recursive backtracking. Exact-pattern pairs are checked precisely. Wildcard pairs must prove disjoint literal prefixes or suffixes; otherwise declaration admission refuses conservatively with `ambiguous_route`. This can reject disjoint complex patterns whose disjointness is not supported in v1. There is no specificity/priority policy or first-declaration winner.

`scv_config_route_v1` requires parsed routes and rejects unsafe subjects, unknown domains and multiple matches. No extension-derived solver is inferred. `scv_config_route_transition_v1` uses only the supplied old accepted configuration for both paths and verifies old metadata. A domain or profile transition rejects with `role_transition_requires_old_policy`; this lane exposes no authorization shortcut to approve it. Parsed candidate routes are never automatically installed. Installing a separately authorized future policy generation belongs to the parent Publisher integration.

`scv_config_effective_v1` takes repository intent plus explicit host, old accepted, local and CLI constraints. Each Boolean is ANDed, provider/secure-algorithm sets are intersected, and the smallest memory bound wins. A denied requested durable hash causes refusal, with no silent algorithm substitution. The API grants no publication authority. A framed, tagged canonical encoding binds typed repository settings, route semantics and all four constraint inputs/generations. Its `canonical_sha256` is distinct from exact raw source hashes; formatting-only changes retain the canonical digest. Route profile, policy generation and resource changes invalidate it. Provider artifact/ABI identities will be bound by the later C04 lock resolver; symbolic IDs are not artifact admission.

`scv_config_legacy_v1()` is explicit and always has `validated=false`, version 0 and no source digests/routes. Missing native files never invoke it internally. Parent startup must select it only where the accepted profile permits legacy operation, while preserving ordinary private saves.

Production modules contain no environment/process calls, registry downloads, compiler imports, mutable global cache or filesystem writes. Load once per admitted configuration generation; retain immutable values in the caller and invalidate after an accepted generation change. Do not reread the tree in request handlers. Startup/latency/RSS measurements are not_run pending the admitted runtime.
