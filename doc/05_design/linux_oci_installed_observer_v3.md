# Actual read-only installed service probe

Status: SOURCE IMPLEMENTED / UNEXECUTED. Native positive acceptance is NOT_RUN and requires root allocation plus review of the native Unix owner's fork-origin fence repair. Neither Unix nor mapping ownership is claimed fork-safe by this slice.

`linux_oci_installed_probe_v3(policy, timeout_ms)` returns a `LinuxOciInstalledProbeTurnV3` containing optional connection owner, optional observation and error. It first validates protected-host policy syntax, creates one checked monotonic deadline for a positive window up to30000ms, and obtains the actual CLI engine observation. Connect, partial writes and reads use the same absolute deadline; it never resets a per-chunk budget. The read-only fixed request is the pinned versioned GET info route, requiring no launch grant and granting no exec authority.

The canonical `local_ipc_v1` owner supplies the protected endpoint and actual SO_PEERCRED/socket identity. The probe checks every owner-returning turn, rejects zero progress, reads at most64KiB per call and accepts only actual EOF. A cap-plus-one byte distinguishes exact2MiB+16KiB completion from truncation. No timeout is converted to EOF. Read/write/connect errors close the actual current connection; a close result retains ownership exactly when its returned owner is Some, including ambiguous failures. A consumed close with an error returns no owner and no observation. `linux_oci_installed_probe_close_v3` provides explicit cleanup retry without raw FD reconstruction.

After EOF, socket close must complete before response parsing can publish an observation. The shared finite decoder verifies same-response API5.2.5. Existing CLI info parsing verifies rootless/local mode, exact store roots/driver/options and stable engine version. CLI version, header API and body version must match. Service/CLI stable identity must agree using the actual CLI executable hash as a correlation input. This does not attest the service executable: actual peer UID is an explicit trusted-service boundary.

Composite identity hashes the installed wrapper digest, unchanged CLI identity, actual peer UID/GID/PID, socket device/inode and API version. It remains separate from the old CLI identity and must not be inserted into V1 matching or old retained receipts. Timestamp and dynamic info counts do not affect stable identity. Query/evidence hashes use distinct SDN domains and raw-byte SHA; actual request bytes and response wire are correlated with the installed identity.

`linux_oci_installed_correlate_v3` is deliberately pure data correlation for testing and composition. Supplied peer/CLI values cannot turn it into a native owner or admitted factory capability. Production calls it only after actual CLI observation, native connection, complete request/EOF evidence and successful close. Socket metadata bounds match the native owner's exact2^60-1 maximum.

Six authored scenarios cover pure correlation, identity sensitivity/stability, version/store/rootless/remote refusal, peer metadata/clock boundaries and actual pre-I/O rejection of invalid policy. All are UNEXECUTED; no fake connection or positive native probe is constructed. Native acceptance must exercise a real protected operator policy and service, exact peer/store/version evidence, bounded EOF, timeout, cap/sentinel, close-consumed-error and retained-close-owner paths. It remains NOT_RUN until allocated and until native process-origin fencing is reviewed. The owned/quarantined common factory is separate remaining integration; this probe performs no exec/create/start or journal mutation.

Publication deadline followup: the actual monotonic clock is checked after EOF and confirmed close, before parsing, and again after correlation immediately before publishing an observation. Equality, expiry or clock failure returns no observation with the connection already closed. This is a fixed I/O/control/publication deadline, not a hard whole-function wall-time guarantee: existing executable hashing and process-governor wait lie outside the capture timeout and can make the function return late. A bounded asynchronous owner/wait design is required for a hard wall-time guarantee. No additional CLI capture or test clock callback is introduced.
