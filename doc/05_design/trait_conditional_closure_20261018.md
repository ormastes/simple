# Conditional trait proof closure

Selected contract: a selected implementation succeeds only after its concrete where-clause and supertrait obligations succeed. No merely queued work counts as proof. Public add_trait/add_impl/add_obligation/solve_obligation/solve_all signatures stay unchanged.

The existing matches_type matcher has no substitution output and treats each TypeParam occurrence independently. It also cannot recognize actual HIR Named binder IDs and discards Function effects. A small invocation-owned matcher now derives assignments using exactly ImplBlock.type_params. Named binders use IDs; legacy TypeParam spellings require a unique declared binder name. Repeated assignments require structural equality. Nominal owner IDs and effect payloads are retained. Where-clause symbols must match declared binder ID/name/owner; unbound clauses refuse rather than inventing records.

Supported matching covers primitive, Named, tuple/union, array/slice, optional/result/dict, pointer/reference/isolation, Function including Throws, Tensor and exact Layer metadata. Unresolved Infer/Any/Error/TypeParam/Projection concrete shapes cannot establish a proof; unsupported shapes return Unsatisfied through existing diagnostics. Nominal IDs retain the existing single-symbol-table solver contract. No cross-module raw-ID relocation is introduced; HM adapter must provide authoritative same-table rows and concrete nominal inputs.

Selected children use bound SymbolId→matched concrete subtree and are solved synchronously. Candidate ambiguity remains declaration-level, before choosing by conditions, matching existing solver policy. An active proof map detects exact (type,trait) recurrence and reports existing CyclicBound. Active scratch clears at the outer call; no global history. No arbitrary recursion-depth cutoff: child arguments are matched subterms, supertraits preserve the type, so the supported finite graph cannot generate progressively larger types. Native stack/resource behavior for extremely deep finite inputs remains UNRUN.

Associated-constraint queries neither read nor write the unconstrained boolean cache. Missing, wrong and successful associated predicates cannot poison simpler trait proofs. This does not add generic associated-type substitution/normalization; that preexisting separate API remains open. Ambiguous/cyclic errors are not cached as booleans. add_trait/add_impl preserve invalidation.

Matcher work follows pattern/type trees, with repeated-binder equality traversals and existing candidate scans. Class scratch avoids eager value-struct copies. No performance/RSS claim; active dictionary and existing cache semantics require runtime verification. No new schema, generated visitor, cache envelope, or runtime gate. No edits to HM owner files.

## Revision2 nominal authority

The matcher receives the existing solver reverse_symbols snapshot, supplied by the HM adapter from the actual owning module. Every concrete Named component must resolve to its exact ID with Struct, Class, or Enum kind. Named TypeParam, absent rows, and absent tables cannot establish nominal proofs. Recursive whole-binder validation retains the declared binder map and this authority, including repeated assignments. Primitive-only create() remains supported. Unnormalized aliases are not admitted as nominal proof. No symbol rows are synthesized and no mutable global lookup is introduced. This closes SOLVER-CLOSURE-001; runtime remains UNRUN.
