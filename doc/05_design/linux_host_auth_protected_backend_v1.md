# Linux protected Host authentication backend

Status: corrective source candidate, implementation cycle 2. R1 independent review found two P1s; R2 explicitly imports WalEntryType and checks full retained ancestry after a cached read before returning bytes. All compiler, native, fixture, transport and live-service execution NOT_RUN. This candidate is not a completion or operational receipt.

The existing Host journal health slots own Linux retained storage alongside the existing legacy/Windows paths. A discriminated JournalStorageBackendV3 selects LegacyPath, Windows or Linux. Protected Linux open acquires its native resources only after reserving the same oracle ticket and attaching its stable resource cell to that slot. Mixed Windows/Linux/lock state refuses before storage I/O. An omitted Linux capability cannot bind the reserved Linux slot through the legacy health entrypoint. Legacy function signatures remain wrappers around explicit backend selection; no protected caller selects pathname fallback.

The actual open port is `distributed_operation_journal_open_linux_v3(root, authority_digest, nonce, maximum_events, retention_profile=nil) -> DistributedOperationJournalOpenV2`. Ready, Rejected and CleanupRequired retain their existing meaning. Existing `open_cleanup_v2` and `close_owned_v2` carry every remaining resource. Linux close leaves immutable journal/lease files in place, like the existing Windows storage path; selectors are not service-liveness evidence. `distributed_operation_journal_linux_current_v3` checks genuine protected backend, lease and exact WAL revision under the oracle. Read/publish/history/checkpoint/assessment and transition replay use that same backend. Linux primary-consumption receipt remains explicitly unsupported: a Windows native receipt is never fabricated.

Registry-free LinuxProtectedStorageResourcesV1 is an unsafe IO implementation mechanism, not a Host facade. A private stable cell records each acquired descriptor before fallible validation and each descriptor consumption before close(2). Value copies share those facts, including after metadata-gate failure. Only a containing canonical slot can dispose it, after removing that value. Its cell/fds are never returned by public Host/journal/reader facades. All actual root/UID/named-inode/security checks run under the genuine Linux process-origin/main-thread proof. This profile supports existing anchored Linux x86_64/aarch64 ABI only; zero/unknown flags refuse.

Root spelling is absolute and canonical, <=4096 bytes/depth128, with no NUL/empty/dot/dotdot component. Actual nofollow ancestor descriptors stay retained. Trusted ancestors must belong to root or current euid and forbid group/other writes; the final directory must belong to current euid with mode0700. Only a missing final directory can be created, with mode0700 and parent fsync. Child directories are fixed relative names, current-euid0700. Files must be regular current-euid0600, one link and bounded length. Root identity/currentness and named bindings bracket reads; cached retained immutable files must preserve original identity/revision. Actual ENOENT alone means absent. Wrong type, symlink, changed revision, malformed UTF8 or unavailable security metadata is an error.

Exclusive600 stage creation and positive metadata/mode checks precede secret bytes. The stage is fully written, fsynced and read back. No-replace linkat preserves existing targets. Mutable CURRENT/parent.lease replacement uses the same single flock writer and oracle plus exact expected bytes; it is not a cross-writer grant. Publication errors quarantine the actual resource; uncertain publication is never compensated or retried as a fresh write. Cleanup unlinks only a stage whose held and named identities still match, then drains descriptors. A substituted stage remains pending instead of deleting another object. Directory fsync is performed at actual namespace changes; no power-loss/hardware qualification is claimed.

LinuxProtectedRootReaderV1 is an opaque readonly input carrier over those SAME health slots. Open returns `{owner,ready,error}`; read(owner,relative,maximum) returns Result<Option<text>,text> and retains genuine original files; current returns Result<(),text>; close returns `{owner,completed,error}`. A retained owner is mandatory even after read error. It creates no writer/lease or Host authority, and returns no raw resource or path getter. Closed resource disposal happens only after canonical slot retirement. This supports Host enrollment/policy decoding from actual bytes without a new registry. Authoritative policy/nonce/grant checks remain the Host's responsibility.

Auth setup/publication reuses auth_publications_v1; Linux ready readers reuse ready_readers_v1. Existing slot/generation handles and Windows behavior remain. Setup opens its protected parent before actual OS entropy, generates V6-only setup, publishes no-replace and returns only UID/digest. Listener publication borrows the existing real TcpListener and same Host journal, binds local_addr, random service incarnation, exact setup pin and selected lease/authority; latest journal is retained by caller before every error check. Reader retains original setup and selected immutable ready files, with fresh transient parent.lease selector reads before/after each current check. V6 and AgentV7 MACs retain existing purpose separation and bracket secret use with actual current checks. No new secret getter or V5 bearer conversion exists.

A fresh challenge and shared-secret possession under the selected protected lease/incarnation authenticate the live exchange. expected_service_pid is diagnostic DATA only. This implementation supplies no PID adoption, external pidfd, kill/liveness proof, workload admission, capacity-release proof or remote transport rewrite. Existing Linux origin R3 guards for connection/exchange are a separately accepted dependency; their files are not changed here.

Trust boundary: the current user's process/permissions and trusted root administrators can already access these files; this is not an OS keystore or defense against same-user/admin memory or filesystem compromise. A stronger OS keystore is future separate work. No inode/selector check turns DTO metadata into execution authority. Authentication-freshness ownership remains the existing connection/exchange slots.

Integration gates remain: exact Host protected acquisition forwarding/installed validation, actual listener startup composition, latest wire R2 pure reader/MAC code plus accepted R3 origin delta, independent source review, and real native/transport fixtures. Stats18 is untouched. No standalone data-only or parser-only landing is authorized.
