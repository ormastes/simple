# Shared solver host V1 local draft slice

Implements part of SCVN-P01/P03/P04/P05, source S02 and DB V01 integration under the approved full-phase2 architecture. No task is qualified complete by this source-only slice.

`SolveRequestV1` contains one `SolveBindingV1` plus request identity, shared logical/payload budgets and cancellation. The caller resolves immutable input objects and previous accepted policy before invoking the host. `SolverHostPolicyV1` is a separate trusted-owner argument, never read from a candidate. It pins accepted domain, source/DB roots, revision/model IDs, schema, policy, routing, identity map, parser/solver/profile/configuration locks, operation bundle and authorization scope. Request bindings must match those pins; actual input bytes/models must match claimed IDs.

The five responsibility names remain `ParserProvider`, `DomainModelProvider`, `SolverProvider`, `ValidatorProvider`, `Publisher`. They are descriptor structs, not an executable third-party ABI. The registry dispatches only reviewed fixed built-in IDs. There is no plugin loader, download, subprocess, compiler, network, filesystem, random source, clock, alias allocator or publication call in this solver slice. External providers return unsupported.

Crucially, accepted descriptor labels do not prove the identity of the implementation actually executing. No admitted loader/runtime build-identity integration exists here. The host therefore keeps real computed source/schema/row drafts and typed conflicts but reports `needs_inputs`, `execution_status = unqualified-builtin-execution`, `complete_proposal = false`, and an empty `deterministic_result_key`. It exposes no optional execution-attestation constructor. An `input_binding_key` binds checked immutable data and declared pins only; it is not an admitted result-cache key. Actual executing-artifact identity, secure artifact/ABI verification and loader admission remain mandatory later work.

Source files contain raw `[u8]`, file identity, exact revision, path, kind and mode. The adapter combines exact equal-content or unchanged-side rules with move evidence whose complete immutable digest is separately approved by the caller. Move preconditions bind identity, base/side revision, from/to path, producer and expected secure byte digests. Copies require distinct IDs. Empty/NUL/non-UTF8 bytes survive. Concurrent incompatible bytes, moves, identity or kind/mode changes conflict. No AST or semantic-equivalence claim follows from a raw-byte proposal.

DB schema invokes the separate V2 schema owner, never source/text merging. Both typed schemas and actual canonical digests/revisions are checked. DB rows invokes existing `db_plan_patch` with the separately accepted `DbPolicyConfig`; snapshot, complete patch transport and complete configuration pins bind actual inputs. `UNVERIFIED_PREVIEW` remains unchanged. Signature/admission and combined-constraint evidence are still required.

The host derives mandatory check manifests by accepted domain. Solver-supplied check claims cannot delete required checks. Every check binds candidate bytes/model or exact inputs plus an explicitly required producer. Missing validators remain unavailable. No external receipt verifier or acceptance API is implemented. The publisher is descriptor data only.

Preflight walks all request/accepted binding/provider metadata, source records/operations, schema history/UIDs/constraints/defaults, recursive row/patch values and complete accepted policy before canonical allocation or hashing. Aggregate accounting uses remaining-space comparisons before multiplication/addition, a fixed 16 MiB accounting ceiling, depth 32, per-collection 4096, source move count 128 and conservative quadratic comparison charges. Sixty-four accounting units per logical input byte/node reserve framing/canonical scratch overhead. These are deterministic conservative input/work limits, not measured heap limits or process isolation. Refusal construction skips identity hashing and bounds check-manifest metadata. Native heap/sandbox enforcement remains P02 work.

Disjoint plan composition preserves the accepted caller order and rejects cross-plan write/write and read/write overlap; boundary insertions conflict conservatively. It does not apply plans, resolve semantic dependencies, race providers or admit a cache entry. Conflict wrappers retain all original source/schema/row inputs in memory. Durable conflict storage, resolution receipts/reuse and retention roots remain P05 work; no persistence claim is made.

Executable source and DB schema scenarios use all eight approved shared helper names with real production calls and assertions. DB rows exercises the real reducer preview. Authored manual mirrors describe expected behavior only. No admitted runtime is available, so checks/tests/docgen/coverage and operational qualification remain unexecuted. Parent owns dependency integration, full verification and landing.
