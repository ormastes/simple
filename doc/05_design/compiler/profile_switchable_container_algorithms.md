# Profile-switchable container detail design

**Architecture:** [profile-switchable container algorithms](../../04_architecture/compiler/profile_switchable_container_algorithms.md). **Requirements:** [feature](../../02_requirements/feature/profile_switchable_container_algorithms.md), [NFR](../../02_requirements/nfr/profile_switchable_container_algorithms.md).

## Source and type contract

The intended source form is `@collection_algorithm("auto" | "linear" | "hash" | "ordered")` on an eligible local container declaration or class/struct field. Both parsers accept initialized local `val`/`var` declarations and class/struct fields with defaults, rewriting only their initializer to an attributed static call. They route direct constructors from the four `AdaptiveTextSet`, `AdaptiveTextMap`, `AdaptiveSet`, and `AdaptiveMap` families, and use an explicit adaptive type annotation to route a factory initializer. The static wrapper must type-check the factory result; the parser does not infer its return type. Invalid spelling and missing initializers are parser errors. Interim local site IDs combine module path, lexical declaration owner, local name, and source-subtree hash; identical declarations within one owner receive a parse-local ordinal, and field IDs use the complete lexical owner path. Byte offsets are excluded, although whole-source profile module identity still invalidates feedback after any source edit. The final compiler path must retain the attribute on the typed declaration so HIR can validate container type, key equality/hash/ordering capability, policy level, and target availability. It must derive a stable `ast://module/function/site#hash` identity from that declaration, without using a line or byte position. A dynamic per-instance API remains available for code that constructs containers at runtime. An unsupported combination is a diagnostic, not a silent fallback.

Both parsers recognize only `new`, `with_profile`, and `with_site_and_target` as common direct constructors; the text families additionally recognize `with_site` and `with_attribute`. A different method or factory requires an explicit adaptive type annotation, and a written family conflicting with a recognized direct constructor is rejected. Typed HIR still needs to own the final proof for arbitrary factory return types.

Named nested `fn` and `me` bodies extend the parse-local collection owner path before their attributed declarations are parsed. Sibling nested functions with identical local source therefore receive distinct site stems independent of parse order. Anonymous lambdas and typed-AST ownership still require a stable identity design before edit-tolerant profile admission can be claimed.

For an attributed constructor with an explicit literal `ast://` site, the wrapper uses that site for feedback lookup and as its embedded site argument, matching the runtime instance's retained site. Both parsers reject a dynamic explicit site at an attribute, even before replay; direct runtime constructors retain the dynamic-site API. During a pure-Simple replay, a dynamic or mismatched explicit target is also rejected before a stale hint can be silently ignored. The Rust parser represents ordinary quoted arguments as a one-part `FString`, so its source-site extraction handles both that form and `Expr::String`. The new Rust test exposed and diagnosed that representation; the final source correction has not yet had a passing run because the session's three-cycle test cap was reached. The pure-Simple replay spec also remains unrun.

## Plan and runtime contract

HIR produces a typed `CollectionPlan` with logical operation, key type, effect/order/duplicate proof, candidate algorithms, source attribute, target profile, and stable site identity. The cost planner reads only an admitted in-memory `.sprof` summary. It ranks candidates after semantic and worst-case policy guards; it records selected and rejected candidates for `--explain-collection-plan`. Robust/critical linear selection requires a proved hard cardinality bound; p95 is never that proof. Ordered selection also requires a proved update bound. MIR lowering uses one runtime interface per supported key/equality family and does not change observable ordering or mutation semantics.

The runtime instance stores one active representation (`linear`, `hash`, or ordered) and a policy attribute. Transitions rebuild from logical keys, preserve membership and length, and reset only switch-local counters. `snapshot_values()` has a stable sorted order. Generic adaptive maps check native key support on every keyed operation, including an empty map lookup: auto demotes before using an unsupported key, while a forced ordered attribute fails clearly. Direct `OrderedMap` lookups, containment checks, inserts, and removals also reject unsupported keys before consulting an empty tree. A forced attribute wins over profile hints; `auto` may use measured p95 and live counters. Direct runtime callers may install an admitted in-memory catalog with `sprof_load_and_install_collection_feedback_file`; `AdaptiveTextSet.attributed_at_site` then consults it without file I/O. For `simple run`, the app-level loader admits `.sprof` once, the parser installs a target-specific index, and each matching attributed initializer is rewritten to `AdaptiveTextSet.attributed_with_prior_at_site` with literal prior counts. This lets a fresh interpreter evaluation context see the feedback without sharing a compiled library global. The handler accepts `--collection-profile`, `--collection-module`, `--collection-workload`, and `--collection-target`, clears parser state after the run, and rejects binary delegation. `interpret_file` bypasses cached SMF execution while the parser catalog is active. The end-to-end runner path has not been executed yet. The ordered implementation must use a true bounded update structure or explicitly restrict its use to read-mostly workloads with a proven update bound.

For an `auto` instance whose policy disallows hash, admitted prior size or lookup pressure selects ordered storage. This applies to the text set/map and generic map/set backing; an instance without prior pressure remains linear. The profile choice survives `clear()`, while changing the instance policy or attribute clears it. The no-hash prior path has focused source-level tests but no qualified runtime result yet.

Live collision adaptation (2026-09-27): an `auto` hash-backed instance reads its own observed hash lookup result, including when it has no capture site. A bounded window contains `lookup_promotion_count` hash lookups. A lookup is high-collision when its collision count exceeds one quarter of its probes; more than one quarter of high-collision lookups in a completed window selects ordered storage. A clean window resets and permits later workload changes to be measured. The choice survives `clear()` and prevents immediate oscillation back to hash; changing the attribute or policy clears it. Forced hash/linear/ordered attributes do not take this transition. Text set/map and generic map use the same pure window rule, and generic set delegates to generic map. Source-level tests cover clean and colliding windows, value preservation, forced hash, and clear; runtime proof is still pending.

Generic ordered-key guard (2026-09-27): the erased native comparator reports unsupported registered aggregate keys with a sentinel. `OrderedMap.put` checks even the first key, which otherwise bypasses all tree comparisons. Before an automatic generic-map transition, every existing key is checked; if ordering is unavailable, the instance retains its ordered preference and stays on hash or linear storage while that key is present. Removing an unsupported key scans the remaining entries only in this rejected state; removal of the last unsupported key permits the retained preference to select ordered storage again. Emptying or clearing the map also resets the rejection. If an empty `auto` instance was initially selected as ordered by prior feedback, its first unsupported key switches it back before insertion. A forced ordered insert fails clearly. This runtime guard does not provide typed aggregate `Ord` dispatch, which remains a compiler-level requirement.

An automatic generic map remembers a rejected ordered key to avoid rescanning all entries after every later collision window. The measured ordered preference remains stored while that rejection is active; promotion skips ordered and may use hash or linear storage. The rejection clears when the map is emptied or cleared, or when the instance policy or attribute changes. A later supported key can then use the retained measured preference to select ordered storage without reinstalling feedback.

Generic key snapshots rebuild linear or hash storage through `OrderedMap`, using the same native comparator as ordered storage. Unsupported keys fail clearly instead of exposing an address-dependent key order. Generic set snapshots inherit this rule through their map backing. Equal-key map replacement retains the newly supplied key in all three representations. Primitive floating hashes canonicalize signed zero because `-0.0 == +0.0`; ordered lookup still rejects unordered keys such as NaN. Typed aggregate ordering is still required to make these snapshots available for aggregate keys.

`OrderedMap.put` now uses one AVL descent for both insertion and equal-key replacement. The recursive result carries the updated subtree root and whether a slot was added; only an insertion rebalances ancestors and increments length. Its comparison counter covers the native usability check and each visited node, so the existing geometric operation-count spec can check a single logarithmic search path instead of accepting a duplicate presearch.

## Profile format and admission

`.sprof` v2 retains the v1 function/block/edge lines and adds collection sample lines. Each set sample carries stable site, target, unique sample ID, peak size, lookups, hits, and misses; the loader validates `hits + misses = lookups` without overflow and calculates nearest-rank p95 per site and target. A second `metric` line supports the eleven named P6 measurements from research §12; selectivity uses millionths. The loader rejects malformed values and duplicate IDs across set and metric lines. `sprof_build_collection_metric_index` groups an admitted profile once and prepares count, min, max, mean, p50, p95, and a 64-bin logarithmic histogram per exact site/target/metric. `sprof_indexed_collection_metric_stats` reads that prepared result without scanning samples or sorting. A parallel prepared set index supplies site/target p95 to `collection_plan_select_with_prepared_profile`. `collection_plan_select_with_prepared_metrics` also consumes paired hash probe/collision p95 values from the prebuilt metric index; under automatic moderate/strict policy it prefers a legal ordered candidate when at least one promotion threshold of probes was observed and collisions exceed one quarter of probes. Explicit hash keeps its semantic legality decision. Missing or contradictory pairs fail closed or remain unknown. The compiler pipeline still needs to retain and use these indexes; the older one-off summary helpers remain for offline analysis. The `simple run` path computes `sprof_source_module_identity` from entry source path and contents and requires the profile header to match; imported-module closure hashing remains to be implemented. Module/workload/schema admission precedes collection parsing. Runtime/compiler instrumentation and use of these metrics in join selection remain outstanding. The runtime never opens a profile file.

## Error handling and invalidation

Unknown attributes, unsupported key types, stale module/workload/target, invalid statistics, or unmet P0 correctness gates produce a diagnostic or retain the original logical algorithm. Compiler cache keys include MIR/body hash, callee summaries, target, registry and policy version, and admitted profile identity. Mutations invalidate indexes by collection identity plus version, not pointer alone.

## Verification boundary

### Identity and toolchain follow-up (2026-09-27)

Generated local and field site hashes now exclude the algorithm attribute, and `.sprof` entry-source identity canonicalizes valid algorithm tokens through lexer ranges. This permits reusing an exact site's measurements when only its requested physical algorithm changes; the identity prefix is `source-fnv64-collection-v2`, so older profiles are intentionally incompatible. Path changes, other source edits, and workload/target mismatches remain rejected. These source-level changes have no admitted runtime PASS because both installed Windows launchers currently identify as Rust seeds; the isolated pure-Simple Stage2 runner link remains unresolved. The final design still needs automatic profile capture, typed retention of lexical ownership, dependency-closure identity, typed planner-to-MIR selection, explain output, and cross-backend verification.

Automatic capture crosses the interpreter execution boundary through `std.nogc_sync_mut.sffi.collection_capture`, backed by opt-in core-C state. The bounded channel keys records by stable site and target, records size, lookup, hash probes/collisions, and public snapshot events in memory, and snapshots once after execution. Generic set delegates to generic map, so its events are recorded once. `contains_key` and `get` are separate lookup events, while insert/remove/clear update peak and current size without incrementing lookup count. `snapshot_values`, `keys`, and `entries` each count once as a public materialization request; map `entries` calls an unmeasured internal key helper to avoid double counting. The channel retains peak size through `clear`, filters target mismatch, and resets between sequential workloads. Each site emits one collection sample plus four base metrics with disjoint IDs; `hash_probe_count` and `hash_collision_count` are emitted only after an observed hash lookup, so an unmeasured site is not reported as zero probes. The cap is 14285 sites, hence at most 99995 total profile samples; excess sites fail capture rather than producing a partially admitted profile. The runtime does not open files. `simple run --collection-profile-out=PATH --collection-workload=LABEL --collection-target=ID` validates the snapshot against `.sprof` v2 and writes it after a successful run; snapshot/write failures return command failure. The six-metric C capture block passed a Linux selfcheck linked with the full current runtime. Simple CLI integration still awaits an admitted interpreter and native runner. Concurrent independent runs in one process remain unsupported by the process-scoped channel.

Generic `AdaptiveMap<K,V>.get` uses key presence for its hit counter when an optional payload reads as `nil`. This preserves hit/miss measurements for a present key with a nil value in linear, hash, and ordered storage. The return API remains `V?`; callers that need to distinguish absence use `contains_key`.

The explicit `--collection-profile-append` option preserves distribution samples across runs. It requires `--collection-profile-out`; when that file exists, the app parses and validates both envelopes, combines their counter rows and raw collection/metric samples, checks the 100000-record limit, then serializes new sample IDs and validates the result before writing. A stale or corrupt existing file causes command failure and is not silently replaced. Without the option, capture retains the ordinary fresh-output behavior.

After validation, both capture output and library profile writers use `file_atomic_write`. Rejected append data never reaches the publication call. This protects the existing profile during a failed replacement; concurrency between separate writers to the same path still needs an ownership policy before production readiness.

For linear and hash maps, `entries()` now builds a temporary AVL ordered map from each stored entry and returns its in-order snapshot. This avoids sorting keys and then linearly searching the original map once per key, which made a forced linear map's entry snapshot quadratic. The public result remains key ordered with the same values, and the temporary index does not change the instance's selected representation. Text and generic map specs cover output values across representation changes, including a nil optional payload in the generic case. Geometric operation counts and memory measurements remain to be run.

The temporary AVL index also replaces the former hash-snapshot key sort plus expected-constant-time lookups. Both paths have an `O(n log n)` ordering term, but the new path may allocate more. The perf gate must compare both at geometric sizes before claiming a hash-snapshot latency or memory improvement.


Existing `AdaptiveTextSet` and `AdaptiveTextMap`, local and class/struct field attribute rewrites, and `.sprof` code exercise text-keyed runtime/profile slices. Generic `OrderedMap<K,V>`, `AdaptiveMap<K,V>`, and `AdaptiveSet<K>` source now adds `Hash + Eq + Ord` keys with focused specs awaiting execution. The parsers route direct constructors and explicitly typed factory initializers from these four families; their new cases remain unrun. Typed HIR attribute retention and MIR selection, validated generic key/value coverage, full metric set, runner/CLI end-to-end proof, explain command, five-engine differential execution, and scaling/RSS evidence must be added before the requirements can pass.

Pure-Simple native-build feedback path (2026-09-27): `native-build` now accepts `--collection-profile`, `--collection-workload`, and `--collection-target` in both value forms. It hashes profile content plus workload and target into a distinct native cache directory so profile-enriched objects cannot reuse source-only or different-target objects. Immediately before compilation, a helper validates the `.sprof` v2 envelope against the entry source identity and workload, prepares the set index, selects the requested target slice, and installs it in the flat parser. The parser embeds exact-site p95 counts into attributed initializers; its frontend parse cache is bypassed while the catalog is active. The helper clears catalog state after compilation, including a failed compile result, and returns an ordinary `CompileResult.CodegenError` on admission failure so the native-build cleanup path still runs. A new integration spec captures a workload, builds a native executable, checks initial hot/cold/forced representations, and rejects a wrong target. This path has no admitted executable PASS yet; native full-CLI bootstrap and cross-backend verification remain open.

Paired hash feedback extension (2026-09-27): the prepared set index now joins admitted `hash_probe_count` and `hash_collision_count` summaries by exact site and target. It exposes both p95 values only when both metrics exist with equal sample counts and a valid aggregate bound; otherwise both remain absent (`-1`). Parser-embedded prior calls carry the pair to all four adaptive container families. For `auto`, probe p95 at least the instance's lookup promotion threshold and collision p95 greater than one quarter of probes select ordered storage. The instance keeps that choice through clear and live lookups; changing its profile or attribute clears the hint, and a forced attribute takes precedence. The runtime rejects malformed pairs. `--explain-collection-plan` now reports the same collision-driven initial choice and both metric values. This is a runtime choice for already eligible adaptive containers; typed HIR/MIR plan lowering and target/policy proofs remain separate unfinished gates. New Simple regression specs cover text and integer-key map/set transitions, parser argument embedding, prepared profile propagation, and explanation, but have no admitted source-matched runner result yet.

System replay proof design (2026-09-27): a separate fixture declares four auto containers (`AdaptiveTextSet`, `AdaptiveTextMap`, `AdaptiveSet<i64>`, and `AdaptiveMap<i64,text>`) plus an explicitly linear control. The SPipe system scenario obtains parser-issued site IDs, writes one admitted `.sprof` workload with paired probe/collision samples for each auto site, runs the fixture through the interpreter, then native-builds and runs it through LLVM with the same profile. Each engine must report ordered storage before insertion and after clear, preserved set/map values, and the explicit control still linear. This is executable proof only after the qualified pure-Simple runtime admission gate passes; it does not prove arbitrary generic key types or typed MIR substitution.

The one-off `collection_plan_select_with_profile` entry now prepares both collection and metric indexes from its loaded profile before selecting. `sprof_collection_profile_for_site` delegates to the same prepared set index rather than duplicating a four-field-only p95 scan. Both therefore expose the same exact site/target collision evidence as prepared callers, including rejection of an incomplete metric pair by the planner. Repeated planner requests must use the prepared API so no hot path rebuilds indexes.

The parser's site key and `.sprof` module identity now share `collection_project_relative_path`: it normalizes separators and strips the current process directory from an absolute source path beneath it. The parser sanitizes delimiter characters only after this shared path step, while module identity hashes the unsanitized relative path. A focused spec requires equal profile module identities for `app.spl` and the same file named by an absolute path from the same working directory. Cross-working-directory invocation still needs an explicit stable project-root contract.

Native build warm reuse now includes the collection profile file's SHA-256 digest in the supervisor's final-artifact key, not only its argv path. Immediately before restoring a hit and before publishing a new receipt, the supervisor recomputes the digest and rejects a changed profile. The compile helper also compares the digest before admission with the digest after compilation and returns a codegen error if the file changed. Concurrent A→B→A mutation or mutation after these checks still needs an immutable-input or locking contract. A missing or unreadable profile disables warm reuse so the real worker can report admission failure. Parse-only shards are skipped for profiled builds because their slim child does not install feedback and its unprofiled parse cache would be bypassed by the real worker; HIR shard children still use the full worker and receive the profile arguments. A focused Simple spec changes bytes at one path and requires a different digest. This path remains unrun on an admitted pure-Simple runner.

The native profile compile helper also hashes the entry source before deriving its profile identity, checks that hash after identity derivation, and checks it again after compilation. A changed source fails the profiled build instead of publishing an artifact under feedback admitted for earlier source bytes. This is a detection check; an immutable source/profile snapshot is still needed to exclude A→B→A races.
