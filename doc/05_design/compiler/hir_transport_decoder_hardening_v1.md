# Exact HIR transport decoder hardening

Status: source candidate; generator execution, executable fixtures and native
memory qualification are **UNRUN**. Canonical codec availability remains false.

## Scope and requirements

The selected scope is the declaration decoder's `HirType`/`SymbolTable`, the
declaration-expression artifact's `HirExpr`, and the selective complete-body
transport's `HirModule`, including every generated callee. No unrelated legacy
cache reader is claimed bounded. Existing wire headers and nil scalar/node
shapes remain unchanged. Astra approved this architecture before implementation.

- REQ-HIR-TRANSPORT-001: enter a charged node/depth budget before reading or
  recursively decoding each generated record/enum; balance depth on failure.
- REQ-HIR-TRANSPORT-002: malformed tags, presence markers and booleans poison
  the shared reader and return nil without exit or recursive fallback.
- REQ-HIR-TRANSPORT-003: check cardinality and multiplication before materializing
  entries; charge text decoding, dictionary backing/key handling and pair shells.
- REQ-HIR-TRANSPORT-004: failed children cannot reach constructors, inserts or
  caller publication. Duplicate dictionary keys are refused in bounded mode.
- REQ-HIR-TRANSPORT-005: publish only after successful complete decode and bounded
  stable byte re-encoding, retaining the owner's existing digest/identity checks.

## Ownership and accounting

`src/app/compiler_schema/codec_gen.spl` owns decoder emission. Its checked-in
artifact contains 97 decoder functions. Shared transport checks live in
`hir_decode_transport_support_v1.spl`; existing `FlatPoolReader` owns cursor,
failure and counters. Generated entry points call `enter_node` before fields
and use `defer leave_node` on every exit. Depth-balance fixtures remain UNRUN.

The existing 4096-byte node allowance covers fixed record/enum shells and their
empty containers. `next_len` reserves its array-slot allowance; pairs add 64 and
dictionaries add 256 logical bytes per entry through checked subtraction and
division. Escaped text and text-key operations use the existing reader ledger.
Character validation charges its bounded UTF-8 temporary representation before
allocating it. Nullable scalar assignment stays inline because staged-native
nullable helper returns previously changed the stored representation.

Declaration/expression readers select 8 MiB input, 128 MiB representation,
65536 nodes, depth 128 and 1000000 work units. Selective-body reading preserves
its existing input limit and the same remaining limits. Re-encoding is bounded
separately; these ledgers are **not** exact allocator/RSS ceilings. Native
copy/allocation behavior and combined peak memory still require qualification.

Each decoder constructs local state. Failed children return before insertion;
the three owners expose no value until their complete-frame, re-encoding and
authority checks pass. They do not install partially decoded repository state.
No global availability switch or new custom typed transport is introduced.
