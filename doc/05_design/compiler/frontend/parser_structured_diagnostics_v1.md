# Original parser diagnostics v1

Status: authored, runtime NOT_RUN. This is one producer in full immutable LSP source analysis, not a claim that the entire pipeline is admitted.

`parser_get_diagnostics_v1()` returns original `DiagnosticV1` records from `parser_expect`, `parser_error`, `parser_error_at`, and the warning producer. Existing formatted error/warning receipts, suppression, error flags and scalar first-error receipts remain compatibility outputs. No formatted receipt or stdout is parsed into structured facts. Legacy producers have no original labels or fixes; these are empty, not invented. The direct record insertion API preserves supplied severity, code, labels, children, macro frames, notes, help and fix replacements.

Current-token errors use canonical `lex_current_token_byte_span`, which already converts lexer scalar indices to UTF-8 bytes. Conditional preprocessing blanks excluded lines. Original and processed line-byte indexes are therefore built once per parse, and binary search remaps each boundary to the original line. Retained preprocessor lines are unchanged (`parser_preprocessor.spl` final `final_lines.push(ol)`). Original CR bytes remain part of CRLF lines. Late `parser_error_at` receives only original line and scalar column: it records a zero-width point, and leaves the span absent if those coordinates are invalid. It does not guess token width from message text.

State ownership includes records, original source/path and indexes in fresh/reset, take/install, transient promotion and full flat snapshot operations. Warning clearing removes warning records as well as compatibility warnings. Consumers must drain before reset or warning clearing. `driver_parse_diagnostics_v1(path)` filters exact original file identity. `driver_parse_producer_observed_v1(path)` proves a parser initialization and matching current original path; its caller must additionally compare a fresh generation, as the retained driver does, to reject stale observations. A clean producer can thus be observed independently from a nonempty error array.

Flat-pool version `spl-flatpool-v15-unsafe-decl-index-parser-diagnostics` rejects older layouts at the canonical top-level version gate, before reading pool fields. The nested diagnostic frame retains every diagnostic field using existing canonical escaped scalar primitives. It is one scalar in the parent stream; nested encoding deliberately does not emit parent packed-pool tracing slots. The canonical `FlatPoolReader` ledger bounds both traversal directions to depth 64, 4096 diagnostic nodes, 4096 entries per collection, a conservative 4 MiB escaped output/input frame, 32 MiB reservations and 16 MiB work units. Poison stops each loop. Over-budget encode returns an explicitly invalid frame, which forces a cache MISS; it never truncates live records or restores a partial successful collection. Invalid booleans, severity/confidence tags, truncation, and trailing data fail closed.

The focused spec is `test/01_unit/compiler/frontend/parser_structured_diagnostics_v1_spec.spl`: original Unicode/CRLF token extents, blanked conditionals, late points, suppression, stale path filtering, clean producer evidence, full rich record/state round-trip, version rejection, recursive budgets and original warning code. These tests are NOT_RUN; runtime correctness, native transient graph survival, packed-cache round-trip and latency/RSS remain admission requirements.

## Canonical guard correction

Baseline comparison against HEAD showed `par_lexical_bindings` still present in `ParserState`, initialized in `parser_state_fresh` and reset through `par_state.par_lexical_bindings` in `parser_init_with_path`. HEAD already had the same exclusion and an extractor recognizing only unqualified assignments. The exclusion was therefore not deleted: the actual defect was that owner migration made every parser field invisible to the guard.

The canonical guard now normalizes only the exact `par_state.` owner at expression boundaries, preserving per-file extraction state, and includes the real `parser_diagnostic_source_set_v1` reset owner. The live lexical stack retains its documented parse-session-only classification. Typed parent-pool adapters call the existing bounded diagnostic encoder/decoder; failed nested restores poison the outer reader instead of accepting an empty collection. These direct field adapters make ownership visible to the canonical encoder/decoder rules.

Fixture I adds qualified-owner success, missing-encoder, missing-decoder and wrong-owner negative controls alongside the existing eight fixture groups. One post-fix canonical run, with `/opt/homebrew/bin/gsed` exposed as `sed` through an isolated temporary PATH directory, ran all selftests and reported exactly: **PASS — 164 pool(s) checked, all encoded and decoded**. The earlier 144-pool failure remains baseline evidence. No passing guard was rerun. This static gate does not admit native runtime behavior.
