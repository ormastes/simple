# Body-free archive nominal transport

Status: implemented candidate; execution and admission pending. This repairs integration of caller/provider nominal transport with the release branch's ArchiveRequests mode. It does not disable archive mode or retain template bodies.

Registration projects each genuine module's nominal declarations into `MonoArchiveNominalDeclV2`: explicit module namespace, local ID, kind, canonical owner/name, visibility, scalar flags, span and qualified binding. No HirSymbol type, SymbolTable scope graph or executable body enters resident facts. The existing body/registration seal validates these rows by replaying the actual collector. Per-module key indexes avoid scanning every declaration when a worker first needs a module.

Workers lazily hydrate fresh scratch SymbolTables from those sealed rows and accepted imports. The existing `hir_relocate_types` validates and transports arguments into template ownership, and the specialized signature back into caller ownership. Both retained and archive modes use relocated arguments. Archive mode reads body-free signatures and its explicit specialization-symbol map; it never looks up a retained specialized body.

Requests record caller module/arguments separately from provider-local arguments. Nominal imports allocate from the same reserved global counter as specializations. Publication records only new compact imports, caller return types and requests. Verification recomputes the actual selected function from the exact admitted input in its owned scratch scope and compares the full delta, rewritten function and complete output digest. It does not weaken the old counter equation or trust supplied provider-local IDs. Parent application happens after verification scope closure. Subsequent workers and final reassembly overlay the accepted declarations so serialized HIR IDs retain their owners.

State, delta, registration-row and registration-receipt digest domains use v2. Function-rewrite stages use `mono-function-rewrite-v2`. The global verification recipe explicitly writes/reads `mono-verification-global-recipe-v2`; old v1 bytes are rejected. Nominal decoding bounds row count, rejects duplicate/key mismatches, validates kind/visibility/boolean tags before decoding, and requires existing exact stable re-encoding and full consumption. Old admitted cache headers/receipts are never relabeled.

Required validation includes the existing retained-mode transport tests and new archive direct/method calls, distinct caller/provider argument IDs, import/spec allocation counts, immutable parent-state controls, versioned recipe preservation and legacy/extra-byte refusal, missing ownership and conflicting destination refusal. Actual admitted archive visitor/apply/final-reassembly tests, negative publication corruption, native cross-module regressions, resource observations, bootstrap/Phase3, formal capture and HelloWorld remain required. The candidate currently has no runtime PASS.
