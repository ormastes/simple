# Same-Host signed workspace staging dependency V1

Status: source authored, **NOT_RUN**, internal dependency only. No user command,
domain/V5 route, provider create/start, Git/bootstrap, exec, observation or terminal
success is implemented by this slice. Production invocation remains blocked.

The existing Host capacity/container/source owners remain together. A distinct
internal `host_authorized_agent_workspace_stage_v1` verifies full invocation
permission before actual source staging. Generic Host execution still rejects
workspace allocations. No CPU projector, identity owner, runtime ABI, signer,
registry, journal or Controller writer is added.

## Immutable inputs and authority

The strict full manifest embeds the existing TaskUse, TaskObject and desired-input
codecs, exact source/catalog bytes, the workspace worker's canonical stage manifest,
actual opaque selection/interactive binding, exact inner argv, credential references,
and fixed deadlines/budgets. The stage manifest remains the sole source/file schema.
This initial slice accepts an explicit full commit OID as the AgentSession revision
reference; logical revision resolution remains unsupported. Nonempty credentials
are rejected before capacity begin until their real projection owner exists.

Fixed signed literals require Codex interactive Start, a bounded inner-exec
continuation, trusted wall clock without caller time namespaces, current separate
Input/Geometry gating, and the complete preparation/Git/verify/exec action list.
A preparation-only packet cannot be relabeled as full invocation permission.

The bootstrap request command is the installed protected program. Its exact args
are `--invocation-manifest-sha256 <full-manifest-digest>`. The full manifest excludes
the final request digest to avoid recursive hashing. The independent
`agent_session_invoke_v1` operation binds the full manifest in its payload and the
actual installed policy digest, actual Host scope and exact Host reservation
operation digest in its environment. Existing `host_execute_v1` signatures and
approval remain separately mandatory. Installed roles must explicitly permit the
new action; test keys, SSH/config identity and parsed DTOs confer no production
permission.

## Actual effect path

1. Check the real current Host journal and retained admitted operation. Decode
   strict canonical packets and rederive policy from the exact desired/catalog
   bytes; DATA is never treated as Controller read authority.
2. Rebuild interactive intent from the actual opaque contained selection and its
   original index-zero receipt. Compare raw task, model, argv, source/catalog,
   image/config, program binding and actual Host scope. No public snapshot can
   construct the selection.
3. Call the SAME source owner's installed-profile projection and program/config
   correspondence methods. Compare native request digest/identity/resources to
   the signed Host plan. Match repository/full OID, original quota slot/profile,
   source snapshot, bootstrap/Git/agent digests, and native image. This enables
   staging validation only; it supplies no workspace-enabled native launch.
4. Run the private common Host prepare branch. Generic callers always use its
   original projector and workspace rejection. Archive the original Host packet,
   full independently signed invocation packet and full manifest immutably under
   the same original operation identity using the existing Host journal archive.
5. Refresh actual context and both independent signature checks. Call the existing
   real capacity begin. Any `Err` can follow a WAL commit: return the latest known
   owner, preserve source/container/cleanup, require recovery, and never stage.
   Adopt an actual success-returned capacity owner before further fallible work.
6. The source continuation rechecks the real executing row, exact retained ledger
   reservation/revision, full signatures, installed source/profile and exact
   archived packet. Refresh again at the staging boundary. Call the actual
   `source.stage_agent_invocation_v1(request_bytes, stage_manifest, digest,
   full_invocation_bytes)`. The source owner publishes `invocation.sdn` last.
7. Always return the actual stage-returned source with the original charged Host
   and container. `staging_complete` means bytes staged only. Even completed
   staging reports the explicit provider-launch dependency and retains recovery
   custody. No end-user route enters a stage-then-error flow in this slice.

Stage copying is finite under the workspace owner's file/byte bounds, with its
canonical generation, original exclusion, potential creation plan and observed
creation identities retained before/after effects. Copied/stale calls cannot
restage under another digest. Its retained-success/partial-failure behavior is a
dependency, not a second registry in this composition.

## Continuations and remaining gates

`host_agent_workspace_stage_begun_v1` is an internal same-owner continuation that
reverifies all required inputs and the real executing journal. It accepts no
portable permission boolean. Original successful staging cannot be claimed
current again without actual artifact revalidation. Dirty/partial custody and
capacity stay retained until separately authorized actual cleanup/settlement.
The domain route must retain these owners in its persistent state before future
operational exposure; that route is not present here.

The signed not-after, preparation/workload duration and original Host accounting
never refresh after Git, copied calls or restart. Inner exec is a bounded
continuation of this full invocation; saved signatures do not prove instantaneous
revocation at exec. Fresh post-Git authorization profiles remain unsupported.

Remaining real dependencies: contained-probe retention on the persistent Host,
workspace-enabled original machine/provider request-key/association/start,
retained asset/cwd exec and genuine Git helper retirement, trusted clock checks
inside bootstrap, scoped credentials, original-subject executable observation,
authorized cleanup/resume and sole smux terminal/Input/Geometry composition.
Windows workspace execution remains unsupported. No native qualification or
privileged fallback is implied.

## Evidence limits

The eight authored scenarios cover strict codecs, independent Ed25519 snapshot
verification using explicit test keys, and actual owned Host journal archiving.
There is no positive full Host/source/opaque-selection fixture. No staging,
container start, branch coverage, performance, compiler, SPipe/docgen or native
result is claimed. The workspace worker's real anchored IO scenarios are a
separate dependency; combined source review is required before landing.
