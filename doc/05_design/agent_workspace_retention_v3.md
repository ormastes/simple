# Same-source terminal workspace retention V3

Status: SOURCE_AUTHORED_NOT_RUN. Source chronology is original R1/R2, mutation
R1/R2, accepted versioned consumer round5, this consolidated round6. Identity
ownership stays untouched at6/6. No compiler, test, native or workload run.

The original source slot owns its root, parent and exclusion. Reader, storage
and quota lease remain borrowed from the original durable coordinator. The
new fields do not create another source registry, storage owner or journal.
V1 profile/stage semantics remain strict. V2 requires the actual protected
compiled bootstrap profile, exact signed fullInvocationV2 executable policy,
and checked request memory >= the common minimum. Host separately checks its
real original journal reservation; lower checks the real admitted request.
The compiled policy floor is bootstrapMemory >336794368 bytes, not a measured
RSS guarantee. Before first V2 write the actual retained original dedicated
root must be empty. This attributes attempted creations; it does not prove a
future dirty workspace clean.

`retire_native_v3` accepts the genuine opaque token from the existing native
subject slot. Its current method re-proves original root/pidfd absence. Source
compares original canonical binding, exact request/invocation/profile hashes,
provider generation and live original quota/root identities; it rechecks the
actual token before committing an irreversible native-retired-retained phase.
The full invocation is strictly decoded; retention comes from the exact
AgentSession item selected by desired.resource_identity in its ResourceSet.
No caller metadata, boolean, PID, marker or copied NativeObservation can
advance this phase. Wrong/stale tokens refuse with the same source owner.

The native token proves no OCI, helper, transport or Host/WAL retirement.
The trusted upper coordinator must verify those actual owners and original
journal fences before calling source, then atomically publish returned
canonical metadata with execution-only CPU/memory settlement. A failed WAL
publication retains the actual source and whole charge. Storage quota remains
charged and recoverable. Generic source close refuses after any attempted
staging, including terminal retention; no automatic deletion or quota release.
Guest-created links and files are never walked by this terminal path.

`retained_metadata_v3` returns defensive copies of the historical canonical
retirement event after checking the original source/root/live lease. It does
not need the now legitimately closed native observer, and is never accepted
back as proof. Repeated retirement while the genuine token is live requires
the exact same event. A retired slot cannot begin another runtime binding.

Before native birth, failures instead use `creation_retained_metadata_v3`:
actual parent/root identities, exact invocation digest, ordered creation plan
and actual receipt digests, and uncertainty. It carries NO native snapshot or
absence/settlement credit. Unknown observations return an error while the
owner, archived request, exclusion and entire charge remain retained.

Common storage/linux_workspace_retention_v3 encodes SDN for original WAL rows;
it has no public authority constructor or metadata-to-owner recovery API.
Upper recovery must preserve the original archived identities, lease request,
profile and charge, and reacquire through approved original durable owners.
The serialized event alone cannot reconstruct a live capability.
