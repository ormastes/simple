# gxHash128 version4.0.0 scalar design and evidence

Root-selected scope:128-bit one-shot only. Public `gxhash128(data: [u8], seed: i64) -> [u8]` returns exactly16 little-endian bytes. Any byte length and signed64 seed are valid. No Rust typed Hasher, streaming, hardware acceleration or SCV provider integration is added. This is noncryptographic.

The owner is `src/lib/common/hash/gxhash.spl`. Private bounded16-byte helpers implement AESENC/AESENCLAST using the existing AES S-box, initialized once per hash. Explicit arrays preserve update/value semantics; signed shifts and masks preserve seed two's-complement bytes. The S-box argument is explicitly `[i64]` rather than generic `list`, preserving typed byte values through helper calls.

The historical author PDF revision1 November2023, SHA256cfd0502072786e4219e7ff18579c6e8e26ccbb60d3e8f92f51d9ab1b2062553e, motivates wide-pipe/AES design (sections4.1-4.4,p9-10) but differs from4.0.0's seed and finalization. Exact pinned source controls output semantics.

Short inputs are copied safely and padded with their length; empty input is the zero block. Length16 uses a prepared seed and length injection. Medium inputs preserve upstream front/tail overlap at32/48/64/96 boundaries. Large inputs use4 lanes through512,8 through2048,16 thereafter, including overlapping final chunks and the exact half-fold merge tree. Length is in the low64 lane. Finalization is regular AES round with pinned key, regular round with zero, last round with zero. A scalar port does not require unsafe out-of-bounds reads or CPU feature availability.
