# Compiler-owned SCV semantic validation bridge

Owner/base/worktree: `/root/impl_solver_host`, `8dcbbbf949c`, `/tmp/simple-scv-buildrunner-semantic-20261027`. This is a source-only implementation slice under the approved BuildRunner-first integration research, not Phase 3 execution or full artifact admission.

The common `scv_semantic_validation_v1(request, provider)` API returns typed `Verified`, `Changed` or `Unavailable` read-set outcomes with exact SCV snapshot/action/manifest/semantic-generation/profile subjects. It reuses `SemanticQueryReadManifestV1`; no replacement semantic manifest is introduced. The caller chooses a trusted provider, independently of request data. `full_artifact_authorized` is always false. There is no new scheduler, CLI route, cache store, producer, grant issuer or receipt authority.

Request data contains an actual immutable `ScvSnapshotV2`, source witnesses, their `VerificationReceiptV1`, source path and raw source-byte digest, action digest, recorded SQR1 manifest and its canonical byte digest, requested compiler semantic generation/profile, and byte/read limits. Common validation replays the source witness verifier, compares the complete receipt fields, checks actual frozen source bytes, validates every existing recorded read and complete coverage, and checks the canonical manifest digest. A source-only receipt alone cannot satisfy semantic validation; caller-created `Complete` labels remain untrusted.

The concrete driver `ScvSemanticValidationAdapterV1` retains the actual `SemanticScopeLiveOwnerV2`, optional actual `CacheGatewayAdapterV1`, and optional context containing original `SemanticScopeWriterBindingV1`, `SemanticScopeConsumptionBindingV1`, and real opaque grant/result/pin handles. It never constructs opaque handles or creates a supposedly complete read set. It delegates to `validate_scope_v2` and `three_payload_worker_result_projection_v2`; those operations revalidate retained owner rows, direct-read authority, cancellation and issuer state. Missing actual context/handles/provider evidence returns `Unavailable`.

With real handles present, the adapter reads verified pinned CAS objects for the recorded forward manifest, requested generation, existing canonical compiler snapshot and source blobs. It checks exact generation membership, current owner-projected read-set digest, canonical semantic snapshot identity, compiler owner, source cardinality, one-to-one source mapping, typed logical path equality and exact frozen bytes. Its initial supported diagnostic scope is one exact path-based module identity and partition. Cross-module producers, arbitrary scopes, resolution/absence universes outside the owner, generated sources and external provider/toolchain inputs refuse explicitly. The existing catalog supplies action-to-current-forward-manifest association only; all consumed object bytes pass the actual verified gateway.

Read-set comparison includes producer/consumer keys, facet/read kind, order, consumed fingerprint, witness, partition and complete coverage. Changed positive values, newly different absence/member witnesses, order or identity cannot be treated as unchanged. Owner lifecycle is checked again after all reads. These comparisons do not independently authorize artifact reuse.

Crucially, exact source/CAS equality does not bind SCV namespace/path policy or requested configuration/target/runtime to the corresponding compiler snapshot domains. No existing actual owner establishes that final relation here. Even matching complete diagnostics therefore return `Unavailable("semantic-nonsource-authority-relation-unavailable")`; this concrete adapter has no production `Verified` return. There is no caller-supplied attestation, fabricated execution receipt, hash translation between snapshot domains, or boolean to bypass that missing authority. `Verified` remains the shared contract outcome for a future actual owner-backed relation.

Preflight bounds source, receipt and read metadata before canonicalization/hash work. It limits recorded reads, text, scope/file cardinalities and aggregate bytes using subtraction before addition; returned remaining byte allowance continues across CAS reads. Actual existing owner projection has its own retained-state limits. The adapter performs no heap/sandbox qualification or performance claim.

Authored tests use real SCV freeze/witness verification and the real semantic owner/adapter in negative scenarios. They deliberately construct untrusted complete-labelled manifests to show that they cannot authorize a hit. No fake issuer/grant or passing mock provider is present. Pure comparison assertions cover fingerprint/absence/membership/witness/profile/partition changes without claiming authority. Current BuildRunner CLI has no actual recorded semantic manifest/opaque owner handles and does not call this seam; its source-only session remains distinct and normal action/environment/result/output checks remain required.
