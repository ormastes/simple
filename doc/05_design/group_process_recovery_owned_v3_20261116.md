# Borrowed broker recovery owner V3

`GroupProcessStreamRecoveryOwnerV3` contains only a private genuine protected reader plus canonical launch bytes and expected identity. It has no registry, native resources, close, public file port or raw getter. Caller-shared launch arrays/maps are encoded defensively and freshly decoded on use. The original Host owner keeps the actual reader on every outcome, including factory failure after retained reads. The factory is Result-valued because it acquires no independent resources; any future separately owned allocation would require an explicit owner-bearing cleanup turn.

Actual API:

- `group_process_stream_recover_owned_v3(actual_reader:LinuxProtectedRootReaderV1,expected_launch:GroupProcessStreamLaunchV2,expected_identity:text)->Result<GroupProcessStreamRecoveryOwnerV3,text>`.
- `current_v3()->Result<(),text>`: existing stream owner shape/identity validator; genuine `require_root_v1` before/after exact claim/request reads.
- `cleanup_proof_v3()->Result<text,text>`: first actual exact no-child archive, otherwise exact collected terminal/reaped/tree-empty/active0 observation and profiled resource receipt. Reader current/root binding surrounds the operation. A terminal row, absent broker or stale path alone never becomes proof.
- `validate_reap_v3(lease:GroupedActionLeaseV1)->Result<GroupedReapReceiptV1,text>`: exact immutable lease, required preexisting tree-reaped bytes, actual cleanup proof, Linux memory receipt and profiled resources, shared exact canonical reap encoding, final actual current/root check. It never calls legacy publishing collect_reap.

All artifact names are fixed privately. The legacy collector now calls the new pure `group_process_stream_reap_lease_validate_v3` and `group_process_stream_reap_bytes_v3`; all existing IO/proof/default publication behavior remains at the old callsite. Pure bytes/receipt values are DATA, not cleanup/admission authority. Host must call the actual recovery owner under its own protected operation/consumption/lease binding, never accept externally supplied receipt DATA as release permission.

The genuine root reader is a filesystem mechanism, not installed administrative authorization. Its new restrictive root predicate checks actual canonical current and private binding against expected spelling, so opening root B with root A's copied claim/request cannot attest A. There is no raw root getter. Actual Host installed selection of a protected external parent/root layout is a separate missing producer. The archive's launch.root only restricts an already independently selected root, never authorizes its opening. Same installed service UID/current genuine namespace and protected ancestry are inherited from the actual reader. The original reader resides in existing canonical health/oracle/resource custody; no new journal/writer/registry is created.

The dependency extension preserves the historical 16777216-byte request ceiling in both read and retained-file current checks; storage publication remains 8 MiB, existing journal/auth callers keep their smaller limits. This dependency is owned by the storage worker and cannot be presumed present until its exact extension freeze is pinned. No stub or path fallback exists. Header/identity/expiry checks reuse legacy validators; an expired positive launch deadline does not revoke historical cleanup and is never refreshed into a new grant.

This is a cold restart/evidence path. Repeated current calls intentionally revalidate the bounded canonical claim/request and retained artifact revisions; it is not added to terminal hot polling or an unbounded recovery loop. Host owns the number/lifetime of recovery views under its existing operation bounds and closes their original readers through bounded owner-bearing cleanup after use. A view cannot close a copied parent's native resources or transfer ownership out of that Host.

Full recovery tracking: (1) genuine installed external-root selection; (2) actual owner-taking output-follow/primary-attach Host evidence wiring; (3) fixed-name anchored nonce/cancel against the existing live broker with retained partial-write/cleanup custody; (4) real nonempty-history restart/fault acceptance. These remain REQUIRED. This slice implements only read-only historical proof validation, not live cancel, old stdout/stdin reconstruction, PID adoption, AgentReady, HostACK, native reap performance or WAL release. Uncertain/missing/incompatible rows stay charged. It is not a blanket empty-history-only policy or final recovery done claim.
