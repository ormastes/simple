# Canonical monomorphization in source-call inventory

REQ-FV2-C1-SM connects the existing source-calls command to the canonical retained-body monomorphizer, clean G7 verification, and the existing resolved-call producer/finalizer. The accepted contract and independent contract review are retained in the external C1-SM packet; this document describes implemented source, not runtime acceptance.

The public source route validates explicit target and limits before parsing, lowers fresh HIR, then invokes `source_calls_monomorphize_v1`. That bridge preflights the entire codec-reachable HIR graph before encoding/copying, fingerprints it with the existing legacy codec, clones mutable symbol/scope indexes and declaration maps, and uses one isolated pass. Its policy never refreshes global diagnostic settings, reads mono environment overrides, writes the global report/profile, or retains a persistent cache. Ordinary pass callers retain their old policy. Failed results remain private.

Canonical template recipe normalization and concrete substitution include retained defaults only under the isolated policy. Defaults are rewritten in declaration order with earlier-parameter evidence and enqueue requests in the same worklist. They are not evaluated there. Specialized declaration placement derives the owning symbol's exact Function signature from actual completed parameters, return and effects; conflicting existing rows refuse. G7 checks the actual completed graph, including defaults, before signature validation and MIR lowering. Unused retained templates still fail G7; there is no blanket template stripping.

The ledger caps specializations at4096, logical work at65536 and schema-recursion depth at128; callers may tighten limits. The canonical type-instantiation depth limit remains16. Checked typed dictionary cardinality follows the actual retained Dict receiver→rt_dict_len provider before key allocation; later snapshot agreement is consistency only. The schema preflight records exact codec/version/provider dependencies and rejects stale declared versions. Native allocator, hash-table-capacity scans, value-copy costs and measured RSS/latency remain unqualified. This is a logical source resource contract, not a claim of compiler/runtime memory safety.

SourceResolvedCalls-v2 retains previous fixed inventory keys and NOT_CHECKED, adding mono_input_hir_hash, mono_output_hir_hash and mono_specializations. Those fingerprints use bounded existing legacy HIR encoding under a distinct local identity domain. They do not enable the canonical portable-codec gate, authorize proof replay, or authenticate a transformation. No in-tree consumer parses v1 as an attestation; source assertions and worker-command oracles explicitly check v2.

No C6 trust anchor, foreign/indirect/dynload call authority, AOP/DI transform receipt or full C1–C7 completion is added. Full compiler/SSpec/Lean/native/performance checks remain UNRUN pending a qualified runner. The 128/129 MIR default-frame controls test the unchanged resolved-lowering API separately: the source-stage work budget can refuse a large module earlier.

## Remaining provider-work obligation

The accepted contract requires source algorithm bounds across the shared work ledger. That requirement is **not complete** for native dictionary key enumeration: the typed provider reads cardinality before allocating the output snapshot, but `rt_dict_keys` scans retained capacity rather than cardinality. A sparse or cleared dictionary can therefore perform provider work not represented by the reservation. Post-snapshot count agreement cannot repair that gap. No supported retained-capacity/scan-limit API or admitted compact-input condition is currently established for this route. A reviewed provider-bound mechanism remains required before claiming the full source-work criterion; measured latency alone would not prove it. Current source publication and component reviews must keep this obligation OPEN, together with native/allocator qualification.
