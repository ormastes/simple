# Contained provider compatibility observations

Status: AUTHORED_NOT_RUN. This extends the accepted adapter DATA slice. It does
not connect a task launcher or establish capacity, credentials, session-store
ownership, vendor provenance, or exclusive control of an engine.

## Actual producer and ownership

`provider_cli_container_probe_begin_v1` accepts the actual common container
owner and original admitted primary request. It invokes the common configuration
producer itself, verifies the exact request/runtime/scope, and requires the fixed
provider probe argv after an absolute executable prefix. The initial profile
excludes mounts, requires the image-default ordered environment, an explicit
absolute working directory and configured user, and actual immutable-image
reference correspondence. Gemini alone permits an absolute Node executable plus
absolute JS module prefix. Linux additionally requires the observed read-only
root. Windows receives no synthetic read-only-root assertion.

The collector observes actual workload exit through the existing common wait
path, then invokes the opaque logs-capture owner. A successful transcript requires
real native terminal/retirement evidence, exact delivered byte counts, bounded
valid UTF-8, exit zero, no output-limit result, and empty stderr. Linux additionally
requires its actual combined EOF, identity, reap, native error, seen/kept and
truncation facts; Windows requires its actual two stream EOF facts without
manufacturing the unavailable Linux facts. This is a platform evidence profile,
not an alternate executor. The common producer rechecks the exact runtime, and
the collector observes configuration again before minting an immutable receipt.

Pending and failed capture turns preserve the updated common owner and actual
capture owner. Cancellation retires only the read-only capture process. It does
not stop the workload, settle its charge, or release Host admission. The first
error is sticky while cleanup remains pending. Once no native capture remains,
failure returns the common owner and no receipt. The collector uses a 30-second
monotonic admission budget before and after synchronous operations; this is not
a hard upper bound on their blocking latency.

Exported diagnostic snapshots deep-copy every nested array and mount projection;
selection storage copies the caller's receipt array. Exported DATA cannot mutate
retained receipt bindings. The production copy helper has a DATA-only regression.

The batch factory consumes only module-private completed receipts, requires every
probe index exactly once, decodes the real version/help transcripts, and compares
the shared image/program/environment/scope/provider-generation binding. Runtime
IDs and exact full configurations remain separately retained for each probe;
probe argv intentionally differs. No public observation DTO is a receipt factory.

## Freshness and execution boundary

A read-only observation of a stopped Windows container does not prove its writable
upper layer has never been modified. Even on Linux, engine administrators remain
outside the app observation's authority. Receipts therefore describe observed
compatibility, not reusable installed-program authority. A later task must use a
genuine newly admitted first-start transaction with the same immutable image,
protected executable mapping and controlled runtime namespace. Reusing a mutable
container is outside this profile. A version string or copied runtime ID cannot
replace that producer. A stable resume UUID does not establish history, workspace
or source-lease ownership.

## Restrictive shared pre-start hook proposal (not implemented)

Current synchronous `host_authorized_execute_v2` handles Linux and Windows. It
durably records the exact newly created identity through
`host_execution_creation_intent_v2` before `simple_container_apply_v2(...,"start",...)`.
The cooperative Windows path records the same identity in the `create` stage of
`host_authorized_execution_step_v4`, then advances to `start`. These are the two
required insertion points; adding only a cooperative hook would omit Linux.

Proposed common DATA `ContainerPreStartConstraintV1` carries an exact immutable
image reference/config binding, program prefix, effective argv/workdir/user,
ordered environment digest, and mount restrictions. It only narrows an already
signed admitted request; no constraint or callback can supply a grant/deadline.
The existing Host owner must retain the optional constraint in its actual
operation state, validate it against the prepared signed request before create,
then itself invoke configuration observation after durable creation and before
first start. The observed exact runtime must equal the native identity returned
by that same creation transaction. Failed or uncertain observation prevents
start and keeps the actual ledger, container, creation intent and cleanup path.
Original APIs remain compatible by selecting no additional restriction.

The app constructs restrictive DATA from its private compatible selection and
fixed task plan, but the Host lifecycle alone produces any first-start receipt.
The common contract must have no import of app classes. The hook cannot establish
exclusive engine custody unless the actual lower owner supplies that precondition;
that limitation must be explicit. Existing admission refresh, journal operation,
recovery, settlement and CoreMux control remain in their current owners. Codex
stdin prompts and all interactive transports still require the existing admitted
terminal/input route; a completed logs observation is not a stdin/PTY capability.

Exact proposed out-of-app edit is the existing
`src/lib/nogc_sync_mut/orchestration/host_authorized_execution_v2.spl` plus a new
`src/lib/common/contracts/container/pre_start_constraint_v1.spl`, and the genuine
HostService wrapper forwarding ports identified by the owning reviewer. Those
files require root/fresh-B ownership coordination before edits. No Host source
or Caret main/source-lease/runtime-provider file is changed by this collector.
