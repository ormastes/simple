# Linux workspace source supporting owner

Status: supporting source implementation, AUTHORED_NOT_RUN. No positive mount execution
or capacity admission is asserted; Linux V5's generic effect refusal remains.

The first proposed profile is one preprovisioned XFS project-quota workspace
root. A strict fixed-child schema binds machine/provider/containment policy
digests, protected parent and leaf, native pool/workspace identity, quota and
hard bytes, and exact guest destination/permission. Profile bytes are read only
through the actual root-protected Linux policy owner. No caller filename, lock
path, budget or alternate filesystem is substituted.

A supporting source owner borrows the real durable workspace owner's
`WorkspaceStorageLeaseV1`; its numeric native token cannot simply be closed.
Observation validates the actual registered lease. Only that original durable
owner may reconcile quota/workspace release after absence; the supporting
owner must return the exact borrowed lease and policy reader on every result.
It owns only its own directory observations and derived generation lock, with
uncertain cleanup retained. This is not a second capacity journal or full mount
grant. A copied metadata record cannot supply quota or installation authority.

The actual `linux_machine_workspace_exclusion_open_v1(storage, lease)` port owns
the fixed-state lock, keyed by native workspace physical identity so aliases
contend. The source factory does not reopen the machine state pathname, acquire
its capacity writer again, or expose a raw lock path. It retains the real typed
exclusion plus borrowed Linux machine storage and reader. `current_v1` verifies
those owners, installed bytes, exact canonical request, native lease receipt,
process context and stable physical workspace identity. The returned sample is
still observation only. The public wrapper contains slot/generation and only
immutable borrowed reader/storage/lease carriers. Owned directories, exclusion
and close progress live exclusively in a bounded canonical
registry (32 active, 4096 lifetime records, no tombstone reuse). The accepted
process-origin guard precedes every registry access. Copied wrappers therefore
observe the same consumed resources and cannot close reused descriptors.
`close_v1` always returns every borrowed carrier, including origin/stale refusals
before registry access. The independent genuine process-origin guard authorizes
cleanup of this capsule's own resources even after a borrowed reader closes;
`current_v1` still rejects dead parents. Actual retained/unknown exclusion owners
keep the cleanup capsule pending.
Each directory leaves canonical custody before its single native close; an
unconfirmed consumed descriptor is never retried. Once all owned resources are
consumed, close reports `closed=true` with the first retained diagnostic, even
when consumption produced an error. Closed tombstones return the same borrowed
carriers and first diagnostic without another native close or active-count debit.

Root approved a narrow trust boundary: all same-euid Host services cooperate;
hostile same-user Host compromise is outside the isolation claim. The workload
must not reach the protected source parent or engine endpoint, and may not
rename the external source-root binding. Arbitrary/nested user-writable Host
sources remain unsupported. Same-euid trust alone does not serialize trusted
cleanup: every relevant writer must use the same actual owner transaction.

Known legacy mutation paths include `worker_materialize.stage_build_inputs_v1`,
prelaunch deletion in `worker_execute.spl`, and stage deletion in
`worker_cleanup_ack.spl`; execute/cleanup share `config.state_dir/worker.lock`.
Artifact snapshot preparation/release has its own staged deletion helper.
The new workspace root must be proven disjoint through real supervisor/inventory
admission or these callers must join its writer. A comment or lexical path
check is not all-mutator exclusion. Machine state and actual engine graph/run
roots are separately forbidden. Genesis remains refused without the actual
migration inventory and supervisor producer.

The observation module checks engine-declared inspect Mounts against one exact
bind mapping and full provider identity/query correlation. This is a production
consumer seam for retained provider receipts, not a test-only alternate parser.
The list does not enumerate kernel/runtime mounts or prove target namespace.
The existing native containment owner lacks target mount namespace observation;
that proof remains separate from engine configuration and installed digest data.

No create/start wiring may consume these observations as a grant. The final
positive owner requires real admitted supervisor/inventory, the shared mutation
transaction held through create and inspect, actual source/containment evidence,
and retained ownership whenever publication/create/cleanup is uncertain.
