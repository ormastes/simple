# Finite Podman Engine exec interoperability codec

Status: AUTHORED / UNEXECUTED. This slice is pure request/response syntax and correlation. It opens no socket, creates no native session, publishes no birth receipt, and implements no retry, journal or lifecycle effects.

The accepted shared `ContainerExecRequestV3` binds the full parent container identity, distinct exec operation, nonce and exact workload payload. The provider codec supports only Linux Podman, literal environment entries, explicit numeric UID:GID, absolute executable/cwd, no stdin and no TTY. Secret references require a separate authorized resolver and are refused here. The 60000 ms limit is a supported finite provider control/observation window, never a workload lifetime or kill deadline.

Create targets `POST /v5.2.5/libpod/containers/FULL_PARENT_ID/exec`; JSON emits typed Cmd, Env, User, WorkingDir and explicit false privileged/TTY/stream flags. Inspect uses `GET /v5.2.5/libpod/exec/FULL_EXEC_ID/json`; detached start uses POST to the corresponding start path with `Detach=true,Tty=false`. Native exec ID must be canonical full64 and distinct from the parent. The nonce stays in local request correlation; Podman create has no idempotency nonce contract, so no invented header or injected environment entry is emitted.

Finite HTTP accepts exactly create201 application/json, inspect200 application/json, and start200 `text/plain; charset=us-ascii` with a single LF body. It requires canonical bounded Content-Length and exact supplied message length; duplicate headers, bare CR/LF, status controls, chunking, encoding, upgrades, redirects, incomplete/trailing bytes and invalid UTF-8 refuse. Headers are limited to 16 KiB and body to 1 MiB. This is a deliberate Content-Length subset: Go may chunk larger inspection responses, which this slice cannot accept. It does not claim complete Engine response capacity. Future transport must bound the entire read and establish its framing/EOF or sentinel policy rather than truncating input to hide trailing bytes.

Strict JSON parsing has a byte bound and a string/escape-aware depth preflight before recursion. Create accepts only `Id`. Inspect requires the pinned eleven outer fields and five ProcessConfig fields, exact parent/exec IDs, false privileged/TTY/open-stream options, configured numeric user and exact executable/tail; nil arguments are valid only for an empty command tail. Env and cwd are not independently observable in this inspect schema and remain correlation from known retained birth. Running=false, exitCode=0 and CanRemove are observations, never sufficient proof of exit or terminal lifecycle.

HTTP evidence uses distinct canonical SDN hash domains over method/path/content type/body digest, request digest, full target and socket-policy digest, then actual response-wire digest and parsed status/body. It never invents a CLI `RuntimeCommand`. These hashes provide integrity, not transport provenance or authorization.

Source provenance is pinned to Podman v5.2.5: `register_exec.go` blob `f1eaaeaf010b9798564251ebe63e502ba732a065`; compat `exec.go` blob `e7f29d727a7c068ca94b584c942fbee64156e481`; `container_exec.go` blob `42f6eae9e4fb5cfa1ad4c003c3c2b81bb162451c`; handler `utils/handler.go` blob `dc425ce6568fa1bf9b17e4c71c090f21a3099ddf`; entity alias `types.go` blob `52901c03f23bf5046ba6f0b0f8d42e294bf8db26`; `version/version.go` blob `5bd86b1af2e3fea82511e4e61a50cbb7f8ca37b6`. The handler's string response uses Fprintln, explaining start's LF rather than JSON or204. Primary repository: [Podman v5.2.5](https://github.com/podman-container-tools/podman/tree/v5.2.5).

Before future effects, actual provider policy must observe exact supported server API version and trusted local socket peer/store identity without remote or PATH fallback. The canonical lower native Unix owner is a separate dependency. Request submission requires fresh verified Host admission and native checks before each send; partial submission is not rollback. A response decoder error never proves no Engine effect occurred.

The future exec journal must reuse existing protected-directory, strict canonical SDN, no-replace first publication, stable lock, mode0600 and directory-fsync owners, with a distinct exec-operation record rather than overwriting parent container intent. Persist full parent/request/nonce/pin before submission; preserve accepted-byte or uncertain-submission outcome. Once any create bytes may have reached the Engine without a qualified returned ID, retain owner-bearing unknown-create and prohibit blind retry. Known native exec birth must be durably correlated before start. This design is not implemented by this codec slice.
