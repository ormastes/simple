# Distributed build and fast feedback: detail design

**Status:** Provisional integration design with partial implementation, 2026-09-25. Full functional scope and N2 numerical targets were selected; executable verification is pending. Contract, scheduler, Linux OCI worker path and signed-build admission modules in the working tree are drafts until a deployed pure-Simple runtime checks them. This document does not claim qualified two-node execution, Clang integration or GitHub build reuse are active.

## Module and ownership map

| Owner | State and interface | Current disposition |
|---|---|---|
| Snapshot owner | Frozen source tree, selected gitlinks, generated inputs and negative resolution observations | `SnapshotManifest`/`InputManifest` structural contract drafted in `src/compiler/00.common/build_contract.spl`; byte capture and producer integration remain. |
| Build action adapter | Target dependency manifest, native compiler invocation, private inputs and output candidate | `src/app/build/targets/artifact_receipt.spl` already parses/validates dependency manifests; `target_executor.spl` currently rejects dependent actions. Native input bridge is in progress. |
| Scheduler parent | DAG, resource budget, attempt journal and current fence | Planner, ledger, journal, coordinator and a provisional `distributed_attempt.spl` driver exist. Crash recovery and target-executor integration remain. |
| Worker or provider | Child-owned process and private scratch result | A one-shot Linux OCI worker, attempt-private staging, fixed SSH invocation and SFTP transfer planners exist. Result fetch has a per-file shell size limit with observed 1024-byte macOS or 512-byte Debian Linux granularity; other controller hosts fail closed. Live two-node execution, image-byte attestation and other OS providers remain. |
| Publication broker | Verify bytes and current fence, then atomically accept one immutable result | Broker transition and parent CAS retention exist. Self-hosted byte verification, power-loss durability, immutable closure pinning and end-to-end durable commit remain. |
| Protected CI controller | Current candidate, protected policy/checker, allowed signer scope, mandatory gate set and result status | Gate, signed-receipt and byte-snapshot providers now have a Simple composition entrypoint. A base-owned workflow must still supply authenticated policy and observations, retrieve the artifact, execute the full-build fallback or reuse the returned private path, and report the required status. |

The owner of each mutable record serializes transitions. A worker receives an immutable snapshot and an attempt envelope, then creates a candidate. It cannot mutate the scheduler ledger or accepted mapping. The parent persists a new fence before dispatch and before reassignment. Results crossing process or host boundaries are encoded copies with explicit length and digest; no mutable memory or raw pointer crosses that boundary.

## Build action flow

1. Freeze a source snapshot and selected gitlinks. Record every source/generated byte digest, dependency output, relevant environment input, ordered invocation argument and ordered negative lookup witness. Reject an incomplete discovery or an untracked read for cache admission.
2. Resolve the selected target closure. Before running any target, reject output collisions, unknown dependencies, unsupported provider/output combinations and an unreadable or malformed dependency manifest. Required producer artifacts must exist at the accepted digests.
3. Copy dependency artifacts into the consumer's attempt-private directory. Re-hash copied bytes and link **those copies**; a validation followed by linking a mutable producer path is unsafe. Preserve declared link order separately from the manifest's sorted identity fields.
4. Pass typed external provider paths through native compile/link options. The existing `SIMPLE_LINK_OBJECTS` path proves the executable linker can consume external objects, but process-global environment mutation is not a safe scheduler interface. Initially support executable consumers of validated archive/object providers; reject dependency-bearing shared/archive/object output modes until each has an equivalent proven consumer path.
5. Compile into an attempt-private output. Require a fresh nonempty artifact, validated digest, expected output kind, complete imported closure and current attempt fence. Publish through an atomic rename or immutable CAS mapping only after all checks pass. Preserve the last accepted output on any failure.
6. Enable executor reuse only when the current authoritative closure receipt and action identity include all semantic inputs. The drafted common contract's structural `ok` verdict does not prove byte provenance or authorize reuse.

Cold compile-to-link construction has two protected phases. The first graph
contains complete producer requests and has an independently pinned manifest
digest. A separate versioned link template names ordered producer
action/output pairs and the intended linker operand positions; it carries no
claimed output-byte digest and is never dispatched as an action. The protected
caller must pin one staged-plan identity over the producer graph digest, exact
template wire/version, link worker and protected execution policy before the
producer phase starts. Validate that each named producer belongs to that graph,
that output names do not collide, and that the link worker/capacity/profile are
eligible before spending producer work.

After all producer results are durably accepted, replay the parent owner and
resolve each link input from the accepted attempt, exact retained manifest and
verified CAS object. Replace only bound linker operands with
`/simple-build/inputs/<name>` in their original order. Build a complete link
`ActionSpec` and canonical request, then derive the second graph from the
original exact producer request wires plus the resolved link request. Its link
attempt/fence fields are intent placeholders; final admission allocates the
fence under the owner lock. On restart, the same protected staged-plan identity
and accepted producer bytes must derive the same link action, resume an active
link fence, or recognize an already accepted link. Changed template bytes under
the original plan identity reject before dispatch. Missing CAS, unresolved
inputs, producer failure or uncertain remote state remain incomplete. This
source API exists in `parent_link_template.spl` and
`parent_link_resolution.spl`. The staged CLI source described below is wired;
native qualification and live execution remain open.

`parent_staged_link.spl` now implements the in-memory two-phase controller. Its
canonical plan digest includes the producer-manifest digest, ordered template,
link intent and the exact bytes of every administrator worker config. The
caller must supply the expected digest independently; computing it from
candidate-controlled inputs at launch is only a consistency check. The
controller verifies the producer manifest and request bytes, template closure,
each referenced producer output declaration, link-worker eligibility and request
identity before producer dispatch. It
replays the owner for link resolution, then builds the second graph from the
original producer wires plus the resolved request. The graph derivation helper
is private to the controller. A bounded versioned template file now names an
exact base-request digest/path and ordered producer output/argv indices. The
staged CLI source reads template, base request, config, manifest and producer
request files without following final path components, then uses one loader
result to construct the plan. Its independently protected expected digest is
an administrator input. Native CLI qualification and the host fixture remain.

Administrator plan issuance remains a separate protected boundary. The proposed
issuer snapshots the exact producer manifest and request files, template and
base request, and ordered worker configurations, runs the same preflight, then
atomically publishes one bounded launch record in an administrator-owned
directory. Execution selects that record by a restricted identifier and derives
all digest and path arguments from it; the caller cannot override them. Both
issuer and runner require trusted ancestor directories and no-follow bounded
reads. The current CLI digest flag is only an integrity pin supplied by a
trusted launcher, not authorization when an arbitrary caller controls it.
`parent_issued_plan_wire.spl` now defines and parses the canonical bounded
record body (plan digest, template digest/path and ordered config paths), but
`parent_issued_plan_store.spl` only accepts content-addressed records under a
caller-supplied trusted root and publishes them without replacement after file
sync. The installed caller still must supply that root independently of CLI,
environment, cwd and repository contents. Administrator approval, restricted
execution, revocation and native qualification remain unwired.
`parent_issued_plan_issuer.spl` now reloads and prepares the full staged inputs
against an independently approved plan digest before publishing a record. It
does not authenticate that approval or choose the trusted root; those are
deployment/controller responsibilities.
`parent_issued_staged_main.spl` is now a distinct restricted source entrypoint:
it accepts only a record SHA-256, loads under compiled
`/etc/simple/dist-build`, rejects hosts other than Linux/macOS using the
in-process platform primitive, and builds all staged arguments from the loaded
record. The `bin/simple_dist_build_parent` wrapper now admits only the
distinct issued binary basename. Installation ownership and credential access
must exclude the raw diagnostic controller; no qualified native artifact exists.
Its version 1 path grammar is intentionally POSIX-only; cross-OS controller
support needs a coordinated path and reparse policy across all input files.

The parent can now export one accepted `.o`/`.obj` object from its retained binary CAS into a caller-owned destination directory. It replays the ledger under the owner lock, binds the selected row to the accepted attempt and retained manifest, verifies binary bytes, stages on the destination filesystem, and reports whether replacement survived destination-directory sync. V3 protected parent configuration pins the export root; `dist-build --export` accepts only the action and source/destination object leaf names. V4 adds a digest-pinned administrator policy whose rows bind action, declared output, kind, destination leaf and local mode. `--export-policy ID` carries only a row selector. Unix object and bounded ELF `ET_EXEC`/Mach-O `MH_EXECUTE` source paths apply and verify fixed `0644`/`0755` modes before rename. V4 refuses the legacy `--export` route. This is an installation mode, not a worker mode claim. The Simple-side retained binary CAS adapter now admits complete regular `.a`/`.lib` archives, rejects thin archives and routes retained dependencies through the same digest namespace. Windows executable mode, ELF PIE/architecture qualification and target-executor consumption remain open. The focused fixture and new parser tests have no current pure-Simple runtime PASS.

Action digests exclude queue priority, worker ID, retry count and scratch path. Attempt identity includes a monotonic fence/epoch. Validation identity additionally binds checker implementation and protected policy. A target cache hit must materialize accepted artifact bytes, not merely find a matching text receipt.

## Local scheduling and recovery

The planner validates a bounded acyclic graph, derives ready actions from **accepted** predecessors, and orders them deterministically by priority, bounded age and digest. The parent admits only ready actions after CPU, private-memory-plus-reserve and file-descriptor checks; exclusive device/license resources require separate leases. The ledger records each admission and revocation before dispatch or reassignment. Each attempt owns one process tree and private output directory.

The broker requires a successful current attempt, matching fence, declared output manifest and independently verified output bytes. A delayed result from a revoked attempt is rejected even if its content digest looks valid. Restart replays durable ledger records and reconciles unfinished attempts; repeated execution is possible, repeated publication is not. Cancellation first detaches a consumer from shared work, then terminates unshared isolated process trees. Preserve failed attempt diagnostics. A known terminal nonzero exit without independent source-diagnostic evidence is `action-failure-unclassified`: close its exact fenced attempt after retaining diagnostics, release capacity and allow only the bounded durable retry count. Do not call exit 1 or 137 a deterministic compiler failure. Source-diagnostic classification requires a separately versioned evidence contract before automatic retries may be suppressed.

For that failure path, the worker must sync the exact terminal observation before it writes bounded diagnostics and an empty `manifest.wire`. It writes `failure-proof.wire` before `result.wire`, binding the request digest, permanent native binding digest, attempt/fence, nonzero exit, terminal marker digest and exact result digest. Its read-only status path recomputes the proof against the saved binding and terminal observation. The parent confirms status, fetches the fixed proof and diagnostic files, checks their canonical identities and hashes, syncs diagnostic CAS bytes, persists cleanup intent and only then appends `action-failure-unclassified` to the journal. A missing proof, unknown exit, provider uncertainty or changed wire leaves the fence active. Failed outputs never enter accepted CAS mappings. Old workers without the proof cannot close a failed attempt under this protocol; old journal readers require migration before reading the new class.

The parent first creates and fsyncs an exclusive per-attempt spool-protocol intent, then journals admission and its fence, then creates and fsyncs the canonical request spool before any upload. The uploaded request digest must match the spool digest. A recovery reader accepts a spooled request only while the owner holds the root lock and the ledger still records the same active attempt, worker, resources and fence. During startup, an active attempt without a spool can be durably revoked only if its exact pre-admission intent proves it followed this spool-before-upload driver. Older attempts without that proof remain reserved. While the same owner is still executing this driver, a local error before its first SFTP call proves no remote request was sent and permits durable revocation. After a transfer begins, or after startup recovers a spooled attempt, capacity stays reserved until the worker proves its result or a cancellation command durably tombstones that exact request before launch. Worker launch and cancellation use the same worker lock: an existing binding blocks cancellation, while an existing tombstone blocks a later launch. The parent revokes only after an exact acknowledgement over pinned SSH when remote execution is uncertain; a disconnected worker keeps its fence. The worker also has a read-only `--status` command, and the parent has a resume path that retrieves a completed result through pinned SSH, then repeats byte fetch, CAS retention and fenced publication without a second launch. The ordinary driver invokes the one-shot worker through a fixed SSH command, downloads result bytes, retains them in CAS and then asks the owner to publish or fail the attempt. Failed local snapshot removal is reported as cleanup debt but cannot prevent launch once remote upload succeeds. Atomic journal order, worker acknowledgement cleanup, status/cancel/resume over a live node, and restart still need fixtures before scheduling is complete.

## Remote node protocol

Before persisting a consumer intent or reserving capacity, the parent now validates every dependency against the accepted producer attempt in its ledger. It loads the exact retained output manifest by digest, checks action/attempt/worker/fence and the complete output row set, matches the named output and digest, then verifies the binary CAS object. It then copies source/generated files from the declared source root and dependency outputs from retained binary CAS into a private per-attempt snapshot. It checks copied digests and prepares and fsyncs both SFTP batches plus the exact worker request and ready marker before persisting intent or admitting the attempt. After admission the driver transfers these prepared bytes, checks the spooled request digest, and preserves the fence on an uncertain remote result. The worker rehashes received bytes. A live positive CAS-backed transfer, two-node producer/consumer fixture and self-hosted validation remain open.

The current one-shot path uses a canonical bounded request, a ready marker uploaded last, pinned SSH host credentials, SFTP payload files and an exact result wire comparison between SSH and SFTP. The worker materializes inputs under an attempt-private root, runs the pinned OCI image, and writes the result marker last. Future long-lived node connections need bounded versioned SDN control frames for capability, heartbeat and cancellation records. Authenticate and encrypt node connections; authorize repository/tenant and exact toolchain/provider ABI before transfer. A content digest is an identity, not permission to read a blob.

The scheduler owns admission and fences. A node agent owns its capacity and process tree, verifies received snapshot/toolchain bytes and returns candidate evidence. The broker alone accepts. Wrong toolchain, unsupported major, duplicate or unknown mandatory field, oversized frame, corrupt payload, stale fence, disconnected node and lost artifact must produce a typed rejection or bounded retry. A heartbeat gap never by itself proves a worker dead; revoke the old fence before relocation. A real two-node compiler/link fixture is required; fake transport unit tests do not establish distributed execution.

## Container-backed worker adapter

`plan_build_job_v1` now constructs the exact fenced `JobV1` for a trusted
`BuildWorkerRequestV1` and authenticated worker capability. It binds the
canonical request digest into metadata, uses the worker's pinned image and
execution OS, disables Orchestrator retry, and sets exact CPU and memory
limits. It then calls `admit_build_job_v1` before returning a Job. The
namespace is a canonical DNS label supplied by the protected controller
(`simple-build` for the current SSH route).
This is a portable controller plan; only a separately qualified Linux OCI
worker may execute it at present. The provider must still submit the Job,
observe its native identity and report fenced output through the broker.
Both current authenticated SSH attempt routes now require this canonical Job
plan after worker capability preflight and before journal admission. They
continue to dispatch the original fenced request to the dedicated Linux
worker; they do not submit the Job to an Orchestrator executor. Controller OS
admission uses the in-process platform detector on macOS, Linux and Windows;
BSD detection retains the existing fallback probe. FreeBSD, OpenBSD and
NetBSD controllers may all admit a qualified remote Linux worker; this does
not claim a native container provider on those controller hosts.
Do not pass this Job directly to the generic CI runner: that runner's bridge
network and mount/attempt setup do not implement the isolated build worker's
network-none, verified input and private output contract.

An app-level adapter composes the build `ActionSpec`/`AttemptSpec` with strict Orchestrator `PodSpecV1`/`JobV1` and the portable `RuntimeProviderV1` lifecycle envelope. Its admission record must state physical host OS/architecture, actual execution OS/architecture, runtime class, isolation and provider identity, toolchain executable/provider ABI, compiler output target, image or artifact digest, requested CPU/memory/FD capacity, network/filesystem policy, immutable input mounts and attempt-private output location. Keep this record out of compiler common imports. A native OS container requirement cannot be satisfied by a VM or a host process; a cross compiler may produce an output for a different OS without requiring execution there.

After pure admission, the platform provider must create and journal a recoverable native identity, launch with read-only verified inputs and bounded resources, collect logs/exit status/output bytes, and clean up. The Linux OCI request now carries attempt-private build mounts and pins the requested compiler entrypoint. The worker binds the configured image digest, engine, compiler entrypoint, mounts and sandbox policy into action identity. The parent receives bounded metadata first, checks aggregate declared output size, then runs each SFTP output fetch with a host-qualified shell file-size limit. The parent still needs independent image/compiler-byte attestation and recovery/cleanup evidence, plus a live size-limit fixture. The same broker checks bytes and the current fence. An unavailable or unqualified provider returns `BLOCKED`/`UNSUPPORTED` before launch. Linux OCI is the only hosted provider present now; Windows HCS, macOS native sandbox/process, FreeBSD jail and SimpleOS need their own concrete adapters and host-level qualification. CI runner OS and sandbox downgrade admission fixes are drafted, with executable verification pending.

## Clang/CMake/Ninja bridge

Ninja remains graph owner in the first adapter. Capture the exact compiler launcher arguments, response files, environment, generated headers and every declared side output. Run a top-level policy gate even when Ninja reports no compile edge, and add the effective policy stamp to native dependencies so a policy-only change cannot be skipped. Strict policy checks both cold and warm paths; a scoped `complex` exception retains complete context in the key; `none` forces fresh preprocessing and forbids enclosing semantic shortcuts.

PCH/PCM/BMI reuse requires complete macro, search-path, compiler, ABI, SDK and policy context. Persistent provider groups are optional after process-isolated reference equivalence, crash retirement and memory bounds are measured. The ZIP's 12 probes are counterexamples for this design, while its 56 HC cases remain unexecuted acceptance work.

## Hooks, signed evidence and GitHub admission

Pre-commit evaluates staged bytes; pre-push evaluates every outgoing committed ref. The existing gate registry owns each mandatory obligation and its destination. A deadline with mandatory IDs outstanding returns `INCOMPLETE`. Ordinary push currently skips advisory rows, while `MUST_CHECK_ADVISORY=1` runs them separately; measurement must distinguish complete ordinary push time, the per-ref blocking budget and optional advisory time.

The protected controller obtains its verifier code, signer allowlist and mandatory set from the base/protected policy, then derives the current base-plus-head candidate. Candidate code executes without privileged controller credentials. `GateReceipt` compares exact candidate, policy, checker, submodule closure and mandatory row observations; the caller must separately authenticate the signed bytes. A local build receipt adds exact target, execution platform, output target, toolchain, action/input manifest, artifact digest/length and authorized signer scope. `signed_build_controller.spl` first verifies independently observed bootstrap gates against a pinned protected manifest, then requires the pinned OpenSSH signature provider and a private byte-verified artifact snapshot. A failed stage returns `FULL_BUILD` with no artifact path. The caller must retrieve the artifact and consume only a returned private path. Neither result itself reports a GitHub status.

Every required GitHub context must run and report a result. Valid scoped evidence can skip duplicate work *inside* that job; missing, stale, revoked, malformed, untrusted, unsupported-platform or artifact-mismatched evidence runs the full job. A note keyed to PR HEAD is transport only and cannot prove the current integration candidate. The V2 controller now has a protected caller-owned private file snapshot path for artifacts above the 16 MiB byte-array ceiling: it copies, fsyncs and hashes a bounded downloaded file, and a successful decision returns only the copied path for the consuming job. The caller must keep that directory private and use precisely that path. A Simple OpenSSH provider now stages protected signer and KRL bytes, pins the executable by digest and verifies exact canonical receipt bytes through owned stdin before passing its observation to the private-artifact verifier. Its live Simple process path still needs an admitted self-hosted binary and a real signature fixture; a local OpenSSH command fixture and early rejection specs are diagnostic evidence only. The protected gate provider and controller composition exist as source; a GitHub workflow handoff remains absent. Existing v1 receipts currently shorten only selected non-required extended code-idiom rows; build job reuse is not wired. The phrase “build claude” awaits user clarification before adding a specific extra agent/build check.

## Submodules and branch policy

Derive selected dependencies from mode-160000 entries in the parent tree, then compare **every gitlink**, including optional ones, with exactly one matching path, URL and pin in `.gitmodules` and the inventory before any fetch. `HEAD` currently selects `.spipe/spipe` and the CUDA example; the other 16 declarations are dormant for this commit. Record required/optional role, provenance, approved branch ref, recursive pins, canary and any scoped exception against the exact gitlink. Fetch only selected required pins by default; an optional example is fetched only when its fixture is selected. Clean exact-pin fetch proves direct reachability. A second fetch of the approved branch from the same declared URL must yield a commit tip whose history contains that pin; record the observed tip and reject missing ancestry. The Simple Git process adapter now invokes fixed POSIX `/usr/bin/env -i` and `/usr/bin/git` paths with system/global Git config disabled, no inherited environment, disabled prompts, replacement objects disabled, and an empty template for each fresh fetch repository. If those paths or HTTPS requirements are unsupported on a host, the probe rejects. Branch ancestry is an observation, not proof of branch protection or parent policy approval. Local parent repository config and live protected-controller wiring still require qualification before its `CLEAN_FETCH_VERIFIED` label is trusted. Publish child commits before parent pin updates, and invalidate dependent actions and exceptions when a pin changes.

Preserve protected `main`, `integration/main`, maintenance release, candidate, review and recovery refs. Short-lived work branches/JJ bookmarks get isolated worktrees and output directories. The tracked main ruleset projection has no bypass, but the 2026-09-25 live ruleset has an always-bypass RepositoryRole actor ID `5`; this drift must be resolved as a separate reviewed remote-policy change. Do not modify a live ruleset to compensate for missing CI evidence.

## Error and evidence rules

| Failure | Required outcome |
|---|---|
| Unknown source closure, absent header witness or undeclared environment read | No trusted cache hit; broaden discovery or execute uncached. |
| Missing/corrupt producer artifact or unsupported dependency kind | Reject before consumer compilation and preserve prior output. |
| Resource exhaustion | Keep action queued with reason; never overcommit. |
| Lost worker or revoked fence | Preserve attempt record, reject late publication, retry only under bounded infrastructure policy. |
| Missing mandatory gate, invalid signer or changed candidate/policy | `INCOMPLETE` or ordinary full remote check/build; never an empty PASS. |
| Unreachable gitlink or changed pin under old exception | Reject selected dependency admission. |
| Unsupported remote platform/host capability | Keep a visible unverified row; do not count another platform's PASS. |

Verification uses named warm/cold fixtures and records P50/P95/P99, complete hook wall time, queue/admission/transfer/execution/publication time, action and cache counts, bytes and private/shared memory. The user selected [N2 thresholds](../02_requirements/nfr/dist_build_scheduler.md); measurements have not passed them. The deployed self-hosted test runner currently exits 139 after cover-check setup in the test-daemon startup path, before specs run; the new unit specs and this design cannot be counted as verified until an admitted pure-Simple runtime is rebuilt and deployed.

`verify_protected_gate_receipt_v2` takes observations only from a base-owned checker, builds the exact expectation from protected IDs and issuer, validates each required row, computes the complete canonical gate digest, and emits a gate result for the signed-build verifier. Missing, failed, exempted, duplicated, or changed rows reject reuse. No workflow invokes this provider yet; the required GitHub job still runs the full build.

`verify_protected_bootstrap_gates_v2` validates a separately pinned protected manifest digest and exact registry header, parses the rows, rejects duplicates and malformed entries, then derives all bootstrap IDs before calling the gate bridge. Current policy has 64 bootstrap rows but only five `push_blocking=true` rows; that flag cannot delimit build obligations. Requiring all 64 is a conservative interim rule and may prevent reuse until exact protected workload applicability is encoded. The adapter cannot substitute for base-owned retrieval of the manifest or independently collected gate results, and does not excuse CI, PR or push rows in other jobs.

## Executable export and staged verification delta (2026-09-26)

The protected export policy's executable row now includes an explicit supported
target triple, while object/archive rows keep their six-field form. A staged
link qualifier compares this target with the resolved link action's toolchain
target before export. The exporter structurally admits bounded target-matched
GNU Linux ELF64 ET_EXEC or dynamic PIE, and target-matched Darwin Mach-O.
Dynamic PIE requires the expected GNU interpreter, a file-backed executable
entry, mapped PT_DYNAMIC, terminated entries and DF_1_PIE. Unknown targets,
static PIE and musl remain unsupported. Previously issued executable policy
files require a new row field and digest. Structural parsing is only format
admission; actual code and dependency behavior require isolated execution.

The staged qualifier currently consumes a digest-pinned verifier receipt but
does not supply a qualified verifier implementation. The production verifier
must use an administrator-pinned OCI image, engine binary and private artifact
snapshot. A pinned Simple worker inside the container executes that artifact
through the owned V4 byte-stream facade with actual descendant containment,
and writes exact stdout bytes plus a durable measured result into a private
output mount that the artifact child cannot modify. The parent checks that
result against the staged artifact and terminal container identity, then emits
the receipt only after container cleanup. The existing OCI `logs()` text result
lacks the completeness contract and is diagnostic only. The worker/parent
composition and live fault matrix are tracked in
`doc/08_tracking/bug/dist_exec_verifier_byte_capture_2026-09-26.md`.
The current V4 runtime rejects cgroup descendant policy and cannot produce a
frozen `tree_empty` receipt; this and result-writer separation are required
before the worker can be qualified.

A separate pure-Simple decoder now parses Docker non-TTY attach frames as raw
stdout/stderr bytes. It rejects malformed framing and bounded-output overflow.
For the staged deterministic fixture, a future pre-start attach transport
could compare observed bytes with a protected expected count and digest, then
verify exact container destruction. This is fixture evidence only: Docker
attach has no terminal total-byte acknowledgement, so frame syntax and EOF
cannot certify arbitrary program output completeness. The transport, daemon
endpoint pin, lifecycle binding and live fixture run are not implemented.

A separate `oci_exact_logs_v1.spl` source helper now observes one pinned
`podman`/`docker logs` invocation with V4 raw-byte EOF/count and frozen-receipt
checks. It retains process and pin ownership through acknowledgement and
cleanup retries. This does not establish the container engine's log provenance
or bind its native ID to the preceding provider lifecycle; a production
verifier must make those checks before emitting the staged receipt. The helper
and spec have no current pure-Simple runtime PASS.
