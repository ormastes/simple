# LSP snapshot freshness: temporary reconciliation profile

Status: implementation authored; runtime, latency/RSS, native fault injection, and authoritative filesystem watcher admission **OPEN**. This is the cycle-2 correction to indefinite reuse of overlay-generation-only diagnostic caches. It is not final qualification of the MCP/LSP plan.

The dispatch owner retains each cached publication's complete dependency receipt, exact expected compiler/environment identity, and original entry URI. Cache entries and metadata share a 16 MiB/256-entry bound. Source sets are reconstructed only for an unchanged editor-owner epoch, avoiding one retained 16 MiB source-set copy per cache entry.

A pull never returns a cached full/clean result synchronously. It retains a bounded request ID and schedules validation through the existing single worker. The worker freshly observes the canonical compiler identity (executable, compiler and interpreted standard-library sources, runtime, ABI admission) and semantic environment. It must not reuse memoized fingerprints as current observations. A mismatch invalidates the cache and queues new analysis.

After that observation, the LSP owner reconciles the exact recorded disk dependencies using `file_read_regular_no_follow_bounded` and SHA256, one file per idle turn. Limits are 4096 files, 64 MiB aggregate, 1 MiB per file, and one 120-second validation deadline. Unreadable, oversized, aliased, changed, or unavailable inputs never become an empty diagnostic list. Editor epochs and observed external-event generations are checked again before commit. The last content read and commit occur in the same idle turn. New worker results use the same admission path before first publication.

Client watched-file/configuration notifications conservatively invalidate candidates and caches; they are hints, never positive freshness authority. External edits detected by content mismatch cause reanalysis. Pull requests have one overall 300-second deadline, at most 256 pending IDs, and retain that deadline across retries. Edits cancel stale work. Existing native cleanup uses a single 3-second parent retirement deadline and retains/report failed ownership before fatal exit.

This repeated-read profile is explicitly justified as an interim correctness repair because available canonical watchers are second-granularity mtime polling, unbounded content polling, or an unavailable native bridge. Reads occur in bounded idle steps, not synchronously in the pull handler. Warm latency is **not qualified**; the full goal still requires an admitted bounded inventory/watch owner with trustworthy generations and measured latency/RSS. Reconciliation describes exact content observations, not an atomic filesystem transaction or proof that an unobserved external writer cannot mutate an earlier file during a later read. No stronger ABA/invalidation guarantee is claimed.

Authored regressions: `analysis_freshness_spec.spl` covers changes after worker completion, changes after previously clean admission, read failure/deadline, deferred cache pulls/full receipt retention, and changed compiler identity. Controlled-owner scheduler cases cover hints arriving before handshake delivery, editor change/close between disk-probe turns, deferred pull commit/expiry, and shutdown during validation. These invoke the actual scheduler and document owner; controlled already-retired worker events do not claim native-process lifecycle qualification. Existing dispatch tests now expect deferred responses. All remain **NOT_RUN** until the rebuilt runtime is admitted.


## Parent-pinned producer identity correction

IPC control version 2 carries the exact 32-byte `OwnedExecutablePin` digest encoded as lowercase hexadecimal plus run identity for both environment and analysis workers. The environment includes this required digest in its version-2 identity framing. The compiler composes its remaining fresh identity components around that explicit digest; ambient `SIMPLE_BINARY` cannot choose the producer image. Direct compiler APIs require explicit launch-context input and return observational results marked `parent_validation_required`; caller-provided text is not loaded-image attestation.

The child binds both responses to the control SHA256, run ID and executable digest. The parent checks them against the same retained pin passed to the native launch lease, complete stdin/terminal receipts and private artifact owner before exposing response bytes. Analysis requests must match that pin before spawn, so a changed binary after handshake is rejected. Existing nonce, directory identity and cleanup rules remain intact. No child self-attestation is claimed.

`source_analysis_launch_spec.spl` distinguishes controlled wire/mismatch tests from a POSIX native-pin observation test. Neither claims complete worker execution qualification; all are **NOT_RUN** pending the admitted runtime.
