# Immutable canonical source analysis V1

The compiler API `check_snapshot_set_v1(request: SourceAnalysisRequestV1)` returns a compiler-owned result containing `receipt: SourceAnalysisReceiptV1` and `diagnostics: [DiagnosticV1]`. Shared request/identity types live in `std.common.diagnostics.source_analysis_v1`; compiler DiagnosticV1 is preserved without projecting to message strings. Compiler-side serialization owns its complete wire form.

Admission freezes at most 256 overlay documents, each at most 1 MiB, with a combined 16 MiB and 4096-byte paths/URIs. Canonical paths are workspace-contained, unique, and bound to full SHA256 source identities. Requests include owner and lifetime generation, exact compiler/config/target/features identity. Dependencies have separate 4096-file/64-MiB totals and 1-MiB file bounds; source lookups have an 8192-work bound. Disk dependencies are read once through bounded regular-file IO then retained immutably for the analysis. Snapshot identity uses unambiguous length-framed fields, never delimiter-only concatenation.

The provider must intercept the canonical loader for entry and imported modules. Cache/streaming/alternate loading paths must consume its exact bytes or reject before analysis. No temporary file replacement or legacy query typechecker is permitted. A successful compiler exit is not enough for Completed: structured diagnostic collection must be complete and every consumed source must be receipted. Source errors and warnings remain completed analyses when the compiler genuinely collected all records. Infrastructure failure remains Failed/Rejected/TimedOut/Cancelled/InvalidPayload and cannot clear LSP diagnostics.

The request owner validates runtime compiler identity and effective configuration; arbitrary caller labels are not proof. LSP publication additionally rechecks live owner lifetime, document versions and all admitted identities. No cache key may use path/mtime in place of content/dependency/environment identities.

Implementation and runtime qualification are in progress. The current driver retains text errors/warnings and needs a structured producer bridge; until established no Completed claim is admissible. Runtime tests, actual serialization round trips, performance and resource evidence are NOT_RUN.

## Implemented source path and explicit limits

`driver_snapshot_provider.spl` owns serial admission and first-read frozen dependencies. Entry/import scans bypass the path cache while active; canonical resolver file and directory probes consult the overlay index, permitting unsaved imports absent on disk. Probe and read work share the 8192 ceiling. Existing disk paths must have the same resolved spelling; aliases/symlinks are explicitly unsupported, and pre/post resolution is compared around bounded no-follow reads. Trusted workspace roots are assumed: this does not claim protection against hostile directory replacement or inode aliases.

The API requires worker cwd equal the captured workspace root and uses actual `native_build_compiler_identity()` SHA256 plus the canonical semantic environment fingerprint, target and default-Check schema. A pinned-worker handshake supplies these actual values to the parent; request labels cannot replace the observation. Features are empty in the admitted default-check environment. The environment is observed again after compilation. Legacy native/group/full-inventory/bootstrap/shard/delegated routes reject explicitly. Snapshot Check selects uncached frontend parsing and disables HIR cache and streaming-surface routes; cache/performance admission remains open.

Source digests are the existing SourceSnapshot-compatible full SHA256 hex encoding. Request/environment/dependency hashes are SHA256 with distinct V1 domain prefixes and UTF8 byte-length framing; order is significant. Request admission recomputes every source digest. The selected memory plan's broader XXH3/BLAKE3 policy migration is not claimed complete by this compatibility contract.

`SourceAnalysisResultV1` retains full DiagnosticV1 values. Completed requires an enabled structured-collection run, actual parser source inventory and actual HM receipt inventory (HM is not required when ParseError terminated that phase), no uncovered legacy diagnostics, and exact consumed source identities. Installation/removal is one serial region with no early return after install; worker crash/cancellation terminates the process. Result diagnostics and provider/source owners are retained across canonical session teardown.

The SDN response names its canonical JSON interoperability payload explicitly. Rendering preflights recursive DiagnosticV1 depth32 and conservative 64KiB aggregate weight, limits diagnostic JSON to256KiB and dependency metadata to256KiB, and caps the final envelope at4MiB. Exceeding any bound is a protocol failure, never truncated completed diagnostics. These conservative limits are independent of the 4096-record admission ceiling.

## Validation obligations and status

Focused executable specs: `test/01_unit/compiler/driver/source_analysis_snapshot_v1_spec.spl`, `source_analysis_dispatch_v1_spec.spl`, and `source_analysis_wire_v1_spec.spl`. They cover provider admission/bounds/owner cleanup, actual canonical clean/error overlays over contrary disk bytes, an unsaved imported module, semantic environment mismatch, and lossless nested diagnostics/fix deletion. All are **NOT_RUN** pending admitted runtime. Worker stdout isolation, end-to-end stdio framing, disk ABA adversarial execution, cancellation races, compiler startup/RSS/latency and broad alternate-route qualification remain integration/verification obligations. A static source patch is not execution evidence or full FIX07/DIAG qualification.


Snapshot resolver numbered-directory lookup avoids `rt_dir_list`: the canonical grammar admits exactly 1110 one-to-three-digit prefixes, so it probes that finite universe through the charged file/directory owner and preserves ambiguity detection. It also sees virtual numbered directories from overlay paths. This is bounded but potentially expensive; no warm-latency claim is made. Overlay path depth is capped at64 components and directory-index metadata at1MiB.

The canonical loader's derived `SIMPLE_NATIVE_BUILD_ENTRY_CLOSURE=1` is owned/restored by the snapshot API on every ordinary outcome; frontend cache-scope publication is skipped, and entry-scan payloads are cleared before/after the run. The effective default-Check schema includes this derived closure mode. Process termination disposes all state on timeout/crash. External dependency roots and path aliases are unsupported by the current workspace-contained provider and remain explicit scope gaps; hashes identify analyzed bytes, not an external filesystem watcher generation.

## Fresh environment observation repair

`native_build_compiler_identity_fresh_v1()` now observes canonical compiler source, stdlib source, executable and runtime-provider components without reading or resetting their process memo state. It shares the existing identity composition and hash owners; the legacy memoized API keeps its behavior. The snapshot API uses one fresh observation at each handshake/before-check/after-check boundary, rejects unavailable component sentinels, and performs no retry loop. ABI admission is still read by its canonical owner. This detects changes hidden by old same-process memos; it does not prove an atomic filesystem generation across a whole-tree scan. Whole-tree traversal cost and warm performance remain OPEN. Focused runtime replacement/source mutation specs are NOT_RUN.
