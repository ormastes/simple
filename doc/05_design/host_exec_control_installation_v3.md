# Signed exec-control installation V3

Authored finite Linux configuration mechanism; NOT_RUN. Installation is a prerequisite for independently authorized child execution, never an exec lease, native capability observation or readiness claim.

The pure common codec binds operation ID, exact current enrollment binding digest, full ContainerHostScopeV2, original V2 provider baseline and raw canonical control-policy bytes/hash. Policy must be a bounded strict canonical SDN object; provider/common probe owns its schema. Intent/request limits are 4MiB UTF8 and policy limit is 1MiB. Original action is `host_exec_control_install_v3`, and exact operation ID/host/environment/full intent digest are checked using the existing common envelope codec. SDK verifier remains the sole signature/approval authority implementation.

The actual owner obtains all expected pins from the retained HostLocalRootV1, checks current private public policy and actual configured Container owner metadata, and verifies fresh dual-role proofs. It archives the full original request privately before SAME journal admission. Successful journal admit, begin and completed updates always replace returned local journal and advance ledger revision. Installation creates **no reservation row/debit**; the read-only historical classifier validates these operation rows without current-epoch promotion.

Publication order: complete private original request; admit; refreshed context and begin; privately staged/readback/synced exact intent artifact; completed outcome binding artifact hash; immutable protected current-scope reference. Fresh clock is sampled after potentially expensive stage and current-pin reads immediately before no-replace publication. Linux retained descriptors validate actual owner UID/exact0600 and unchanged identity; existing final is never chmod-repaired or overwritten. Ambiguous publication preserves stage/final evidence. Linux consumed-close errors report recovery required and never retry a raw descriptor. Windows explicitly refuses before POSIX publication; its native ACL-backed consumer is separate.

Retries: different operation for same actual scope is refused by scanning real retained installation journal rows, even if the first reference was interrupted. Same executing/unknown packet can reconcile only exact intent/publication with fresh proof before unperformed publication; changed proof bytes never replace immutable archive. Completed exact artifact may repair only its scope reference using the **latest** journal/current-pin guard, without re-admission, artifact rewrite, outcome rewrite or renewed old grant. Loader refuses absent/wrong reference, incomplete/mismatched outcome/artifact and changed current pins. It carries original full signed request as data, not a decoded live owner. Child producer must call loader and perform its own current authorization and actual common native probe.

Reference namespace is per actual retained scope hash. Old references survive; a new service epoch has a new reference path and needs fresh explicit signed installation. Within one scope a different installation is refused. No automatic epoch adoption, replacement or raw-packet grant renewal is invented.

Public finite route is `host-exec-control-install <protected-root> <signed-packet-file>` through canonical host core owned-open/finish. Input is bounded nofollow4MiB. Canonical response says `installed: true, execReady: false`. Every failure returns latest local before owned journal close and preserves typed cleanup/state. App allowlist belongs to architecture. The source fixture covers real signatures/WAL/private IO faults but uses scripted native metadata; manuals record exact NOT_RUN gaps.

Cold-path performance bound: installation history scan is bounded by 4096 retained rows and decodes only install packets. Worst-case history IO can reach 16GiB if every install packet reaches4MiB. This is explicit conservative uniqueness checking, not a hot request-path design or measured latency claim. A trusted persisted per-scope index could reduce it only after preserving interrupted-first-install exclusion; no performance qualification is claimed. Ordinary native exec must consume the installed loader rather than repeat this scan.

Classifier: `host_exec_control_installation_projection_v3(journal,capacity,operation)` validates actual exact row/request, common intent match, physical host and trusted authority equal to host plus enrollment digest. It recognizes only admitted/executing/outcome-unknown/completed. Completed requires exact intent artifact and outcome hash; unsupported states/actions are not silently skipped. The capacity insertion is a narrow verified metadata branch before reservation decoding; workload/helper allocation/release bodies remain unchanged. Real owned WAL source cases cover successful reopen with original charge, old-scope quarantine, malformed packet, completed artifact mismatch and orphan row refusal.

Shared private publication is extracted to `host_exec_private_publication_v3`, consumed by installer and child producer. `published_new` is returned exactly from native no-replace, not inferred from readback. Existing successful publication is idempotent config provenance but must never issue another child lease. True with error remains uncertain, and false with error is not proof of no effect. Stage evidence is retained and propagated through every uncertain finalread/sync/cleanup error. Explicit native Linux guard remains; Windows ownership is unsupported in this helper.
