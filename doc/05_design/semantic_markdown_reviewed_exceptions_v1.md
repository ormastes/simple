# Reviewed transient diff/forensics link exceptions

Status: architecture GO with constraints from independent Astra review and independent Sol source GO (2026-10-25); implementation and SSpecs authored, exact-commit confirmation pending, runtime UNRUN.

Authority: selected DOC-MARKDOWN-LINT / 06-3 B3 in `doc/03_plan/plan.md`; originating `doc/01_research/language/simple_vs_rust_mission_critical_2026-07-27.md` §5.4 explicitly permits a reviewed exception only for transient diff/forensics documents. REQ-MC-008 otherwise denies line links in critical. These sources define no record or authentication schema. This document proposes its smallest explicit enforcement contract; it does not add a new requirement choice.

A root lint caller may explicitly supply `--semantic-exception-file <SDN>` and `--semantic-exception-sha256 <64 lowercase hex>`. The hash is a trusted caller's pin of an already-reviewed record, never inferred from the document or calculated by the loader. Repository/CI review owns admission of that pin. This is review authorization supplied by the caller, not proof that the tool contacted a review service or authenticated a human; callers capable of replacing trusted invocation arguments can replace policy. Reviewer/name fields alone grant nothing.

One bounded SDN record covers exactly one Markdown file and one line-link destination occurrence: version 1, rule W-DOC-AST-001, document (exact invocation path), markdown_sha256, start, end, target, kind (`transient-diff` or `transient-forensics`), reason, reviewer, review_reference, expires_utc (strict YYYY-MM-DD, valid throughout that UTC day). All fields required, exact keys only, no duplicate/unknown keys. No wildcard, directory exemption, ordinary-maintained-doc kind, or exemption for semantic URI validation. Entire file capped at 16 KiB, text fields each capped at 1024 bytes. A command accepts at most one record; broader registries are outside this slice. No automatic search, env read or network request.

Admission checks exact record digest before parse, required field types, strict known keys, nonempty descriptive review fields, strict calendar validity through existing timestamp component round-trips, expiry against the current UTC clock (clock failure fails closed), exact document identity and Markdown SHA256, and exact ordered byte interval/target matching one W-DOC-AST-001 line-link finding. The existing scanner remains the only syntax owner. Any absent, forged/hash-mismatched, stale, expired, malformed, unused or overscoped record fails the command without edits; missing options retain current warning/critical behavior. A record never hides malformed/dangling spl: URI failures. Explicit invalid grants fail independently of lint-family suppression.

The existing planner gains an optional receipt argument defaulting to nil; existing callers retain the no-exception path. `SemanticMarkdownPlanV1` retains that receipt separately from findings and repair counts. A validated exception removes exactly its matching line-location finding from the immutable plan. Apply replans with the retained raw bytes and original pin and revalidates expiry after source revision checks, preserving exempted bytes. The adapter revalidates adjacent to atomic publication. The record is read once per Markdown input and never silently reread/repinned. Generic fixes with a supplied receipt refuse before writing, even if all semantic findings were exempted. No findings means no semantic write; no auto-fix or repaired-source count is invented.

Integration covers root lint, shared planner/app compatibility facade, and identical optional flags in doc check-links/fix-links. The doc commands retain their existing explicit source authority requirements. Process generation has no explicit review authorization owner and keeps passing none. A new leaf semantic owner holds bounded record parsing/validation using existing SDN issue reporting, SHA256, timestamp arithmetic and filesystem/clock owners; no duplicate Markdown scanner/resolver. The optional receipt adds bounded constant-size parsing/clock work only on explicit grant paths; no ordinary startup, workspace scan or new cache. Qualification targets are unchanged from the semantic Markdown design, with runtime/latency/RSS measurements UNRUN.

Acceptance uses actual root lint on real files: valid reviewed critical exception preserves bytes; no pin, wrong pin, changed Markdown, changed target/interval/path, wrong kind, missing reviewer/reason/reference, expired record, unrelated second finding and invalid semantic URI refuse or retain their original deny. Dry-run/fix preserve exempted bytes; a nonexempt valid line-link still rewrites with revision authority. All runtime, generated-manual, performance and core/MCP qualification remain UNRUN pending the coordinated runtime. Source review must not claim completed selected acceptance.
