## Scope and ownership

The persistent smux service owns one direct provider connection to the exact Docker process container. Common `ContainerOwnedTerminalSessionV2` preserves the Linux V1 owner and adds an opaque Windows Engine pipe owner. A connection is not a helper process: it has no reconstructed PID, Job, cgroup, pidfd, or process-reap receipt. Linux remains behind its existing Simple Container provider.

`ContainerPrimaryConnectionPlanV2` binds the exact execution plan, full runtime ID, Host scope, parent allocation chain, connection resources, protected installation and provider policy pins, actual journal writer lease digest, terminal mode and timeout. Planning uses a fresh typed provider inspection and refuses scripted fixtures. Public plans and deadlines are correlation data only.

## Generic V5 service integration (working source)

The canonical command is `host-primary-service <backend> <installed-anchor> <policy-pin-or-dash> <binding-file-or-dash> 127.0.0.1:0 <credential-file>`. The Host library selects the actual installed backend and rejects unsupported direct-provider routes before opening a writer. Linux continues to use V4. The application neither parses Windows enrollment into authority nor accepts a root/endpoint/policy from a request. Only the retained credential owner reads the secret and publishes the actual loopback endpoint. Startup and AlreadyRunning failures return every Host, credential and service recovery owner; the CLI reply carries them only in process memory and performs one bounded cleanup step.

The existing authenticated smux listener consumes canonical `runtime-connection-v5` envelopes. There are at most 16 clients and 16 retained binding entries. Wire input is capped at 2,796,500 bytes per client (approximately 45 MiB aggregate byte buffers before object/decoder overhead), with a 2 s absolute request deadline and one 64 KiB read per client per turn. Newline scanning visits only the appended suffix. These are implementation bounds, not measured latency/RSS results; performance qualification is NOT_RUN. Existing commands retain their 4096-byte dispatch limit.

One canonical thread progresses the Host execution continuation, read-only inspection, or one attach exchange per listener turn. No thread receives a live Engine pipe or another Host writer. The current Host root is supplied again on every continuation turn; tasks do not retain copied journal roots. Input records reserve the full immutable frame, target, nonce hash, lease revision/deadline, byte range and attempt as Unknown before a write. A missing receipt stays unresolved, Queued never becomes delivered, and a known partial completion permits only the exact suffix. Prepared-only cancellation waits for the actual protected preparation deadline and calls the shared admitted-only expiry transition. It never expires an executing helper.

The close path retains the canonical pane until an exact native closed/no-pending proof is published to the same journal, the helper reservation is settled, and a typed matching acknowledgement reaches that pane. The parent workload reservation remains charged. An executing helper without a terminal session can settle only through the separately reviewed private attempt proof: positive one-use abandonment before native acquisition, or an actual acquired pipe observed closed with no pending IO. Uncertain publication or a competing claimant remains charged; an error string or empty session is not absence evidence.


## Geometry consumer and recovery

The same authenticated V5 envelope exposes `geometry-resolve`, `geometry-issue`,
`geometry-resize`, `geometry-observe`, `geometry-revoke`, and `geometry-cancel`.
`capabilities` reports current protected-policy availability. Geometry uses its
own issuer kind, nonce, revision and deadline. The coordinator permits one
pending Geometry exchange, checks the actual current attachment and issuer on
every step, and cancels it before releasing the primary session. Cleanup can
retain and close the Geometry owner even when the pane is no longer resolvable.

The Host reserves immutable attempt/terminal record pairs under the same actual
journal. An opaque process-local history cursor skips only an already verified
prefix; restart scans at most one pair per turn. Missing terminal evidence or
Unknown blocks a new Geometry exchange. A candidate rejected before any durable
reservation restores the prior committed request/history, allowing the next
sequence to be retried with fresh authority. Actual API acknowledgement and
native cleanup are separate facts; no receipt claims guest terminal dimensions
without an independent guest observation. Input leases and receipts are unchanged.
