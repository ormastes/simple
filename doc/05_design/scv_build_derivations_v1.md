# SCV complete consumer derivation roots

This is the derivation index slice of the approved BuildRunner-first SCV contract. It reuses compiler-owned semantic evidence; it does not replace `SemanticQueryReadManifestV1`, assign semantic meaning to source hashes, or authorize artifact reuse.

`std.scv.build_derivations_v1` stores immutable roots bound to exact opaque snapshot IDs. Each consumer manifest binds its source generation, attempt ID, complete outgoing uses and required candidate/directory scope roots. A use records its unique ID, kind (`macro`, `generic`, `pointcut`, `semantic`), producer UID, consumed facet digest and optional scope root. Compiler owners supply exact candidate universes, including negative candidates and empty universes. Equal scope roots with differing candidate lists are refused. The module never classifies source text, guesses a match, interprets producer digests, or grants completeness from a public struct.

`scv_build_register_attempt_v1` creates a candidate for the owner to persist before scheduling work. It supersedes the current consumer attempt without deleting accepted outgoing uses. Fresh retry IDs may use the same source generation; historical IDs cannot be resurrected. `scv_build_replace_consumer_v1` requires the accepted root CAS, exact snapshot and registered consumer/generation/attempt. It replaces the entire outgoing manifest, derives a new canonical root and records an operation digest. Identical replay returns the current state, preserving any subsequent work; another payload under that ID refuses. Failed or cancelled producers must never call this candidate constructor as admission.

`scv_build_publish_consumer_v1` additionally requires the parent owner's completed producer outcome, prepares the candidate, invokes the trusted owner persistence callback with expected root and an independent candidate copy, and returns publication only after the callback returns that exact candidate root. The owner must independently verify actual successful compiler evidence and perform its existing durable journal and atomic CAS before returning. A caller-supplied status or callback is not an attestation. There is no mutable in-memory claim of durability. Existing SCV HEAD/workspace WAL was inspected and is intentionally not repurposed for unrelated roots.

The parent alone owns producer admission and root publication. Registration, receipt binding and snapshot advance also return candidates that require its same persistence discipline. A failed callback returns an error and the caller retains its previously accepted state. Production durability requires an owner-backed integration test; a callback returning `Ok(root)` is insufficient evidence.

Forward manifests are authoritative for this index. Reverse users and demand are sorted exact sets derived from them, with optional kind-specific queries. Demand keys escape percent and slash before joining consumer and use IDs, preserving identity without shared increment/decrement counters. Candidate queries include nonmatches; old/new comparison unions both complete universes. Queries require an already validated, owner-accepted root; they are not independent admission checks.

`scv_build_bind_receipt_v1` associates an actual parent-accepted receipt identity with an exact consumer manifest digest only when that manifest's snapshot equals the current graph snapshot. Root validation enforces the same relation, so historical manifests cannot gain new receipt bindings after snapshot advance. Replacement invalidates those bound receipts atomically with outgoing replacement. Parent semantic validators own additional dependency/semantic invalidation; the index does not guess a producer/consumer authority relation. `scv_build_advance_snapshot_v1` binds a new exact snapshot, clears current attempts, invalidates all old receipt bindings, and preserves historical manifests until successful current producers replace them.

Canonical roots use length-framed scalars, canonical use/scope ordering and SHA-256 domain separation. Version candidates deep-copy nested arrays. Input bounds are 4096 consumers/current attempts, 4096 uses or scopes per manifest, 4096 candidates per scope, 65536 aggregate graph rows and replay/history/receipt records, one MiB per manifest and eight MiB retained graph metadata before root validation hashing. Full root validation and exact query enumeration are bounded reference operations; no startup, latency, RSS or high-scale performance qualification is claimed.

TDD commits precede implementation. Sixteen real-assertion scenarios are authored under `test/01_unit/lib/scv/build_derivations_v1_spec.spl`; the mirror manual labels execution pending. The admitted general CLI audit is owned by the parent. No Rust seed or bootstrap-stage producer is used for test evidence. Native execution, generated docgen/maintenance scoring, coverage and actual durable owner integration remain pending until that runtime exists.
