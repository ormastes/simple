# SimpleOS lint/test launch environment evidence

The full acceptance set remains six CPUs (x86_64, i686, ARM32, AArch64, RV32 and RV64), each executing real lint and test payloads through both external native and internal Simple linker builds: 24 independent guest cases. The selected engine must be observed on the actual tool payload link; kernel provenance is recorded separately. Filesystem interpreter/compiler/loader role checks cannot substitute for this matrix.

Canonical lint and test implementations remain `src/app/cli/lint_entry.spl` and `src/app/test_runner_new/main.spl`. The standalone test runner requires an explicitly selected, different genuine compiler child. A guest-only substitute, disabled identity guard or requested linker string is insufficient.

The current scheduler adoption owner validates and copies the complete executable launch tuple, including its ordered environment, but previously discarded the environment when reserving its execution observation. This prevented terminal consumers from checking which compiler selection the process actually received. The observation now retains that owned environment, clears it when consuming the slot, and returns it through both one-shot evidence consumption APIs. Entry order and duplicates are preserved exactly; this change neither normalizes environment semantics nor authorizes any executable.

The existing installed-tool probe submits an empty environment. It now rejects evidence containing an environment the request never issued. This does not enable arbitrary caller environment injection or bind a future compiler child automatically. An authenticated staging/launch extension must still admit the distinct target-native compiler artifact, bind its exact launch recipe and validate observed compiler selection before the real test entry can be credited.

Ownership is unchanged in shape: the launch validator creates an encoded copy of each bounded UTF-8 environment entry before the scheduler lock. The scheduler owns the resulting vector in its generation/nonce-scoped observation slot; callers retain no mutation authority over it. Exit/reap updates stay under the existing observation lock. Terminal evidence transfers the retained value snapshot before the owner retires the slot and clears its vector. The ordered comparison does not depend on process completion order, and no raw pointer or borrowed environment crosses the process boundary.

Focused controls exercise the real scheduler adoption, exit, reap, delivery and one-shot consumption lifecycle. They cover ordered duplicate environment entries, independence from later caller mutation, empty compatibility adoption, rejection of unissued probe environment and preservation of the existing empty-environment route. These are owner-level host controls with synthetic admitted-image fixtures; they are not target execution or guest authority evidence.

The hosted verification executor uses the existing RC63 macOS arm64 package only as a candidate. It binds archive, provenance, compiler, test runner, build runner and runtime bytes; checks actual CLI positive/negative check behavior; then runs the focused controls through the separately hashed standalone test owner with an explicitly different compiler. SDK observer controls and required compiler/MCP checks have separate source bindings and outcomes. The job stops on its first failure, performs no retry and never builds P3. Successful host controls would establish only their scoped capability, not SDK or guest admission.

Remaining work includes distinct canonical payload staging, authenticated compiler-child binding, production guest workflow calling, real target runtime/ABI/kernel integration, lint diagnostics and test assertion receipts for all 24 cells. The current probe only admits x86_64 output capture. Other architecture capture paths and all new payload authority must be qualified independently; no readiness flag is enabled by this change.
