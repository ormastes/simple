The actual public opener calls the installed peer-policy gateway, preserving Rejected, OpenCleanupRequired and CloseCleanupRequired without inventing a domain or ledger. Ready means one current finite Linux native-boot Host domain and actual SDK phase1 metadata transport opened with empty error. It is not future V2 fresh-service-incarnation/quarantine bootstrap, native containment/provider readiness or Windows support.

Trusted local configuration provides protected root, pinned peer-policy digest, selected mapped client UID and endpoints/capacities. Service UID is only the actual EUID observed on the protected loaded policy descriptor. The selected UID must uniquely occur in the installed map, differ from service UID and already permit host-status; the runtime never adds that permission. DomainOnly preserves the actual opened gateway if selection fails before listen. SDK open retains every acquired listener on partial failure; OwnedFailure/OpenBlocked never means Ready, and phase4 is not relabelled1.

One parent owns the returned runtime and replaces it after every turn. Tagged DomainOnly/Transport/NoTransport carries exactly one actual domain location. Struct copying is not uniqueness proof. The Live callback maps the existing Host classifier into SDK ControlRead/Work, then delegates actual gateway callback and retains its latest owner before publication. No synchronous effect handler is added. Existing domain effect actions remain explicitly refused. Root-independent peer/action/scope/shape mapping is shared by the original gateway and cleanup-only status, preserving original error order.

Trusted local stop closes the actual canonical Host journal first. Before any listener disposal or response, it retains the complete returned canonical close turn and replaces Live with data-only CleanupOnly or Closed; no HostLocalRoot/provider/WAL snapshot remains in callbacks. Only Released + closed + absent cleanup + empty error permits transport stop. Retained cleanup retries use only its exact canonical carrier. Unknown, stale and consumed-error outcomes are not raw-descriptor retries; nil cleanup does not imply success. Canonical error and status remain available. Fully opened phase1 can serve only its mapped selected client's host-status in cleanup mode; mutations refuse. Partial phase4 supports local cleanup only.

After exact journal release, SDK stop consumes only actual transport owners; retained partial connections/listeners remain in the returned runtime. Transport phase3 reports physical handles consumed, not clean success or workload termination. A nonempty prior transport error remains recorded on later stop calls. There is no wire stop action, no automatic native cancellation, no child-resource settlement and no additional journal. Trusted admin endpoints and the existing Linux private-root model remain prerequisites; no Windows POSIX privacy fallback exists.

Authored cases use real owned-WAL/private-policy/native-listen calls but scripted root/Container observations and explicit SDK request-frame fixtures. They do not demonstrate public native root enrollment, kernel peer authentication, native send/close fault campaign or scheduling latency.
