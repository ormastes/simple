# Installed local Podman policy wrapper

Status: IN_PROGRESS / UNEXECUTED. Wrapper codec and actual read-only probe source are implemented. Native probe qualification and an owned/quarantined factory are still required before this policy can enable exec.

`LinuxOciInstalledPolicyV3` embeds the unchanged `LinuxOciEnginePolicyV1` plus a protected local socket pathname, expected service UID and exact API version5.2.5. Canonical SDN kind `linux-oci-installed-policy`, version3 stores the exact original CLI policy bytes and their existing digest. The wrapper digest hashes canonical wrapper bytes under their explicit version/kind; it does not embed a recursive self digest. Existing V1 policy bytes remain unchanged and no requested exec policy falls back to V1.

The strict outer parser bounds source to 1 MiB, depth2 and32 nodes. This leaves room for the existing legal CLI policy cap and escaped large option inventories. Embedded CLI decode applies its own unchanged bound and exact reencode check. Duplicate, unknown, missing, wrongly typed and noncanonical fields refuse.

Expected service UID must be positive, within the supported UID range and equal the CLI policy's expected rootless UID. Endpoint syntax accepts canonical absolute printable-ASCII Unix paths only, total<=4095 bytes, components<=255, leaf<=107. URI/network/relative paths, dot segments, repeated slash, controls and trailing slash refuse. These lexical bounds mirror the canonical native owner's stated API, not a proof that connect succeeds: its anchored `/proc/self/fd/<parentfd>/<leaf>` sockaddr representation has a further descriptor-length-dependent bound that may refuse before connect.

Decoding establishes no socket ownership, symlink protection, peer credentials, service executable attestation or store identity. The actual native owner must positively check endpoint/ancestors and peer identity. A future installed factory must compare fresh server API/store observation to the actual CLI engine baseline and retain every quarantined adapter/connection on unresolved cleanup. Reusing CLI info parsing with an observed CLI executable hash must not be mislabeled as attestation of the service executable.

Four authored pure-codec scenarios are UNEXECUTED. The finite shared HTTP decoder supports typed info responses with bounded Content-Length or chunked framing and requires exact API5.2.5 from that same response's Libpod-API-Version header. No separate ping is needed. The actual `installed_observer_v3` source composes CLI and native Unix observation, complete EOF and close-before-publish. Native service qualification is NOT_RUN and on hold for the Unix owner's fork-origin fence repair; owned factory integration remains pending. No observation stub, fake service or transport fallback is supplied.
