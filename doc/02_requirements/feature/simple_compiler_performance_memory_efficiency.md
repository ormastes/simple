# Simple Compiler Performance and Memory Efficiency Requirements

## Selection

Selected by the user on 2026-08-22: **Feature Option C — Full Six-Phase Performance and Memory Program**.

## Goal

Make Simple's optimizer activation, performance diagnostics, shared compiler analyses, collection planning, memory behavior, and compiler/tool hot paths truthful, semantics-preserving, measurable, and production-hardened without replacing pure-Simple owners with C or Rust.

## Functional requirements

- **REQ-001 — Active vector safety containment.** The existing elementwise auto-vectorization rewrite must reject any candidate unless exact induction identity, step `+1`, dominance, trip-count, dependence, alias, effect, and target legality are proven. Until then, the unsafe rewrite is excluded from the effective pipeline while analysis/missed remarks may remain.
- **REQ-002 — Truthful pass model.** Every registered pass has `PassStatus` (`Active`, `AnalysisOnly`, `RemarkOnly`, `Skeleton`, or `Disabled(reason)`) and a separate `PassExpectation` (`MayTransform`, `MustTransformSentinel`, or `NeverTransforms`). Backend delegation is recorded separately.
- **REQ-003 — Activation integrity.** Every active transform has a positive sentinel that reports `changed=true`, a negative witness that remains unchanged with a reason, per-run candidate/transformed/rejected counts, before/after instruction counts, elapsed time, and stable rejection reasons. CI rejects active identity/empty wrappers and unsatisfied sentinels.
- **REQ-004 — Effective pipeline truth.** Text and machine output distinguish requested versus effective passes, statuses, backend decisions, analysis-only entries, disabled reasons, and transformation outcomes. Unknown pass names and unavailable required facts fail closed rather than silently succeeding.
- **REQ-005 — Post-transform verification.** Test/debug builds can verify CFG, SSA, types, dominance, ownership, and applicable memory invariants after every changed pass. Verification failure identifies the pass and preserved input/output evidence.
- **REQ-006 — Shared frontend ownership.** Compiler, lint, formatter/source mapping, IDE/LSP, and performance checks consume one parsed/typed module representation per revision. Standalone lint is a thin session owner and does not perform a second parse when a current compiler/daemon artifact exists.
- **REQ-007 — Structured diagnostic model.** `PerfRuleId` and `PerfDiagnostic` represent warning/error policy separately from passed/missed/analysis/failure optimization remarks, with exact spans, related spans, confidence, tier, symbolic cost/resource evidence, fixes with applicability, suppression rationale, profile/hotness, and versioned text/JSON output.
- **REQ-008 — Diagnostic compatibility.** Typed migration preserves existing `COLL001`-`COLL008`/`COLL019` severity, exit status, ordering, suppression, fixes, and observable behavior until each rule is separately baselined and deliberately migrated. Every new rule is centrally configurable by stable identity/group.
- **REQ-009 — Fast typed facts.** One shared HIR traversal collects resolved calls/receivers, collection capabilities, type layout, copies, allocations, effects, loop nesting, and operation events. Rules consume indexed facts rather than recursively walking HIR independently. Authoritative alias/memory versions remain MIR/ownership facts.
- **REQ-010 — First-release diagnostics.** Implement high-confidence coverage for hidden COW copy in loops, multiple deferred enumeration, nested linear lookup, repeated sort/materialization, missing reserve, expensive loop-variable copies, large by-value parameters/stack objects, redundant clone/copy, duplicate associative lookup, improved invariant work, and allocation/COW remarks, including fixed-small-bound and unknown-proof suppressions.
- **REQ-011 — Full rule catalog.** Implement or explicitly stage the selected `COLL009`-`COLL018`, loop/offload/stride/vectorization rules, `COPY001`-`COPY005`, `LAYOUT001`-`LAYOUT003`, `ALLOC001`-`ALLOC004`, `ESCAPE001`, `RETENTION001`-`RETENTION003`, `MEM001`-`MEM002`, `CACHE001`-`CACHE003`, and `STACK001`, with placement and action matching the selected research.
- **REQ-012 — Operation and resource contracts.** `OperationSummary` describes time, allocation count/bytes, peak-live bytes, cardinality, effects, access, order, uniqueness, laziness/enumeration, and invalidation. `CostExpr` is bounded, canonical, distinguishes expected/amortized/worst cases, and propagates `Unknown(reason)` on unsupported or exhausted analysis.
- **REQ-013 — Shared MIR fact service.** Revision-bound `PerfFacts` owns CFG successors/predecessors, RPO, dominators/post-dominators, canonical loop forest/preheaders/latches/exits, def-use/liveness, induction/range facts, region aliases/effects, memory versions/MemorySSA-lite, escape facts, and explicit preservation/invalidation.
- **REQ-014 — Conservative escape and ownership.** Unknown/unresolved flows never become `NoEscape`. Returns, aggregates, fields/globals, closures, suspension, concurrency transfer, FFI/unknown calls, variants, copies/moves, size/alignment/frame thresholds, lifetime endpoints, and proof reasons are covered before stack promotion or allocation elimination consumes escape results.
- **REQ-015 — First-class COW evidence.** Proposed COW MIR operations and a bounded uniqueness lattice expose clone candidates, copied bytes, lost-uniqueness reasons, loop multiplicity, and profile counters. Automatic clone elimination requires ownership, alias, effect, last-use, destruction-order, and lifetime proof.
- **REQ-016 — CollectionPlan execution.** After type/effect completion, CollectionPlan extraction computes local cost/cardinality, fuses proven pure pipelines, proposes indexes, eliminates proven non-escaping intermediates, and lowers to MIR. Unknown equality/order/effect/alias/cardinality facts reject semantic substitution and emit a precise remark.
- **REQ-017 — Loop transformation legality and profitability.** Adjacent/general fusion, LICM, unrolling, BCE, strength reduction, vectorization, and related transforms consume canonical loop/dependence/alias/effect/range facts. Fusion preserves domain, global effect/exception/destruction order, early exits, numeric reduction order, and only runs with a positive target-aware profitability result.
- **REQ-018 — Pass rehabilitation.** Dormant scalar transforms are rehabilitated one at a time in the selected order with positive/negative fixtures, semantic differential execution, idempotence, malformed/irreducible CFG, overflow/FP/trap/zero-trip/alias/unsafe-pointer, and applicable target/backend evidence. Incomplete passes remain honestly non-active.
- **REQ-019 — Interprocedural cost summaries.** Stable, fingerprinted `CostSummary`/`PerfSummary` artifacts propagate through bounded SCC fixed points, record assumptions/confidence/unknown reasons, and invalidate callers only when imported summaries or relevant target/config/cost-model identities change.
- **REQ-020 — Complexity regression CI.** `.sperf` stores stable function identity, IR hash, time/allocation/copy/stack/peak-space bounds, confidence, and assumptions. CI rejects confident polynomial-degree or critical peak-space regressions, reports coefficient/resource regressions by policy, and never treats timeout/unknown as certification.
- **REQ-021 — Profile-guided evidence.** `.sprof-v2` extends existing function/block/edge profiles with optional loop/cardinality/allocation/copy/COW/escape/suspension/cache/remark-outcome records. Diagnostics rank estimated waste by execution count and avoidable work/bytes while treating runtime evidence as prioritization, not semantic proof.
- **REQ-022 — Empirical complexity curves.** A bounded performance-curve workflow measures multiple sizes and repetitions, subtracts fixed startup cost, records confidence, time/allocation/COW metrics, and never classifies complexity from one timeout.
- **REQ-023 — Compiler/tool hot-path repair.** The lane removes or records measured blockers for repeated parsing, repeated CFG construction, quadratic worklists/membership/def-use pairing, textual expression keys, array concatenation, redundant full-tree reads, and hot-path subprocesses. Cold maintenance scans are not mislabeled without measurement.
- **REQ-024 — Pure-Simple and facade ownership.** Compiler/lib/app owners are fixed in Simple first. No new raw runtime/env/process shortcut, C/Rust rewrite, backend poke, or fixture-only bypass is accepted without boundary evidence and the repository's facade decision record.
- **REQ-025 — Knowledge and traceability.** Research, final requirements, NFRs, architecture/TLDR, detail design, agent/system-test plans, executable SSpec, generated/manual docs, compiler/lint guides, feature/layer expert pages, and unfixed bug records remain current. Every `REQ-NNN` maps to executable or explicitly blocked evidence.

## Scope constraints

- Automatic rewriting requires proven equivalence, lifetime, aliasing, effects, ordering, safety, and profitability.
- Source lints describe actionable likely source problems; ordinary missed optimizations are remarks; compiler-integrity defects fail compiler CI rather than user lint.
- General fusion, stack promotion, BCE, GVN, LICM, TCO, string building, and vector rewriting remain non-active until their individual gates pass.
- This multi-release program uses staged internal milestones but does not redefine the selected end state around an early phase.
- Release, version bump, tag, and push are not part of this selection.
