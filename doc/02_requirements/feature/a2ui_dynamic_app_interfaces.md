# Feature Requirements: A2UI and Dynamic App Interfaces

**Feature:** `a2ui_dynamic_app_interfaces`  
**Design Doc:** [a2ui_dynamic_app_interfaces.md](../../05_design/a2ui_dynamic_app_interfaces.md)

## Functional Requirements

- **REQ-A2UI-001 (Express G4 Import & Shared VM):** Import pinned `Express.g4` into strict-SDN grammar representations (`a2ui_import_express_g4` / `a2ui_grammar_to_sdn`), reject unsupported ANTLR directives with line numbers, and execute Express constructor expressions on `std.common.structural.parse.grammar_cpu_v1` preserving `_` omission vs explicit `null` and rejecting trailing tokens or `@index()`.
- **REQ-A2UI-002 (Flat SDN Screen Table & Keyed Repetition):** Parse one anonymous root SDN table (`|id, parent, slot, order, region, repeat, key, expression|`) via `strict_v1`, validate single root, acyclicity, slot cardinality, and unique orders, and expand 1-level keyed repetition (`order`/`by_key`) into deterministic opaque IDs (`c_<hex>`) that survive row reordering.
- **REQ-A2UI-003 (Wire Protocol v1.0 & Bounded JSON):** Support all 6 agent-to-renderer operations (`createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`, `callRendererFunction`, `agentFunctionResponse`) and renderer-to-agent `action` encoding; enforce byte, token, and nesting-depth budgets before descent in `json_parse_strict_bounded_with_error`.
- **REQ-A2UI-004 (Multi-App Isolation & Qualified Handles):** Isolate concurrent apps sharing identical wire IDs (`root`, `refresh`, `main`) inside `A2uiSurfaceRegistry` and SimpleUI `UITree` via reversible `A2uiQualifiedHandle` (`owner + surface + generation + component`); reject duplicate `createSurface` within one owner.
- **REQ-A2UI-005 (Complete Replacement & Reactive Dependencies):** Lower `UpdateComponents` with full replacement semantics (clearing omitted properties), `UpdateDataModel` with exact path replacement/deletion, and maintain path-to-component dependency tracking.
- **REQ-A2UI-006 (Typed App Interface & View/Draft Separation):** Register resources, queries, commands, and draft contracts in `AppInterfaceRegistry`; keep `/view` read-only, enforce writable vs protected `/draft` paths, and use conditional draft reconciliation.
- **REQ-A2UI-007 (Restricted SPL QueryIR & Change Journal):** Parse restricted SPL query text (`from ... where ... select ... order ... limit ...`) rejecting imports, FFI, and raw SQL; execute bounded `QueryIR` plans in O(N) indexed snapshots; deliver independent upserts/removals via cursor-based `BoundedChangeJournal`.
- **REQ-A2UI-008 (Separate Trusted Regional Authority & Privilege Hardening):** Enforce default-deny `*.authority.sdn` region ceilings, HMAC-SHA256 authenticated grants with store membership and atomic one-shot consumption, field-level query/release separation, and release audiences; harden `approval_broker.spl`, `privilege/store.spl`, and `privilege_service.spl`.
- **REQ-A2UI-009 (Caret Suite Vertical Slice & Send Flow):** Project Caret `CsDashboard` + `SessionView` snapshots preserving `-1` sentinels, sanitizing terminal ANSI sequences, hiding denied pane output, enforcing Message-only `caret.send` with `send_draft_guarded`, `SessionControlLeaseV2`, exact deduplication/revision conflict checks, and honest delivery states (`Sent`/`Acknowledged`/`Rejected`/`Unknown`).
- **REQ-A2UI-010 (Dynamic UI Composition Without Code Reload):** Admit new screen tables at runtime via `admit_screen_composition`, validating mount ceilings and registered actions while preserving drafts and leaving `code_generation` unchanged.
- **REQ-A2UI-011 (Hot Swap via Request-Boundary Leases):** Reuse `std.common.aspect_dynload_lifecycle_v1` in `HandlerGenerationOwner` for ABI-checked generation swaps, async suspend/resume lease retention, stale surface commit refusal, quiescence, and reclamation, wired into `CaretA2uiHost` and Caret CLI (`--a2ui`, `--a2ui-json`, `/a2ui`).
- **REQ-A2UI-012 (All-App Reuse via SimpleOS ClockApp):** Mount `ClockApp` (`src/os/apps/clock/clock_a2ui.spl`) onto the shared `A2uiSurfaceRegistry` with zero Caret dependencies, dynamically updating ECS stopwatch/timer views.
