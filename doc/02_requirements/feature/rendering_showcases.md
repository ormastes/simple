# Feature Requirements — Rendering Showcases

Date: 2026-09-24. Selected from
`doc/02_requirements/feature/rendering_showcases_options.md` (deleted after
selection — options A and B rejected). Research:
`doc/01_research/local/rendering_showcases.md`. NFRs:
`doc/02_requirements/nfr/rendering_showcases.md`.

**Selected decisions:** Architecture C (hybrid: trait hosts for interactive +
`.ui.sdn` data for static item-lists/themes). Tier split = separate core /
extended entry files importing a shared core module (compile-time loading win).
Location = new subtree `examples/06_io/ui/rendering/`.

## REQ-001 Web-server GUI backend (ask 0)

A "webserver GUI" rendering showcase: the shared item-list document is served
over HTTP by the pure-Simple UI server (`src/app/ui.web/server.spl`,
`WebServer`, HTTP + WebSocket live updates) via `bin/simple ui web
examples/06_io/ui/rendering/rendering_items.ui.sdn --port 8080`, rendering the
full widget item list in a browser. Run command documented in the subtree
`doc.md` and the wiki guide.

## REQ-003 Tier split (ask 2)

- TUI and GUI ship a **brief (core/kernel)** and a **full** showcase each;
  2D and Web ship **core** and **extended** each.
- Implemented as separate entry files importing a shared core module
  (e.g. `rendering_2d_extended.spl` imports the core scene and adds extended
  scenes). The extended entry must not re-declare core content.
- Loading-overhead reduction is compile-time real (see NFR-001); the current
  env-knob-only state is replaced for these eight entries.

## REQ-004 Shared item list + UI-base switch (ask 3)

- `rendering_items.ui.sdn`: one item-list document enumerating ALL rendering
  items — 30 TUI-rendered kinds, all 43 `WidgetKind`s (13 without a TUI renderer
  are tagged `(no tui)`), the Engine2D API groups, and the web feature
  groups. Rendered by the TUI loader, the GUI loader, and `ui web`
  (web-server GUI) with per-backend tags/config only.
- `rendering_switch.spl`: UI-base switch showcase — the same item list driven
  through TUI, GUI, and the web-server backend, selectable at launch
  (env/argument), demonstrating one definition across UI bases.

## REQ-005 2D showcase content (ask 4)

- Core: every Engine2D primitive group (rect/line/circle/ellipse/arc/
  triangle/polygon/polyline/bezier/rounded), text API, and **bitmap and vector
  fonts side by side with visible word spacing** (via shaped runs /
  advance-width calls — no `word_spacing` engine param exists; gap recorded).
- Extended: gradients/effects (linear/radial/blur/shadow/glass), images and
  nested compositing, a **draggable, overlapping rendered panel** (app-level
  pointer tracking; no engine drag API — gap recorded) and a **button with
  click-event handling** (hit-testing via compositor).

## REQ-006 Web showcase content (ask 5)

- Core: one web page of multiple text lines **with an image** (local fixture
  file generated by the showcase; data-URI decode unsupported — gap recorded)
  and a **scrollbar example**.
- Extended: **CSS examples applying every current aqua-family theme**
  (`aqua_light`, `aqua_dark`, plus `glass_*`, `ios_*`, `dark`, `light` as
  available), forms-media and animation features, and all GUI-rendered
  examples ported to web rendering.
- The **primary rendering showcase has multiple tabs**, one per example
  family; tab definitions are shared data across backends (Option C), with
  only tags/config differing per backend.

## REQ-007 Duplication reduction + grammar verdict (ask: research, report)

- Shared tabs/item lists live once (core module or `.ui.sdn`); per-backend
  entries are thin (host construction + env only), per the existing
  `app.ui_showcase.showcase_core` ScreenHost pattern.
- Grammar verdict recorded in research §2: **parameterized imports do NOT
  exist** (`parse_use_decl` has no argument production); the sanctioned
  mechanism is runtime trait hosts + `.ui.sdn` data + env config. A
  functor-style module-parameter feature (extension to `decl_use_import` +
  instantiation cache in `src/compiler/40.mono/`) is the concrete
  feature request if import-time sharing is ever wanted.

## REQ-010 WM lane behavior (2026-09-24 amendment)

The WM entries run the WM itself: launching `rendering_wm_full.spl` opens the
window-manager window by default (the single physical window via
`GuiRenderer`), then opens the showcase windows **on the WM** as internal
windows — admitted through the WM file bridge (`wm_app_process_contract.spl`,
`SIMPLE_WM_APP_MODE=client` children or in-process
`apply_bridge_request(COMP_CREATE_WINDOW, …)`), each with taskbar chrome from
`taskbar_model()`. Headless fallback (`SIMPLE_GUI` unset /
`SIMPLE_WM_HEADLESS_CAPTURE=1`) writes the composed PPM instead of presenting,
with the same honest-fail gates as `src/app/wm_showcase` (windows
open/accepted/rendered counts, taskbar entries, distinct checksums).

## REQ-011 GUI internal-window demo (2026-09-24 amendment)

The GUI full showcase demonstrates the **internal window feature** (the
scene-level window type the WM manages): build a desktop inside the GUI app
with `simple_gui_internal_window` / `simple_gui_internal_window_scene`
(`src/lib/common/ui/window_scene.spl:477-501`) — at least one `titled` and one
`borderless` (`WM_CHROME_KIND_*`) window — rendered through
`shared_wm_scene_render_to_backend` with `wm_chrome_theme()`, per the
invariant in `doc/05_design/os/desktop/simple_gui_internal_window_impl_spec.md`
(Host WM and SimpleOS WM differ only in backend/config glue; never per-pixel
FFI).

## REQ-009 Verification

- `bin/simple check` (compile gate) passes for all 8 `.spl` entries +
  `rendering_switch.spl`; `.ui.sdn` parse gate passes for `rendering_items`.
- 2D/GUI entries produce a PPM capture headlessly (`SIMPLE_SHOWCASE_CAPTURE`
  or host capture path); `bin/simple ui web rendering_items.ui.sdn` boots and
  answers one HTTP request (bounded probe).
- Core-tier module-closure census ≤ 60% of full tier (NFR-001).
- Pre-existing gaps (no TUI renderers for 13 of 43 kinds, no word-spacing engine
  param, no drag API, no data-URI images, stale deployed toolchain) are
  recorded as bugs, not silently worked around.
- Known compile defect blocking the web standalone showcase on the current
  tree: `semantic: missing return in non-unit function '_level_rank'`
  (gpu_web text cuda_line_break import chain) — must be resolved or proven
  to be another lane's in-flight dirty edit before web gates can pass.
