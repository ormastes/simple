## Verified routes and gaps

| Area | Current committed evidence | Gap against the full objective |
|---|---|---|
| Route census | [Positioned-I/O manifest](../runtime/sosix_unification/sosix_route_manifest_v1_2026-09-26.md) classifies hosted, raw descriptor, compiler in-memory, and SimpleOS positioned paths. | RU-001 still lacks the repository-wide service/`rt_*`/Future/renderer/interpreter/loader/provider census. No complete route manifest or retirement proof. |
| Common and hosted owners | `src/lib/common/contracts/sosix/*_v1.spl` holds operation, completion, error, capability, wait, VFS, and service-ID contracts. `src/lib/nogc_async_mut/sosix/fs.spl` owns a `SimpleRing` and operation retirement arrays; `file_driver.spl` has portable and Linux io_uring provider classes. | Shared contracts exist, but the full service registry, provider parity, task/Future bridge, and all profiles are not qualified. The portable file driver performs synchronous path-based I/O behind a ring submission. |
| Raw descriptor alias | `src/lib/nogc_async_mut/sosix/posix.spl` forwards through `std.nogc_sync_mut.sffi.fs` to `rt_fd_pread`/`rt_fd_pwrite`; the Rust interpreter and C runtime have separate implementations. | Object-code proof of a direct libc call without an intermediate wrapper is still absent. The current raw route does not itself enforce normative POSIX `pwrite` behavior for Linux `O_APPEND` descriptors. |
| Future/Promise | `src/lib/nogc_async_mut/async/future.spl` stores a `Poll<T>` result. `async/promise.spl::Promise.new` returns an independent pending `Future<T>` and a promise with only a `completed` flag; `complete(value)` does not publish `value` or wake that future. | RU-021 compatibility is incomplete. The documented `promise.complete` example is contradicted by its implementation. A canonical task-backed, owned result/retirement bridge is required before claiming Promise semantics. |
| Compiler/interpreter/loader | `src/compiler/80.driver/` owns CLI, cache and pipeline seams; `10.frontend/core/interpreter/eval_calls.spl` dispatches builtins/functions; `eval_builtins.spl` and `_FlatAstBridge/module_assembly.spl` have direct host effects; `99.loader/loader/` owns module and executable loading. `90.tools/sffi_gen/` is a separate generator. | Host effects remain distributed. RU-040/041/042 need one registry-generated dispatch and injected SOSIX host services while preserving the driver descriptor, bootstrap recovery, and lazy loader generation. A mass `rt_*` rename would not establish those invariants. |
| SimpleOS positioned syscall | `src/os/sosix/fs/{positioned_syscall_v1,kernel_positioned_dispatch_v1,positioned_dispatch_owner_v1,positioned_syscall_provider_v1}.spl` has typed envelope, owner, authentication and VFS transaction seams. `src/os/kernel/abi/syscall_shim_positioned.spl` exports C handlers. | At baseline, `scripts/check/check-sosix-positioned-live-route.shs --source` fails: `examples/09_embedded/simple_os/arch/x86_64/boot/baremetal_stubs.c` lacks trap cases 134/135. This change adds only C-ABI forwarding and passes the source guard; linked strong-symbol, installed registry, live QEMU and hardware evidence remain open. |
| Rendering/GPU | `src/os/sosix/host/` contains display, input, configuration and library adapters; the proposal preserves Engine2D/renderer owners. | Adapter/source presence does not prove native render/present/readback or GPU-originated request completion. Proxy and direct device queues require separate backend-specific evidence. |
| SimpleOS release | `src/os/sosix/qemu_evidence/` has typed receipt/importer contracts. `.spipe/sosix_runtime_unification/state.md` and `doc/08_tracking/todo/sosix_unification_blocked_rows_2026-09-05.md` retain AC-3b/QEMU and platform/device blockers. | The recorded AC-3b direct guest serial observation and qualified pure-Simple compiler are still missing. Existing release reports classify broader QEMU/physical rows as unproved; static source or model specs cannot promote them. |

- The 2026-09-05 feature expert and parallel plan refer to `doc/10_metrics/runtime/sosix_unification_baseline_2026-09-05.md` and a perf report; neither is present in committed `main`. Numeric release thresholds need a fresh admitted baseline rather than those stale references.
- `doc/00_llm_process/knowledge_registry.sdn` has no exact `sosix_runtime_unification` feature route at this baseline, though a feature-expert file exists. The kernel route is `mdsoc_only`; avoid treating the expert file's existence as a registered selection receipt. The common SPipe locator resolved the reviewed legacy `.spipe/spipe` route; no company or private wiki scope was assumed.
- Lower-model read-only research covered compiler, library, and OS paths; this synthesis checked the decisive Promise body and trap/source guard against committed main. The OS sidecar's initial inference that all live 134/135 routing existed was corrected by the failing guard. No source scanner or passing model test proves a native release.
- The next implementation/evidence sequence is RU-001 completion, explicit requirement selection, verified trap/link/owner installation, task/Promise value propagation, cross-runtime dispatch, provider parity, then renderer/GPU and SimpleOS release gates. The full objective remains open.
