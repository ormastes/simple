## 2. The production defect (what is wrong today)

1. **Macro families are never published.** `incremental_reverse_reference_generation_v1` emits schema 1 over `REVERSE_REFERENCE_FAMILIES_V1`; no production code calls `reverse_reference_owner_register_v1` with a macro family (`git grep 'macro-definition-consumer' src/compiler` hits only the key/receipt lists and the incremental query).
2. **Therefore every incremental edit over-invalidates.** The consumer loop queries `macro-definition-consumer` first (after the V1 families) for every changed path; the schema-1 receipt answers `unknown-projection-family`, the caller sets `_incremental_reverse_reference_fallback_reason_v1` and marks all entries `DependencyChanged`. (Bug: `doc/08_tracking/bug/reverse_reference_macro_generic_production_gap_2026-10-30.md` items 3–4.)
3. **The only macro→forward-manifest bridge was deleted.** `macro_reference_sealed_manifests_for_module_v1` lived in `80.driver/cache/generic_spec_rr_producer_v1.spl`, removed by `ab9305d783e` ("remove every caller of the deleted 40.mono pass"). `test/02_integration/compiler/cache/reverse_reference_macro_generic_lifecycle_spec.spl` still imports it, so that spec cannot load on release.
4. **Macro effects are not recorded.** Nothing persists, per expansion site, what the macro introduced (generated items/symbols, imports, attributes/AOP-DI effects). `MacroUseV1.generated_symbols_digest` exists in the contract but there is no effect inventory to compare or drop.
5. **Per-file caches do not key on macro inputs.** Neither `DependencyEntry` nor the HIR closure digest folds the resolved `MacroDefKey`s / absence witnesses consumed by the file; a macro body edit in module A leaves module B's own fingerprint, `interface_digest`, and `deps_iface` unchanged (A's public interface did not change), so without the RR hop B's HIR/MIR/obj would be reused stale. Today this is masked only by the full-inventory widening in (2).

## 3. Expansion inputs and per-file cache keys (chain)

Filled from the production call-chain survey; see `doc/04_architecture/compiler/macro_rr_invalidation.md` §2 for the resulting edge model.

- Expansion inputs (frontend/types): macro definition (contract + body), bound arguments / invocation AST, def-site scope (imports of the defining module, nested macro names), active guards, hygiene scope. The projector already digests all but the def-site imports and CTFE reads (named gaps).
- Expansion outputs: generated public member names (`macro_def_generated_public_names`), which `module_public_macro_facts_v1` joins into the site module's `PublicSummaryV1`; introduced imports / attributes / AOP-DI effects are **not** inventoried anywhere.
- HIR cache key: `hir_tldr_cache_closure_digest_v1` over admitted import authority digests; no macro facet.
- MIR/object: `DependencyEntry.module_witness` + `deps_iface` (dependency interface fold) + own fingerprint; no macro facet.
- SCV: read-set equality — exact only if the read set contains the macro reads, which it does not today (the forward manifests are not produced in the driver).

## 5. Scope decisions for this lane

- Keep `ReverseReferenceKeyV1` / `ReverseReferenceEdgeV1` / `SemanticQueryKeyV1` as the one RR key/edge model (shared with `generic-rr`). Macro subjects are canonical `macro.def` / `macro.resolve` semantic keys; the legacy source-path receipt binds them to source paths through the existing alias mechanism, never by inventing a second key.
- Add a **macro effect record** contract (common layer) and a **macro input root** folded into the per-file cache identities (HIR closure digest, `DependencyEntry`), so (c) is exact by key, not by scanning.
- Restore the macro half of the deleted producer as a macro-owned driver module built from committed companions (plan §8.4: complete old+new forward manifests), and wire `incremental_reverse_reference_generation_v1` to schema 2 with real macro facts.
- Replace the unconditional `macro-source-subject-unmapped` widening with an exact changed-subject computation (old vs new companion def tables of the changed path) and a bounded transitive closure over `macro-definition-consumer` edges for macro-uses-macro chains.
- Fail closed everywhere the inventory is incomplete (missing/stale/corrupt companion, unsealed manifest, receipt generation mismatch): widen with a recorded reason; never answer "no dependents".

## 6. Named gaps carried forward (not solved here)

- CTFE reads inside macro bodies are not modelled (fixed "none" root in the projector); an effectful macro is uncacheable (`macro_use_cacheable_v1`) and its users are always re-expanded.
- The coordinator's live-authority gates and SOSIX expected-generation CAS (plan §8.5) remain closed; this lane publishes through the existing legacy receipt path and the v2 projection, both of which retain prior edges on failure.
- `MacroExpansionCacheV1` remains without a production caller; the expansion-site re-expansion in this lane is driven by BuildCache `DependencyChanged`, not by the expansion cache.
