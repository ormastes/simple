# Build/Test Abnormality Detection Local Research — TLDR

The repository already had fragmented process limits, timing rows, compiler logs, and platform lifecycle owners, but no common truthful resource-and-regression contract.

## Core Shape

- Keep enforcement, declared-budget evaluation, and historical anomaly detection independent.
- Preserve distinct memory quantities and explicit evidence quality; never infer OOM or timeout from exit 137/139.
- Reuse runtime/process owners, stable test identities, append-oriented run evidence, compiler phase hooks, and explicit baseline promotion.
- Measure whole build/test scopes first; nested compiler-unit enforcement waits for frozen-graph worker transport.
