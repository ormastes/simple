## Primary external research and resulting constraints

- GCC exposes separate x86 extension controls and distinct ISA/tuning choices. Therefore an operation's legal instructions cannot be inferred from a coarse width or vendor label. [GCC x86 options](https://gcc.gnu.org/onlinedocs/gcc-15.1.0/gcc/x86-Options.html).
- Linux SVE state and VL are per thread. Therefore a fixed-VL specialization needs a qualified worker domain; process-global host selection is insufficient. [Linux SVE](https://www.kernel.org/doc/html/latest/arch/arm64/sve.html).
- RISC-V Linux vector enablement is controlled for the calling thread; libraries should not override inherited process policy. Keep detection/authorization distinct and avoid privileged-register assumptions. [Linux RISC-V vector interface](https://docs.kernel.org/arch/riscv/vector.html).
- Linux dynamic XSTATE facilities such as AMX need explicit permission and sufficient state storage; a hardware bit alone is not execution authority. [Linux XSTATE](https://docs.kernel.org/arch/x86/xstate.html).
- RVV tail-agnostic values are not promised zero; VLEN, active VL and register grouping are different quantities. Test defined zero/merge/agnostic behavior explicitly. [RISC-V vector specification](https://docs.riscv.org/reference/isa/extensions/vector/_attachments/riscv-v-spec.pdf).
- LLVM separates loop and SLP vectorization and applies profitability analysis. This supports shared legality with different matchers/target costs, not copying one vectorizer per ISA. [LLVM vectorizers](https://llvm.org/docs/Vectorizers.html).
- CUDA dispatch may return before device completion; streams/events establish the actual dependency and completion boundary. Keep submitted resources retained until that boundary, and measure transfers/synchronization separately from kernel time. [CUDA asynchronous execution](https://docs.nvidia.com/cuda/cuda-programming-guide/02-basics/asynchronous-execution.html).
- Vulkan explicitly distinguishes execution and memory dependencies. A signaled fence does not itself replace every required host visibility operation for noncoherent memory; use each API's actual memory contract in the shared retirement adapter. [Vulkan synchronization](https://docs.vulkan.org/spec/latest/chapters/synchronization.html), [Vulkan memory](https://docs.vulkan.org/spec/latest/chapters/memory.html).
