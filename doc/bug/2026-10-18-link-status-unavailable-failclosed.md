# Unavailable native link status incorrectly admitted as success

Date:2026-10-18. Source repair proposed; normal runtime/native/core verification UNRUN. Bug DB reconciliation pending. Separate from PR3641 and all frozen compiler/probe sources.

`link_status_text` converted a status rendering as literal nil into empty success. Its comment inferred that only a successful empty value could have been lost. The historical incident did not establish that: the recovered report explicitly retained genuine failure with missing detail as an unconfirmed possibility. No independent success token accompanies this status text.

Actual callers include native runtime-provider selection and Darwin tool identity/publication admission. Those helpers can reject real provider path/bundle/archive or tool/receipt failures. Therefore unavailable status cannot safely authorize the caller to continue. The repair preserves explicit empty success and unchanged valid failure text, while returning a site-named nonempty failure for nil rendering. It removes the unconditional treating-as-ok message; existing callers retain exit and diagnostic authority. This is conditional source evidence, not an observed deployed native admission bypass.

Behavior specs cover explicit empty success, unchanged failure, the public text boundary's nil rendering and a genuine configured provider rejection through the actual helper. The nil-string case tests the rendering policy; it does NOT manufacture a typed nil via unsafe cast or claim reproduction of the underlying native return-channel defect. The provider case requires the exact owner rejection, not any nonempty error: ordinary mode rejects core-c-bootstrap with runtime path none; if the real managed authority is active, the test observes its current path and requests a guaranteed different path, requiring the exact managed-authority mismatch. No environment/authority is changed or provider created. This removes the platform-specific missing-directory assumption; a helper-unavailable message cannot pass. The exact diagnostic must survive normalization unchanged. These behaviors remain UNRUN.

Native-channel nil reproduction control: UNRUN; no legitimate source-level way to force the historical missing return payload has been established. The existing interpolation normalizer and its API remain in place; only its unsupported success inference is replaced by rejection. No unrelated native fallback or return-channel workaround is removed.
