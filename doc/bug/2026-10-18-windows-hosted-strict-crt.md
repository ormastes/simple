# Windows hosted link CRT and duplicate policy

Date: 2026-10-18. Bug DB reconciliation pending. Source repair proposed; native and required core verification UNRUN because a qualified full self-hosted CLI is unavailable. No Rust seed verification substitution.

The generated MSVC entry used the compiler's default CRT while runtime C objects explicitly used `/MD`. Ordinary hosted links also enabled duplicate forgiveness, emitting `/FORCE:MULTIPLE`. Explicit extra flags could restore that option even when the config disabled forgiveness; internal COFF combined the two settings with OR.

The repair gives the generated MSVC entry `/MD`, disables automatic duplicate forgiveness in Windows hosted links, and validates strict Windows extra flags before internal/external engine dispatch. It rejects FORCE variants, GNU duplicate permission, and nested response/driver arguments that cannot be inspected as direct linker options. It reports unsupported nested arguments rather than silently stripping them. Generic explicitly permissive callers and non-Windows policy remain available. Rejected strict requests do not reach engine selection or object reads.

The Windows GNU owner `_link_native_mingw` also appended `-Wl,--allow-multiple-definition` unconditionally, ignoring the config policy. It now appends that flag only when `config.allow_duplicate_definitions` is true, preserving explicit permissive callers. Read-only dry-runs of the actual supported native LLVM23.1.1 clang reject `-zmuldefs` and `-z=muldefs` as unknown arguments; no speculative guard for those forms is added. Native verification of the GNU owner change remains UNRUN.
