# Integrate and qualify parallel graph wave dispatch on two Linux workers

Status: BLOCKED. Priority: P1. Owner: distributed-build Linux integration.

The pure `parent_graph_wave_plan_v1.spl` proposes independent worker slots against a copied ledger. The remote attempt has separate source-level prepare, transport and commit phases with an approved-node and request envelope check. A bounded pure process handoff/observation codec, exact result-inventory planner and conditional parent retained-byte verifier now exist, but no qualified child launcher or production runner consumes them. The production graph runner still executes one remote attempt at a time. The focused wave, phase-boundary, codec, inventory and retention specs are source only under the current Mac session's exhausted self-hosted verification cap. The Mac native beneath-root file-view selfcheck passed on 2026-09-27; this does not qualify the Simple integration. No Linux two-worker execution or speedup has been proved.

On a clean Linux checkout, run `sh scripts/check/check-dist-build-host-handoff.shs --sdn` on each proposed worker host and retain both receipts with the source commit. Require a source-matched admitted Stage 4 compiler and run `sh scripts/check/check-dist-issued-native.shs <Stage-4-binary> <adjacent-Stage-4-provenance>` before installing issued controller and worker candidates. A `PREFLIGHT_ONLY` or `CANDIDATE_BUILT_UNQUALIFIED` receipt is never a distributed-build PASS.

Before a parallel candidate can be issued, extend the native candidate set to include `parallel_transport_child_main.spl` and bind its executable digest in the protected parent launch configuration. The current `check-dist-issued-native.shs` builds the existing parent, worker, verifier and execution worker only. Do this in the owner session for that already-staged script, then qualify the child binary and source provenance with the rest of the candidate set.

The local Mac can develop the pure planner and retained-byte verifier, but cannot certify child writer cessation with the current process-owner APIs. Do not issue a production Mac wave from a leader-only wait receipt. Linux integration must separately qualify the child process tree and result-writer shutdown before parent reads any result bytes.

A pure V4 supervisor policy now rejects the current `POV4_CAP_LEADER_ONLY` capability and requires a reserved positive `POV4_CAP_EXACT_TREE` capability plus an exact frozen receipt with monotonic clock evidence, reaped leader, tree control, tree empty, complete streams and no deadline or process errors before the parent handoff deadline. The current hosted provider does not advertise that bit. This predicate does not launch or acknowledge a child. A production owner must request a V4 wall budget no longer than the remaining handoff time, collect and acknowledge each live lease, and qualify the native provider's exact-tree contract against escaped descendants and inherited result writers before it may set the bit.

A source-only `parallel_transport_process_session_v1.spl` now binds the staged handoff to a pinned child executable and cwd, requests a finite V4 wall budget, and keeps the lease and pins through collect, frozen-receipt validation, and acknowledgement. It rejects the current leader-only provider before acquiring pins or launching. No production runner calls it, and its focused Simple spec has not executed. V4 startup can still return an error after native launch while losing the lease on Simple-side receipt decode or ticket validation. The session treats that outcome as uncertain and retains pins and staged storage; repair the owner boundary and prove fault-injected cleanup before dispatch is enabled. See [bug 351](../bug/process_observation_v4_unowned_start_decode_2026-09-27.md). A source-matched child candidate, hard parent deadline enforcement during blocking transport, exact-tree provider qualification, and child observation/result binding remain required.

The Mac source now also has a parent handoff builder that binds the approved node, canonical request, pinned small batch/control files, result root, monotonic deadline and output limits into encoded bytes and a digest. A parent staging helper writes those bytes under the approved private state root, fsyncs them, and checks a bounded no-follow readback before launch. The parent must retain that staging root until the child stops; private-directory ownership protects its path ancestors. The child handoff/input validator checks exact canonical batches and bounded pinned input hashes. A source-only child runner stages under an exclusively published result root and publishes its observation last. A fixed-argument child CLI reads a bounded no-follow handoff file and requires the parent-supplied digest. The child checks an absolute host monotonic-millisecond deadline between transport phases; the future parent process owner must enforce the hard deadline during blocking SSH/SFTP calls and supply that digest through an owned launch. Neither entrypoint has a production parent caller. The downloader accepts handoff file/aggregate limits, checks manifest-declared output sizes before object transfer, and retains exact accepted-byte checks. A pure-Simple flat inventory check now runs one bounded physical `/usr/bin/find` on the child-owned output directory, rejects extra names and wrong file kinds, then leaves exact byte acceptance to the parent pinned verifier. The Mac `find` fixtures for regular files, an extra empty directory and symlink passed; its Simple specs are unrun and live transfer is unqualified. Before enabling a wave, freeze prepared files across SFTP's pathname reopen. Add a positive transport fixture and collision/cleanup tests. The source-only negative and budget specs do not qualify the runner.

The [bounded-transfer bug](../bug/parallel_transport_child_download_budget_gap_2026-09-27.md) tracks the first of these gaps and its focused regression cases.

Integrate a bounded concurrent child-process owner around the wave planner. Reopen the exclusive journal and recheck each proposed slot against the ledger containing every preceding durable admission; persist the actual fence before dispatch. Pass immutable encoded requests to separate children, never mutable scheduler state through an unqualified thread/`Any` boundary. Collect and terminate every child before parent-side file verification. Check the exact result inventory, then read each regular file through descriptor-pinned beneath-root access, match its byte count and digest, and copy into a fresh parent-exclusive stage before invoking the current reply/output or failure-proof verification. Reconcile, cancel or clean every active attempt, including a worker disappearing after admission. Keep global CPU, memory and FD tokens bounded and the parent as sole publication authority.

Prepared upload source now copies inputs through a 1 MiB pinned streaming view instead of allocating one 256 MiB input array. Its Simple binary-boundary spec and realistic peak-memory measurement remain unrun; see [memory bug 350](../bug/dist_build_prepared_upload_whole_file_memory_2026-09-27.md). The parent must retain the prepared root until every child using it has stopped, because SFTP reopens its paths.

Clock qualification: the child deadline uses `std.io_runtime.time_now_monotonic_ms`. The `simple-core` provider's `core_process.spl` calls `clock_gettime(1)` with a Linux clock-ID assumption, while the hosted C runtime uses host `CLOCK_MONOTONIC`. A native probe on this Mac returned `CLOCK_MONOTONIC=6`, `clock_gettime(1)=-1`, and `clock_gettime(CLOCK_MONOTONIC)=0`; therefore a Mac binary linked to that `simple-core` implementation cannot use this handoff clock. Before any macOS or mixed-runtime parent/child handoff, prove the linked providers return the same host monotonic-millisecond domain; otherwise keep child dispatch disabled. The parent must reject late observations independently even if a child has published one.

Acceptance: two independent actions overlap on distinct scoped Linux workers in retained monotonic traces; a dependent consumer waits for producer acceptance, then consumes the exact accepted bytes. Exercise shared capacity, worker loss, stale fence, corrupted transfer, timeout, replay, cleanup and attempt-free cached repeat. Record actual wall/queue/transfer/action/publication times, bytes and peak private/unique/PSS memory for the selected N2 fixtures. Run the focused Simple specs on the source-matched runtime and preserve the exact binary, image, toolchain, policy and host digests. Until these pass, report `BLOCKED` and no measured speedup.
