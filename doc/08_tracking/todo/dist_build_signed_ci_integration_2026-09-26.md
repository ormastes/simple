# Distributed build: signed local evidence and GitHub integration

Status: BLOCKED

The build workflow and pre-push/PR hook scripts remain dirty work in other lanes. Draft signing and admission modules do not qualify skipping a GitHub build. Current protected checks and candidate-tree scope must be read from live policy before any workflow edit; a local signature alone is a claim by its signer, not proof of mandatory execution. `src/app/build/distribution_acceptance_v1.spl` now rejects incomplete, mixed-candidate or fallback product rows as a pure copied-observation check; its focused spec is authored but has no self-hosted Simple PASS. It does not authenticate downloaded bytes, provenance or CI observations. A bounded `GateReceipt` wire codec and CI fallback adapter are now drafted in separate new files; they have focused unrun specs and Astra static review, but still lack the protected collector and live workflow integration.

Acceptance: coordinate file ownership, keep a reporting GitHub job, use base-owned verification of approved signer, revocation, job/platform scope, exact integration candidate, toolchain/policy/submodules, mandatory gate receipts and retrieved artifact bytes; invalid or missing evidence runs the full remote build. Prove fork, changed base, changed checker, revoked signer, altered artifact and multi-ref negative cases. Preserve all required check contexts. Clarify the user's earlier phrase “gh check on build claude too” before assigning any separate Claude-specific job.

Workflow owner handoff: collect the requested target matrix from base-owned policy; bind each result to current event/ref, run attempt, job, exact artifact ID/name/bytes/hash, authenticated native product provenance and mandatory execution cases on the declared host. Windows seed fallback and skipped Linux execution remain diagnostic or blocked, never distribution PASS. Route signed reuse and ordinary build through one artifact/smoke/acceptance path. Add a stable final job with `needs` across build and execution jobs plus `always()` so missing/cancelled/failed rows report. Redesign path-filter behavior before requiring that context remotely.
