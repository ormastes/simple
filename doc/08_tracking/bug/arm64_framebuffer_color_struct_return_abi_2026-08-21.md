# ARM64 framebuffer `Color.rgb` struct return faults before SimpleOS desktop-ready

Date: 2026-08-21
Status: OPEN — exact reproducer restored; fresh native and QEMU evidence pending
Owner: native aggregate-return ABI / SimpleOS ARM64 rendering
Severity: P0 for the resumed QEMU desktop-rendering goal

## Observed failure

The 2026-08-11 attested ARM64 QEMU lane reached RAMFB discovery but faulted
before `[desktop-gui-arm64] desktop-ready`.  After explicitly rebinding the
live `FramebufferDriver` scanout fields, the final bounded run moved from a
nil receiver in `Color.to_u32` to PC `0x4037c300` in `Color.rgb`.  This isolates
the remaining boundary to returning the four-`u8` framebuffer `Color` value.

The old evidence directory has since been overwritten by a
`canonical-kernel-missing` result.  Historical messages are diagnosis only;
fresh evidence is required before closing this bug.

## Owner boundary and rejected shortcuts

- `runtime_need`: none; this is value transport generated by native codegen.
- `facade_checked`: `FramebufferDriver` and `Color.rgb` use ordinary Simple
  values and require no runtime capability.
- `chosen_path`: fix the native aggregate-return owner, then prove the exact
  color fixture and the adjacent aggregate-return class.
- `rejected_shortcuts`: framebuffer-local raw runtime calls, hardcoded packed
  pixels, a QEMU-only color special case, weak/fabricated symbols, or treating
  interpreter success as native evidence.
