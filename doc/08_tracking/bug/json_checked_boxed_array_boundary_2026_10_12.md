## Defect and repair

The preserved MCP failure passes json_to_array(any)->any? directly to foreach. Optional payload metadata is a tuple shape, and Any does not prove a boxed-array layout. Keep public json_to_array unchanged. A private json_array_flatten_items first checks the JSON tag, then asks the owning runtime whether payload storage is a registered boxed array. Only that successful branch publishes [any] metadata. Non-array JSON/nil keeps the existing empty-array result. Forged array-tagged scalar/nil/tuple/packed payload returns nil for the entire flatten operation, including malformed nested elements; it is never reinterpreted or silently dropped.

C checks registry membership before header flags and rejects tuple1/packed-byte8/packed-u6416 combinations. Pure-Simple checks its registry before flags and marks rt_tuple_new as tuple only after the existing nil-initialized allocation. Rust uses with_typed_ptr under its registry lock, proves HeapObjectType::Array, and rejects BYTE_PACKED/U64_PACKED. Rust tuples use distinct heap type4; its GC bit1 is deliberately accepted, rather than copying the C tuple bit rule.

The public alias lives in the existing nogc_sync_mut SFFI runtime owner and the explicit nogc_async_mut facade re-exports it. JSON imports generic std.sffi.runtime, preserving configuration selection. C header, Rust exports, runtime signature I64->I8, symbol catalogue, and ELF/JIT lookup are wired. No JSON leaf direct runtime call, arbitrary pointer probing, ownership transfer, allocation, global freeing, or C/Rust heap cast is introduced.

## Memory, performance and remaining qualification

The predicate returns only a boolean; registry lock protects the Rust membership/header read, with no escaped pointer/reference. It does not pin lifetime for subsequent iteration: normal borrowed-value lifetime and owner/thread rules still apply. No concurrent-free guarantee beyond that contract is claimed.

Root C microbenchmark:500k queries at1024/8192/65536 live arrays approximately10.0/10.7/17.5ns/query, peak12444KiB. These C hash-registry results do not qualify Pure-Simple: its array_is_valid walks a linked registry in O(live arrays), a separately recorded OPEN performance limitation. Rust build/test/JSON timings are diagnostic bounds, not before/after optimization or leak measurements.
