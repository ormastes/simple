# MC/DC saved token stack aliases a mutable array

Status: confirmed native failure; repair not applied in this landing. Next repair and native verification are a separate bounded scope.

One inspection of the existing core found repeated `mcdc_static_probe_abort -> mcdc_static_local_aspect -> mcdc_static_probe_abort` frames, ending in stack exhaustion. Disassembly contains 11 generated abort calls in each excluded helper, matching the 11 preceding fixture decisions.

`lower_mcdc_decision` assigns `saved_tokens = self.mcdc_active_tokens`, calls `saved_tokens.push(token)`, then restores `saved_tokens`. Array push mutates and returns the same array: the Simple lowering owner `lower_unresolved_array_push`, hosted `rt_push`, and core-C `rt_array_push` implement that contract. Restoring the alias therefore retains the appended token. Completed decisions leak local handles into subsequent functions and modules; excluded probe helpers acquire orphan abort calls. This is a compiler stack-ownership bug, not evidence of a new native value-copy ABI defect.

The repair must use a genuinely independent active token array or explicitly restore stack length, and maintain a function-boundary invariant. Regression coverage must use one real lowerer for included decisions followed by excluded runtime helpers, assert an empty stack after completed decisions and no generated probes in excluded functions, and preserve nested early-return abort behavior. Native acceptance still requires the existing module-statics value assertions and positive recorded MC/DC count. Disabling coverage or adding a recursion guard would conceal the invalid generated calls.
