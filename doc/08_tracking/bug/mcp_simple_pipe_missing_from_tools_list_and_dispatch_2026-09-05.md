# MCP `simple_pipe` is declared everywhere but neither advertised nor dispatched — the wrapper admission probe therefore rejects every native

- **Date:** 2026-09-05
- **Host:** aarch64 Ubuntu 24.04, `origin/main` @ `5864dbfd054`
- **Severity:** blocking for `simple-mcp` — no native built from current source can be admitted by `bin/simple_mcp_server`
- **Scope:** `src/app/mcp/**`, `scripts/setup/setup.shs` (wrapper generator)

## Symptom

Driving `bin/simple run src/app/mcp/main.spl` over stdio JSON-RPC (initialize ->
notifications/initialized -> tools/list -> tools/call) with the **exact payload the
generated wrapper uses as its admission probe**:

```
{"method":"tools/call","params":{"name":"simple_pipe","arguments":{"surface":"search","query":"main","scope":"app"}}}
```

returns

```
{"id":"3","result":{"content":[{"type":"text","text":"ERROR -32601: Unknown tool: simple_pipe"}],
 "isError":true,"structuredContent":{"code":-32601,"message":"Unknown tool: simple_pipe"}}}
```

and `tools/list` returns **166 tools, none of them `simple_pipe`**
(`serverInfo` = `{"name":"simple-mcp-full","version":"4.0.0"}`, process exits 0 on EOF).

## Why this blocks the server

`bin/simple_mcp_server` is generated by `scripts/setup/setup.shs:172-184`. Its
`mcp_probe_native()` admits a native binary only when all of these hold:

- `grep -q '"simple_pipe"'` in the response stream (tools/list must advertise it)
- `grep -q '"id":"3".*"result"'` and **no** `'"id":"3".*"error"'`
- `grep -q 'simple_search query=main'`

Against current source, condition 1 fails, condition 3 fails, and the `tools/call`
result carries `isError:true`. So the wrapper logs
`native_probe_failed ... reason=simple_pipe_search_call_failed`, exhausts its
candidate list, and exits 127 — **even with a perfectly good native binary and a
valid `.sha256` sidecar in place**.

## Root cause: the descriptor row was lost, the rest of the feature was not

`simple_pipe` is still referenced by every collaborator *except* the two that matter:

| site | state |
|---|---|
| `src/app/mcp/tool_table.spl:649` | declares the entry, full `props_json`, `read_only`, timeout 30 |
| `src/app/mcp/main_static_tools.spl:140` | `_mcp_static_props_for_tool` has a `simple_pipe` branch |
| `src/app/mcp/main_static_tools.spl:87` | `_mcp_static_pipe_props()` exists |
| `src/app/mcp/main_static_tools.spl:487` | `_mcp_core_tool_names()` pushes `"simple_pipe"` |
| `src/app/mcp/main_dispatch_core.spl:6` | `dispatch_tool_core` handles it — **file has ZERO `.spl` importers** (`grep -rn 'dispatch_tool_core\|main_dispatch_core' --include=*.spl src/` returns only its own definition + `export`), i.e. dead code |
| **`_mcp_static_tool_table()` (`main_static_tools.spl:231-402`)** | **no `simple_pipe` row** — this table is what `tools/list` serves |
| **`dispatch_tool()` (`main_dispatch.spl:15-28`)** | **no `simple_pipe` arm** — falls through to `-32601` |

`_mcp_static_tool_table()` has carried no `simple_pipe` row at HEAD~1, HEAD~5,
HEAD~20 or HEAD~60, so this predates the current session; the likeliest origin is
one of the tracked tree-wipe/restore incidents.

`main_dispatch_core.spl` being unimported also means the "core" tool-set path
(`SIMPLE_MCP_TOOL_SET=core`) has no dispatcher at all.

## Why `check-mcp-wrapper-contract.shs` stayed green

It passed on this host (`mcp_wrapper_native_contract=pass`,
`mcp_config_cached_artifact_contract=pass configs=4`,
`t32_wrapper_native_contract=pass wrappers=2`). Its fixtures are **fake natives that
echo whatever the probe wants** (`check-mcp-wrapper-contract.shs:100,125,141,145,157,161,231`),
so it verifies hash admission and fallback ordering, never that the real server
answers the probe. Secondary gap: those fixtures are hardcoded under
`release/x86_64-unknown-linux-gnu/`, so the gate passes on aarch64 **without ever
exercising the `aarch64-unknown-linux-gnu` candidate** that was added to all four
wrapper lists.

## Fix options

1. **Restore the descriptor + dispatch** (preferred, matches the rest of the tree):
   add a `_mcp_static_tool("simple_pipe", ...)` row to `_mcp_static_tool_table()` and
   route `simple_pipe` in `dispatch_tool` (either wire `main_dispatch_core.spl` in, or
   add an arm alongside `_is_query_tool`). Requires a native rebuild to take effect.
2. **Retarget the probe** to a tool that exists — `simple_search {"query":"main","scope":"app"}`
   was measured working: `isError:false`, 5014 bytes, and it emits the exact marker the
   probe already greps for (`-- simple_search query=main scope=app --`,
   `main_lazy_query_tools.spl:613`). This admits the in-flight binary **without** a
   rebuild, but leaves the `simple_pipe` feature broken and the four specs above red.

Not applied here: the change fans out across 6 scripts and 4 specs
(`scripts/setup/setup.shs`, `check-mcp-wrapper-contract.shs`,
`check-mcp-native-smoke.shs`, `validate_mcp_native_smoke.spl`,
`stage4-tooling-matrix.shs`, `use_target_resolves_baseline.txt`, plus the specs), and
option 2 would additionally need `_MCP_PROBE_WRAPPER_VERSION` bumped (it is the
stamp-cache key) and `bin/simple_mcp_server.cmd` mirrored for Windows.

## Related, filed here for the record

- **No automated `.sha256` sidecar writer.** `native_hash_is_valid()` fails closed on a
  missing `<native>.sha256`. `scripts/setup/setup.shs` only *validates*; nothing under
  `src/app/cli/native_build*.spl` or the Rust `native_project` pipeline writes one.
  After a native lands, `sha256sum <bin> | awk '{print $1}' > <bin>.sha256` is a manual
  step. It is documented only in `CLAUDE.md` (§ MCP Servers) — **not** in
  `doc/07_guide/app/mcp/mcp.md`.
- **No LSP native is in flight.** The running build's `--entry` is `src/app/mcp/main.spl`
  only, so `simple-lsp-mcp` will keep exiting 127 after it lands.
- `~/.codex/config.toml` declares `spipe`, `simple-mcp`, `simple-lsp-mcp` but **no
  `stitch`** block, unlike `.mcp.json`.

## RESOLVED 2026-09-05

Fixed in `fix(mcp): advertise and dispatch simple_pipe — the wrapper's admission
probe needs it`. Three additions, no new behaviour: the tools/list entry in
`_mcp_static_tool_table()`, the `_is_query_tool` predicate arm, and the dispatch
arm to the already-existing `handle_simple_pipe`.

Verified by replaying the wrapper's exact probe against the interpreter
(`bin/simple run src/app/mcp/main.spl`): tools/list advertises `simple_pipe`,
the `tools/call` returns a result with no error, and the payload contains
`simple_search query=main` — all four conditions `mcp_probe_native` tests.

The wider fan-out this record describes (6 scripts + 4 specs referencing
`simple_pipe`, and `main_dispatch_core.spl` having zero `.spl` importers so
`SIMPLE_MCP_TOOL_SET=core` has no dispatcher) is NOT addressed and remains open.
