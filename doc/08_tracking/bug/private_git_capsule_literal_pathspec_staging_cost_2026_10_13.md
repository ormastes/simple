# Large literal-pathspec Git staging delays authenticated source capsules

Status: diagnosed in private bootstrap preparation; bounded index repair completed. This is not a compiler/runtime performance result. Bug DB reconciliation pending.

The complete immutable cce267e717684e7f87aea1603df3da7c0745258d capsule contained 145,182 authenticated original blobs (2,406,972,146 bytes). After those byte checks, the initial private projection used `git add -f --pathspec-from-file=... --pathspec-file-nul` with one literal pathspec per file. The owned Git process consumed 429.0625 CPU seconds, retained a zero-byte index lock, and had created zero loose or packed objects when stopped. RSS at that observation was 95,342,592 bytes. The observed delay occurred before blob staging; large pathspec matching is the suspected cause, not a measured Git-internal complexity proof.

The exact process identity, creation time, command, CPU sample and zero-object observation are retained in `build/native_probe/core-c-worker-profile-20261013-sol`'s corresponding native packet at `C:/p3/build/native_probe/core-c-worker-profile-20261013-sol/STAGING_PERFORMANCE_FAILURE.json`. Only that verified private staging process was stopped. Its absence was checked before removing its zero-byte private index lock. No compiler invocation, shared Git mutation, source deletion or cache eviction occurred.

The completed repair uses the previously authenticated private projection 283b5649b6a236e0533115193bf23aeca22f567f as an immutable object provider, reads that tree into the new private index, and stages only four owned overlay paths. The final private commit is 3347135016948759aee94c6fee85ca2be1353995. Its parent is the pinned provider commit; its parent diff contains exactly those four paths. Its 145,185 tracked paths exactly equal the final authenticated physical manifest: three new files and one changed existing file. The provider and shared working tree/index were not modified.

Two receipt preparation errors were retained and corrected without repeating staging: Windows text output added CR to an alternates path, so the metadata was rewritten with literal LF; the seal initially misinterpreted the provider's root-cache exclusion count and Git-quoted Unicode filenames. NUL-delimited tree output establishes exact path equality. These were preparation errors, not compiler failures or passed test cases.

Prevention: after byte-authenticating a coherent source cut, reuse its immutable object identity with a private index and stage only the changed files. Keep provider commit/tree, source manifest and overlay hashes in the receipt. Use literal-LF Git metadata and NUL-delimited filename protocols. Do not infer source completeness from Git exit status or rewrite cache identity stamps. The source files still require authenticity checks; a private object reference does not substitute for them.

The successful full-size acceptance is the actual repaired capsule, not a synthetic timing test. No speedup ratio is claimed because preparation timing was not collected as a controlled pair.
