# Windows bootstrap session rewrites cmd.exe switches

Bug: BUG-WINDOWS-BOOTSTRAP-CMD-ARGV-20261017. Database reconciliation pending.

Observed during the diagnostic producer Hello qualification: a guarded direct `cmd.exe /d /c <build.cmd>` invocation printed an interactive Windows command banner and returned zero without starting the compiler. That exit was rejected as qualification evidence. A separate driver setting `MSYS2_ARG_CONV_EXCL=*` around the actual cmd launch subsequently executed the genuine compile. Existing evidence is under phase2-value-diagnostic-producer-exception-20261017/hello-qualification in the external phase3-validation evidence root.

The canonical C bootstrap-session helper reconstructs argv from the guard's NUL-separated workload.spec, then starts every command through the pinned MSYS shell with `exec "$0" "$@"`. MSYS native-child argument conversion can interpret cmd slash switches as POSIX paths. The fix selects the exact case-insensitive cmd.exe basename (slash/backslash paths or bare executable), and assigns MSYS2_ARG_CONV_EXCL only to that exec. Arguments remain positional parameters; none become generated shell source. Other executable behavior, resource admission, containment, timeout and exit classification remain unchanged. A file named mycmd.exe does not select the exception; bare cmd without .exe is outside the bounded contract.

This is bootstrap orchestration C, not a product C implementation or a compiler bootstrap retry. The canonical helper installer naturally invalidates its cache when these source bytes change.

A real Windows-only regression test invokes the canonical watchdog/helper for absolute, mixed-case, and bare cmd.exe commands. Each must emit an actual command marker, exit 37, and report quiescence. It also checks the retained workload.spec for literal /d and /c before C-helper execution, distinguishing earlier argument conversion from the proposed trampoline fix. An ordinary POSIX shell workload checks literal metacharacters and exit 23. Evidence is retained, including failures. The test does not treat an interactive banner or exit zero as success.

Status: focused real Windows regression PASS. The canonical installer compiled the unchanged baseline and patched helper in separate source-keyed entries using LLVM 23 clang-cl. Baseline direct cmd returned zero instead of required 37; patched absolute/mixed-case/bare cmd cases each emitted the marker, exited 37, and reported quiescence. The ordinary shell control preserved literal metacharacters and exited 23. All four patched stderr files were empty. Retained workload.spec inspection confirmed switches were intact before helper launch. Receipt: external windows-session-cmd-argv-20261017/before-after-receipt.json. Initial setup failures (Windows sort shadowing MSYS sort, then an absent sparse setup dependency) preceded helper compilation and are not test passes; the retained runner uses the canonical setup with /usr/bin first and both setup scripts materialized. No Phase3/compiler/native-object qualification is claimed.
