# devhub native: `messenger rooms` fails with "schema column missing in table 'room'"

Status: verification-pending
Priority: P1
Date: 2026-11-14

## Symptom
Native `devhub.exe messenger rooms --target dense --json` exits 2 and prints:

    {"target":"","action":"rooms","status":"error","code":2,"error":"config_error: schema column missing in table 'room'","warnings":[]}

`messages --target dense --room 1 --limit 1 --json` fails the same way.

## Interpreter vs native
- Interpreter (`bin/simple.exe run src/app/devhub/main.spl messenger rooms --target dense --json`): exit 0, payload equals ground truth `rooms_payload` (2 rooms).
- Native: exit 2 as above. `doctor` is ready in both. No authentication error in native, so decryption/open appears to succeed and the failure is after the rows are read.

## Suspect
`_col()` in `src/app/devhub/messenger/adapter/db_common.spl` (compares `row.columns[i] == name`); under native codegen no named column of the returned `DbRow` matches the schema profile names (`room.id`, `title`). `_missing_column_error` is the only source of the message.

## Setup used
- sdn: generated by `cli_sdn_text` in `test/support/devhub_messenger_cli.spl` (target `dense`, `read_provider: sqlcipher4_database`, schema profile `dense_v1`, db `test/fixtures/database/sqlcipher4/dense_multipage.sqlcipher4`), at `$HOME/.config/devhub/messenger.sdn`.
- env: `SIMPLE_SECRET_MESSENGER_DENSE=public-test-passphrase-not-a-secret`, HOME/USERPROFILE pointing at `build/nb/home`.

## Reproduction
    export PATH="/c/Users/user/.simple/toolchains/llvm-mingw-20260922-ucrt-x86_64/bin:$PATH"; unset CC CXX
    SIMPLE_NATIVE_BUILD_RUST=1 SIMPLE_NATIVE_INCREMENTAL=1 bin/simple.exe native-build src/app/devhub/main.spl -o build/nb/devhub.exe --cache-dir build/nb/cache
    export DEVHUB_NATIVE_BIN=$PWD/build/nb/devhub.exe
    bin/simple.exe test test/03_system/app/devhub/messenger/native_binary_sqlcipher_read_spec.spl

Covered by the in-development spec `native_binary_sqlcipher_read_spec.spl`.

Fix: `optional_struct_inner_type` admits Tuple payloads (control.rs) and
`lower_tuple_index` (access.rs) projects the Some payload via
`rt_unwrap_or_self` before the positional Index (the `.0` form is
Expr::TupleIndex, not FieldAccess). Evidence: native probe `.0/.1` on
`(text,i64)?` prints `dot0=` / `dot1=nil` unfixed, `dot0=room` / `dot1=4` fixed;
native devhub rebuilt with the fixed seed passes native_binary_sqlcipher_read_spec
(2/2) and open_spec (4/4). Awaiting independent native verification.
