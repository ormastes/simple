# test_result.md is frozen at 2026-05-19 — it is NOT being rewritten daily

**Filed:** 2026-08-18 · **Lane:** TALLY · **Status:** OPEN (diagnosis complete)

## Premise correction

The reported symptom was "`doc/08_tracking/test/test_result.md` is being rewritten
today (mtime 2026-08-18 03:56) without its content being refreshed (header says
`Generated: 2026-05-19`)".

**That is not what is happening. The file is not being written at all.** Evidence:

```
$ git status --porcelain doc/08_tracking/test/test_result.md   # (empty — clean)
$ md5sum doc/08_tracking/test/test_result.md
fdcc7c5515b9ecb15d7bd9cef7c6ed81
$ git show HEAD:doc/08_tracking/test/test_result.md | md5sum
fdcc7c5515b9ecb15d7bd9cef7c6ed81
$ git log -1 --format='%H %ad %s' -- doc/08_tracking/test/test_result.md
ae55a7467197350bdf8b91c48444c167219ce8bb Tue Aug 11 07:22:12 2026 +0000
  fix(vcs): restore tree wiped by 6f86ff32a7d
```

The working-copy bytes are identical to the committed blob. The fresh mtime comes
from a checkout / `jj`-`git` tree restore rewriting identical bytes, not from a
generator run. Today's mtime is therefore not evidence of a run.

## Why the header could never be stale if it HAD run

The live file's format (`**Generated:**`, `**Total Tests:**`, `🔐 Qualified Ignore`,
`🔄 Recent Status Changes`) is produced by the **Rust** generator, not the Simple one:

- `src/compiler_rust/driver/src/test_db/docs.rs:11` `generate_test_result_docs`
- `docs.rs:16-18` — the timestamp is `chrono::Local::now().format("%Y-%m-%d %H:%M:%S")`.
  **Hardcoded to "now"; not a DB field, not copied from a row.** Any real invocation
  necessarily changes the header. A 2026-05-19 header therefore proves the last real
  invocation was 2026-05-19.
- `docs.rs:27-38` — counts are computed live from `db.valid_records()`
  (`src/compiler_rust/driver/src/test_db/types.rs:535-537`), not stored. So
  120809 / 12328 are a snapshot of the DB *as it stood on 2026-05-19*.
- `docs.rs:370` — `fs::write(output_dir.join("test_result.md"))`.

`src/lib/nogc_sync_mut/test_runner/doc_generator.spl:25` `generate_test_result_md`
emits a *different* markdown shape (`*Auto-generated by Simple test runner (unified
database)*`, `| Metric | Count |`). It is **not** the writer of the live file and is
a red herring for this symptom.

## Why it stopped being invoked

Call sites, all passing the **relative** path `doc/08_tracking/test` (so CWD-dependent):

- `src/compiler_rust/driver/src/simple_test.rs:589-591` — result discarded via `let _ =`
- `src/compiler_rust/driver/src/cli/test_runner/test_db_update.rs:187`, `:292`
- `src/compiler_rust/driver/src/cli/doc_gen.rs:852` — `simple test-result-gen`

All of these sit *after* the run completes. Per lane RUNNER
(`test_runner_never_exits_after_summary_post_run_db_report_2026-08-18.md`) the runner
prints `Results:` and then never exits, so post-run doc generation is never reached;
and `--no-db` skips the DB path entirely. Corroborating: `test_db.sdn` is live (149 KB,
mtime today) while `test_result.md` describes 120,809 tests — a much older, far larger
DB. A real regeneration would shrink the file drastically.

## Consequence

`test_result.md` is a **3-month-old committed artifact**, not a report. Its
12,328-failures figure must not be quoted as the current tally. Deliberate refresh:
`simple test-result-gen` from the repo root — but that only helps once the runner
actually exits and the DB is closed out.
