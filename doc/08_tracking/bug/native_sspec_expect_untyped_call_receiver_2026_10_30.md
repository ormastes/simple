## Refined source diagnosis and candidate

Further tracing found an existing return-only path: `rti_rows_from_hir_v1` publishes `HirFunction.return_type` independently of parameter annotations, and `enum_match_expr_type(Call)` consults RTI. Therefore the missing complete Function symbol above does not itself prove that MIR cannot recover i64. No runtime trace of the returned RTI term was retained; the runtime-fallback diagnostic describes the original receiver annotation, not the recovered type.

The concrete native dispatch gap is separate: `register_trait_impls_of` records non-Named implementing types under generic owner keys, while the Unresolved method fallback handles record owners but has no primitive trait lookup. The candidate preserves the existing trait-object map and adds scalar dispatch entries keyed by exact primitive width/sign/kind and method. Registration follows lexical bindings (including import aliases) and requires the consumer's visible trait identity to match the provider. Only nongeneric impl/trait/method declarations with a relocated callable can be selected. Unsupported generic candidates poison the matching scalar key; a blanket type-parameter receiver poisons that method for every scalar. Selection requires the existing complete-closure flag. Different targets for a scalar key mark ambiguity; selection runs only after established builtin/field dispatch and shares the resolved TraitMethod emitter, reusing the already evaluated receiver. Existing RTI supplies call return metadata; untyped parameters remain untyped.

Production regressions are in `test/fixtures/compiler/scalar_trait_call_receiver/`: imported untyped-input/typed-return call with i64 and bool implementations, aliased trait visibility, hidden same-name provider, receiver evaluated exactly once, compile-negative ambiguous/generic/blanket implementation cases, a blanket-trait/text-length builtin precedence control, and actual SSpec green/red assertions. The unit fixture additionally checks width/sign distinctions and lexical alias shadowing. Native compilation and execution are pending build-owner scheduling; source inspection is not native qualification.

Independent review caught early generic rejection preempting string length builtins; the repaired candidate moves recovery to the final Unresolved fallback and extracts the existing trait call emission unchanged for shared use. No runtime result is claimed.

A second review found that globally unique static-method recovery preceded the final fallback and could steal the scalar call. Proven scalar receivers are now excluded from that ownerless recovery; the positive fixture includes an unrelated static method with the same leaf name and separately calls it by its explicit owner.
