# LLM Caret Codex App Server piped-stdio blocker

Date: 2026-08-02
Status: OPEN (P3)
Status re-verified 2026-08-17 by source inspection (triage shard 02).

## Scope

The new pure-Simple Codex App Server v2 codec matches the schema generated by
the installed Codex CLI 0.146.0. Its unit specification passes. A real
integration gate attempted to spawn `codex app-server --listen stdio://`
through the canonical `app.io` piped-process façade, send `initialize`, notify
`initialized`, and send `thread/start` without starting a model turn.

## Evidence

Three bounded integration attempts failed before the response diagnostic was
printed. The failure is therefore at process spawn/aliveness or the initial
pipe write, not proven to be response parsing. The wrapper returned a failing
SSpec result each time. No live App Server PASS is claimed.

The failed executable spec was removed rather than leaving a permanently red
test in the suite. Do not restore it until the piped-process boundary can emit
diagnostic evidence for spawn, aliveness, and write failures.

## Required resolution

1. Add an owner-facade diagnostic result for piped spawn and initial write.
2. Prove newline-delimited JSON-RPC initialize against the installed server.
3. Prove `thread/start`, `thread/inject_items`, structured `turn/start`,
   preconditioned `turn/steer`, and `turn/interrupt`.
4. Only then connect `CodexAppServerAdapter` to the live process client.

## Re-verification 2026-08-17 (app-rest lane) — LIVE as a MISSING FEATURE

This doc's own "Required resolution" item 1 asks for a piped-spawn diagnostic
that does not exist in the tree, and the reproducing spec it referenced has been
deleted. There is nothing in `src/app/llm_caret/messaging/cli.spl` to verify
statically, and reproduction needs an installed `codex` CLI, which this host
lacks. Classify as a missing-feature record, not a silent-wrong-result defect.
