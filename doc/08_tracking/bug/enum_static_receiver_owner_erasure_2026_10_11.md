The MethodCall arm in `expr_dispatch.spl` sends empty static-owner hints. Its enum recovery in `method_calls_literals.spl` requires a unique variant leaf. Both `DbType` and `DbValue` in `database/sql/types.spl` declare Integer/Real/Text, so that fallback cannot establish the receiver owner. All six implicated library sources are identical in the actual snapshot, b58 and release226d6963aa9e59a97d0db219553a15394c38650f. Release226d retains the same empty hints and unique-leaf fallback; this fix is not an upstream duplicate.

The repair decodes a type-valued receiver in a separate helper frame. It admits only an Enum declaration in the active module SymbolTable. NamedVar uses the current lexical binding and rejects a conflicting numeric identity. Constructor selection requires the exact provider-qualified variant registry; the existing enum constructor performs payload validation and evaluation. Resolved StaticMethod calls retain normal dispatch. Other associated-method names retain normal dispatch with the known owner, so missing metadata cannot trigger unrelated unique-leaf recovery. Exact payload metadata with a missing exact owner registry is fatal. Runtime variables named DbValue do not qualify. No broad enum matching, bare homonym fallback, payload cast, Any substitution or native trait change is introduced.

Nine compiled-only unit cases include real parse/HIR→MIR construction and a transported MethodCall through actual lower_expr, inspect the emitted exact enum identity, and cover provider-registry inconsistency, resolved associated methods, runtime shadowing, conflicting symbol identity and wrong payloads. Native three-module positive coverage has two imported same-name enums plus a local homonym, shared variant leaves with different payload types, array construction, associated methods and a payload function evaluated exactly once. A separate wrong-payload entry must fail rather than borrowing the other provider's variant type. These tests are UNEXECUTED. Acceptance requires a newly built exact-source producer, own Hello, native object/natural-link/run0 for the positive fixture, normal diagnostic rejection for the negative fixture, and all compiled unit cases with no skips.

This only addresses static enum receiver authority. The separate PostgreSQL bitmap-trait carrier failures, Result tuple unwrap, array remove, numeric parse contracts, and other receiver-method gaps remain open.
