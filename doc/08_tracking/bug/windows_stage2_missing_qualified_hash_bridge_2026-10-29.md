# Windows Stage 2 link misses qualified hash bridge

Status: hash bridge cause and fix verified; full Stage 2 admission remains open.

On 2026-10-29 the fresh LLVM-MinGW bootstrap (`mingw-compiler-rt`) compiled 1,090 modules, then LLD failed with undefined symbol `lib__nogc_sync_mut__src__hash__rt_hash_text` referenced by `libspl_objects.a(mod_1023.o)`. The build did not admit a Stage 2 compiler. The log is `build/bootstrap/mingw-compiler-rt/logs/x86_64-pc-windows-gnu/stage2-native-build.log` in this worktree.

LLVM `nm` shows that `mod_1023.o` defines other functions in `lib__nogc_sync_mut__src__hash`, references the qualified symbol, and does not define it. The source module declares a public `rt_hash_text` body, while runtime archives provide the unqualified `rt_hash_text`. This evidence does not establish why the qualified definition was omitted or whether substituting the runtime symbol would preserve the intended semantics.

A cold-initialized diagnostic remains in startup; its exact inherited environment was not captured, so its handler cannot be established reliably. A separate isolated invocation explicitly setting `SIMPLE_NATIVE_BUILD_RUST=1` compiled the hash module and its dependency using the Rust handler. Its MIR for `rt_hash_text` calls `rt_str_hash`; LLVM `nm` on the resulting hash object shows an undefined `nogc_sync_mut__src__hash__rt_hash_text` and no corresponding definition, while other qualified hash functions are defined. The source-root difference explains the shorter prefix relative to Stage 2. This local reproduction narrows the failure to the module emission path, but does not establish why the definition is omitted.

The focused invocation subsequently failed while compiling a main stub because clang could not start with the diagnostic's environment; the object evidence was emitted before that failure. Its `--emit-object` argument was interpreted as an additional source directory by this Rust handler, so the invocation is evidence about those emitted objects, not a successful object-only build. Do not treat the preserved failed build or the diagnostic seed as an admitted self-hosted compiler.

Cause: runtime declarations deliberately skip locally defined names, but on-demand method dispatch maps `hash` to `rt_hash_text` and used to overwrite the local body's `func_ids` entry with a runtime import. If that dispatch is compiled before the bridge body, `compile_function` sees Import linkage and skips the body. The on-demand paths now preserve an existing entry. The focused `builtin_hash_method_does_not_replace_local_rt_hash_text_body_id` Rust compiler regression passed on the gnullvm/LLVM-MinGW toolchain on 2026-10-29; it checks that this ordering emits the qualified definition in the object. A fresh rebuilt seed subsequently compiled all 1,090 modules and linked Stage 2 successfully with clang; the rerun log is `build/bootstrap/mingw-compiler-rt-rerun-20261029/logs/x86_64-pc-windows-gnu/stage2-native-build.log`. Stage 2 was nevertheless rejected by its frontend admission smoke because it could not resolve the invoking executable; that separate failure remains under investigation.
