# Distributed build artifact export lacks qualified consumer contracts

**Status:** Open feature completion gap; V4 Unix mode policy source drafted, no current pure-Simple runtime PASS.

V3 exports declared `.o`/`.obj` leaves. V4 adds a digest-pinned administrator policy selecting a declared output, destination leaf, kind and fixed local mode (`0644` object/archive, `0755` executable). The source exporter stages accepted bytes and applies/verifies mode before rename on Unix. It checks bounded ELF `ET_EXEC` program headers or Mach-O `MH_EXECUTE` load commands, but does not prove runnable compatibility on the destination OS/architecture. ELF `ET_DYN` (including common PIE executables) is currently rejected. The compiler binary CAS owner admits ELF/Mach-O/COFF magic; the scheduler now adds a bounded regular-ar adapter in `retained_binary_cas.spl`, sharing the digest namespace while rejecting thin archives, malformed member lengths and corrupt bytes. `MZ` executables remain unsupported. `src/app/build/targets/target_executor.spl` does not consume the resulting file. Existing `std.nogc_sync_mut.sffi.fs.file_mode` returns permission bits or -1; `std.nogc_sync_mut.package_sffi.set_permissions` provides Unix chmod, while its Windows runtime branch is a successful no-op. Windows executable export is denied.

**Unblock:** Qualify executable platform/architecture and PIE forms before claiming a runnable output. Qualify regular archive retention and export on the deployed runtime. Wire the target executor to the exact accepted object or archive and prove a real linked consumer changes output when only its producer changes. Test stale or failed attempts, corrupt CAS, traversal, destination replacement, permission bits and crash windows on a deployed pure-Simple runtime.
