# Native inventory decimal conversion tests raw integers as Option values

Status: OPEN — source workaround prepared; native producer correction and actual replacement-object qualification remain pending.

The actual terminal utility reads a genuine canonical inventory with `generation=3`. Its compiled decoder calls the retained C39 `rt_string_to_int_lenient` provider, which returns raw `strtoll` integer 3. The compiled `to_i64() ?? -1` expression then tests `rt_is_some(3)` as an Option tag, receives false, and selects -1. Actual disassembly at offsets 0x8d70/0x8d78 and the genuine inventory establish the mismatch. This is a compiler/provider representation fault; changing the inventory or fabricating metadata is not a repair.

The workaround parses the existing inventory generation/count/size wire fields directly with an explicit `(valid, value)` result. Accepted grammar is `0|[1-9][0-9]*`, capped at INT64_MAX. Each multiply/add is preceded by the overflow threshold check. Empty, signed, whitespace, nondecimal, leading-zero and overflow inputs fail closed. Count comparison avoids overflowing `count + 3`. Existing row validation and canonical re-encoding remain authoritative; the schema and genuine metadata are unchanged. The previous decoder also refused these malformed/noncanonical inputs; some now receive an earlier field-invalid diagnostic.

Public decoder tests cover generation/size zero, reserved native small words, INT64_MAX, malformed and overflowing spellings in all three numeric fields, count mismatch, malformed rows, unsafe paths and noncanonical trailing newlines. The retained-gen13 interpreter executed all three cases successfully under the canonical 3 GiB / 120 second guard: raw status 0, quiescent=1, peak RSS 390608 KiB, no observer errors, and identical source/runtime hashes before and after. Evidence: `/Users/ormastes/wt/release-phase2-review/build/verify/inventory-decimal-native-regression-20261026-01`. Interpreter execution alone does not qualify native ABI behavior.

No P2, Rust or runtime rebuild is authorized by this workaround. A native changed-module compile/relink must use cloned frozen utility inputs, real source and runtime hash joins, and an actual symbol/dependency audit before reusing unchanged objects. Snapshot path differences can alter native symbol identities; no aliases, forged cache hits or edited manifests may substitute for that audit. The existing active/frozen utility inputs remain untouched and full native P3 remains pending.
