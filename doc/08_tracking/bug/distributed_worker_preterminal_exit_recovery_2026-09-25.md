# Distributed worker cannot recover a pre-observation exit code

**Status:** Source fix drafted; runtime verification open. **Owner:** Simple Linux OCI provider and distributed build worker.

`src/app/build/scheduler/worker_execute.spl` records the compiler exit code after `provider.wait` returns. A crash between native process exit and that durable observation formerly left a permanent launch binding and no publishable result: the OCI provider reconstructed terminal state with `exit_code: -1`. The source fix extends the identity-bound Podman/Docker inspect response with `.State.ExitCode`. `--status` may persist a missing observation only for the exact native `exited` container with a canonical `0..255` code. It rejects changed identity, running/dead/stopped state, malformed code, and disagreement with an existing durable observation. The crash path has not passed a current pure-Simple Linux worker test.

**Unblock:** Run scripted Podman and Docker fixtures for crash before observation, unknown exit, wrong native ID, running state and terminal success/failure. Run the worker recovery scenario through a current pure-Simple binary on Linux and show zero duplicate create/start calls and one fenced parent commit. Do not release capacity from an unknown exit. Official inspect fields: [Podman container inspect](https://docs.podman.io/en/latest/markdown/podman-container-inspect.1.html), [Docker inspect](https://docs.docker.com/reference/cli/docker/inspect/) and Docker's [container state type](https://pkg.go.dev/github.com/docker/engine/api/types#ContainerState).
