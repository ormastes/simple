# rti007: bare `Result` return gives E-RTI-007 / E-RTI-002 in linker modules (2026-10-31)

## Root bug
A function declared `-> Result:` (no type arguments) has an `Any` payload. The
return-type-interface (RTI) builder refuses to emit an interface row for it
(`E-RTI-007: declared return is Any; not representable in an interface row`,
see doc/05_design/compiler/types/return_type_interface_design.md). Callers in the
same module then fail MIR with `E-RTI-007` and, for sibling callees whose rows
were never produced, `E-RTI-002: qualified callee ... has no exact return-type row`.
Same family as bare_result_return_type_any_payload_2026-10-24.

Affected modules (stage3 build, rev8): linker_wrapper_helpers (1), native_linking (114 RTI-007, ~107 RTI-002), shared_linking (1).

## Workaround sites (all `-> Result` -> `-> Result<text, text>`, payload is the output path / "off,size" text, error is text)
- src/compiler/70.backend/linker/linker_wrapper_helpers.spl: `detect_self_contained`
- src/compiler/70.backend/linker/_LinkerWrapper/shared_linking.spl: `_link_native_mingw`
- src/compiler/70.backend/linker/_LinkerWrapper/native_linking.spl: `internal_link_native`, `internal_link_native_with_operations`

## Removal condition
Remove once the compiler infers/accepts bare `Result` (or a root fix is in the stage2 used for bootstrapping). Behaviour is unchanged: all `Ok(...)`/`Err(...)` payloads are already text.
