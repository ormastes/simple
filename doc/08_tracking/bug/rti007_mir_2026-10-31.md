# rti007: bare `Result` return gives E-RTI-007 / E-RTI-002 in linker modules (2026-10-31)

## Root bug
A function declared `-> Result:` (no type arguments) has an `Any` payload. The
return-type-interface (RTI) builder refuses to emit an interface row for it
(`E-RTI-007: declared return is Any; not representable in an interface row`,
see doc/05_design/compiler/types/return_type_interface_design.md). Callers in the
same module then fail MIR with `E-RTI-007` and, for sibling callees whose rows
were never produced, `E-RTI-002: qualified callee ... has no exact return-type row`.
Same family as bare_result_return_type_any_payload_2026-10-24.

Affected modules (stage3 build, rev8): linker_wrapper_helpers (1), native_linking (114 RTI-007, ~107 RTI-002), shared_linking (1).

## Workaround sites (all `-> Result` -> `-> Result<text, text>`, payload is the output path / "off,size" text, error is text)
- src/compiler/70.backend/linker/linker_wrapper_helpers.spl: `detect_self_contained`
- src/compiler/70.backend/linker/_LinkerWrapper/shared_linking.spl: `_link_native_mingw`
- src/compiler/70.backend/linker/_LinkerWrapper/native_linking.spl: `internal_link_native`, `internal_link_native_with_operations`

## Removal condition
Remove once the compiler infers/accepts bare `Result` (or a root fix is in the stage2 used for bootstrapping). Behaviour is unchanged: all `Ok(...)`/`Err(...)` payloads are already text.

## Re-verification at release/1.0.0 (2026-11-01, label: seed)

Status: FIXED IN SOURCE at release/1.0.0 (933a0979878 "represent Any in return type
interfaces", with 1c8132a5952 / b6d71af144b). OPEN only for the frozen stage2
(`C:/dev/p3new/stage2.exe`, ef0681fc0e1); the tagged sites stay until the stage2 refresh.

Fixture (no workaround; bare `-> Result` callee plus a same-module bare-`Result` caller,
the linker shape):

```simple
fn detect(path: text) -> Result:
    if path == "":
        return Err("empty")
    Ok(path)

fn link(path: text) -> Result:
    val r = detect(path)
    match r:
        case Ok(p): Ok(p)
        case Err(e): Err(e)
```

Run: the Rust seed (`src/compiler_rust/target/bootstrap/simple.exe run`) interpreting the
current pure-Simple frontend + HIR + `return_type_interface_v1.spl`
(`parse_full_frontend` -> `HirLowering.lower_module` -> `rti_rows_from_hir_v1`). The seed
cannot parse the release stdlib as-is
(`windows_tracked_seed_cannot_parse_release_stdlib_2026-10-10.md`), so the run used a
scratch copy of `src/` with block-form `@when(os=...)` flattened to the Windows branch and
`rt_xxh3_128_text` routed to its pure-Simple fallback; no compiler file was altered.

Result: both callees publish `0|decided|result(b:any,b:any)`; no `E-RTI-007`, so the
dependent `E-RTI-002` (missing sibling row) cannot arise. Already pinned by
`test/01_unit/compiler/hir/return_type_interface_any_rows_spec.spl`
("publishes an opaque Result<any, any> row for a bare `-> Result`").

Not run: a MIR-lowering probe of the same fixture crashed inside the seed's Cranelift JIT
(`compiled_blob.rs:58` `TryFromIntError(PosOverflow)`; seed tooling limit, not this bug),
and further runs were held for phase-3 memory. MIR reads the same row through
`ReturnTypeInterface.callee_return`, so the row evidence covers the root cause. The spec
runner itself cannot run under the seed on Windows (`Windows file ABI: integer ABI
argument required`), so the spec is UNRUN here.

Revert-ready: yes, once the bootstrap stage2 is rebuilt from a revision containing
933a0979878.
