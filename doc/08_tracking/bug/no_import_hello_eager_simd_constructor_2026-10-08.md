# No-import Hello retains eager SIMD initialization

Status: focused native C qualification PASS; source review/landing and whole-runtime Simple image qualification pending. Windows and race-detector execution unrun.

Actual qualified cf89 Hello ELF evidence lives at `build/review/item5-hello-image-audit-20261008/REPORT.md`: LLVM26992bytes and Cranelift26944bytes both retain simd_case_init in .init_array, which calls simd_text_init and keeps scalar/SSE2/AVX2 dispatch targets. This happens even though runtime_simd_case's three public APIs are disabled unless SPL_SIMD_TEXT_CASE_PROVIDER. The default APIs belong to runtime_native.c and are unchanged by this patch. No AVX512/compiler/GPU/Office body was identified in these Hello images.

The draft removes the case constructor and calls its initializer at the existing opt-in case API boundary. Base UTF8 initialization and case upgrades use separate atomic0/1/2 once states; the winning thread initializes slots before release-publication and readers acquire before using them. The case owner waits for base publication first, so there is no cycle. UTF8 readers access only UTF8 fields; case readers access their three fields only after the case guard. The g_simd_text layout and existing kernels/CPUID+XCR0 guards remain unchanged. No new cross-TU dependency is added. String reserved-field caching is not repaired here; tests give each worker an owned string.

A separate search TU has its own existing lazy table and is outside this constructor repair. Direct external access to the internal dispatch table without calling its initialization owner is not newly supported. The profiler constructor is deliberately unchanged: it implements opt-in startup sampling via SIMPLE_PROF_SAMPLE_FILE, so removing it would change an independent effect contract. Aspect-pack startup is also unchanged.

## Proposed finite native qualification

After source review, compile immutable baseline/candidate C owner snapshots in a private native directory, no Cargo or Simple compiler. Use the same target, optimization, function/data-sections and link --gc-sections for both. Link a no-demand Hello from simd_lazy_init_selfcheck.c with SIMPLE_SIMD_NO_DEMAND and both production TUs explicitly included: inspect ELF constructors, retained symbols and load sections before/after, without stripping either artifact. This is an owner-isolation experiment, not a new full Simple Hello qualification.

Run the authored first-use selfcheck once per meaningful default/opt-in-case/forced-no-AVX2 configuration. It observes the table empty before first use, starts16 threads together, validates ASCII lengths0..129, astral tails, codepoint counts and an invalid byte at every position; opt-in builds exercise both case conversions and ASCII detection. Preserve exact outputs/exits/source and binary hashes, timeout/RSS receipts. Add a supported race-detector configuration if available; a parallel PASS alone does not prove the absence of C data races. Inspect actual AVX2 code/call selection separately from macro enablement. No full runtime rebuild until these checks and source review pass.

Measure identical warmed public-call workload p50/p95 and high-water RSS before/after because the acquire guard replaces an unsynchronized load; no performance-equivalence claim is made without those observations. The isolated no-demand ELF improvement cannot substitute for a future whole-runtime/candidate Hello image check with matched captured link inputs.
