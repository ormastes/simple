# Bootstrap typed Dict membership binds a foreign method

## Observed failure

The admitted Linux Stage 2 executable for frozen `5da86869df06`, SHA256
`a45ede92cdbb972d26369ccaa6c42960ec2fca64e560e106ec7a0ca2c8e3747b`,
was generated by the Rust bootstrap compiler. Disassembly supplied by the
independent bootstrap review shows `register_imported_symbol_inner` calling
`AdaptiveMap.contains_key` at `0x6a07c5` and `0x6a0fb4`. The source receivers
are `HirLowering.imported_enums` and `imported_traits`, aliases of Dict, at
`module_import_registration.spl:499` and `:518`. Kernel crash records map
`0xc7c7ac` to `AdaptiveMap.promote_if_useful+188`; the invalid address is
`0x2000000010`. The foreign method writes beyond the 32-byte runtime Dict
header before the fault. There is no core dump.

## Cause and change

The alias resolver also rewrote a registered alias to its textual family
before looking up its complete target TypeId. For an alias of `Dict<K, V>`,
that discarded K/V and resolved the bare family as Any. Registered alias
bindings now take precedence over that textual fallback.

The bootstrap MIR method lowerer can identify the structural `HirType::Dict`
through the receiver or its recovered field type. Without an intrinsic
membership arm, it qualifies the call as `Dict.contains_key`. The codegen
safe builtin path protects bare method names, while qualified-name recovery
can discard the qualifier and bind a same-named nominal method.

Typed Dict `has`, `has_key`, `contains`, and `contains_key` now lower directly
to the existing `rt_contains` ABI. Receiver and key are evaluated once, and the
existing RuntimeValue argument boxer preserves integer, unsigned, float, and
boolean key tags. Alias spellings and specific nominal classes are not used
to choose the intrinsic. Nominal receiver methods retain their existing path.

The JIT regression also exposed the literal write path leaving boolean keys
unboxed. Owned-process debugger evidence showed an integer key written and
queried as `0x8`, while `true` was written as `0x1` and queried as the correct
tagged boolean `0xb`. Literal keys now use the same general RuntimeValue boxer
as membership reads. The original integer and boolean result assertions are
retained.

Boolean and float literal **values** still use the pre-existing integer-only
write boxer. Their value representation remains a separate unresolved gap;
this membership-key change does not claim to fix value boxing.

Other existing key ABI gaps remain: typed Dict `.set`/`.insert` box integer
keys only, and Dict indexing boxes integer/boolean keys but not float keys.
This change therefore does not claim a general scalar-key Dict roundtrip.

## Regression evidence

Focused bootstrap compiler tests cover aliases and alias chains retaining
their Dict key/value types, alias-typed class fields for all four
membership spellings, a nominal class exposing the same methods, scalar key
boxing, actual JIT predicate results for present/missing integer and boolean
keys, and actual AOT object relocations from the Dict probe. The object must
reference `rt_contains` and must not reference the foreign nominal method.
Test execution status and hashes are recorded separately in the isolated
`seed-dict-dispatch-fix-240d-20260929` recovery evidence directory.

The independent pure-Simple compiler alias-target metadata gap is a separate
issue. This change does not claim to resolve that gap or to admit a new
bootstrap executable.
