# Full native link exceeds the shell's single-argument limit

Status: FIX CANDIDATE; native transport regression did not reach linking.

Current final native linking sends all object paths to `process_run`: the direct Unix linker executes through `mold.execute_linker`, and the hosted C-driver branches execute in `_LinkerWrapper/native_linking.spl`. The POSIX `io_runtime.process_run` owner reaches `rt_process_run_array` in `runtime_native.c`, which quotes and concatenates the complete argv into one `popen` command. There is no response file in these paths. The archive-output option has a separate unbounded invocation and is outside this repair.

The Linux host reports PAGE_SIZE=4096 and ARG_MAX=2097152. The relevant failure boundary is Linux MAX_ARG_STRLEN, 32 pages (131072 bytes here), because the shell receives the entire command as one `-c` argument. ARG_MAX is the aggregate argv/environment limit and does not rescue an oversized single argument. Hundreds of long private object paths can cross this boundary even when the total argv remains below ARG_MAX. The 1293 HIR modules include objectless facades, so final qualification must record actual object membership and command byte count rather than equate HIR count with object count.

The narrow fix routes the direct linker and all three hosted C-driver execution branches through the existing canonical `process_run_bounded` facade, with the original executable and argv, timeout 0 and a 67108864-byte capture bound. Its POSIX runtime owner uses `execvp(cmd, argv)` directly. Zero adds no deadline, linker stdin is `/dev/null`, tool identity checks and recorded argv remain unchanged, and the complete object inventory is preserved. Captures above the bound retain head and tail with an explicit `[output truncated: N bytes omitted]` marker; full diagnostic retention is guaranteed only within the bound. No response-file grammar or managed-tool argument policy is weakened.
