# Windows terminal raw-byte preservation failure (OPEN)

Actual final artifact-only run 38203727926 linked successfully and exited zero with empty stderr. The real Simple entry constructed the 20-byte UTF-8 value `Windows é terminal\n`, passed it through the SOSIX terminal facade and the Rust-owned string accessors. The provider returned 20, but redirected stdout contained 21 bytes ending CRLF. PE SHA256: 56cab628b0023d9afe59923da0e07865fa8719a3e8a6e9d26edeeadef75c59ff.

The retained adapter copies frozen82 `runtime_core_io_exports.c`'s `rt_term_write` body exactly. Its `fwrite(..., stdout)` runs in Windows CRT text mode. This conflicts with the SOSIX facade's raw-text contract and counted byte return, so it is a canonical provider issue. No exact-output assertion was relaxed.

Proposed repair: preserve POSIX fwrite. On Windows, serialize through the existing C stdout FILE owner, flush previously queued bytes while holding its lock, then use the actual stdout WinAPI handle for counted unmodified writes. Do not mutate process-wide CRT text/binary mode or install a second buffering registry. The candidate uses documented _fflush_nolock inside the FILE lock to avoid recursive-lock assumptions; actual native console/error behavior and the fixtures remain unexecuted. Rust std::io buffering is a distinct owner; mixed-owner ordering requires an explicit contract and is not qualified by this proposal.

Required prevention cases: redirected UTF-8, embedded NUL, LF, CRLF, multiple newlines and empty input; byte count compared to actual pipe bytes; mixed queued C fwrite then terminal write with pre-exit pipe observation; error/short-write behavior; concurrent C stdout ordering without global mode changes. Use the real Rust string constructors/accessors and SOSIX caller, no direct application runtime access. Platform guards must retain Linux/macOS/BSD behavior; simpleOS capability stays explicit.

The prior tiny source compile and artifact-link feature caps are exhausted. This document and candidate are source-only, unexecuted. No fourth tiny compile/link or new runtime rebuild is authorized here. Typed/lossy decoder9df remains uncompiled. Original Stage2 namespace and full compiler admission remain open.

Primary source contracts: Microsoft [_fflush_nolock](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/fflush-nolock?view=msvc-170) permits flushing inside an existing FILE lock; [_get_osfhandle](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/get-osfhandle?view=msvc-170) returns a borrowed handle and invalid descriptors require admission guards. Candidate uses `_fileno(stdout)` rather than unrelated GetStdHandle, preserves freopen redirection, guards negative descriptor and -1/-2 handles, and never closes the handle.
