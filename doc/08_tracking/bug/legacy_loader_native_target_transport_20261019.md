The old API dropped target at every boundary: loader hash, watcher config/request, daemon field map, SMF compile helper and persisted manifest used after source changes. The scoped repair transports the explicit value to normalized CompileOptions and validates actual generated source/options/dependency receipts before acceptance and watcher manifest publication. Target fields containing line breaks or surrounding whitespace are refused at writer/submission/compile ingress because existing key=value wire cannot carry them exactly. Target recognition stays with the backend.

The validated loader now loads/regenerates the actual derived cached SMF path, not the source file. Explicit target with a preexisting source/cached/generated loaded-record key refuses before reuse because this path cache retains no target authority. Repeating the same target is also refused; use a fresh loader. No implicit unload/remap or lifetime API change.
