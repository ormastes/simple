# Source-view feature knowledge

The public application composition is `app.source_view.service`: source_open_result_v1 and source_open_bound_result_v1 return SourceOpenResultV1(payload,is_error), with source-contract JSON and no MCP/HTTP envelope. Both protocol adapters consume that owner. Common/source carries contracts; nogc_sync_mut/source carries pure projection/session policy; compiler/tools/source_outline_v1 adapts canonical native token syntax.

Default Simple outline, focused syntax and raw pages are authored, not runtime-admitted. Do not advertise installed capabilities until actual process evidence exists. The token parser is not external Tree-sitter and never claims semantic resolution. Source/query hashes bind continuations, exact segments remain distinct from numbered display, and noncontiguous import groups use range sets.

Only the authenticated session host supplies agent/workspace authority and commits first-help. Body IDs, transport identity and workdir inference are not authentication. The service assumes its host maps the configured workspace to actual canonical root; ordinary MCP declares its isolation limitation.

Read the architecture, guide, inline-body bug and SDN/SHS provider-gap record before extending this lane. The full selected acceptance matrix, cache/debug/semantic integration, runtime, concurrency, hostile-path and performance gates remain open.

Bound service calls carry the authenticated owner's explicit canonical `workspace_root`; they do not reread process cwd after authorization. The unbound local MCP path captures cwd once. Descriptor-relative protection against malicious directory replacement remains a separate open IO requirement.
