# Simple staged XRay integration expert

Read doc/03_plan/compiler/aspect_dynload/simple_xray_staged_implementation_plan_2026-11-03.md and its parallel delivery plan. Selected order: Linux LLVM, Linux Simple-owned, then Windows Simple-owned. One backend-neutral V1 contract, resident code/maps/providers, raw edges baseline, optional independently qualified paired spans/live patching. Windows tracing remains off during Linux stages; SimpleOS compiler-rt XRay remains off.

Compiler semantic selection owns visibility/type/owner information; backend emission owns physical sites; runtime owns bounded generation admission and collector lifetime; SOSIX host leaves own effects. Common code must not import private OS/backend APIs. A source-only adapter, serial model or proposed ABI is not native qualification. Consume the feature-plus-layer knowledge receipt and preserve artifact provenance. Optional HIR/host semantics remain pending user clarification in the artifact-information design.

PR2 (2026-11-06): the V1 runtime contract lives in `src/lib/common/trace/` (pure, `std.common.*` imports only) plus the stage-2 ring `src/lib/nogc_sync_mut/trace/observer_native_channel_v1.spl` (lockless CAS/fetch-add). The only compile-time touch is `xray_observer_request_check` in `driver_xray_policy.spl`, called once from `CompileContext.create`; never add per-entry-point gates. Trap: the Nov-5 seed interpreter missed `case 1:` on a `u64` scrutinee (fixed in `e36e4e9dfa4`); run trace specs with a seed built after that commit. `rt_par_atomic_sub_i64` is C-only (seed has no backing) — use `rt_par_atomic_add_i64(addr, -1)`.

PR3 (2026-11-06): LLVM attrs live in `70.backend/backend/_MirToLlvm/core_codegen.spl` (`llvm_xray_function_attrs`, recorded per module in `fn_xray_mode`/`xray_module_on`). `xray_mode 2` -> `"function-instrument"="xray-always"`; mode 1 is a codegen error (LLVM has no attr that keeps exit sleds but drops tail sleds; `xray-skip-exit` is never emitted); non-Linux `target_os` and the bootstrap translate path are codegen errors too; never-listed fns get `xray-never` only when the module has a sled fn; no `xray-instruction-threshold`. A sled fn drops the `is_small` alwaysinline (forced inlining only; the -O2 inliner may still inline it, plan §5.4 physical-function rule). A `MirToLlvm` cannot translate two modules (string-builder handle is finished), so per-translator state is per module. Off = byte-identical IR. `trace.instrumentation: off|dynamic` is read from cwd `simple.sdn` by `simple compile` BEFORE CompileOptions is built (so cache identities see it); `compile_options_hash_compute` appends `xray-v1` last and only when on (LiveKey pos 49 `opts_xray`, review `src/verification/cache_protocol/xray_source_review_2026-11-06.txt`). Evidence: `llc` 23.1 on the emitted IR gives `xray_instr_map`/`xray_fn_idx` per sled fn on x86_64 and aarch64, none for off. Trap: a spec module named `xray.*` makes every `contains("xray")` off-check false-fail.

PR4 (2026-11-06): stage-1 Linux LLVM runtime adapter. Control plane `src/lib/nogc_sync_mut/trace/xray_llvm_adapter_v1.spl` (`XrayLlvmAdapterV1` over the `XrayLlvmLeafV1` port: prepare validates + translates every selected site to an LLVM id in one function and patches nothing; start publishes the channel arena + handler, then patches only selected ids; on failure it closes admission (`trace_native_channel_close_v1`) and rolls back; `ONGOING` is retried 8x; a FAILED/INVALID id is never recorded as patched (compiler-rt's mprotect failure writes no byte); a failed rollback or stop is `Faulted`, never off, and `recover` is the only exit). Host leaf `xray_llvm_host_leaf_v1.spl` binds the C boundary `src/runtime/xray/xray_llvm_adapter_linux.c` (`simple_xray_llvm_*`, deliberately not `rt_*`, not in any runtime source list — linked only into `--xray` binaries). Its handler shim is the C twin of `trace_native_channel_record_words_v1` (same arena layout and gate CAS; keep them in lockstep); ids are bounded to 24 bits (compiler-rt packs object<<24, DSO ids are dropped); build it WITHOUT `-fxray-instrument`, with `-mgeneral-regs-only` and, on aarch64, `-mno-outline-atomics` (otherwise every atomic becomes a `bl __aarch64_cas8_*`). The pinned clang-23 aarch64 `__xray_FunctionEntry/Exit` saves x0-x8, x30, q0-q7 only. Evidence: `scripts/check/check-xray-llvm-adapter-e2e.shs` (native host run through `libclang_rt.xray`, `XRAY_OPTIONS=patch_premain=false`, `-Wl,--wrap=mprotect` failure injection works because `xray_interface.cpp.o` has `U mprotect`; other arch object-only — no cross compiler-rt here). Traps: `__xray_set_handler` returns 0 unless `-fxray-instrument` is on the LINK line; tiny C functions get no sleds without `xray-always`, so the fixture is `.ll` with PR3's exact attributes. Not done: the driver link step adding `-fxray-instrument` + the adapter object for `simple compile --xray --native`, and a Simple-compiled binary through the facade (no deployed pure-Simple compiler).

PR5 (2026-11-06): pure-Simple native AArch64 sleds. `70.backend/backend/native/xray_sled_emit.spl` runs after `regalloc_module_aarch64` and before encoding (wired in `mod.spl compile_native_aarch64`, only when some MIR function has `xray_mode > 0` — off takes the untouched old path): pseudo-op `A64_OP_XRAY_SLED` (141) as the first instruction (entry) and before every `RET` (exit); the selector emits no tail calls, so no tail sled. The encoder emits the V1 contract template `trace_native_off_template_v1` (Arm64Branch26, plan §10.3: `B +32` / stp x16,x17 / stp x0,x30 / movz+movk w0=site id / `bl` / ldp / ldp) with an `R_AARCH64_CALL26` to `__simple_xray_trampoline_v1` at +20 — NOT LLVM's `B #32 + 7xNOP` sled, because the landed validator checks these exact bytes and llvm-xray never reads `.simple_xray_map` anyway. Sleds are located after encoding from those relocations (count and bytes must match, else panic). `.simple_xray_map` format v1 is owned by `src/lib/common/trace/xray_native_map_format_v1.spl` (encode + strict decode, x86-64 isa reserved for PR6 → UnsupportedTarget); it is a new `ElfSectionKind.XrayMap` (SHF_ALLOC|SHF_LINK_ORDER, link .text, no section symbol, name added to shstrtab only when present). Site addresses are `.text`-relative; `text_base` relocation, the root symbol, init-array registration and the resident trampoline are NOT done. x86-64/RISC-V/Mach-O native with `--xray` panic `XRAY-E-UNSUPPORTED-TARGET` (fail closed). Patcher: `src/lib/nogc_sync_mut/trace/xray_native_sled_leaf_v1.spl` is a second `XrayLlvmLeafV1` under `XrayLlvmAdapterV1.create_for_backend(_, Simple)` — no second state machine; admission = `trace_native_map_validate_v1`; switches only the first word (B+32 ↔ NOP) via `XrayCodePatchPortV1` begin(RX→RW)/store_u32/end(RW→RX + I-cache)/close; `end` always runs, a failed `end` marks the page dirty so recover cannot report off over a writable page. Host port `src/os/sosix/host/code_patch_adapter.spl` = `rt_mprotect` + `rt_ptr_*_i32`; the C runtime's `rt_mprotect(RX)` already runs `__builtin___clear_cache`. Trap: the Rust seed's interpreter `rt_mprotect` returns -1 for PROT_EXEC on aarch64 Linux, so the patcher cannot own a real RX page in-process under the seed; `scripts/check/check-xray-native-aarch64-e2e.shs` records the Simple patcher's ops and a C harness replays them on a real page (plus objdump/readelf object checks and a negative control). Off identity without a deployed compiler: `check-xray-static-off-identity.shs --native-emitter-baseline <base worktree> --simple <seed>` (4 objects byte-identical). Under the seed interpreter the native aarch64 path fails on a cross-function call fixture ("cannot convert object to int", same on the base) — fixtures avoid calls.

PR5b (2026-11-06): in-process native AArch64 tracing. Resident runtime `src/runtime/xray/xray_native_runtime_aarch64.c` (linked only into `--xray` native builds by `80.driver/driver_xray_link.spl`): asm `__simple_xray_trampoline_v1` saves x1-x15, x18, x29/x30, NZCV, FPCR, FPSR, q0-q31 (Simple twin `std.common.trace.xray_native_trampoline_aarch64_v1`, compared word for word by `check-xray-native-inprocess-e2e.shs`), handler resolves (sled return = x30, site id = w0) through a registered module table and calls the one C producer `xray_channel_producer_v1.h` (shared with PR4). Entry points are PROTECTED: sleds BL directly (no PLT), each `--xray` module owns its runtime copy. Map base: `.rela.simple_xray_map` PREL64 at header +36 → runtime text = field address + signed(field). Registration is Simple-driven, NOT init-array (deliberate A.5 deviation, recorded in design C.6): `nogc_sync_mut/trace/xray_native_module_v1.spl` finds the map via /proc/self/maps + the ELF section table, builds the manifest/image for leaf admission and registers through dlsym (`XrayNativeDlModuleV1`, also the `XrayNativeDispatchPortV1` binding; `install` publishes the arena before any patch). `XrayLlvmLeafV1.sled_kind()` — prepare refuses a leaf whose sled kind is not the adapter backend. Selection: aspect ext `simple.trace/observer-v1.pointcuts` (canonical function names) → `xray_native_selection_v1`. Seed fix: interpreter `rt_mprotect` grants PROT_EXEC on aarch64 Linux with DC CVAU/IC IVAU sync (fail closed PROT_NONE), so the patcher owns real RX pages in-process (needs a seed built from PR5b). Traps: `XrayLlvmAdapterV1` is a STRUCT — passing it to a helper copies it, so thread it back or the next prepare reuses incarnation 1 and the C install rejects the arena generation; seed `run` returns the TAGGED word (value*8) for `?` on `Option<i64>` (bug `seed_option_question_mark_returns_tagged_int_2026-11-06.md`) — use match/sentinels in hot control-plane parsers; `layout_solver` passed the `SymbolId` struct as an i64 (any 2-function module crashed "cannot convert object to int") — fixed to `.id`.
PR6 (2026-11-06): native x86-64 SysV. 13-byte V1 `X64Rel32` sled (`EB 0B`|`66 90`, `E8 rel32` PLT32 at +3, `EB 04`, imm32 id), 2-aligned by a `90` pad; map isa 1 / abi 2, `R_X86_64_PC64` text_base; leaf switches one aligned u16 (`store_u16`/`load_u16` on the port; load composes two `rt_ptr_read_u8` — there is no `rt_ptr_read_i16` in every lane). Runtime `xray_native_runtime_x86_64.c` (asm trampoline, bounded SysV remedy) + shared `xray_native_registry_v1.h` (static inline bodies; ISA TU defines the exported entry points via `SIMPLE_XRAY_NATIVE_ENTRY_POINTS_V1`). Cross-build needs `-ffreestanding` (no x86 sysroot on aarch64 hosts). Check: `check-xray-native-x86-64-objects.shs`. Trap: the refactored AArch64 register function contains a coincidental `b +0x20` word — count sleds as `B +32` followed by `stp x16, x17`, never by the word alone. Execution of patched x86-64 code needs an x86-64 host.
PR5b limits (review): only dlopen'd modules have a registration binding (no dlopen(NULL) in the runtime ABI; the main executable waits on the in-binary control plane); one `.simple_xray_map` per module (multi-object --xray links concatenate maps and are rejected InvalidMap); register() rejects a map whose sled BLs do not target THIS runtime instance's trampoline; the seed refuses PROT_EXEC without PROT_READ on aarch64 (DC CVAU needs read).
