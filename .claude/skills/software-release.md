# General Protected Software Release

Use `doc/07_guide/infra/software_release.md`. Preserve isolated session authoring with one branch and worktree, one canonical version manifest, reviewed exact bug-fix backports for beta/maintenance lines, immutable build-once candidates, and exact signed annotated tag promotion without rebuild. Before every candidate attempt, after each bootstrap-failure repair, and before release admission, compare exact `main` and `release/X.Y` snapshots read-only. Every reviewed `kind=fix` must cross through an isolated exact backport or forward-port with stable patch-ID equivalence, renewed evidence, graph-verified divergence receipt, and protected CAS integration before candidate admission; adapted patches fail closed until a separately reviewed equivalence protocol exists and bug fixes have no waiver. Only a `non_fix` release-specific compatibility classification with reason, owner, and expiry may remain release-only. GitHub forbids a PR author `APPROVED` review, so protected integration uses the required `SPipe Self Review Admission` status and never claims provider/independent approval. Ordinary code/text is default allow absent operator deny/constrain; scopes are `code`, `text`, exact `file`, immediate `directory_files`, and recursive `directory_recursive`. On rejection/invalidation, follow the reason: drift/expiry needs fresh exact-head review+dispatch; deny needs external policy-owner action or an independent route; uncovered scope needs a smaller diff/new constraint; unsafe or secret material must be removed and credentials rotated. Never reuse a stale check or weaken candidate/release/publication authority. Generic Actions App trust risk is accepted, not independent security. Keep `spipe-review-admission/1` candidate and environment approval separate. `main` remains the independent development trunk. Rollback redeploys; withdrawal preserves identity. Ask before external push/publication.
