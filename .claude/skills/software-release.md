# General Protected Software Release

Use `doc/07_guide/infra/software_release.md`. Preserve isolated session authoring with one branch and worktree, one canonical version manifest, reviewed exact bug-fix backports for beta/maintenance lines, immutable build-once candidates, and exact signed annotated tag promotion without rebuild. Before every candidate attempt, after each bootstrap-failure repair, and before release admission, compare exact `main` and `release/X.Y` snapshots read-only. Every reviewed `kind=fix` must cross through an isolated exact backport or forward-port with stable patch-ID equivalence, renewed evidence, graph-verified divergence receipt, and protected CAS integration before candidate admission; adapted patches fail closed until a separately reviewed equivalence protocol exists and bug fixes have no waiver. Only a `non_fix` release-specific compatibility classification with reason, owner, and expiry may remain release-only. Prefer a closed commit-bound high-capability/high-effort `spipe-review-admission/1` receipt; owner fallback is allowed only for unavailable verification with exact reason `no eligible independent reviewer`, exact PR/session/server-head/check bindings, expiry, audit digest, and unavailability receipt. Local dispatch emits only a blocked server-resolved request plan; only a future external signed broker App may provide the receipt and status. Live apply is unsupported and existing environment reviewers remain. `main` remains the append-only development trunk and never tracks, is repointed onto, or absorbs the whole release line. Rollback redeploys; withdrawal preserves published identity. Require verified focused and whole-suite evidence. Ask before external push or publication; missing authority remains blocked.
