# General Protected Software Release

Use `doc/07_guide/infra/software_release.md`. Preserve isolated session authoring with one branch and worktree, one canonical version manifest, reviewed exact bug-fix backports for beta/maintenance lines, immutable build-once candidates, and exact signed annotated tag promotion without rebuild. Before every candidate attempt, after each bootstrap-failure repair, and before release admission, compare exact `main` and `release/X.Y` snapshots read-only. Every reviewed `kind=fix` must cross through an isolated exact backport or forward-port with stable patch-ID equivalence, renewed evidence, graph-verified divergence receipt, and protected CAS integration before candidate admission; adapted patches fail closed until a separately reviewed equivalence protocol exists and bug fixes have no waiver. Only a `non_fix` release-specific compatibility classification with reason, owner, and expiry may remain release-only. Protected PR integration uses `SPipe Self Review Admission` instead of provider Approve: explicit self-attested PASS is user-authorized, not independent authentication; resolve and re-resolve protected target/ruleset, head, base, merge-base, and diff; deny exact operator records, aliases, secrets, symlinks, submodules, non-UTF-8, and traversal; expire the check after ten minutes. Generic Actions App trust risk is accepted, not independent security. Keep `spipe-review-admission/1` candidate and environment approval separate. `main` remains independent. Rollback redeploys; withdrawal preserves identity. Ask before external push/publication.
