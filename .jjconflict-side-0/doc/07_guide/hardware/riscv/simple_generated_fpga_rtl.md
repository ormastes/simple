# Simple-Generated RV32/RV64 FPGA RTL

Date: 2026-07-18
Status: **contract-not-ready**

This guide is the operator path for the selected compiler-first RV32/RV64
Linux FPGA work. It deliberately distinguishes materialized contract files from
a CPU generated by the Simple compiler.

## Current truth

The canonical candidate now compiles the protected RV32 and RV64IMAC entries,
wraps both on the same WB64 SoC bus, and connects that bus to KV260 PS DDR
through one shared AXI-HP bridge. Both generation scripts reject copied,
handwritten, empty, or missing CPU RTL. This is still not acceptance evidence:
the fresh Stage 4 compiler, actual entry outputs, GHDL/formal, Linux login/`ls`,
and FPGA proof remain unqualified.

The older bundle generator still materializes `contract-not-ready` metadata and
diagnostic placeholder files. Do not mix that bundle with the product path.

Accordingly, current bundles report:

```text
readiness = "contract-not-ready"
reason = "placeholder-core-no-semantic-rvfi"
authoritative_rtl_provenance = "none"
pure_simple_authoritative_rtl = "false"
```

Generated CPU, smoke, Linux-handoff, and formal testbench execution terminates
with:

```text
GENERATED_RTL_NOT_IMPLEMENTED lane=rv32
GENERATED_RTL_NOT_IMPLEMENTED lane=rv64
```

This is intentional. It prevents the old time-zero PASS reports from becoming
Linux, MMU, formal, or product evidence.

## Product profiles remain IMAC

The qualified product metadata stays `rv32imac_zicsr_zifencei` / `ilp32` and
`rv64imac_zicsr_zifencei` / `lp64`. RV64 behavioral F/D decode, register bank,
FCSR, and `mstatus.FS` are preserved, but the VHDL product entry is deliberately
RV64IMAC and has no F/D qualification evidence. Promote to `rv64gc`/`lp64d`
only after F/D crosses the same generated-VHDL, ACT4/differential, formal, and
board gates. `GC` is a display alias, never an internal capability boolean.

VHDL **entity/file/package** names that still contain `rv32gc`/`rv64gc` (e.g.
`simple_rv32gc_core.vhd`, `*.debug.json`) are identifiers, not capability
claims, and are renamed only in a coordinated pass with the `simple-riscv`
child repo — do not confuse them with the metadata above.

## Artifact-truth gate

`scripts/check/check-riscv-rtl-truth.shs` classifies every `.vhd` lane
(`reference-handwritten` / `fixture` / `generated-contract` / `generated-real`
/ `absent`) and **fails closed** on fake-CPU evidence: empty architecture, a
`smoke_handoff` step-counter "core", a decode-free / PC-only-incrementer core
(dependency-aware, so a legitimate `core.vhd`+`decode.vhd` split is not a false
positive), and a wrapper instantiating an entity defined in no tracked file. It
ships with a deliberate-red fixture so the gate itself is proven able to fail.
Run it before trusting any generated-RTL claim; a RED result is a finding to
file, not a rule to relax.

## Required compiler

Use a current pure-Simple self-hosted CLI. A binary that prints the Rust
bootstrap warning is not allowed for normal generation, testing, or docgen.
The canonical VHDL command is:

```bash
bin/simple compile --backend=vhdl path/to/hardware_root.spl -o build/path/entity.vhd
```

Successful production generation must write one transactional, fail-clean
artifact triplet:
`entity.vhd`, `entity.vhd.map.json`, and `entity.vhd.gen.json` version 2. The
manifest binds compiler identity/hash, reachable source closure, selected
entry/entity, exact flat ports, target/profile, design-catalog counts, VHDL hash,
and source-map hash. Any write failure removes the partial triplet.

At the time of this guide update, executable checks remain blocked by the
unstable pure-Simple runner. The staged runtime and semantic fixes have not yet
produced a qualified Stage 4 CLI. Qualify Stage 4 before treating source
execution, testing, or doc generation as acceptance.

## Generate the contract bundle

Once a current pure-Simple CLI is available:

```bash
bin/simple run src/hardware/fpga_linux/generate_riscv_fpga_bundle.spl /tmp/simple_fpga_bundle
```

Optional metadata flags:

```bash
bin/simple run src/hardware/fpga_linux/generate_riscv_fpga_bundle.spl \
  --board=mlk_s02_100t \
  --product-level=lab-rtl \
  --profile=compiler-first \
  --rv32-luts=25000 --rv64-luts=45000 \
  --rv32-mhz=50 --rv64-mhz=50 \
  /tmp/simple_fpga_bundle
```

These flags describe a target contract. They do not promote readiness or prove
the budgets.

Inspect:

- `/tmp/simple_fpga_bundle/riscv_fpga_rtl_manifest.sdn`
- `/tmp/simple_fpga_bundle/board_linux_boot_products.sdn`
- `/tmp/simple_fpga_bundle/rv32/rtl/simple_rv32gc_core.debug.json`
- `/tmp/simple_fpga_bundle/rv64/rtl/simple_rv64gc_core.debug.json`
- per-lane CPU, formal harness, `.sby`, and formal `.sdn` files

The manifest uses `contract_file`, not `authoritative_file`. Sidecars have
`authoritative: false`, no source-map claim, zero observed semantic RVFI ports,
no runner success markers, and `linuxBootValidated: false`.

## Generate the product candidates

After Stage 4 qualification, generate each lane independently:

```bash
bash scripts/fpga/generate_rv32_vhdl.shs
bash scripts/fpga/generate_rv64_vhdl.shs
```

RV32 compiles `src/lib/hardware/rv32i_rtl/protected_entry.spl` to
`core32_protected_product_entry`; RV64 compiles
`src/lib/hardware/rv64gc_rtl/imac_entry.spl` to
`core64_imac_product_entry`. Each script then analyzes the compiler product,
WB64 adapter, CLINT, PLIC, UART, interconnect, external-DDR SoC, AXI bridge, and
K26 PL top with GHDL. Missing product artifacts fail the command; there is no
template fallback.

After generation, run the real product-core protection harnesses:

```bash
sh scripts/fpga/ghdl_rv32_product_sv32_pmp.shs
sh scripts/fpga/ghdl_rv64_product_sv39_pmp.shs
```

Each harness executes a compiled RISC-V program through the compiler-emitted
core and WB wrapper, observes the Sv32/Sv39 target page-table walk, and requires
load-access-fault cause 5 while proving the final PMP-denied physical address
never reaches Wishbone. Missing generated cores fail; no CPU stub is accepted.
Each successful log carries a content digest over the core, wrapper, testbench,
fixture, and runner; the RV32/RV64 preflights recompute that digest and reject
marker-only, changed-input, or disconnected logs.

The board synthesis entrypoints reuse one PS-DDR block design:

```bash
bash scripts/fpga/build_k26_rv32.shs --synth-only
bash scripts/fpga/build_k26_rv64.shs --synth-only
```

Build the pinned soft-float Buildroot toolchain/rootfs first, then the
architecture-specific OpenSBI, Linux, DTB, and initramfs:

```bash
sh scripts/os/build_riscv_buildroot.shs rv32
sh scripts/os/build_riscv_buildroot.shs rv64
sh scripts/os/build_rv32_linux_assets.shs --all
sh scripts/os/build_rv64_linux_assets.shs --all
```

Asset compilation defaults to two jobs; set `RISCV_ASSET_JOBS` to another
positive value when host capacity permits. If Buildroot completed the rootfs
and toolchain but only manifest finalization failed, recover without rebuilding:

```bash
sh scripts/os/build_riscv_buildroot.shs rv32 --finalize-only
sh scripts/os/build_riscv_buildroot.shs rv64 --finalize-only
```

Buildroot is fixed at commit
`e4a5ab3b319753f41e2b5cf22e90b6b0304ca225`; OpenSBI v1.4, Linux v6.6,
and BusyBox 1.36.1 are independently commit/source-hash pinned. The two
Buildroot outputs reuse one download cache and retain per-architecture
incremental stamp/output state, while their manifests keep distinct RV32 ILP32
and RV64 LP64 identities. Linux's boot header requires RV32 at
`0x80400000` (4 MiB RAM offset) and RV64 at `0x80200000` (2 MiB); the K26
DDR aliases are respectively `0x40400000` and `0x40200000`. OpenSBI passes
the previous boot stage's DTB pointer through unchanged: the generated FPGA
boot ROM supplies `a1=0x88000000`, while QEMU supplies its `-dtb` address.

After normal PS firmware initializes and reserves
`0x40000000..0x4fffffff`, load each image before programming its PL product:

```bash
K26_PS_DDR_RESERVED=1 RISCV_ARCH=rv32 \
  bash scripts/fpga/load_elf_k26.shs \
  build/fpga/k26_rv32/k26_rv32_product.bit \
  build/os/rv32_soc

K26_PS_DDR_RESERVED=1 RISCV_ARCH=rv64 \
  bash scripts/fpga/load_elf_k26.shs \
  build/fpga/k26/k26_rv64_product.bit \
  build/os/rv64_soc
```

The architecture selects a distinct load log consumed by preflight. A valid
board transcript records host input as `UART_TX_INPUT=root` and
`UART_TX_INPUT=ls /` in order; ILA, RTL preload, marker-only, or unordered
fixture text fails the physical row.

## Operator flow

### 1. Generate RV32 and RV64 RTL from Simple sources

Production acceptance requires the tracked RV32 protected and RV64IMAC product
entries, a qualified pure-Simple compiler, deterministic nonempty clocked/bus
VHDL, the versioned artifact triplet, and changing semantic RVFI. Their exact
flat ports and reset-owned state are source-reviewed, but they are not qualified
until the actual entries compile and execute through the downstream gates.

The CPU boundary owns architectural state and emits physical bus requests. The
SoC owns memory/DTB bytes, address decode, request completion, CLINT, PLIC, UART,
and external DDR. Do not move DTB or memory-image material into the CPU entry.

### 2. Exercise Sv32 and Sv39 translation plus PMP protection

The production CPU must call RV32 `MmuState`/`mmu_*` and RV64
`MmuState64`/`mmu64_*` for instruction and data paths, then apply CPU-owned PMP
before issuing the physical bus request. Acceptance includes SATP,
SFENCE.VMA, TLB refill/invalidation, page/superpage permissions, precise page
faults, A/D policy, TOR/NA4/NAPOT, R/W/X, priority, and locked PMP entries.

Static source integration is not executable MMU/PMP evidence. Require runner,
formal, and generated-RTL results before promoting this step.

### 3. Boot Linux to an interactive login on generated RTL

Build and hash OpenSBI/firmware, Linux, DT, and rootfs separately for RV32 and
RV64. QEMU first validates the media/platform contract. A generated-RTL
simulator must then boot the identical hashes and produce DUT-origin OpenSBI,
kernel, init, and `login:` bytes.

Run the repeatable media oracle only after the matching assets exist:

```bash
sh scripts/os/check_riscv_linux_qemu.shs rv32
sh scripts/os/check_riscv_linux_qemu.shs rv64
```

The wrapper verifies manifest hashes, exposes QEMU's UART over localhost TCP,
and reuses the pure-Simple terminal probe to send `root` and `ls /` in order.
QEMU success is recorded as `qemu-media`; it never satisfies `rtl-sim`.

### 4. Run terminal login and list guest files

The RTL terminal driver must send credentials and `ls /`, observe the accepted
shell prompt and deterministic root entries, and preserve byte-direction and
timestamp evidence. Output-only UART, testbench-origin prompts, reordered
markers, or an injected completion string fail.

Build the pure-Simple probe once, then reuse that artifact after the serial
bridge is listening:

```bash
set -o pipefail
mkdir -p build/fpga/tools
bin/simple native-build \
  --source scripts/fpga --source src/lib --entry-closure \
  --entry scripts/fpga/riscv_linux_terminal_probe.spl \
  --cache-dir build/fpga/tools/cache \
  --output build/fpga/tools/riscv_linux_terminal_probe
build/fpga/tools/riscv_linux_terminal_probe 127.0.0.1 2326 120000 \
  | tee build/fpga/k26/rv64_simpleos_run.log
```

RV32 uses `build/fpga/rv32/rv32_simpleos_run.log` instead. The probe
prints timestamped received chunks and a distinct probe-status marker only
after it observes `login:`, sends `root`, observes the shell, sends `ls /`,
sees the DUT-origin `SIMPLE_RISCV_LINUX_LOGIN_LS_PASS` entry, and observes the
next shell prompt. The fixture token must come from received bytes; the probe
never synthesizes it.

### 5. Program each FPGA image and capture board-origin evidence

Build and program RV32 and RV64 KV260 bitstreams independently. Retain the
board/part/JTAG identity, compiler/RTL/media/bitstream hashes, DRC/timing/
resource reports, programming log, and cold/warm interactive transcripts.

The current host sees the KV260 Xilinx FTDI devices but no external PL UART
adapter. Use an attached 3.3 V PMOD UART or prove a bidirectional PS/PL serial
bridge. ILA-only markers and zero-byte UART captures are diagnostic evidence,
not login/`ls` proof.

## Evidence planes

| Plane | Proves | Cannot prove |
|---|---|---|
| `qemu-media` | firmware/kernel/DT/rootfs and platform contract | generated RTL or FPGA CPU |
| `rtl-focused` | entity/program/MMU/PMP execution | Linux boot or board implementation |
| `formal` | named properties bound to emitted DUT | Linux/terminal/physical behavior |
| `rtl-linux` | generated RTL boots and interacts with pinned Linux | FPGA timing or physical I/O |
| `synthesis` | implemented netlist, DRC, timing, resources | software boot or terminal input |
| `physical-board` | programmed KV260 cold/warm login and `ls` | another XLEN or another bitstream |

Each plane reports `pass`, `fail`, or `blocked`; no plane inherits success from
another.

## Gates

The public dual-lane smoke command is currently expected to return nonzero and
show the diagnostic placeholder:

```bash
sh scripts/check/check-riscv-rtl-linux-smoke.shs --timeout=30
```

It may return zero only after both generated CPU lanes retire real instructions
and their runners require DUT-origin success evidence.

Formal readiness and strict proof are separate:

```bash
sh scripts/check/check-riscv-formal-dual-track.shs
sh scripts/check/check-riscv-rtl-sby-proof.shs
```

Current placeholder harnesses deliberately fail. A port manifest, generated
BYL, or Lean profile proof cannot replace non-vacuous RVFI/SymbiYosys proof of
the emitted CPU.

FPGA preflight and live execution remain separate:

```bash
SIMPLE_BINARY=bin/simple sh scripts/check/check-riscv-fpga-simpleos-preflight.shs --local-only
sh scripts/fpga/check_kv260_simple_riscv_fpga.shs rv32 --with-ghdl
sh scripts/fpga/check_kv260_simple_riscv_fpga.shs rv64 --with-ghdl
```

Do not run these with the Rust bootstrap. Missing bidirectional terminal, DDR,
product bitstream, or board-origin login stays blocked.

## Acceptance and troubleshooting

- `GENERATED_RTL_NOT_IMPLEMENTED`: expected until a canonical compiled CPU
  slice replaces the placeholder. Do not suppress or reinterpret it.
- `check-riscv-rtl-truth.shs` VIOLATION: a real reproducibility/fake-CPU
  finding — file it (see the tracked `soc_top_rv64` dangling-entity bug for the
  pattern), never weaken the checker rule to make the tree green.
- Rust bootstrap warning: restore the current pure-Simple CLI; do not use the
  seed for normal tooling.
- Full CLI exits 139 after a successful Stage3 link: inspect unresolved startup
  stubs in the native-build log; `--version` alone does not qualify the CLI.
- If GDB reaches `rt_process_run_inherit`, do not retry normal delegation. The
  current self-exec fallback also times out in source interpretation; follow
  the tracked full-CLI bug rather than substituting the Rust seed.
- Empty/constant RVFI or missing assertions: fail the formal lane.
- `login:` seen only in QEMU: media oracle passed; RTL/FPGA remains incomplete.
- zero UART bytes with an ILA marker: routing/adapter blocker, not terminal pass.
- negative timing slack or DRC errors: physical implementation fails even if
  simulation passes.

Requirements, architecture, detailed design, system-test plan, and executable
acceptance use the slug `riscv32_riscv64_fpga_simpleos_production`. The mirrored
SPipe manual must be generated from the executable spec after current pure-
Simple docgen is restored; a hand-written substitute is not acceptable.
