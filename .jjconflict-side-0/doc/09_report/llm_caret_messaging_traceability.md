## Retained direct evidence

- `caret messaging status` reports pure-Simple `PureDatabase` with the cached
  `build/database/llm_caret_messaging_db` native carrier. The worker build/run
  command contract is implemented and interpreter-hosted callers select it.
- Runtime evidence is currently blocked: standalone SMF rejects 57 reachable
  PureDatabase functions containing interpreter-only constructs, and bounded
  native database, MCP, and hook carrier builds produced no final artifact.
  No interpreted database fallback was used.
- Focused MCP durability SSpec: 6 examples, 0 failures. It proves restart
  recovery for memberships, profiles, tasks, artifacts, context manifests, and
  non-message idempotency.
- System MCP SSpec: 3 examples, 0 failures. It proves twelve tool discovery,
  private-room send/read, and process-bound workspace authorization.
- Composite plugin validation passes with packaged messaging skill and
  non-secret durable MCP launch configuration.
- The composite plugin runtime system SSpec passes 3/3 for the Claude, Codex,
  and Gemini hook/MCP/compiled-carrier configuration surface.
- Claude/Codex/Gemini hook normalization is implemented, but live session
  control remains unproven. Provider-neutral composition passes 2/2 for attach,
  context injection, submit, steer, cancel, and lifecycle normalization, but
  this is not credential-backed live-provider evidence.
- Claude and Gemini hook stdout now uses each provider's structured
  `hookSpecificOutput.additionalContext` contract. Context is reconstructed
  from the correlated task and ACL-bound PureDatabase room history, redacted,
  byte-bounded, and denied on room mismatch. Focused response and durable hook
  bridge specs pass.
- Gemini now validates as an isolated extension root containing its own hook
  schema, MCP registration, command, context file, and skill; it no longer
  risks loading Claude's same-named root hook file.
- Installed-bundle evidence applies 23 managed operations, validates the
  installed Gemini subroot with the native CLI, plans activation against that
  subroot, and removes 22 owned payloads with zero preserved conflicts.
- The Codex v2 JSON-RPC codec now follows the schema generated by the installed
  CLI, including structured turn input and `expectedTurnId` steering. Its two
  focused examples pass. Three real piped-stdio attempts failed before response
  diagnostics, so the adapter is not yet connected to the live client; see the
  open piped-stdio blocker report.
- The legacy process launcher now resolves Gemini CLI explicitly through
  source-compatible `*_with_gemini` entrypoints instead of silently falling
  through to Claude.
- Correlated provider launches use `launch_messaging_agent_plan` to supply only
  task, room, agent, and PureDatabase identifiers to managed hooks; its focused
  provider-runtime SSpec exits 0 and asserts that no transport token is added.
- The standalone `pure_sql_store_spec.spl` passes 3/3, including restart
  recovery for transport bindings and canonical-to-external message/thread
  references. `composition_spec.spl` also passes 3/3 after reopen.
- The working-tree direct-env audit is blocked by unrelated concurrent work in
  `src/app/build/cli_entry.spl`; the staged audit passes. Messaging code uses the
  canonical `app.io` process/environment facade.
- MCP `tools/list` advertises all twelve `chat_*` tools with object schemas.
- MCP `chat_open_private` → `chat_send` → `chat_read` returns
  `primitive_direct_room`, `accepted`, `canonical_history`, one message, and
  the actual message body.
- A real Claude hook payload was durably queued; `bridge --once` reported
  `{"handled":1,"failed":0}`.
- Plugin validation passes. Isolated install applied 16 operations, check
  verified 15 payloads with zero drift, and uninstall removed 15 unchanged
  plugin-created files with zero preserved changes.
- Installer `--agents` selection is now validated and hash-owned instead of
  ignored. The focused selection SSpec exits 0; prior isolated install counts
  predate the added activation record and are retained only for the earlier
  bundle version.
- The root pure-Simple CLI source now routes `simple caret` to
  `src/app/llm_caret/main.spl`; its focused command-route SSpec passes 2/2 and
  the changed dispatch sources check. The deployed `bin/simple` has not yet
  been rebuilt with this route, so runtime command evidence remains pending.
- Installed integration manifests use `caret messaging` directly, avoiding a
  dependency on the root alias deployment. The launcher interprets only the

  bridge, server, and database operations retain compiled-carrier selection.
  The refreshed composite runtime SSpec exits 0 for all 3 scenarios.
- `src/app/llm_caret/messaging/main.spl` is now the minimal command entrypoint,

## Composite plugin activation evidence

- The executable plugin runtime SSpec passes 7/7, covering compiled carrier
  selection, all three agent lifecycle fragments, MCP credential isolation,
  readiness truth, Claude marketplace publication, and guarded native
  activation planning.
- An isolated install/activation-dry-run/uninstall applied 18 install
  operations, produced Claude marketplace/install, Codex MCP, and Gemini
  extension commands without transport secrets, then removed 17 payloads with
  zero preserved conflicts. Native activation remains an explicit `--apply`
  operation because it changes user-owned agent configuration.
- The reusable pure-Simple PostgreSQL-mimic entry now uses minimal argument
  parsing and owner-module free façades, removing broad CLI/IO imports and
  cross-module database method calls. Its closure contract test exits 0;
  artifact evidence remains pending after Task #145 caused exit 132 on the
  final allowed compile.
- Native offline validation passes with Claude Code 2.1.220 and Gemini CLI
  0.38.1; Codex CLI 0.146.0 accepts the direct stdio MCP configuration through
  a non-persistent config override. This does not claim live provider control.
- `status`, `mcp --probe`, `bridge --probe`, and plugin health now share real
  freshness checks. Missing workers produce explicit not-ready fields and exit
  1; the corresponding system SSpec passes 5/5.
- Compiled readiness additionally requires a build-produced provenance record
  matching the exact worker source, declared PureDatabase/protocol dependency
  hashes, and compiler binary identity. A focused SSpec proves missing and
  forged records are rejected; no artifact is claimed merely from timestamps.
