# Baseline for scripts/check/check-crypto-verify-symbol-collisions.shs
#
# Known-open same-signature collisions between a PURE-Simple implementation and
# a NATIVE rt_-extern SFFI wrapper. Each line: SYMBOL COUNT.
#
# These are the SAME defect class that was proved to break Ed25519 TLS 1.3
# certificate verification on 2026-08-02: a module importing any symbol from
# std.nogc_sync_mut.io.signature_sffi has its explicitly-imported pure verifier
# silently replaced by the SFFI wrapper, which returns false for every input on
# the interpreter engine. The victims for RSA-PSS are the same two files that
# were victims for Ed25519 -- src/os/tls13/_CertVerify/{der_parsing,
# signature_verify}.spl import rsa_pss_sha256_verify / rsa_pss_sha384_verify /
# rsa_pss_sha512_verify from the SFFI module by name.
#
# THEY ARE NOT ACCEPTED. Each needs its own authoritative-backend decision plus
# a caller enumeration before renaming, because unlike the ed25519 case these
# collisions are between two REACHABLE modules -- renaming reroutes live
# callers rather than deduplicating them. Filed as follow-up, not waived.
#
# This baseline may only ever SHRINK. Adding a line requires the same evidence
# bar as removing the guard: don't.

ecdsa_p256_verify 2
rsa_sha256_verify 2
rsa_sha512_verify 2
rsa_pss_sha256_verify 2
