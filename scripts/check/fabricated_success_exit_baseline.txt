#
# Each row is `<path>:<line-of-TEST-FAILED>` for a guest entry that prints
# `TEST FAILED` on the serial console and then calls `rt_qemu_exit_success()`
# within 3 lines. Any lane grading on the guest's exit code reads that as a
# pass. (Both current riscv64 consumers grade on the transcript, so this is a
# latent hazard rather than a currently-firing one — see the bug record.)
#
# WHY THESE ARE STILL HERE, i.e. the exact blocker: `rt_qemu_exit_failure` is
# defined in exactly ONE place tree-wide,
# `examples/09_embedded/simple_os/arch/riscv64/boot/baremetal_runtime_core.inc.c:95`.
# arm32, arm64 and riscv32 have no definition at all, so flipping their call
# sites would either break the link or silently auto-stub the symbol — a worse
# fabrication than the one being fixed. Implementing `rt_qemu_exit_failure`
# for those three arches is the prerequisite; the riscv64 sites were fixed in
# the same commit that created this file, which is why none appear below.
#
# THIS IS NOT AN ALLOWLIST. It is dated, shrink-only debt. A NEW row fails the
# guard, and a row that no longer describes the tree fails it as a STALE
# BASELINE — a baseline that has drifted is how a ratchet silently stops
# ratcheting. Never add a row to make a new failure go away.
