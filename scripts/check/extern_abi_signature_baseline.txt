# Baselined rt_* extern ABI signature mismatches.
# Gate: scripts/check/check-extern-abi-signatures.shs
# Family: doc/08_tracking/bug/rt_extern_abi_divergence_family_2026-08-10.md
#
# Format (tab-separated, exactly as the gate emits it):
#   ARITY  row:  <symbol>  <compiler_arity>  <definition_arity>  <defining_file>
#   RETURN row:  <symbol>  ret:<compiler_class>  ret:<definition_class>  <file>
#
# This baseline is a TWO-WAY ratchet. A new mismatch fails the gate, AND a
# baselined row that stops reproducing fails it as a stale baseline -- so
# fixing a row here without deleting its line is caught too. That is
# deliberate: it is the difference between a baseline and a permanent
# exclusion. Do not add a row here to make a red gate green.
#
# ---------------------------------------------------------------------------
# ARITY rows: NONE. All 21 Class-1 rows (15 symbols) were converted to the
# (ptr, len) ABI, each with a reproduction against the real translation units
# and a re-run in every C link order. The Class-2 rows were fixed, not
# baselined. Header definitions (platform/unix_common.h, platform/platform_win.h)
# are now scanned as well, and added no arity rows.
# ---------------------------------------------------------------------------
#
# RETURN rows: the return-type comparison is NEW. It was added to catch
# rt_file_read_text, which returned `const char*` where the compiler declares
# `&[I64]` -- a RuntimeValue. That symbol is FIXED and is therefore NOT in this
# file. The 33 rows below were triaged into three groups. Nothing is excluded;
# everything the gate found is listed, with what is known about it.
#
# GROUP A -- CLOSED 2026-08-10 (Q35). All 7 rows removed; each fix has an
# execution proof against the real translation units in all three C link orders
# (probe: compiler-emitted ABI, X-padded non-NUL-terminated buffer,
# rt_string_new("hello") as positive control, prior-commit build as revert-proof).
#
#   * rt_array_set -- FIXED in runtime_native.c (void -> int8_t, 1 on write,
#     0 on null array or out-of-range index). CORRECTION to the previous note
#     here: it claimed "the canonical Rust definition already agrees,
#     collections.rs:778 returns bool". There is NO `extern "C"` Rust
#     definition of rt_array_set at all -- that line is an interpreter
#     Value-level helper, not a C-ABI symbol. The agreeing third
#     implementation is src/runtime/simple_core/core_array.spl:182, which
#     already returned i8. Measured before: an IN-RANGE store returned 42, an
#     OUT-OF-RANGE store returned 3, a negative index returned 5 -- leftover
#     argument registers, so a FAILED store reported success. After: 1 / 0 / 1,
#     identical in all three link orders.
#
#   * rt_channel_send -- FIXED in runtime_native.c, both copies (void ->
#     int64_t, 1 queued / 0 dropped). Same correction: channels.rs:103 is not
#     an extern "C" definition either. There IS a live consumer:
#     src/compiler_rust/lib/std/src/async/sffi/channel.spl:7 declares
#     `-> bool`. Measured before: a SUCCESSFUL send returned 0 and a send
#     AFTER CLOSE returned 1 -- the answer was not merely garbage, it was
#     inverted. After: 1 / 0 / 0, identical in all three link orders.
#
#   * rt_invlpg, rt_write_cr3 -- FIXED in runtime_sffi.rs:707-708,
#     `&[I64] -> &[]`, as the previous note prescribed. Nothing anywhere
#     produced that value.
#
#   * rt_file_close -- FIXED, and the return value turned out to be the
#     smaller half of it. The two definitions did not merely disagree on the
#     return: they disagreed on the PARAMETER. descriptor.rs:98 took an fd
#     (i32, matching the compiler); runtime_native.c:8819 took a stdio FILE*.
#     Same arity, so no arity gate could ever have seen it, and under
#     -z muldefs the C copy won -- `rt_file_close(3)` called fclose((FILE*)3).
#     Measured: SIGSEGV on every call in all three link orders, at the prior
#     commit. That C copy is the twin of the fopen() helper a previous commit
#     had already renamed to rt_file_open_stream; it is now
#     rt_file_close_stream, leaving the fd-based definition unopposed (0
#     definitions of rt_file_close remain in the C bundle, verified by nm in
#     all three orders).
#     The return: descriptor.rs now returns close(2)'s real status as i8
#     rather than dropping a File and discarding it, because
#     src/compiler_rust/lib/std/src/infra/file_io.spl:439 reads it and close()
#     is where deferred write-back errors (ENOSPC, EIO, EDQUOT) surface -- a
#     close whose failure is invisible loses data silently. Fixing the caller
#     to stop reading the value would have removed the only place that error
#     could ever have been noticed. The three Simple declarations now agree on
#     `-> bool`.
#
#   * rt_exit -- FIXED IN THE GATE, not in the code, exactly as the previous
#     note prescribed. rust_ret_class now maps `-> !` to a "never" class that
#     the comparator skips: the never type is not a value, so no return
#     register is written or read and there is nothing to compare.
#
# GROUP B1 -- CLOSED 2026-08-10. All 8 symbols resolved, each with its own
# reproduction against the real translation units in all three C link orders:
#   REAL DEFECTS, fixed: rt_env_cwd (tag=0 raw address), rt_platform_name
#     (tag=4, a .rodata pointer that is not even 8-aligned), rt_bytes_to_text
#     (SIGSEGV when the runtime.c copy won the link), rt_dir_walk (legacy
#     SplValue array returned untagged; a 3-file directory read as 0 entries),
#     rt_dir_list (SIGSEGV on EVERY call in EVERY link order -- the compiler's
#     path LENGTH was written through as an `int64_t* out_count`).
#   SPELLING ONLY, bodies already returned correctly tagged values (verified
#     tag=1 with decodable contents before and after): rt_bytes_from_raw,
#     rt_process_run, rt_process_run_timeout.
# Five of eight were real. None was benign by assumption.
#
# GROUP B2 -- pointer-sized value that is genuinely a raw address (rt_alloc,
# rt_array_new/_copy/_repeat/_with_cap_u64, rt_byte_array_new/_len,
# rt_string_data, rt_value_to_ptr, rt_process_spawn). `I64` is how
# RuntimeFuncSpec spells "pointer-sized", so pointer and I64 occupy the same
# return register and the row is ABI-compatible.

#   * rt_coverage_dump_sdn -- WAS A REAL DEFECT, now FIXED, row removed.
#     Measured raw_tag=0 (untagged malloc'd char*) where every Simple

#     producer is now rt_coverage_dump_sdn_cstr (runtime_coverage_core.c,
#     runtime/src/coverage.rs) for the in-process Rust caller and the C

#     After: raw_tag=1, len=219, in all three link orders.
#
#   * rt_host_gpu_queue_last_payload_text -- WAS A REAL DEFECT, now FIXED,

#     exports the *const c_char function under the bare name -- the
#     RuntimeValue-returning rt_host_gpu_queue_last_payload_text_rv carries
#     `#[export_name = "rt_host_gpu_queue_last_payload_text"]` instead.
#     After: raw_tag=1, len=0 (empty queue), in all three link orders.

#   * rt_cli_get_args, rt_get_args -- MEASURED COMPATIBLE, rows KEPT.
