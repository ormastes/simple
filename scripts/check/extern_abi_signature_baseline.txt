# Baselined rt_* extern ABI signature mismatches.
# Gate: scripts/check/check-extern-abi-signatures.shs
# Family: doc/08_tracking/bug/rt_extern_abi_divergence_family_2026-08-10.md
#
# Format (tab-separated, exactly as the gate emits it):
#   <symbol>  <compiler_arity>  <definition_arity>  <defining_file>
#
# Every row here is a CLASS-1 defect: the C copy still takes a single
# `const char*` where the compiler and the Rust SFFI definition agree on a
# (ptr, len) pair. They are latent only while the Rust definition wins the
# link in a given lane; in any lane where the C copy wins they read a
# non-NUL-terminated Simple `text` as a C string and return wrong answers --
# exactly the rt_file_is_char_device failure fixed in 81fca37cdd4.
#
# This baseline is a TWO-WAY ratchet. A new mismatch fails the gate, AND a
# baselined row that stops reproducing fails it as a stale baseline -- so
# fixing a row here without deleting its line is caught too. That is
# deliberate: it is the difference between a baseline and a permanent
# exclusion.
#
# The four CLASS-2 rows (rt_dir_glob, rt_file_find, rt_file_open,
# rt_process_run_with_limits) were fixed, not baselined.
#
# THIS FILE IS NOW EMPTY. All 21 Class-1 rows (15 symbols) were converted to
# the (ptr, len) ABI and removed one group at a time, each with a reproduction
# against the real translation units and a re-run in every C link order. The
# empty state is the goal state: the gate still runs, still selftests, and a
# NEW mismatch fails it immediately. Do not add a row here to make a red gate
# green -- the baseline existed only for the enumerated Class-1 backlog, and
# that backlog is closed.
#
# Two gaps this exercise exposed, worth knowing before trusting a PASS:
#
#  1. The gate parses only src/runtime/*.c at depth 1. It never saw
#     rt_dir_create / rt_dir_remove_all, which are DEFINED in
#     src/runtime/platform/unix_common.h and platform/platform_win.h and pulled
#     into runtime.c's translation unit via #include "platform/platform.h".
#     Definitions in headers are invisible to it.
#
#  2. The gate compares ARITY only. rt_file_sync (runtime.c and
#     runtime_legacy_core.c) already had the correct arity and so was never
#     flagged, but it did `(void)path_len;` and used the pointer as a C string
#     -- the identical defect, invisible to an arity check. Both copies were
#     fixed alongside this family. A parameter-TYPE check (const char* where the
#     spec says a text pair) would catch that class; so would a return-type
#     check, which would catch rt_file_read_text still returning char* where
#     the compiler declares I64.
