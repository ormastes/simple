# Baselined rt_* extern ABI signature mismatches.
# Gate: scripts/check/check-extern-abi-signatures.shs
# Family: doc/08_tracking/bug/rt_extern_abi_divergence_family_2026-08-10.md
#
# Format (tab-separated, exactly as the gate emits it):
#   ARITY  row:  <symbol>  <compiler_arity>  <definition_arity>  <defining_file>
#   RETURN row:  <symbol>  ret:<compiler_class>  ret:<definition_class>  <file>
#
# This baseline is a TWO-WAY ratchet. A new mismatch fails the gate, AND a
# baselined row that stops reproducing fails it as a stale baseline -- so
# fixing a row here without deleting its line is caught too. That is
# deliberate: it is the difference between a baseline and a permanent
# exclusion. Do not add a row here to make a red gate green.
#
# ---------------------------------------------------------------------------
# ARITY rows: NONE. All 21 Class-1 rows (15 symbols) were converted to the
# (ptr, len) ABI, each with a reproduction against the real translation units
# and a re-run in every C link order. The Class-2 rows were fixed, not
# baselined. Header definitions (platform/unix_common.h, platform/platform_win.h)
# are now scanned as well, and added no arity rows.
# ---------------------------------------------------------------------------
#
# RETURN rows: the return-type comparison is NEW. It was added to catch
# rt_file_read_text, which returned `const char*` where the compiler declares
# `&[I64]` -- a RuntimeValue. That symbol is FIXED and is therefore NOT in this
# file. The 33 rows below were triaged into three groups. Nothing is excluded;
# everything the gate found is listed, with what is known about it.
#
# GROUP A -- compiler declares a result, the definition returns `void`
# (6 rows: rt_array_set, rt_channel_send, rt_file_close x2, rt_invlpg,
# rt_write_cr3) plus the inverse rt_exit (declared void, Rust returns i64).
# REAL: the caller reads a return register the callee never wrote. Bounded in
# practice only by callers discarding the value, which the ABI does not
# guarantee. Not fixed here -- each needs its own call-site audit and per-lane
# reproduction, the standard the Class-1 rows were held to.
#
# GROUP B1 -- SAME CLASS AS rt_file_read_text, NOT YET FIXED (8 symbols):
#   rt_bytes_from_raw, rt_bytes_to_text, rt_dir_list, rt_dir_walk, rt_env_cwd,
#   rt_platform_name, rt_process_run, rt_process_run_timeout
# For each of these the canonical Rust definition returns a TAGGED
# `RuntimeValue` while the C copy returns a raw `char*`/pointer. That is
# exactly the defect just fixed for rt_file_read_text: in any lane where the C
# copy wins the (-z muldefs) link, a successful call decodes as an untagged
# value and reads as empty -- indistinguishable from "not found". These are
# baselined, not dismissed; each needs the same reproduce-fix-verify-in-three-
# link-orders treatment.
#
# GROUP B2 -- pointer-sized value that is genuinely a raw address (rt_alloc,
# rt_array_new/_copy/_repeat/_with_cap_u64, rt_byte_array_new/_len,
# rt_string_data, rt_value_to_ptr, rt_process_spawn). `I64` is how
# RuntimeFuncSpec spells "pointer-sized" and no RuntimeValue-returning
# counterpart exists, so pointer and I64 occupy the same return register and
# the row is ABI-compatible. NOTE the residual: for rt_cli_get_args,
# rt_get_args, rt_coverage_dump_sdn and
# rt_host_gpu_queue_last_payload_text there is no Rust counterpart to compare
# against, so they are placed here for lack of evidence, NOT proven benign.
#
# Removing a row from this file is the correct outcome of fixing it; the
# ratchet enforces that.
