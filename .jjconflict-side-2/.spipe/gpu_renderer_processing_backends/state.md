## Task Type

## Refined Goal
Make web-renderer and Engine2D processing kernels compile through the shared ProcessingIR contract to validated SPIR-V/Vulkan, runnable CUDA, and Metal MSL backends, with device-origin correctness evidence on available hosts and explicit resumable native-host evidence for unavailable CUDA or macOS capabilities.

## Acceptance Criteria
- AC-1: A documented shared `ProcessingIR` input and `ProcessingBackendArtifact` result contract drives Vulkan/SPIR-V, CUDA, and Metal MSL generation without backend-specific public renderer APIs.
- AC-2: Representative web-renderer and Engine2D offload kernels lower through the LLVM/processing pipeline to SPIR-V, pass `spirv-val`, submit to Vulkan, and produce device-origin readback exactly matching a CPU oracle on the current Linux host.
- AC-3: The same representative processing semantics generate CUDA code, compile with the repository's canonical CUDA toolchain path, and, where an NVIDIA device is available, execute with device-origin readback exactly matching the CPU oracle; otherwise the executable evidence remains blocked with a tracked prerequisite and exact resume command.
- AC-4: After research and architecture/design artifacts exist, a Metal backend generates deterministic MSL from the same ProcessingIR semantics and host-independent tests validate its source and binding contract.
- AC-5: Native macOS Metal tests compile the generated MSL, execute it on a Metal device, and compare raw device readback to the CPU oracle; when macOS is unavailable, executable specs report `blocked`/`unsupported` without skip or PASS and `todo_db.sdn` records the host, prerequisites, retained artifacts, exact resume command, owner, and final reviewer.
- AC-6: Backend selection and failure handling fail closed: invalid artifacts, validation/compiler failures, unavailable devices, and unsupported kernel features cannot be reported as GPU execution or silently substituted with CPU-mirror evidence.
- AC-7: Focused unit, integration, and SPipe system scenarios cover generation, validation, selection, submission, readback provenance, oracle parity, and semantic invalidation for all three backends; mirrored `doc/06_spec` manuals are usable without opening source specs.
- AC-8: Processing backend architecture/TLDR and operator guide remain current and describe startup/hot paths, artifact caching and invalidation, backend order, latency/RSS targets, and native-host evidence commands.
- AC-9: Focused compile/lint/duplicate and direct-runtime guards pass once per acceptance criterion, generated-spec layout count is zero, and final verification reports unavailable native-host rows as blockers rather than claiming full completion.
- AC-10: Integration preserves unrelated dirty work and the final high-capability review confirms the three lane results use the shared interfaces and satisfy generated-manual quality before any done mark.
- AC-11: Representative GPU drawing-access kernels preserve resource bindings, coordinate/pixel semantics, and CPU-oracle results through CUDA-to-Vulkan and CUDA-to-DirectX translation, native Vulkan-to-Vulkan execution, and Metal-to-Metal execution; focused tests reject unsupported or lossy translations.
- AC-12: CUDA-to-DirectX generation has host-independent artifact/binding tests and an executable Windows DirectX device-readback test; if Windows is unavailable, the executable row remains blocked with a tracked host prerequisite and exact resume command rather than being counted as PASS.
- AC-13: Environment tests identify runtime library, HAL/wrapper, physical device or emulator, compiler/validator, memory capabilities, and backend readiness without treating library presence as execution proof.
- AC-14: Vulkan and CUDA environment tests prove CPU-to-GPU upload, GPU execution, GPU-to-CPU readback, stable device identity/handle, exact byte/pixel parity, repeated dispatch, and fail-closed invalid transfer behavior through the canonical HAL/wrapper owners.
- AC-15: Metal emulation tests prove MSL artifact/binding/dispatch/readback state-machine semantics and rendering parity without claiming physical Metal execution; the same scenario is executable against native Metal on macOS.

## Scope Exclusions
Unrelated Engine3D HUD/world rendering is outside this feature. CPU fallback remains an oracle/fallback below ProcessingIR, not evidence of GPU execution.
