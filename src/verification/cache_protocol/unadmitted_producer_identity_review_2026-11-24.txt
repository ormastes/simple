Unadmitted producer identity live-key source review (2026-11-24)

Reviewed binding (Generated/LiveKey.lean, T-K1):
  incremental.spl#native_build_compiler_identity

What changed: when SIMPLE_ABI_POLICY or SIMPLE_ABI_ADMISSION_RECEIPT is unset,
the function used to return
`uncacheable-abi-admission-<reason>-<pid>-<micros>` and now returns
native_build_unadmitted_producer_identity(...), i.e.
native_build_producer_identity(exe hash, compiler+stdlib fingerprint, runtime
provider fingerprint, bundle, ABI version, ABI deferred, policy,
"unadmitted-v1"). The two runtime ABI reads moved above that branch; their
values are unchanged. The named-but-unreadable and rejected-receipt branches
and the no-executable-hash fallback still return a per-process identity.

Why: the per-process value was folded into the object scope directory and
every module witness, so no per-file batch and no re-run of an unadmitted
compiler ever reused an object (p3r 2026-11-24: 85 scope dirs for 85 batches,
77 modules rebuilt byte-identically).

Model impact: none on the modelled key. Field set, component order and the
length framing of native_build_producer_identity are untouched, so each
producer_* change-visibility theorem holds for the new branch exactly as for
the admitted one: exe, compiler source, runtime, bundle, ABI policy, ABI epoch
and admission are all still encoded. "unadmitted-v1" is a fixed admission
value that no admitted identity (`policy=...;receipt-sha256=...`) can equal.
What is relaxed is a policy outside the model: an unadmitted compiler may now
match its own earlier entries instead of never matching anything. No Lean
change required.

Validation: source-binding --update re-pinned only the binding above.
