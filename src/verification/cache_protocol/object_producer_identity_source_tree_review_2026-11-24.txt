Object producer identity: cwd source trees as producer vs input (2026-11-24)

Reviewed source change: src/compiler/80.driver/driver_build/incremental.spl
  native_build_compiler_identity           body moved, value unchanged
  native_build_identity_for_tree_rule_v1   the former body, plus the tree rule
  native_build_object_producer_identity    new: scope directory + witness config
  native_build_source_tree_is_producer_v1  new: pure fail-closed rule
  native_build_producer_source_term_v1     new: pure compiler= term encoding

What changed in the key. producer_compiler_src (pos 2) and producer_stdlib_src
(pos 36) are framed into the compiler= term exactly as before by default. Only
in a process that took the CLI dispatch branch into the worker entry linked into
the image (native_build_declare_linked_worker_entry_v1), with both seed probes
false, the hashed executable equal to the running image, a known worktree root
and no debug info, is the term "embedded+worktree:<sha256(cwd)>" in the two
per-module object consumers (scope directory and module witness config).
The probes alone prove nothing (constant false outside the seed), so they are a
second gate, never the reason.

Model. No component or gap is added or removed; live_object_key.sdn and
Generated/LiveKey.lean are unchanged. The per-field visibility theorems are
statements about the framed field value and still hold for the value that is
framed. What moves is the route by which src/lib and src/compiler CONTENT is
key-visible for a native producer: it is no longer a producer scalar, it is an
input that reaches the key through entry_module_witness (pos 35), whose MIR
identity is computed after lowering, which always runs on the default object
path (the same route the schema already states for impl sets and inline/const
bodies at pos 40-42).

Consumers that reuse a result without lowering keep the tree-bound identity
(native_build_compiler_identity): the MIR resume ledger run key, the opt-in
pre-lowering cache, no-op admission and the stage receipts. Their keys are
byte-identical to before.

Capsule MIR identity (native_capsule_mir_identity.spl) now also carries the
emitter-read attributes it omitted: function naked/inline/section/align/global/
comdat/SIMD requirement/nogc_strict/short_call_contracts, static alignment/
linkage/is_external, module xray_ring_wrap. Each row or suffix appears only
when not at its default, so ordinary identities are unchanged. Spans are not
added; debug-info builds keep the tree-bound identity instead.

Not proven here (static review only, no build or spec run was possible):
- what the shared backend_session lease handed to the emitter carries;
- that serialize_mir_function is lossless for instruction-level detail;
- a hand-made run of a compiler SMF given the worker argv and marker.
