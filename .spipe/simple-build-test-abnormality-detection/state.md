# Feature: Simple Build/Test Abnormality Detection

## Raw Request

Update the supplied research, create the plan and design documentation, and implement performance and memory abnormality-detection infrastructure for Simple builds and tests.

## Task Type

feature

## Refined Goal

Provide first-class, cross-platform build/test resource evidence, deterministic budgets, structured compiler/test work metrics, cohort-safe approved baselines, and robust historical anomaly detection without conflating enforcement, measurement, or regression policy.

## Acceptance Criteria

- AC-1: The selected feature and NFR requirements preserve independent hard limits, declared budgets, and historical anomaly decisions; a baseline can neither weaken a budget nor promote itself automatically.
- AC-2: `ExecutionResourceScope` reports explicit evidence quality and termination cause plus wall/CPU, direct-child memory, aggregate tree memory when available, I/O, and process-count evidence without calling unlike metrics “RSS”.
- AC-3: Linux provides cgroup-v2 tree accounting/enforcement with a documented lower-quality `wait4`/process-tree/RLIMIT fallback; Windows Job Objects and macOS/Unix process-group fallbacks have explicit supported or blocked evidence rows.
- AC-4: Exit 137/139, SIGSEGV, external SIGTERM, watchdog timeout, cgroup OOM, and PID-limit events are classified from affirmative evidence; ambiguous cases remain unverified rather than being guessed.
- AC-5: Build and test runs persist compatible stable-subject and volatile-observation SDN records containing hierarchical spans, stable phase IDs, work counters, resources, budgets, anomalies, and external artifact digests.
- AC-6: Cohort identity separates semantic configuration/scenario from machine environment and includes mode, target, optimization, cache state, bootstrap stage, concurrency, aspects, workload, and tool/schema digests.
- AC-7: Approved baselines remain frozen until explicit promotion; provisional/suspect/superseded states, paired robust comparisons (absolute + relative + MAD), confirmation policy, tail evidence, and gradual-drift detection are testable.
- AC-8: Build/test commands enforce standard resource quantities and resource classes without historical data silently loosening explicit budgets; whole-scope enforcement precedes efficient nested/per-unit supervision.
- AC-9: Parser/HIR/type/monomorphization/MIR/optimization/AOP/backend/link work counters and stable spans support work-normalized and missing-phase detection, including suspicious apparent speedups.
- AC-10: Tests cover direct-child and grandchild memory, proven memory/PID/wall violations, real SIGSEGV, external termination, cohort separation, frozen-baseline +25% regression, missing required phase, retained tail spike, incremental invalidation evidence, and N/2N/4N/8N complexity regression.
- AC-11: The implementation uses pure-Simple owner facades first; any runtime additions document `runtime_need`, `facade_checked`, `chosen_path`, and `rejected_shortcuts`, and every kill/wait rejects `pid <= 0`.
- AC-12: Research, requirements, architecture, detailed design, system-test plan/spec/manual, agent-task plan, developer guide, feature-expert and layer-expert skills are current; unresolved gaps have file:line bug/Todo records and actionable owner/unblock data. Workflow skill/agent/command changes are N/A unless the implemented command or verification contract changes.
- AC-13: Focused Simple tests/lint/duplicate checks, direct-runtime guards, generated-spec layout guard, supported platform contract tests, and production-readiness verification pass once against the exact changed surfaces.
