# Feature: UTF-8 Internationalized Text Architecture

## Raw Request

Extend the UTF-8 and internationalized-text research, design the architecture and implementation plan, include Simple 2D and 3D text rendering, and require intensive correctness, 100% branch-coverage, memory, and performance testing across all supported profiles and backends.

## Task Type

feature

## Refined Goal

Define and implement one validated-UTF-8 text, Unicode, localization, and rendering architecture whose canonical Simple 2D and separate Engine3D text consumers share shaping and transient font material, with exhaustive branch coverage and retained correctness, latency, throughput, allocation, RSS, binary-size, and device-readback evidence across every supported profile and backend.

## Acceptance Criteria

- AC-1: Research audits the current `text`, Unicode, codec, I/O, parser, i18n, Draw IR, Engine2D, Engine3D, shaping, atlas, font-renderer, test, coverage, and benchmark implementations against pinned primary standards and current repository evidence; every contradiction or unsupported claim is recorded with an owner and unblock condition.
- AC-2: Safe APIs cannot create malformed `text`; arbitrary bytes remain byte types; strict streaming decoding is the default; lossy behavior, encoding labels, coordinate units, boundary errors, and complexity are explicit and typed.
- AC-3: The public architecture uses the shared interfaces `TextView`, `TextSlice`, `TextIndex`, `TextCursor`, `TextBuilder`, `Utf8Buf<N>`, `TextDecoder`, `TextEncoder`, `TextSink`, `IndexedText`, `GraphemeView`, `LocaleContext`, `MessageId`, `MessageSchema`, and `MessageIR`, layered on the existing validated UTF-8 `text` primitive without a competing base string object.
- AC-4: Simple source parsing remains byte-span based, uses an ASCII/block fast path and pinned Unicode slow paths, borrows source ranges before allocating, unifies ordinary/f/raw/i18n string scanning, and converts byte positions to scalar, grapheme, UTF-16, or display coordinates only at explicit boundaries.
- AC-5: Web and GUI text producers emit semantic `DrawIrComposition`; selected shaping crosses Draw IR only through handle-free `DrawIrGlyphRunPayload`; Engine2D lowers text through `draw_text` into the canonical `FontRenderer` and transient `FontRenderBatch`; atlases, face handles, caches, and backend resources never enter Draw IR.
- AC-6: Engine3D HUD, screen-space, billboard, world-space, and depth-aware text are designed as separate consumers of the same shaping, glyph identity, `FontRenderConfig`, `FontRenderer`, atlas, and transient batch ownership, without becoming a GUI/Web/Draw IR/Engine2D shortcut or creating a second renderer/cache/atlas.
- AC-7: Text layout and rendering define normalization, grapheme, BiDi, script/language shaping, fallback, cluster mapping, line breaking, hit testing, selection, terminal display policy, DPI/scale, transforms, depth/occlusion, antialiasing, hinting, color glyphs, and accessibility semantics, with fail-closed unsupported combinations.
- AC-8: Localization preserves explicit named-message syntax, uses stable typed IDs and schemas, compiled one-pass `MessageIR`, pinned CLDR plural/select behavior, explicit `LocaleContext`, BiDi isolation, deterministic fallback, and dead-strippable default-only, single-locale, multi-locale, embedded, and no-allocation profiles.
- AC-9: Every normative requirement maps to executable SSpec scenarios using built-in matchers and typed evidence. The primary manual flow uses exactly: `Load the pinned multilingual font manifest`; `Accept exact-face-bound simple-script shaping`; `Prepare one shared font batch for 2D and 3D`; `Emit the selected font composite program and plan compilation`; `Prove native submission and device readback`.
- AC-10: Test design targets 100% branch coverage for every newly introduced or materially changed text/i18n/rendering owner and all error/recovery branches. Coverage is measured per owner and aggregate; unreachable defensive branches require reviewed proof and are excluded from the denominator rather than marked covered. Existing untouched third-party/vendor code is excluded per repository policy.
- AC-11: The intensive matrix covers scalar and every compiled SIMD backend; sync/async and GC/no-GC/mutable/immutable/noalloc profiles; UTF and selected legacy codecs; every short-input chunk partition and output-capacity boundary; malformed encodings; normalization and segmentation conformance; parser differentials; catalog/message behavior; 2D and 3D layout/material/rendering; CPU oracle parity; GPU emission, compilation, submission, fence, device-origin readback, and pixel/hash parity; unavailable native rows remain blocked, never skipped or passed.
- AC-12: Performance evidence records baseline and after results for latency, throughput, cycles/byte, allocations, bytes copied, transient workspace, builder growth/waste, sparse-index overhead, peak/steady RSS, linked Unicode/catalog data, binary size, startup, parser throughput, frame preparation, upload, queue/device completion, readback, and frame time on deterministic multilingual corpora and boundary sizes. ASCII and i18n-disabled paths do not regress beyond calibrated gates.
- AC-13: Reference scalar, optimized portable, and architecture-specific implementations share one semantic contract, generated vectors, forced-backend differential tests, fuzz targets, and dispatch inventory; an optimized backend is complete only with active dispatch, correctness parity, coverage, and retained performance evidence.
- AC-14: Requirements, architecture, detailed design, 2D/3D rendering design, system-test plan, performance plan, migration plan, agent-task plan, executable specs, mirrored manuals, and implementation sequencing exist at canonical paths and are internally traceable.
- AC-15: Knowledge updates cover `doc/01_research`, `doc/02_requirements`, `doc/03_plan`, `doc/04_architecture`, `doc/05_design`, `doc/06_spec`, affected `doc/07_guide` pages, `doc/00_llm_process/feature_expert/text_i18n/skill.md`, and `doc/00_llm_process/layer_expert/text_rendering/skill.md`. Gaps not fixed receive `doc/08_tracking/bug` or Todo DB records with file/line evidence, named owner, and actionable unblock condition. Workflow skill/agent/command files are N/A unless the lane changes SPipe behavior itself.
- AC-16: Verification runs each acceptance command at most once after its last relevant change, stops after three distinct fix/verify cycles, proves generated-manual quality and zero executable specs under `doc/06_spec`, and reports implementation, host, backend, coverage, and performance gaps honestly without converting planned tests into PASS evidence.

## Scope Exclusions

- Replacing the canonical flat `text` primitive with UTF-16, UTF-32, a variable-width multi-representation string, or a second unrelated heap `Text` object.
- Treating terminal display cells, grapheme clusters, scalar ordinals, UTF-16 positions, and byte offsets as interchangeable.
- Creating a private Web, GUI, Engine2D, or Engine3D font renderer, atlas, cache, shaping implementation, or GPU dispatch system.
- Claiming unavailable physical GPU, operating-system, architecture, or no-allocation evidence from source inspection, emulation, fallback pixels, synthetic handles, or CPU mirrors.
- Vendored/third-party runtime source is outside owned-code coverage unless explicitly modified.
