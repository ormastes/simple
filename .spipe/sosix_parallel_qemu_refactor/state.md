## Raw Request

## Task Type

code-quality

## Refined Goal

Refactor SOSIX and the SimpleOS QEMU harness around one reusable, fail-closed contract, then prove boot, filesystem listing, and target-native program execution for every required host and x86/ARM/RISC-V 32/64 guest row with explicit retained evidence.

## Acceptance Criteria

- AC-1: One canonical QEMU descriptor/settings API owns emulator, machine, CPU, firmware, accelerator, memory, disks, network, serial, QMP, timeout, markers, artifact paths, and host overrides; all SOSIX system lanes consume it without copied argv fragments.
- AC-2: SOSIX is refactored into typed operation/completion, cancellation/deadline, capability/buffer reference, filesystem, compatibility, and GPU-proxy owners while existing POSIX offset/errno behavior remains covered.
- AC-3: Executable SPipe scenarios cover Windows, Linux, macOS, and FreeBSD host rows and SimpleOS guests for x86_32, x86_64, ARM32, ARM64, RISC-V32, and RISC-V64; absent hosts are `blocked`/`unsupported`, never skipped or passed.
- AC-4: Every guest row proves real firmware/board-representative boot, serial identity, and a clean boot marker using its canonical descriptor; QEMU fixed-command fixtures are rejected.
- AC-5: Every SimpleOS guest row mounts the intended filesystem and executes in-guest `ls` (or the canonical SimpleOS equivalent), retaining output that includes the expected toolchain/program payload.
- AC-6: Every SimpleOS guest row executes at least one arbitrary program loaded from that filesystem; compiler-in-filesystem rows additionally run `/usr/bin/simple --version` and compile/run `hello.spl` in guest.
- AC-7: Artifacts are bound to source revision, compiler path/hash/provenance, guest kernel/image hashes, QEMU path/version, exact argv, accelerator, host/guest identity, exit status, serial transcript, and filesystem/program receipts.
- AC-8: KVM/HVF/WHPX native applicability requires the executed argv to contain the available accelerator; TCG rows prove correctness only. macOS may be postponed only through an open row with prerequisite, exact resume command, retained-artifact path, owner, and final reviewer.
- AC-9: QEMU settings scripts provide `--check`, `--print`, `--prepare`, and bounded `--run` behaviors; resolve `SIMPLE_BIG_STORAGE_ROOT`, then a workspace-local configuration, then `$HOME/.simple`; use `/mnt/data/.simple` through the local configuration on this host; never delete another lane's artifacts; and pass shell/self-tests.
- AC-10: Queue, capability, cancellation, timeout, reset/epoch, partial-progress, filesystem offset/errno, boot, mount, listing, and filesystem-exec behavior have non-vacuous unit/integration/system coverage plus deliberate-red sabotage evidence.
- AC-11: The host/guest matrix runs at most once per unchanged criterion per session and caps each row at three distinct fix/verify cycles; unavailable native rows remain active and block umbrella PASS.
- AC-12: The generated/manual SPipe document is an operator manual using the shared steps `Load the canonical QEMU settings`, `Prepare isolated guest media`, `Boot the requested host and guest row`, `Inspect the mounted filesystem`, `Run an arbitrary filesystem program`, and `Retain the correlated evidence bundle`, with zero stubs and no executable `.spl` under `doc/06_spec`.
- AC-13: Documentation is updated in research/requirements/architecture/design/plans, the QEMU operator guide, `.claude/skills/spipe.md`, corresponding Codex/Claude/Gemini workflow surfaces or explicit N/A rationales, and both feature/layer expert wiki entries; every unfixed gap gets a `doc/08_tracking/bug/` record with file:line and unblock condition.
- AC-14: Final verification runs the direct env/runtime guards, focused SOSIX/QEMU specs, all six guest rows, all available native-host rows, required compiler/core/MCP checks if touched, and the release-bound `bin/simple test test --whole --mode=interpreter`; every required row has fresh evidence before STATUS: PASS.
- AC-15: WM/GUI/Web/Draw IR/Engine2D host dependencies are inventoried and refactored behind typed SOSIX display, input, timer, configuration, file, process/IPC, and library capabilities without moving rendering semantics or transient GPU state into SOSIX.
- AC-16: Deferred host operations (present/readback, input wait, timers, evidence I/O, QMP/process, and window control) use typed asynchronous SOSIX operations with cancellation/deadlines; compatibility waits are notification-based and frame/pixel hot paths do not issue fine-grained host requests.

## Scope Exclusions

- Physical-board proof is not substituted for QEMU proof and is not required unless a later requirement adds it.
- macOS native execution may be handed off, but is not removed from completion scope.
- GDS/RDMA and SOSIX-G network/USB tiers are later waves unless selected after the filesystem slice.

## Runtime Boundary Decision

- `runtime_need`: QEMU process execution and evidence file I/O only.
- `facade_checked`: required before implementation through `std.io_runtime`/`app.io.mod` and existing `QemuRunner` owners.
- `chosen_path`: reuse existing facades and extend the smallest QEMU owner.
- `rejected_shortcuts`: raw test-local `rt_process_*`/`rt_env_get`, fixed-command guest stubs, host-side `ls` or compile/run, copied argv strings, and seed substitution.
